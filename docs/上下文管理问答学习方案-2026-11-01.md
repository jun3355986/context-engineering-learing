# 上下文管理问答学习方案

> [!important] 接手请先读 [[上下文管理学习计划]]
> 那份是入口和交接文档，含当前进度、操作手册、环境和开场提示词。本文档保留方案的设计理由；**进度日志已并入那份，本文档第 9 节停更。**

> [!abstract] 速览
> - **目标**：直接、高效地学会 agent 上下文管理。不亲自读源码，源码层的证据由 AI 核对。
> - **做法**：AI 出 5 题 → 我答 → AI 批改、给带证据的标准答案、讲原理、补我的薄弱点。
> - **产出**：每轮的 HTML 讲解页（图文 + 交互）一点点长成**第四版**。第四版以问答主线为准，不对齐第三版。
> - **疑问通道**：我随时可以提自己的疑问，AI 当轮解答，与主线相关的纳入第四版。
> - **公众号**：不是每轮都出。我觉得熟悉了、内容满意了才生成。
> - **取代**：本方案取代 [[程序猿/ai/上下文管理/docs/上下文管理自学方案-2026-10-29|2026-10-29 的自学方案]]。U01 的材料和实验保留，当证据来源用。

## 1. 为什么换

旧方案要我自己跑实验、读源码、写笔记。我现在不需要练这些，缺的是**被追问、被纠错**。旧方案里的第 5 步（出题考问）原本就是这个，现在提到主线，读源码和写笔记交给 AI。

第三版里有错（比如「压掉的细节绝不可能找回」），所以第三版只当**素材和待核对的清单**：每轮把要考的论断对照源码核一遍，错的改掉，告诉我真正的原理。

## 2. 每轮怎么走

```text
AI:核对本轮涉及的第三版论断 → 出 5 题（只出题，不给材料）
我:直接在对话里答，不确定就写「不知道」
AI:逐题批改 → 带证据的标准答案 → 原理解析 → 针对我的错因补讲
   → 生成 HTML 讲解页（第四版的一章草稿）
   → 列一份简单的第三版勘误（只列条目，供扫一遍）
   → 登记薄弱点
```

- **通过标准**：✅ 记 1 分，🟡 记 0.5 分，满 5 分，≥4 分过关。没过就补考 3 道薄弱点题，再进下一单元。
- **复测**：之后两轮，每轮插 1 道旧薄弱点的题，改条件重考，不重复原题。

### 2.1 题型配比（每轮 5 题）

| 题型 | 数量 | 考什么 |
|---|---|---|
| 列结构 | 1 | 有哪几块、什么顺序 |
| 预测 | 2 | 改一个条件会怎样（含量级估算） |
| 诊断 | 1 | 现象反推原因 |
| 取舍 | 1 | 选哪个、代价是什么 |

具体数字（上限是多少字节）不单独出题，只在解析里给。要懂的是为什么有上限、超了怎么办。「不知道」是合法答案。

### 2.2 批改标记

✅ 对 · 🟡 半对 · ❌ 错 · ⬜ 不知道。🟡 和 ❌ 再标错因：漏项 / 因果或顺序反 / 概念混淆 / 以偏概全 / 数字记错。

## 3. 让标准答案可核对

出题的 AI 同时给标准答案，我分不清是我错了还是 AI 错了。所以：

1. **每条结论带证据等级**：【源码 文件:行号@提交】【实验】【官方文档】【第三版原文，未核】【推测】。没核对到的标出来，不装作确定。结论写明版本（Codex 源码 `76ed3b4`，CLI `0.165.0`）。
2. **每轮附一条 30 秒能复现的检查**（一条命令或一段实验输出），我不读源码也能抽查。
3. **随时说「给证据」**，AI 要拿出出处。
4. **单元收尾的独立复核**：用新会话或子代理审一遍该单元的标准答案，避免 AI 自己批自己的卷。开之前先问我。
5. Claude Code 只有非官方源码，引用时标「来源：Claude Code 非官方源码 v2.1.88」。官方没公开的服务端行为，只能标官方文档或推测。

## 4. 解答用 HTML 交互

每轮的解答做成一个 HTML 页，放在 `ai codiing 工具上下文对比报告/第四版/`。

| 规范 | 内容 |
|---|---|
| 形式 | 单文件，CSS 和 JS 内联，不依赖网络，双击能开；跟随系统浅色/深色；手机宽度能读 |
| 固定四块 | ① 本轮批改（我的原话、判定、错因，标 `data-personal`，成书时去掉）② 主线讲解（图 + 能自己改条件的交互）③ 一页纸小结 ④ 证据表（每条结论的出处与等级） |
| 交互 | 用真实实验数据驱动，让我能改条件看结果。不做纯装饰的动画 |
| 例子 | U01：请求拆解条形图，点每一块看原文；滑块改 AGENTS.md 大小，看截断落在哪 |

## 5. 第四版怎么长出来

- **每轮的 HTML 讲解页就是第四版的一章草稿。** 章节顺序跟着问答主线走，不对齐第三版的 61 页。
- `第四版/index.html` 是目录，每轮追加一项。
- 第三版冻结，只当参考。第四版里和第三版不同的地方，以核对过的证据为准。
- 成书时去掉 `data-personal` 部分，补章节间的过渡。
- 公众号文章从第四版的章节里取，用「设计卡 → 成稿 → 冷读」的流程。**不是每轮都出**：同一薄弱点复测连续答对、我能不看解析复述主线、我对解析满意，才由我决定生成。

## 6. 我的疑问通道

- 我随时可以提疑问，不用等到下一轮。
- AI 当轮解答：短的在对话里答；需要图的，做成 HTML「疑问卡」挂到相关章节。
- 记在 `自学单元/我的疑问.md`：问题 / 归属单元 / 状态 / 回答在哪。
- **主线仍是上下文管理。** 与主线相关的疑问，纳入对应章节和第四版；偏离主线的，简答并标「支线」，不进第四版。

## 7. 学习路线

沿用 U01–U11。顺序按前后依赖排，一个单元一轮；疑问可能插入新的轮次，路线随之调整。

| 单元 | 问题 | 第三版可参考 |
|---|---|---|
| U01 | 我只说了一句话，请求里装了什么，各占多少 token？ | intro-01/02、main-01/02/04/05、src-codex-02/03 |
| U02 | 一条命令输出几万行，agent 怎么没被撑爆？ | intro-03、main-06/07、src-codex-04 |
| U03 | 压缩之后，它还记得我的哪句话？ | main-08/09、src-codex-01、adv-02 |
| U04 | 对话越长越贵吗？缓存省的是什么？ | intro-05、main-13 |
| U05 | 工具接得越多，agent 为什么越容易用错？ | main-03 |
| U06 | 子代理替主会话省了什么？ | main-10 |
| U07 | 回退、分叉、恢复，各能撤销什么？ | main-11 |
| U08 | 新开一个会话，它怎么还记得我？ | main-12 |
| U09 | 窗口真满了会怎样？ | main-14 |
| U10 | 怎么判断一种做法更好？ | main-15/16、adv-05 |
| U11 | 结业：给一个具体场景设计上下文策略 | adv-01/03/04 |

主例以 Codex 为主，其他 agent 只在做法明显不同时对照。
