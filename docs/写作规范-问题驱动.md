## 0. 读者与参考

**读者**：有软件开发背景，正在学 AI 编程 agent 的上下文管理；不读源码，要结论、原理和证据。

**参考的三本书，各借一样东西：**

| 书 | 借什么 |
|---|---|
| 《操作系统导论》（OSTEP） | 每章开头写清「关键问题」。先讲最朴素的做法，看它在哪出问题，再引出改进 |
| 《数据密集型应用系统设计》（DDIA） | 按问题组织，不按产品组织；产品只在讲概念时当例子出现；每章用取舍收尾，参考资料集中放 |
| *Crafting Interpreters* | 正文跟着一个实现讲到底（这里是 Codex）；作者的观点和取舍放在章末的设计笔记里，不打断主线 |

## 1. 一章的结构

按顺序：

1. **标题**：写本章的结论或问题，不写「××详解」。上方一行小字写章号和适用条件（版本、模型）。
2. **开篇问题**：3–5 个，放在正文之前。读者先看问题，再读正文。
   - 每个问题只问一件事，先交代前提。
   - 问题里出现的术语先给一句白话。
   - 问题要有具体条件（「你只说了一句 24 字节的话」），不问空泛的「什么是 X」。
3. **正文**：一节回答一到两个问题。节内按「朴素做法 → 它在哪出问题 → 实际做法」推进。写到能回答某个问题的地方，放一个**答案框**：
   - 框头写「回答问题 n」，再重复一遍问题，然后给答案。
   - 答案要短，能单独看懂；细节留在正文里。
4. **对照框**（可选）：其他 agent 的思路明显不同时才写。只写思路差别，不罗列参数。
5. **看源码框**（可选）：每章最多一个，摘 30 行以内，配几句说明。
6. **设计笔记**：放章末，一屏以内。写取舍、设计理由和推测；推测要标【推测】。
7. **小结**：每个开篇问题一句话答案，按问题顺序排。
8. **证据表**：每条结论的出处和等级。

## 2. 写法规则

**要做：**

- 段首第一句就是这段的结论，细节放后面。
- 一个概念只在一处讲透，别处一句话加链接。
- 数字带条件：哪个版本、哪个模型、哪次实验。
- 术语第一次出现给一句白话；不用自己造的简称。
- 一个小节只讲一件事；句子短。
- 正文 3,000–5,000 字（不含证据表、代码和交互控件里的文字）。

**不做：**

- 不编故事开头（「下午三点四十七分……」）。开头最多 3 句，用真实数字或现象。
- 同一个概念不换 2–3 种讲法反复讲。一张图加一段文字就够；比喻可以没有，有也只用一个。
- 不放「读完你能做到」「你可能会问」「先想一想」这类固定框。开篇问题已经替代了它们。
- 不写没有证据的「为什么」。代码里没写理由的设计意图，放进设计笔记并标【推测】。
- 不逐个罗列 8 个 agent。参数差异放附录总表。
- 不写读者没见过的旧说法再去纠正（例如「第三版说……其实……」）。

## 3. 证据

AI 写、AI 核，读者没法自己判断对错，所以证据不能省：

- **等级标签**：【源码 文件:行号@提交】【测试 文件:行号@提交】【实验 目录或命令】【官方文档 网址，抓取日期】【推测】【待核实】。
- **正文里**：结论后放一个上标编号，链到证据表；【推测】【待核实】直接写在正文里，让读者看得见。
- **证据表**：列「#、结论、出处、等级」。等级写「高 / 中 / 推测」，「中」要说明缺了什么（比如「读了源码，没做实验」）。
- **版本**：Codex 源码 `76ed3b4`，CLI `0.165.0`。Claude Code 优先用官方文档（写抓取日期）；用非官方源码 v2.1.88 时写明来源。
- 核对不了的，不写，或者写了标【待核实】。不把直觉写成结论。

## 4. 素材怎么用

| 素材 | 怎么用 |
|---|---|
| 第三版非源码部分（入门、主线、进阶、附录） | 只抽**知识点清单**，用来检查本章有没有漏讲。不参照写法，也不修正它 |
| 第三版源码部分（`src-*`） | 当线索：文件、函数名、行号。写进正文前必须重新对照源码核对；对不上的以源码为准 |
| `自学单元/` 里的实验、答案卡、材料 | 证据来源，可以直接用，引用时写目录 |

**agent 范围**：Codex 当主线；Claude Code 做对照；pi、Grok Build、oh-my-pi、DeepSeek Harness 只在思路明显不同时出场；opencode 只进附录总表。

**源码章**：不再单独成章。需要时在章里放一个「看源码」框；完整的文件和行号索引放附录。

## 5. HTML 形式

- 单个文件，CSS 和 JS 内联，不依赖网络，双击能打开；浅色/深色跟随系统，并有切换按钮；手机宽度能读。
- 组件：开篇问题卡（每题可跳到答案）、答案框、对照框、看源码框、设计笔记、小结、证据表。
- 交互只做「改条件看结果」的，数据来自真实实验或明确的源码规则（后者要标明「按源码规则画，未实验」）。不做纯装饰的动画。
- 本机没有浏览器时，只做静态检查（标签配对、脚本里用到的 id 都存在），并告诉读者页面没在浏览器里打开过。

## 6. 交稿前自检

- [ ] 每个开篇问题在正文里都有答案框，小结里都有一句话答案。
- [ ] 开头没有编出来的场景。
- [ ] 同一个事实只在一处展开。
- [ ] 每个数字有条件，每条结论能在证据表里找到。
- [ ] 推测和待核实在正文里看得见。
- [ ] 正文字数在 3,000–5,000 之间。
- [ ] 术语第一次出现有白话解释。
