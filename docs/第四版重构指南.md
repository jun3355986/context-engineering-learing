## 2. 项目是什么

- **读者**：Drake，有软件开发背景，在学 AI 编程 agent 的上下文管理。Drake 不读源码、不跑实验、不写笔记、不做题；Drake 读章节、提疑问、反馈写法和显示问题。
- **目标**：讲清一次请求里装什么、命令输出怎么不撑爆窗口、压缩后还记得什么、缓存、工具、子代理、回退、跨会话记忆、窗口满了怎么办、怎么评估。
- **方式「问题 + 教程」**：每章开头列 3–5 个问题，Drake 带着问题读，正文写到相关处给出答案。不出题，不批改。
- **产出**：`ai codiing 工具上下文对比报告/第四版/` 下每章一个 HTML 文件，目录页 `index.html`。
- **agent 范围**：Codex 主线；Claude Code 做对照；pi、Grok Build、oh-my-pi、DeepSeek Harness 只在思路明显不同时出场；opencode 只进附录总表。源码不单独成章。
- **暂停的事**：薄弱点判断（以后 Drake 做个人网站时，用 LLM 问答界面来做）。公众号文章只有 Drake 说「可以出文章了」才写。

## 3. 写法

参考三本书，各借一样：《操作系统导论》（OSTEP）借「每章先写关键问题，从最朴素的做法讲起，看它在哪出问题，再引出改进」；《数据密集型应用系统设计》（DDIA）借「按问题组织，产品只当例子，取舍放章末」；*Crafting Interpreters* 借「跟着一个实现讲到底（这里是 Codex），作者观点放设计笔记，不打断主线」。

### 3.1 一章的结构

按顺序：

1. **标题**：写结论或问题，不写「××详解」。标题上方一行写章号；标题下方一行小字写日期和条件：Codex 源码版本、CLI 版本、模型名、思考级别（写法见 3.4）。
2. **开篇问题**：3–5 个，放正文前。每个问题只问一件事，先交代前提，问题里的术语先给一句白话；要有具体条件（「你只说了一句 24 字节的话」），不问空泛的「什么是 X」。每题带一个跳到答案的链接。
3. **正文**：一节回答一到两个问题。节内按「朴素做法 → 它在哪出问题 → 实际做法」推进。写到能回答某个问题的地方，放**答案框**：框头「回答问题 n」，重复一遍问题，再给短答案，单独看也能懂。
4. **对照框**（可选）：其他 agent 思路明显不同时才写，只写思路差别。
5. **看源码框**（可选）：每章最多一个，摘 30 行以内，配几句说明。
6. **设计笔记**：章末，一屏以内。写取舍、设计理由和推测，推测标【推测】。
7. **小结**：每个开篇问题一句话答案，按问题顺序。
8. **证据表**：列「#、结论、出处、等级」。

### 3.2 要做 / 不做

**要做：**
- 段首第一句是这段的结论。
- 一个概念只在一处讲透，别处一句话加链接。
- 数字带条件：哪个版本、哪个模型（含思考级别）、哪次实验。
- 一个小节只讲一件事；句子短。
- 正文 3,000–5,000 字（不含证据表、代码和交互控件里的文字）。

**不做：**
- 不编故事开头（「下午三点四十七分……」）。开头最多 3 句，用真实数字或现象。
- 同一个概念不换几种讲法反复讲。比喻可以没有，有也只用一个。
- 不放「读完你能做到」「你可能会问」「先想一想」这类固定框。
- 不写没有证据的「为什么」；代码没写理由的设计意图放设计笔记并标【推测】。
- 不逐个罗列 8 个 agent，参数差异放附录。
- 不写读者没见过的旧说法再去纠正（如「第三版说……其实……」）。

### 3.3 写法教训（Drake 反馈过的，必须遵守）

| # | 规则 | 反例 | 来源 |
|---|---|---|---|
| 1 | 模型写**名字和思考级别**（如 `gpt-6.1-sol`，思考级别 low）。不用「普通格式」「Lite 格式」「默认模型」这类分类名：模型一直在换，没有常驻的「普通」模型。内部开关名（如 `use_responses_lite`）只在解释原因时出现 | 「换成普通格式，工具定义挪到……」 | 2026-11-02 第 2 章 |
| 2 | 说上限、大小、多少，**给数字和单位**。拿不到数字就标【待核实】 | 「按需加载的文件上限更小」 | 2026-11-02 第 2 章 |
| 3 | 讲一个功能，先说**在哪里用**：写在哪个文件里、配置里，还是在输入框里打；给一行例子。层数、次数要说清从哪算起 | 「支持 @路径 导入别的文件，最多套 4 层」 | 2026-11-02 第 2 章 |
| 4 | 对比内容在**第一次出现的地方**讲完；后文只用一句话引用。不让一个新说法在后面某节突然冒出来 | 第 2 节突然出现「换成普通格式」 | 2026-11-02 第 2 章 |
| 5 | 「只差一处」「完全一样」这类概括，逐项比过才写 | 「它和普通格式只差一处」（实际工具集、系统提示词、条目数都不同） | 2026-11-02 自查 |
| 6 | 术语第一次出现给一句白话；不用自己造的简称 | 「多代理两条」 | 2026-11-01 |
| 7 | 方法类的词写出具体动作和命令 | 「怎么确认」没说用什么命令 | 2026-11-01 |
| 8 | 精简：不编场景，一个概念一处讲透，按问题组织 | 第三版每节场景开头、同一概念复述 2–3 遍 | 2026-11-01 |

### 3.4 HTML 版式（所有章统一）

2026-11-02 Drake 要求：左边显示章节目录，正文排版参考阮一峰的网络日志。版式已经做成共用文件，**新章从模板复制，不自己写样式**。

**共用文件**（都在 `第四版/` 下）

| 文件 | 管什么 |
|---|---|
| `assets/book.css` | 全部样式：颜色、浅色/深色、左侧栏、正文排版、各种框、表格、交互组件 |
| `assets/book.js` | 主题切换、左侧目录（按 h2/h3 自动生成，滚动时高亮当前小节）、窄屏顶栏和抽屉、章末上一章/下一章、答案框里的「↑ 回到问题」。全书章节列表 `BOOK.chapters` 也在这里 |
| `_模板.html` | 新章的起点：骨架和每种组件各一个示例 |

用相对路径引用，双击能打开，不联网。`book.css`、`book.js` 和章节文件要放在一起，单独拷走一个 HTML 会丢样式。

**版式**（参考阮一峰网络日志，改的话改 `book.css`，全书一起变）
- 米黄底 `#f5f5d5`；正文单栏，正文 17px、行高 1.85；手机上 16px。
- **正文列宽**（2026-11-02 定）：桌面（宽于 1000px）整列 1064px（含左右留白），左右留白各 56px，所以正文实际宽 952px，约 55 个汉字。中等宽（620–1000px）留白 28px。手机（620px 及以下）留白 16px，不变。桌面的整列和留白、中等宽的留白，都是改之前（整列 760px、留白 40px、中等宽留白 20px）的 1.4 倍。改数字只改 `book.css` 里 `.page` 的两行。
- 左侧栏 272px，固定在左边：书名（回目录）→ 已写好的章 → 当前章的目录。宽度 1000px 以下收起，顶部出现「☰ 目录」按钮。
- 二级标题下一条细线，节号用橙褐色；链接深蓝 `#223472`，悬停变橙 `#d03500`；代码块浅灰底、3px 米色边框、圆角。
- 深色主题是同一套结构的暖深色。
- **节号用中文**（2026-11-02 定）：二级标题前的节号写「一、」「二、」「三、」……，十一起写「十一、」「十二、」。`span.sn` 里带顿号。正文里提到第几节也写中文「第一节」，不写「第 1 节」。章号「第 2 章」不变，仍用阿拉伯数字。

**骨架**（照 `_模板.html`）

```html

<link rel="stylesheet" href="assets/book.css">
<script src="assets/book.js"></script>
<style>/* 只放本章交互专用的样式，没有就不写 */</style></head>
<body class="chapter"><main class="page">

  <p class="lede">…</p>

  <section id="notes"><h2>设计笔记</h2>…</section>
  <section id="summary"><h2>小结</h2>…</section>
  <section id="evidence"><h2>证据表</h2>…</section>

```

**组件**（类名都在 `book.css` 里，直接用）

| 写法 | 用途 |
|---|---|
| `<p class="kicker">` / `<p class="meta">` | 章号 / 标题下的日期和条件 |
| `<p class="lede">` | 开头最多 3 句 |
| `<p class="note">` | 补充说明（条件、估算方法），浅黄底 |
| `<section class="qs">` | 开篇问题，米色粗边框；问题 `li` 的 id 是 `q1`… |
| `<div class="answer" id="aN">` + `p.qh` + `p.qq` | 答案框，绿色左边线；`book.js` 自动加「↑ 回到问题」 |
| `<div class="compare">` | 对照框（其他 agent），蓝灰左边线 |
| `<div class="source">` | 看源码框，米色粗边框；里面放 `<pre>` |
| `<h2><span class="sn">一、</span>…</h2>` | 带节号的节标题（中文，见上面「节号用中文」）；设计笔记、小结、证据表不带节号 |
| `.tablewrap > table`、`td.num`、`span.tag.lvl-h/m/l` | 表格、右对齐数字、证据等级（高/中/推测） |
| `.ctrl`、`.btn[aria-pressed]`、`input[type=range]`、`.panel`、`.meter`（`.keep/.cut`）、`.bar`、`.chips/.chip`、`.legend`、`.grid2`、`.ladder` | 交互控件 |
| 颜色变量 `--tools --system --session --project --user --reply --ok --bad --half --cut --keep` 等 | 交互图表配色，自动跟随深浅主题 |

**规则**
- 不改 `book.css` 来迁就某一章；本章专用的放 `<head>` 里自己的 `<style>`，颜色只用变量（第 3 章的「四道闸」`.gates` 就是这样）。
- 不自己写主题按钮、主题脚本、目录、翻页，`book.js` 都做了。
- 左侧目录按 h2（一级）和 h3（二级）生成：h3 标题要短，能单独当目录项读；`.qs` 的 h2 加 `data-toc="开篇问题"`。h2 是 section 的第一个子元素时，目录链到 section 的 id。
- `<title>` 写 6–10 字的短名，和 `BOOK.chapters` 里的 `name` 一致。
- 写完一章：在 `assets/book.js` 的 `BOOK.chapters` 按顺序加一行（只放写好的章），再在 `index.html` 的列表里把那一项换成链接。

## 4. 证据规范（不可省）

写的和核的都是 AI，Drake 没法自己判断对错，所以：

1. **每条结论带出处和等级**：【源码 文件:行号@提交】【测试 文件:行号@提交】【实验 目录或命令】【官方文档 网址，抓取日期】【推测】【待核实】。正文用上标编号链到证据表。证据表的等级写「高 / 中 / 推测 / 待核实」，「中」要写缺了什么（如「读了源码，没做实验」）。
2. **版本**：Codex 源码 `76ed3b4`，CLI `0.165.0`；实验写模型名和思考级别。Claude Code 本机没有源码，用官方文档（`code.claude.com/docs`，写抓取日期和文档里写的版本号）；用非官方源码 v2.1.88 时写明来源。
3. **没核对到的不说成确定**，标【待核实】或【推测】，并且在正文里看得见。
4. **Drake 说「给证据」，立刻给出处。**
5. **数字口径**：请求大小统一用每条 `input` 条目（或顶层 `tools` 字段）的 `json.dumps` 字节数相加；token 用「UTF-8 字节数 ÷ 4 向上取整」估算，并说明这是 Codex 本地估算，不是真实分词。

**犯过的错（别再犯）：**
- **没测就认可**：曾认可「MCP 多了非常占空间」，实测挂 40 个假 MCP 工具请求体不变，只好收回。
- **实验条件没交代**：第二次请求的实验用本机假服务器，走的是 HTTP，而官方通道默认 WebSocket。结论要写实验条件。
- **概括没逐项核对**：写过「两个模型的请求只差一处」，实际差好几处。
- **照搬第三版**：第三版有错，也自相矛盾。非源码部分只取知识点，源码部分必须重新核对。
