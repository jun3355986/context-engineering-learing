## 2. 项目是什么

- **读者**：Drake，有软件开发背景，在学 AI 编程 agent 的上下文管理。Drake 不读源码、不跑实验、不写笔记、不做题；Drake 读章节、提疑问、反馈写法和显示问题。
- **目标**：讲清一次请求里装什么、命令输出怎么不撑爆窗口、压缩后还记得什么、缓存、工具、子代理、回退、跨会话记忆、窗口满了怎么办、怎么评估。
- **方式「问题 + 教程」**：每章开头列 3–5 个问题，Drake 带着问题读，正文写到相关处给出答案。不出题，不批改。
- **产出**：`ai codiing 工具上下文对比报告/第四版/` 下每章一个 HTML 文件，目录页 `index.html`。
- **agent 范围**：Codex 主线；Claude Code 做对照；pi、Grok Build、oh-my-pi、DeepSeek Harness 只在思路明显不同时出场；opencode 只进附录总表。源码不单独成章。
- **暂停的事**：薄弱点判断（以后 Drake 做个人网站时，用 LLM 问答界面来做）。公众号文章只有 Drake 说「可以出文章了」才写。

## 3. 写法

参考三本书，各借一样：《操作系统导论》（OSTEP）借「每章先写关键问题，从最朴素的做法讲起，看它在哪出问题，再引出改进」；《数据密集型应用系统设计》（DDIA）借「按问题组织，产品只当例子，取舍放章末」；*Crafting Interpreters* 借「跟着一个实现讲到底（这里是 Codex），作者观点放设计笔记，不打断主线」。

### 3.1 一章的结构

按顺序：

1. **标题**：写结论或问题，不写「××详解」。上方一行小字写章号和条件：Codex 源码版本、CLI 版本、模型名、思考级别。
2. **开篇问题**：3–5 个，放正文前。每个问题只问一件事，先交代前提，问题里的术语先给一句白话；要有具体条件（「你只说了一句 24 字节的话」），不问空泛的「什么是 X」。每题带一个跳到答案的链接。
3. **正文**：一节回答一到两个问题。节内按「朴素做法 → 它在哪出问题 → 实际做法」推进。写到能回答某个问题的地方，放**答案框**：框头「回答问题 n」，重复一遍问题，再给短答案，单独看也能懂。
4. **对照框**（可选）：其他 agent 思路明显不同时才写，只写思路差别。
5. **看源码框**（可选）：每章最多一个，摘 30 行以内，配几句说明。
6. **设计笔记**：章末，一屏以内。写取舍、设计理由和推测，推测标【推测】。
7. **小结**：每个开篇问题一句话答案，按问题顺序。
8. **证据表**：列「#、结论、出处、等级」。

### 3.2 要做 / 不做

**要做：**
- 段首第一句是这段的结论。
- 一个概念只在一处讲透，别处一句话加链接。
- 数字带条件：哪个版本、哪个模型（含思考级别）、哪次实验。
- 一个小节只讲一件事；句子短。
- 正文 3,000–5,000 字（不含证据表、代码和交互控件里的文字）。

**不做：**
- 不编故事开头（「下午三点四十七分……」）。开头最多 3 句，用真实数字或现象。
- 同一个概念不换几种讲法反复讲。比喻可以没有，有也只用一个。
- 不放「读完你能做到」「你可能会问」「先想一想」这类固定框。
- 不写没有证据的「为什么」；代码没写理由的设计意图放设计笔记并标【推测】。
- 不逐个罗列 8 个 agent，参数差异放附录。
- 不写读者没见过的旧说法再去纠正（如「第三版说……其实……」）。

### 3.3 写法教训（Drake 反馈过的，必须遵守）

| # | 规则 | 反例 | 来源 |
|---|---|---|---|
| 1 | 模型写**名字和思考级别**（如 `gpt-6.1-sol`，思考级别 low）。不用「普通格式」「Lite 格式」「默认模型」这类分类名：模型一直在换，没有常驻的「普通」模型。内部开关名（如 `use_responses_lite`）只在解释原因时出现 | 「换成普通格式，工具定义挪到……」 | 2026-11-02 第 2 章 |
| 2 | 说上限、大小、多少，**给数字和单位**。拿不到数字就标【待核实】 | 「按需加载的文件上限更小」 | 2026-11-02 第 2 章 |
| 3 | 讲一个功能，先说**在哪里用**：写在哪个文件里、配置里，还是在输入框里打；给一行例子。层数、次数要说清从哪算起 | 「支持 @路径 导入别的文件，最多套 4 层」 | 2026-11-02 第 2 章 |
| 4 | 对比内容在**第一次出现的地方**讲完；后文只用一句话引用。不让一个新说法在后面某节突然冒出来 | 第 2 节突然出现「换成普通格式」 | 2026-11-02 第 2 章 |
| 5 | 「只差一处」「完全一样」这类概括，逐项比过才写 | 「它和普通格式只差一处」（实际工具集、系统提示词、条目数都不同） | 2026-11-02 自查 |
| 6 | 术语第一次出现给一句白话；不用自己造的简称 | 「多代理两条」 | 2026-11-01 |
| 7 | 方法类的词写出具体动作和命令 | 「怎么确认」没说用什么命令 | 2026-11-01 |
| 8 | 精简：不编场景，一个概念一处讲透，按问题组织 | 第三版每节场景开头、同一概念复述 2–3 遍 | 2026-11-01 |

### 3.4 HTML 形式

- 单文件，CSS 和 JS 内联，不依赖网络，双击能打开；浅色/深色跟随系统，并有切换按钮；手机宽度能读。
- 样式、主题切换、组件（开篇问题卡、答案框、对照框、看源码框、设计笔记、小结、证据表）直接从第 2 章复制。
- 交互只做「改条件看结果」的，数据来自真实实验，或明确的源码规则（标「按源码规则画，未实验」）。不做纯装饰动画。

### 3.5 交稿前自检

- [ ] 每个开篇问题都有答案框，小结里都有一句话答案。
- [ ] 开头没有编出来的场景。
- [ ] 同一个事实只在一处展开。
- [ ] 每个数字有条件（版本、模型名、思考级别、实验），每条结论在证据表里找得到。
- [ ] 推测和待核实在正文里看得见。
- [ ] 正文 3,000–5,000 字。
- [ ] 术语第一次出现有白话解释。
- [ ] 过一遍 3.3 的 8 条：搜一下「普通」「默认」「更小」「更多」「一些」「只差」这类词，换成具体说法。

## 4. 证据规范（不可省）

写的和核的都是 AI，Drake 没法自己判断对错，所以：

1. **每条结论带出处和等级**：【源码 文件:行号@提交】【测试 文件:行号@提交】【实验 目录或命令】【官方文档 网址，抓取日期】【推测】【待核实】。正文用上标编号链到证据表。证据表的等级写「高 / 中 / 推测 / 待核实」，「中」要写缺了什么（如「读了源码，没做实验」）。
2. **版本**：Codex 源码 `76ed3b4`，CLI `0.165.0`；实验写模型名和思考级别。Claude Code 本机没有源码，用官方文档（`code.claude.com/docs`，写抓取日期和文档里写的版本号）；用非官方源码 v2.1.88 时写明来源。
3. **没核对到的不说成确定**，标【待核实】或【推测】，并且在正文里看得见。
4. **Drake 说「给证据」，立刻给出处。**
5. **数字口径**：请求大小统一用每条 `input` 条目（或顶层 `tools` 字段）的 `json.dumps` 字节数相加；token 用「UTF-8 字节数 ÷ 4 向上取整」估算，并说明这是 Codex 本地估算，不是真实分词。

**犯过的错（别再犯）：**
- **没测就认可**：曾认可「MCP 多了非常占空间」，实测挂 40 个假 MCP 工具请求体不变，只好收回。
- **实验条件没交代**：第二次请求的实验用本机假服务器，走的是 HTTP，而官方通道默认 WebSocket。结论要写实验条件。
- **概括没逐项核对**：写过「两个模型的请求只差一处」，实际差好几处。
- **照搬第三版**：第三版有错，也自相矛盾。非源码部分只取知识点，源码部分必须重新核对。

## 5. 每章怎么写

```text
A 准备（核对事实）→ B 写章 → C 检查 → D 记录 → [Drake 读] → E 按反馈改
```

**A 准备**
1. 从第 6 节路线表找到本章对应的第三版页面，只抽知识点清单（标题和要点），用来检查有没有漏讲。不照搬写法，也不修正第三版。
2. 第三版 `src-*` 页面里的文件、函数、行号当线索，到 Codex 源码里逐条核对；Codex 自带测试（`core/tests/suite/`）也是好证据。
3. 能做实验就做，脚本和输出放 `自学单元/` 下（见第 9 节）。
4. 列 3–5 个开篇问题，确认每个都能用已核对的事实回答。

**B 写章**：按第 3 节。文件名 `第四版/NN-标题.html`。

**C 检查**：本机没有 node 和浏览器，做静态检查：标签配对、脚本里用到的 id 都存在、页内锚点都存在、括号平衡；统计正文字数；过一遍 3.5 自检。告诉 Drake 页面没在浏览器里打开过。

**D 记录**：更新本文第 1 节任务表、第 7/8 节（新确认的事实、未决事项）、第 13 节日志，以及 `第四版/index.html` 的章节状态和链接。

**E 按反馈改**：Drake 的疑问当场答。和本章有关的，改本章正文（必要时加开篇问题和答案框）；和别章有关的，写进任务表那一章的备注；和上下文管理无关的，简答。反馈里能推广的写法问题，加进 3.3。

**独立复核**（可选）：一章写完，可以开新会话或子代理独立核对证据表。开之前先问 Drake。

## 7. 已确认的事实（后续章节要和它一致）

### 7.1 第 2 章（详细出处见第 2 章证据表）

条件：Codex 源码 `76ed3b4`，CLI `0.165.0`，模型 `gpt-6.1-sol`，思考级别 low（实验脚本固定 `model_reasoning_effort = "low"`）。

- `gpt-6.1-sol` 的请求没有 `instructions` 字段、没有顶层 `tools`。`input` 7 条：工具定义 → 系统提示词 → 技能目录 + 权限 + 协作模式 → 子代理说明 → 子代理开关 → user：AGENTS.md + 环境信息 → user：你的话。没有 system 角色，历史里的 system 消息也会被过滤。
- 一句话的请求 53,637 字节 ≈ 13,410 token：工具定义 47%，系统提示词 41%，你的话 0.04%。
- `gpt-5.5`（思考级别 low）：工具在顶层 `tools`（9 个，9,414 字节），`input` 4 条，合计 36,201 字节 ≈ 9,051 token；工具集和系统提示词是另一套。工具放在哪由模型表（`models-manager/models.json`）的 `use_responses_lite` 决定，`76ed3b4` 的表里只有 gpt-5.5 是 false。其他差别对应哪项设置没核对。
- AGENTS.md：项目根默认以 `.git` 为标记；根到当前目录每级取一份（`AGENTS.override.md` 优先）；不看子目录；不信任的项目不读；全局 `~/.codex/AGENTS.md` 排最前；项目文件合计 32,768 字节，先给根目录，尾部静默截断（只写日志）；文件里的 `@` 不展开。
- 会话中途：会话设置按状态比较，没变不加、变了在末尾追加，不改前面。**全局 AGENTS.md 每次请求前重读；项目 AGENTS.md 一个会话只读一次**（工作环境或信任级别变了才重读）。依据源码 + Codex 自带测试，没做自己的实验（任务 14）。
- 传输：官方通道默认 WebSocket，出错重试用尽后本会话改走 HTTP；自定义通道只走 HTTP。HTTP 下第二次请求整份重发；WebSocket 只发新增条目（只读了源码）。
- Claude Code（官方文档 `code.claude.com/docs/en/memory`，2026-11-02 抓取）：当前目录及以上每一级的 CLAUDE.md 启动时加载，单个文件超过 4 MiB 整份跳过；子目录的 CLAUDE.md 在 Claude 读写那个子目录里的文件时才加载，单个文件上限 40,000 字符（20 万 token 窗口；100 万窗口时 Opus 4.6、Sonnet 4.6 是 200,000，之后的模型 150,000；v2.1.309 起），超了只给开头并提示用 Read 工具读剩下的；CLAUDE.md 里写 `@路径` 可导入别的文件，最多 4 跳。

第 3 章已写完，详细出处见它的证据表。要点：

import sys
from html.parser import HTMLParser
class P(HTMLParser):
    skip = 0; out = []
    def handle_starttag(self, t, a):
        if t in ("script", "style"): self.skip += 1
    def handle_endtag(self, t):
        if t in ("script", "style"): self.skip -= 1
    def handle_data(self, d):
        if not self.skip and d.strip(): self.out.append(d.strip())
p = P(); p.feed(open(sys.argv[1], encoding="utf-8").read()); print("\n".join(p.out))
EOF
