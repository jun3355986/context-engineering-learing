# 公众号文章：设计卡与事实表

> 2026-10-29。文章标题：**AI 越改越严谨，我越读越累：一次防御性写作踩坑**。
> 事实表里每条数字都带出处；标【待确认】的，要 Drake 回答或实测后才能写进正文。

## 1. 设计卡

- **读者**：用 AI 写或改技术文档、方案、文章的开发者。没听过「防御性写作」，没读过那篇论文，不知道作者在做什么项目。
- **一个问题**：让 AI 把稿子改「严谨」，为什么越改越难读？怎么避开？
- **核心结论（两句话）**：AI 在被要求核查、审稿时，会往正文里加没有依据的限定，加规则清单压不住，问题会换个样子再出现。要避开它，把「核查」和「写作」拆开，并且在动笔前先定好读者和结论。
- **读者最可能的误解**：① 限定语多就是更严谨；② 加一句「不要防御性写作」就能管住；③ 是某个模型的毛病，换一个就好。
- **贯穿例子**：第 20 章「月底账单是上月三倍」那一句，改前、改后、改回的三个版本。
- **不讲什么**：上下文管理的技术内容；8 个 agent 的源码细节；Claude Code 源码来源；批次、口径表等内部名词。

## 4. 论文要点

论文：*Defensive Writing in GPT Models*，Junchi Liao 等 5 人，arXiv 2610.11355，v1 2026-10-08，v2 2026-10-13。

**怎么测的**：77 段、20 篇 ChatGPT 发布前的英文计算机论文；让模型把段落改到「经得起同行评审」，或者根据只列事实的「证据清单」重写。「防御性写作」的定义：材料不支撑的收窄或质疑。指标：每百词新增的无依据限定（RU）、撤回原论断比例（Ret）、弱化原论断比例（Soft）。

**什么会触发（§3.2）**：只要求润色，几乎不加（GPT-6-astra 0.94→0.03，GPT-5.5 0.29→0.04，附录表 9）；任何「核查说法」的要求都会引出；点名「审稿人可能提的意见」（P5）最强。「按证据支持的强度写」（P9）也会引出，只是少一些（GPT-6-astra：P4 0.77→P8 0.61→P9 0.39）。

**多轮审改（表 2，每百词 RU / 撤回%，第 1→3 轮）**

| 模型 | RU | 撤回 |
|---|---|---|
| GPT-5.5 | 0.95 → 1.23 → 1.10 | 10.8 → 14.5 → 10.2 |
| GPT-5.6-sol | 1.42 → 1.62 → 1.44 | 18.3 → 24.3 → 19.1 |

| Claude Opus 5.5 | 0.54 → 0.64 → 0.70 | 1.2 → 2.5 → 4.6 |
| 只润色（三个模型） | ≤ 0.07 | ≤ 0.6 |

**是不是纠错（§3.3）**：2 名博士生对照全文，核查 GPT-6-astra 的 58 条论断：48 处改动里 28 处两人都认为该改，10 处不必要；原稿被两人判为夸大或矛盾的论断，20 处改动全部合理；被两人判为有依据的论断，4 处改动全部多余。60 句新增限定：36 句多余、16 句合理、3 句有错。

**评审和读者（§3.4）**：两个 AI 评审给限定多的版本更高分（GPT-6-astra +1.22）；只删限定后，总分降 0.82、严谨性降 1.12。4 位博士生读者，20 对段落：限定多的版本更难读（易读性 5.05 对 5.75），作者显得更不确定（3.38 对 4.35，1–5 分），理解题两版都 100%（天花板）。

**作者的局限**：只测英文计算机论文；编码用 LLM；闭源模型会变；评审只有两个；读者实验只有 4 人。

## 5. 我们的数字和论文的数字不能直接比

- 我们的限定语数的是中文词表（`prose_check.py hedge`：每千字含限定词的句子数）；论文数的是人工标注后由 LLM 编码的「无依据限定」每百词。
- 我们的数据是不同章节、不同提示词、不同模型的实际修订，不是对照实验。
- 论文没有测 Codex 这类编程 agent，也没有测中文。
