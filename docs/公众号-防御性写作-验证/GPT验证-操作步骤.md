## 步骤

1. **会话一（核查）**：在上面的目录里启动 gpt-sol max（和第一轮同一设置），新开会话，粘贴 `GPT-提示词-步骤1-核查.txt` 全文。它要能联网读 GitHub 源码（`raw.githubusercontent.com`）；联网受限的话，它拿不到依据，核查会变成猜。交付物：`review/核查-main-13.md`、`review/替换-main-13.md`。
2. **回来告诉我。** 我审替换表：不是错误、只是「可以更严谨」的行删掉；「改成」里混进「不能据此」「仍取决于」这类限定的行删掉；抽查几条依据；然后把核查清单挪出目录，免得会话二读到。
3. **会话二（改写）**：在同一目录**新开**会话，不要接着会话一聊，粘贴 `GPT-提示词-步骤2-改写.txt` 全文。
4. **回来告诉我。** 我自己重跑检查，不采信它的自述：`hedge`（上限 1.9）、另外三种弱化形态、`check`、`time`、残留数字和栏目名的 grep、结构前后对比（id、class、链接、标签、脚注），再对照评分表打分，和上面的对照放在一起。

## 两条规矩

- 会话二如果超标，不要让它「再检查一遍」，那会再加一轮。我会列出多余的句子，你再开一个会话，用 `评测-第20章-两步改写提示词.md` 第 5 节那段提示词，只删这几句的限定部分。
- 会话二仍然反复超标的话，下一步是会话二换模型（会话一仍用 GPT）。

## 已知的混杂因素

第一轮 GPT 的环境里没有 CONVENTIONS 的「限定语」规则和 `hedge` 脚本，这次有。所以这次测的是「两步法 + 限定语规则 + 自检脚本」这个组合，不是单测两步法。要拆开，可以另建一个 worktree，让 GPT 用一步法（`评测-第20章-改写提示词.md`）在同样的新规则下再改一次。建议先跑两步法，结果看不清时再加这一组。
