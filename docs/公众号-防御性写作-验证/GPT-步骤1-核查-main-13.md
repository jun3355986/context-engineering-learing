## 保留意见

- 范围与证据口径：核查正文 01～06、两张 SVG 图及图注、7 个弹窗、8 行对比表、5 组设计取舍、3 道测验和脚注；交叉阅读 intro-05、intro-06 及 research 的事实卡片/源码地图。源码使用页面指定的完整提交号；Claude Code 继续保留“非官方 v2.1.88”声明，opencode v2 继续保留 v2.0.29 beta 范围。同仓 README 是可用文档证据，不因不是逐行实现就判为错误。
- “追加不改旧内容”“相同前缀仍可复用”作为内容布局原则成立。TTL、最低长度、模型/请求设置、缓存写入与查找边界、路由、缓存是否还在，都是实际命中的额外条件；不把正文每处省略这些条件都记作错误，也不要求每句都加一串限定。
- 第 01 节团队账单变三倍写在“场景”中，没有给实测来源。按教学情境保留，不把三倍当成测量结果；数值无法从页面给出的信息复算。

- pi 避免一次性摘要写入、dsh/Grok 对齐摘要请求旧前缀，是两种有源码/文档支持的优化。读缓存与写缓存是两个轴，改写时可让这个比较更清楚，但不把“两种选择/两派”的表述单独算成互斥协议错误；真正错误的“摘要不写就全额付费”另列。
