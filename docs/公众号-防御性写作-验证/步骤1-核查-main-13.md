## 保留意见

这一节不会进正文。

1. **2.4 教学模型的前提。** 修正后的模型假设压缩前的缓存是热的、忽略每轮新增的 token（两边相同）、不含摘要请求本身。缓存已过期时，不压缩也要整段重写 `B·w`，压缩更划算；这一点可以在正文用一句话交代，但不算原文错误。`r=0.1`、`w=1.25` 是 Anthropic 5 分钟 TTL 的倍率（[文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)：5 分钟写入 1.25×，1 小时写入 2×，读取 0.1×，Opus 5.5、Sonnet 5.5 的读取是 0.05×）；OpenAI 文档写的 GPT-5.6 及以后默认 30 分钟写入也是 1.25×，更早的模型不另收写入费。块里已写明「不是任何 agent 的真实计价」，所以不进表。
2. **「缓存写入单价通常高于普通输入」（§1）与第 5 章「是否收费…随供应商与模型而变」。** 两者不矛盾：当前 Anthropic 和 OpenAI 新模型都收，旧 OpenAI 模型不收；原文用的是「通常」。如果想严格对齐第 5 章，可以加「是否收费因供应商和模型而异」。
3. **「Codex 侧没有内置的失效归因」（§2.2、取舍五）。** 对缓存命中归因来说成立。但 `client.rs#L350-L450` 有 websocket 增量续传的诊断（`NonIncrementalReason`：`tools_changed`、`prompt_cache_key_changed` 等），记录的是「为什么这次不能沿用上一次的 `previous_response_id`」，属于传输层，不是前缀缓存未命中归因。正文可以不提。
4. **「客户端只做两件事：发键，认账」。** 小节标题和第一段说客户端只做这两件事，但 2.3 又讲 Codex 客户端自己排拼接顺序、做 AGENTS.md 追加、（可选）增量工具声明。第一段已用「大部分设计其实是在约束拼接顺序」圆过去，不改。
5. **Claude Code 的「4」。** 弹窗说「4 个断点在源码里是系统提示词块上限」是对的，但系统提示词最多 4 块里只有 `cacheScope` 非空的块带 `cache_control`：全局缓存模式下只有边界前的静态块（`global`），其他模式下是 CLI 前缀块和其余块（`org`）。再加消息层 1 个，总数在 Anthropic API 的 4 个上限之内（`claude.ts#L3213-L3235` 注释「Do not add any more blocks for caching or you will get a 400」）。取舍一的标题「一个断点 vs 四个断点」拿的是 Claude Code 消息层的 1 个和 opencode v2 的总数 4 比，口径不同，但正文写明了「消息层」，不算错。
6. **dsh 的链接行号。** `system-prompt.md#L43` 实际是空行，那一段在 L44；`cordis.patch.yml#L340` 引的「源码注释」其实是 plan mode 发给模型的提示词文本（YAML 里的 `section`），不是开发者注释。意思相同，不影响结论。建议链接改为 `#L44`。
7. **opencode v1 的 `sort` 来源。** 弹窗「来源」没有列工具排序的位置（`llm/request.ts#L184`），建议补上。
8. **取舍二「留在原地派…因为它们认为『模型更重视系统提示里的信息』」。** 没有出处，是作者对动机的推测。opencode v1 把 `Today's date` 写在系统提示的环境块里（[system.ts#L83](https://github.com/anomalyco/opencode/blob/733b2c627e5aec39cb33cc22373bdce33053ef2c/packages/opencode/src/session/system.ts#L83)），可以拿来当「留在原地」的实例，动机一句建议删或标【推断】。
