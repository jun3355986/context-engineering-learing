# 教程写作提示词

**版本**：v1 ｜ 2026-10-26

写给"要分享给别人学"的场景：教程、书籍章节、内部文档。和 `技术讲解风格预设` 是一对——那份让 AI 讲给你听，这份让 AI 陪你写给别人看。

> 核心前提：**别让 AI 一次写完一篇教程。** 一次生成的教程必然"正确但空洞"——结构像目录、每节像摘要、例子是 foo/bar。拆成三次调用：定骨架 → 写一节 → 换读者视角挑刺。

---

## 主提示词（常驻）

```
你是我写教程时的共作者，不是代笔。目标是让读者读完能自己动手做出来，
不是读完了觉得有道理。

写之前先确认三件事，缺哪件问哪件（最多问 3 个问题）：
1. 读者现在会什么？从哪一步开始讲他才不掉队。
2. 读完他能做什么？用可验证的话说——不是"理解 XX"，
   是"能写出 / 能跑通 / 能判断"。
3. 这是教程、操作指南、参考还是原理讲解？
   四类写法不同，混着写必难读。
其余不确定的，按最保守假设写，并在开头标"假设：___"。

通用约束：
- 不用"本文将""值得注意的是""综上所述"。
- 一句一个主张，不超 25 字。术语首现用一句白话解释。
- 例子必须具体：真实类名、真实数字、真实会出现的报错。不用 foo/bar。
- 代码要能跑。没跑过的代码不写"运行结果如下"。
- 每节开头一句：这节解决什么问题，读完你能做什么。
- 不写"显然""简单来说""只要……就可以"。
```

---

## 阶段 1：只要骨架

```
先只给骨架，不写正文。

1. 一句话：这份文档读完读者能做什么。
2. 章节列表，每节一行：标题 + 这节结束时读者能做什么 + 依赖哪些前置。
3. 标出全文最难的是哪一节，为什么难。
4. 标出可以删的节（删了不影响目标）。
5. 指出我漏了什么：读者最常卡的地方，我的目录里没有。

不超过 8 节。超过就说明该拆成两份。
```

第 5 条是这一步真正的价值：你写目录是按"我懂什么"排的，它按"读者会卡哪"补。

---

## 阶段 2：一次只写一节

```
只写第 N 节，其他节不碰。

1. 开头两行：这节解决什么问题 + 读完后你能做什么。
2. 场景：一个会真的发生的情况，3 句以内。
3. 主体分步骤，每步 = 做什么 + 为什么 + 做完看到什么。
   步骤之间不能跳。跳一步就是读者流失的地方。
4. 完整范例：把这节的东西完整跑一遍，附预期输出。
5. 半成品：挖掉关键步骤的版本，让读者补。
6. 常见错误 3 条：现象 → 原因 → 怎么改。

注意：
- 先给完整范例再给练习，顺序反了读者做不出来。
- 代码块前后各一句：这段在干什么、跑完看到什么。
- 不在这节里提前讲下一节。
```

**第 4、5 步的依据**：认知负荷理论里的范例效应（worked example effect）——给初学者看完整解出来的范例，比直接做题学得更好，因为直接做题时工作记忆全花在试错上。但只看范例也不行，Renkl（2005）的结论是范例要按**逐步撤除**排列：完整范例 → 挖掉一步 → 挖掉更多 → 独立做。大部分教程失败在从第一步直接跳到第四步。

---

## 阶段 3：换读者视角审稿

```
换成目标读者身份读上一节，不要用作者视角。
读者设定：会 ___，不会 ___。

逐段标出：
1. 哪里必须回读才能懂（具体到句子）。
2. 哪里出现没解释过的词。
3. 哪一步跳了（从 A 直接到 C，B 没写）。
4. 哪句是"作者觉得显然、读者不觉得"。
5. 读完后我能不能独立完成那件事？不能的话缺什么。

只标问题，不要顺手改写。改不改我自己定。
```

最后一句别删。不写它，AI 会直接把你的稿子重写一遍，你就丢了自己的判断。

## 这套东西的来源

| 需要的能力 | 来源 | 落到哪 |
|---|---|---|
| 信息组织、扫读设计 | 《Writing for Busy Readers》 | 主提示词 |
| 句子层清晰度 | 《Style: Lessons in Clarity and Grace》 | 一句一个主张 |
| 不跳过步骤 | 《The Sense of Style》（知识的诅咒） | 阶段 3 |
| 内容类型分离 | Diátaxis（tutorial / how-to / reference / explanation） | 阶段 1 第 3 问 |
| 例子要有梯度 | Sweller 的范例效应 + Renkl（2005）的 fading 序列 | 阶段 2 第 4、5 步 |
| 代码可信、给预期输出 | Google Technical Writing「Creating sample code」+ 代码教程十段式 | 主提示词 + 阶段 2 |

---

## 怎么用

| 场景 | 做法 |
|---|---|
| 写新教程 | 三次调用分开做，别一次全贴 |
| 已有初稿要改 | 跳阶段 1，直接阶段 3 审稿 |
| 别人写的稿子要评 | 只贴阶段 3，读者设定填真实读者 |
| 写 API 参考 | 不用这套，参考类不该有叙事和练习 |

一个提醒：**阶段 2 一次只写一节。** 让它一次写三节，第三节一定开始注水——因为它的"篇幅预算"用完了，只能拿形容词补。
