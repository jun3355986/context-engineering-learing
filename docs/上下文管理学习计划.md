# 上下文管理学习计划（交接版）

> [!abstract] 速览：换一个 agent 接手，先读这一节
> - **这是什么**：Drake 学习 AI 编程 agent 的上下文管理。2026-11-02 起的方式是 **「问题 + 教程」**：agent 一章一章写第四版教程，每章开头先列几个问题，Drake 带着问题读，正文写到相关处给出答案。不再出题让 Drake 作答、不再批改。
> - **本文档的用途**：它是入口。读完它，任何 agent 不需要原对话，就能接着往下写。
> - **写法**：严格按 `docs/写作规范-问题驱动.md`。样章是 `第四版/02-一次请求里装了什么.html`。
> - **当前状态（2026-11-02）**：第 2 章样章已写完，等 Drake 读后反馈。下一步建议写第 3 章（素材已备齐，见第 6 节）。
> - **接手三步**：① 读本文档第 3、4、6 节和写作规范 → ② 跑 `git status` → ③ 按第 3 节写下一章。想直接开工，复制第 10 节的开场提示词。

## 1. 目标与方式

**目标**：Drake 直接、高效地学会 agent 上下文管理（一次请求里装什么、命令输出怎么不撑爆、压缩后还记得什么、缓存、工具、子代理、回退、跨会话记忆、窗口满了怎么办、怎么评估）。

**方式（2026-11-02 起）**：agent 写一章 → Drake 读 → 有疑问或觉得哪里不对就说 → agent 当场回答、修改。每章开头列 3–5 个问题，正文写到相关处放「答案框」，章末小结里每个问题一句话答案。

**Drake 不做的事**：不读源码、不跑实验、不写笔记、不做题。

**Drake 做的事**：读章节；提疑问；反馈写法和显示问题。

**第三版怎么用**（`ai codiing 工具上下文对比报告/第三版/tutorial/pages/*.html`，冻结）：
- **非源码部分**（intro、main、adv、appendix）：只抽知识点清单，检查新章有没有漏讲。**不参照写法，也不修正它。**
- **源码部分**（`src-*`）：当线索（文件、函数、行号），写进正文前必须重新对照源码核对。

**产出**：`ai codiing 工具上下文对比报告/第四版/` 下每章一个 HTML 文件，目录页 `index.html`。

**公众号文章**：只有 Drake 说「可以出文章了」才写。

### 2.2 已确认的事实（后续章节要和它一致）

条件：Codex 源码 `76ed3b4`，CLI `0.165.0`，模型 `gpt-6.1-sol`（Lite 请求格式）。详细数据和出处在第 2 章的证据表。

- 会话中途：会话设置按状态比较，没变不加、变了在末尾追加。**全局 AGENTS.md 每次请求前重读；项目 AGENTS.md 一个会话只读一次**（工作环境或信任级别变了才重读）。来源：源码 + Codex 自带测试，**没做自己的实验**（实验需要不带沙箱执行命令，被本机自动权限检查拦下）。

## 3. 每章怎么写（agent 操作手册）

```text
A 准备（核对事实）→ B 写章 → C 检查 → D 记录 → [Drake 读] → E 按反馈改
```

### A 准备

1. 从第 6 节路线表找到本章对应的第三版页面，**只抽知识点清单**（读标题和要点，不照搬正文）。
2. 第三版 `src-*` 页面里的文件、函数、行号当线索，到 Codex 源码里逐条核对；Codex 自带测试（`core/tests/suite/`）也是好证据。
3. 能做实验就做实验，脚本放 `自学单元/` 下对应目录（见第 5 节）。
4. 列出本章的 3–5 个开篇问题，确认每个都能用已核对的事实回答。

### B 写章

- 按 `docs/写作规范-问题驱动.md`：开篇问题 → 正文（写到相关处放答案框）→ 对照框（可选）→ 看源码框（可选）→ 设计笔记 → 小结 → 证据表。
- 正文 3,000–5,000 字。不编故事开头；一个概念只讲一次。
- 文件名：`第四版/NN-标题.html`（如 `03-命令输出几万行.html`）。样式和脚本可以从第 2 章复制。

### C 检查

- 本机**没有 node 和浏览器**：做静态检查（标签配对、脚本用到的 id 都存在、页内锚点都存在、括号平衡），统计正文字数。
- 告诉 Drake 页面没有在浏览器里打开过，请 Drake 反馈显示问题。
- 对照写作规范第 6 节的自检清单过一遍。

### D 记录

| 文件 | 更新什么 |
|---|---|
| `第四版/index.html` | 本章状态和链接 |
| 本文档第 2 节和第 11 节 | 进度、新确认的事实、未决事项、日志 |
| `自学单元/我的疑问.md` | Drake 提的疑问（主线/支线）、答在哪一章 |
| `memory/qa-learning-plan.md` | 仅限 Claude Code：同步进度 |

### E 按反馈改

Drake 读完提的问题当场答。和本章相关的，改进本章正文（必要时加一个开篇问题和答案框）；和别的章相关的，记进那一章的待写清单；和上下文管理无关的，简答并标「支线」。

**独立复核**（可选）：一章写完后，可以用新会话或子代理独立核对证据表。**开之前先问 Drake。**

## 4. 证据规范（不可省）

写的和核的都是 AI，Drake 无法自己判断对错，所以：

1. **每条结论带出处和等级**：【源码 文件:行号@提交】【测试 文件:行号@提交】【实验 目录或命令】【官方文档 网址，抓取日期】【推测】【待核实】。正文用上标编号链到证据表。
2. **版本**：Codex 源码 `76ed3b4`（本机 `/home/ubuntu/work/codex-76ed3b4/codex-rs`，仓库外），CLI `0.165.0`。
3. **没核对到的不说成确定**，标【待核实】或【推测】，并且在正文里看得见。
4. **Drake 说「给证据」，立刻给出处。**
5. **Claude Code**：本机没有它的源码。优先用官方文档（`code.claude.com/docs`，写抓取日期）；用非官方源码 v2.1.88 时写明来源。

### 犯过的错（避免重犯）

- **没测就认可**：曾认可「MCP 多了非常占空间」，实测 40 个假 MCP 工具请求体不变，只好收回。
- **实验条件没交代清**：第二次请求实验用假服务器（自定义通道）走了 HTTP，官方默认是 WebSocket。结论要写明实验条件。
- **数字口径不统一**：统一用整条 `input` 条目的 `json.dumps` 字节数（如工具定义 25,347 B）。
- **用了自己的简称**：如「多代理两条」，Drake 看不懂。
- **照搬第三版**：第三版有错，也会自相矛盾。非源码部分只取知识点，源码部分必须重新核对。

## 8. Drake 的偏好与约束

- 用**中文**交流。Drake 有开发背景，是学习者，不读源码、不写笔记、不做题。

- 教程用图文 + 交互式 HTML。
- Drake 随时会提疑问，**当场回答**；主线始终是上下文管理。
- **不要提交、不要推送**，除非 Drake 明确要求。
- 对外发布类动作（发布 Artifact、发消息等）**先问**。章节是本地文件，不需要发布。
