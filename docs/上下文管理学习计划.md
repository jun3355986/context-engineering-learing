# 上下文管理学习计划（交接版）

> [!abstract] 速览：换一个 agent 接手，先读这一节
> - **这是什么**：Drake 用「AI 出题 → Drake 作答 → AI 批改并讲解」的方式学习 AI 编程 agent 的上下文管理。每轮讲解做成一页交互式 HTML，逐轮长成「第四版」教程。
> - **本文档的用途**：它是入口。读完它，任何 agent 不需要原对话，就能接着往下做。方案的设计理由在 `docs/上下文管理问答学习方案-2026-11-01.md`，本文档不重复。
> - **当前状态（2026-11-01）**：U01 已完成（第 1 轮 2.5/5，补考 2.0/3，过关）。**下一步是 U02 第 1 轮**，开头要插 1 道 W1 旧题复测。
> - **接手三步**：① 读第 2、3、4 节 → ② 跑 `git status` 看有没有没提交的改动 → ③ 按第 3 节的流程开始 U02。想直接开工，复制第 10 节的开场提示词。

## 1. 目标与方式

**目标**：Drake 直接、高效地学会 agent 上下文管理（一次请求里装什么、命令输出怎么不撑爆、压缩后还记得什么、缓存、工具、子代理、回退、跨会话记忆、窗口满了怎么办）。

**Drake 不做的事**：不读源码、不跑实验、不写笔记。源码层的证据确认全部由 agent 做。

**Drake 做的事**：在对话里回答问题；觉得讲解页有问题就说；随时提自己的疑问。

**用第三版做什么**：第三版教程（`ai codiing 工具上下文对比报告/第三版/tutorial/pages/*.html`，59 页）冻结，只当**素材和待核对的论断清单**。里面有错，agent 要对照源码核实，错的改掉，告诉 Drake 真正的原理。第三版的错只在勘误清单里**简单列条目**，不展开。

**产出**：`ai codiing 工具上下文对比报告/第四版/` 下每轮一页 HTML，就是第四版的一章。章节顺序跟问答主线走，不对齐第三版。

**公众号文章**：不是每轮都出。只有 Drake 说「可以出文章了」才生成。

### 2.3 U01 已确认的事实（后续单元要和它保持一致）

条件：Codex 源码 `76ed3b4`，CLI `0.165.0`，模型 `gpt-6.1-sol`（Lite）。详细数据和证据在 U01 讲解页的「证据表」一节。

- Lite 模型的请求没有 `instructions` 字段、没有顶层 `tools`。`input` 共 7 条：`[0]` developer 工具定义（`additional_tools`）→ `[1]` developer 系统提示词 → `[2]` developer 技能目录+权限+协作模式（合并成一条）→ `[3]` developer `multi_agent_role` → `[4]` developer `multi_agent_mode` → `[5]` **user** AGENTS.md+环境信息 → `[6]` user 用户的话。
- 请求里**没有 system 角色**，只有 developer 和 user。
- 一句话的请求约 53.6 KB ≈ 1.34 万 token：工具定义 47%，系统提示词 41%，会话配置 11%，AGENTS.md+环境 1.1%，用户的话 0.04%。token 估算 = UTF-8 字节数 ÷ 4 向上取整（Codex 自己的算法）。
- AGENTS.md 上限 32,768 **字节**，多级目录共用预算（先读根），从**尾部**截，不报错、不通知模型，只写 warn 日志。
- 传输方式：官方通道默认先走 **WebSocket**，出错重试用尽后本会话永久退回 HTTP；自定义通道只走 HTTP；没有用户开关。U01 的第二次请求实验走的是 HTTP（假服务器属于自定义通道），**WebSocket 路径只读了源码，没做实验**。

## 3. 每轮怎么做（agent 操作手册）

```text
A 准备 → B 出题（只出题）→ [Drake 作答] → C 批改 → D 讲解页 → E 记录 → F 收尾
```

### A 准备（出题前，Drake 看不到）

1. 读本单元的「第三版可参考」章节（第 6 节路线表），把可核对的**论断**列出来。
2. 对照源码和实验逐条核对。结论分级：对 / 错 / 版本相关 / 待核实。
3. 写一份**答案卡**：每题的标准答案、评分要点、证据出处。存到 `自学单元/.答案卡/Uxx-Rn.md`（隐藏目录，Obsidian 不显示；目录不存在就新建）。**批改前不要把答案卡的内容给 Drake。** U01 的答案卡没有保留，要点都已并入 `自学单元/U01-题与答.md`。
4. 准备一条 **30 秒可复现检查**（一条命令或一段输出），讲解时给 Drake。

### B 出题

- **只出题，不给材料。** 每轮 5 题。
- **题型配比**：1 列结构、2 预测（含量级估算）、1 诊断、1 取舍。具体数字不单独考。「不知道」是合法答案。
- **除第 1 轮外，插入旧薄弱点复测**：见 2.2 节的安排。每轮只插 1 道；换条件，不重复原题。
- **措辞规矩**（Drake 因此卡住过：U01 疑问 1、2 和补考 3(c)，见 `自学单元/我的疑问.md`、`自学单元/U01-题与答.md`）：
  - 每个小问只问一件事，先交代前提。
  - 方法类的词（如「确认」）要写出具体动作。
  - 术语第一次出现给一句白话解释，不用只有 agent 自己懂的简称。

### C 批改

- **标记**：✅ 1 分 · 🟡 0.5 分 · ❌ 0 分 · ⬜ 不知道（0 分）。🟡 和 ❌ 标错因：漏项 / 因果或顺序反 / 概念混淆 / 以偏概全 / 数字记错 / 审题。
- **过关**：5 题 ≥ 4 分。不过就出 **3 道补考题**（针对薄弱点，换条件），≥ 2 分过关，过关才进下一单元。
- **顺序**：逐题批改 → 带证据的标准答案 → 原理解析 → 针对 Drake 错因的补讲。加分题不计分。
- **标准答案如果后来发现错了**：当场更正，写明改了什么，分数不追改（对 Drake 有利的方向不收回，不利的方向不追加）。U01 第 5 题就是这样处理的。

### D 讲解页（第四版的一章）

放在 `ai codiing 工具上下文对比报告/第四版/Uxx-….html`，并在同目录 `index.html` 追加一项。**U01 的页面是格式样板**：`第四版/U01-一次请求里装了什么.html`。

| 规范 | 内容 |
|---|---|
| 形式 | 单文件，CSS 和 JS 内联，不依赖网络，双击能开；浅色/深色跟随系统且有切换按钮；手机宽度能读 |
| 固定块 | ① 本轮批改（标 `data-personal`，成书时去掉）② 主线讲解（图 + 能改条件看结果的交互）③ 一页纸小结 ④ 证据表（每条结论的出处与等级）；Drake 的疑问做成「疑问卡」一节 |
| 交互 | 用真实实验数据驱动，让 Drake 能改条件看结果。不做纯装饰的动画 |
| 验证 | 本机目前**没有 node 和浏览器**。做静态检查：标签配对、`$('#id')` 的 id 都存在、括号平衡。**告诉 Drake 页面没有在浏览器里打开过**，请 Drake 反馈显示问题 |

### E 记录（每轮都要更新）

| 文件 | 更新什么 |
|---|---|
| `自学单元/Uxx-题与答.md` | 本轮题、Drake 的原话、判定、错因、标准答案、补考结果 |

| `自学单元/我的疑问.md` | Drake 提的疑问（主线/支线）、回答在哪 |
| `第四版/index.html` | 追加本章 |
| 本文档第 2 节和第 11 节 | 进度、薄弱点、未决事项、日志 |
| `memory/qa-learning-plan.md` | 仅限 Claude Code：同步进度 |

### F 单元收尾

- 一个单元结束时，**建议**用新会话或子代理独立复核该单元的标准答案，避免自己批自己的卷。
- **开之前必须先问 Drake。**

### 疑问通道

Drake 随时可能提疑问，当轮回答，不要等到下一轮。短的在对话里答；需要图的做成讲解页的「疑问卡」。与上下文管理相关的归入对应单元（主线）；无关的简答并标「支线」，不进第四版。

## 4. 证据规范（不可省）

出题和批改的 AI 是同一个，Drake 无法自己判断对错，所以：

1. **每条结论带证据等级和版本**：
   - 【源码 文件:行号@提交】【实验 目录或命令】【官方文档】【第三版原文，未核】【推测】【待核实】
   - Codex 版本：源码 `76ed3b4`（本机 `/home/ubuntu/work/codex-76ed3b4/codex-rs`，仓库外），CLI `0.165.0`。
2. **没核对到的不说成确定。** 标【待核实】或【推测】。
3. **每轮附 1 条 30 秒复现检查**，Drake 不读源码也能抽查。
4. **Drake 说「给证据」，立刻给出处。**
5. **Claude Code**：本机没有它的源码。引用 Claude Code 非官方源码时标「来源：Claude Code 非官方源码 v2.1.88」。官方没公开的服务端行为，只能标官方文档或推测。

### 上一位 agent 在 U01 犯过的错（避免重犯）

- **没测就认可**：批改时认可了「MCP 多了非常占空间」，后来实测 40 个假 MCP 工具请求体不变，只好收回。别在没测量前认可直觉。
- **实验条件没交代清**：第二次请求实验用假服务器，它属于自定义通道，所以走了 HTTP；官方默认是 WebSocket。结论要写明实验条件。
- **数字口径不统一**：同一个块出现过三种字节数。统一口径：整条 `input` 条目用默认 `json.dumps` 序列化（如工具定义 25,347 B）。
- **用了自己的简称**：「多代理两条」没解释，Drake 看不懂。
- **照搬第三版**：第三版的五层图把系统提示词画在最前，实际 Lite 模型是工具定义最前。第三版也会自相矛盾（intro-02 与 main-01）。

`u01_capture.py` 的选项：`--prompt`、`--no-agents`、`--agents-file`、`--disable`/`--enable`（特性名）、`--tool-call`（第一次回工具调用，抓第二次请求）、`--model`、`--mcp-tools N`（挂 N 个假 MCP 工具，配 `u01_fake_mcp.py`）、`--out`。

**踩过的坑：**
- Shell 每次调用工作目录会重置：用绝对路径；`--out` 必须是绝对路径。
- `codex exec` 必须 `stdin=/dev/null`，否则会卡住等输入（脚本已处理）。
- 看到 `could not create PATH aliases` 的警告是无害的（临时目录）。
- 本机没有 node、deno、浏览器，没法跑页面里的 JS。
- 做新单元的实验，新脚本放进 `自学单元/Uxx-实验/`，不要往 `/tmp` 放要留的东西。

## 8. Drake 的偏好与约束

- 用**中文**交流。Drake 是学习者，不读源码，不写笔记。
- **解答用图文 + 交互式 HTML**；**第三版勘误只要简单列表**，供扫一眼。
- 第四版可以和第三版完全不同，**以问答主线为准**。
