# U01 第 1 轮 题与答

> [!abstract] 速览
> 得分 **2.5 / 5**（线是 4 分），未过关，补考 3 题。讲解页：`ai codiing 工具上下文对比报告/第四版/U01-一次请求里装了什么.html`（含图文和交互，证据表在页尾）。
> 条件：Codex 源码 `76ed3b4`，CLI `0.165.0`，模型 `gpt-6.1-sol`，2 行 AGENTS.md，只有内置工具。基线是我自己写的 [[U01-一次请求里装了什么|我原来以为]]。

## 1. 列结构 🟡 0.5

**题**：这次请求里从前到后有什么？每块是什么角色？有没有单独放系统提示词的字段？

**我的原话**：从前到后，依次是: AGENTS.md(system), 系统提示词(developer)，工具定义，你的消息（user）.我猜测codex没有单独放提示词的字段

**对的**：没有单独的系统提示词字段；你的话在最后。
**要改的**：真实顺序是 工具定义 → 系统提示词 → 技能目录/权限/协作模式 → 多代理两条 → AGENTS.md + 环境信息（这两段在同一条 **user** 消息里）→ 你的话。漏了会话配置类片段和环境信息。
**错因**：顺序反 · 概念混淆（AGENTS.md 是 user 不是 system）· 漏项

## 2. 估量级 ❌ 0

**题**：总共多少 token？你的话占多少？几类内容怎么排序？最大块占几成？

**我的原话**：几千。我那句话大概占1/10。排序：系统提示词、AGENTS.md、你的话、工具定义。最大一块占 80% 。

**实测**：≈1.34 万 token；工具定义 6,337（47%）、系统提示词 5,445（41%）、会话配置 1,475（11%）、AGENTS.md + 环境 148（1.1%）、你的话 6（0.04%）。
**错因**：数量级直觉偏差——总量低估、你的话高估约 250 倍、工具定义被排成最小。

## 3. 改条件 🟡 0.5

**题**：AGENTS.md 换成 40000 英文字符 / 15000 汉字，各进多少？截哪一端？报错吗？

**我的原话**：40000 个英文字符全部进入请求。15000 个汉字，有 1000 多个左右没有进入请求，最后面的 1000 多个字被截断。不会报错，不会提示

**对的**：从尾部截；不报错；按字节算的思路（汉字丢的数目是按 3 字节折算的）。
**要改的**：上限是 32,768 字节（32 KiB），不是 40000。英文只进 32,768 字符，汉字进 10,923 个，丢约 4,078 个，末尾被切坏成 `�`。
**错因**：数字记错。我猜 4 万来自 Claude Code 的单文件字符告警线（第三版转述，未核）。

## 4. 第二次请求 ✅ 1

**题**：HTTP 方式下第二次请求和第一次比，哪些不动、哪些追加？工具定义和系统提示词还在吗？为什么？

**我的原话**：系统提示词、AGENTS.md、工具定义、前面你的话原样不动。第一次的响应、工具调用结果是追加的。工具定义和系统提示词还在。这是为了保证有上下文背景信息，大模型是没有记忆的，第一次请求都是全新的请求，没有这些内容大模型不知道前面干嘛了。发出的内容和大模型看到的内容是一样的。

**判定**：全对。补充：前缀不变还有缓存的好处（U04）。
**加分题（不计分）**：「发出的内容和模型看到的一样」只在 HTTP 整份重发时成立。WebSocket 路径用 `previous_response_id` 续传，线上只发新增条目，模型仍看到全部（源码证据，未实验）。

## 5. 取舍和排障 🟡 0.5

**题**：想让窗口装更多有用内容，(a) 自己的话写短 (b) 精简 AGENTS.md (c) 砍工具/MCP，先动哪个？怎么确认？

**我的原话**：依次是C 、B、A。不用的工具和 MCP 是最没用的内容，这些内容多了非常占空间。精简 AGENTS.md，相比自己的话，这个没那么重要。

**对的**：排序 C、B、A 与数据一致。
**缺的**：「怎么确认」——先用 `codex debug prompt-input` 或抓请求量每块大小，再动手；边界——内置工具砍不掉，干净环境里 C 没得砍；与第 2 题的工具排名自相矛盾。
**错因**：缺方法 · 漏边界
