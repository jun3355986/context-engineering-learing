## 一、核对到的事实（出题依据）

命令输出从产生到进入请求，最多过 **四道闸**（按先后）：

| 闸 | 谁 | 做什么 | 证据 |
|---|---|---|---|
| ① 进程输出缓冲 | `HeadTailBuffer`，上限 1 MiB | 头 512 KiB + 尾 512 KiB，中间丢掉，计数 `omitted_bytes`；最终文本最前面补一行 `... N bytes omitted ...` | 【源码 core/src/unified_exec/head_tail_buffer.rs:11-19、unified_exec/mod.rs:75】【实验 out/seq300000-direct：199 万字节 → 标记 `940319 bytes omitted`（= 1,988,895 − 1,048,576）】 |
| ② 工具层 | `exec_command` 的 `max_output_tokens`，默认 10,000 token；与模型目录的 `truncation_policy` 取小 | 中间挖掉：头尾各一半，中间换成 `…N tokens truncated…`；开头加说明头 `Warning: truncated output (original token count: N)` + `Total output lines: M` | 【源码 core/src/tools/context.rs:482-493,550-580、unified_exec/mod.rs:74,221-222、output-truncation/src/lib.rs:23-35】【实验 out/seq50000-direct：输出 40,217 B ≈ 10,055 token，标记在 50% 处】 |
| ③ 代码模式外层（仅 Lite） | `exec`（模型写 JS，JS 里调 `tools.exec_command`）的最终结果 | 又按 `exec` 自己的 `max_output_tokens`（默认 10,000；JS 第一行 `// @exec: {...}` 可改）截一次，说明头可叠两层 | 【源码 core/src/tools/code_mode/mod.rs:263-300,318-335】【实验 out/seq50000-lite、seq50000-lite-req50000（模型把 exec_command 的上限调到 5 万，仍被外层截回 1 万：出现两层说明头）】 |
| ④ 历史层兜底 | `record_item_with_metadata`，预算 = 模型 `truncation_policy` × 1.2 = 12,000 token；`config.toml` 的 `tool_output_token_limit` 能改这个基数 | 再截一次；**只作用于活历史，rollout 里留的是进入这一层之前的文本** | 【源码 core/src/context_manager/history.rs:555-577、models-manager/src/model_info.rs:32-45】【实验 out/seq50000-lite-both30000：两处都开到 3 万 → 请求里 48,027 B ≈ 12,007 token；rollout 里最大一条 142,500 B 保留着三万 token 那版】【实验 out/seq50000-lite-limit2000：基数 2000 → 2,400 token】 |

**5 万行实测（`seq 1 50000`，288,894 B，估算 72,224 token，50,000 行）：**
- 进入第二次请求的工具输出：Lite 路径 40,158 B ≈ 10,040 token；直发路径 40,217 B ≈ 10,055 token。第二次请求体 103,975 B ≈ 25,994 token（Lite），比第一次约多 1 万。
- 留下：头约 1～4221 行 + 尾约 46,667～50,000 行（切在行中间，如头尾各有半截数字），中间约 4.24 万行（含第 25000 行）整个丢掉。标记 `…62224 tokens truncated…`。
- 标记不占预算 → 输出比 10,000 token 略多（40,158 B > 40,000 B）。

**原文去哪了：**
- **没有地方留着。** 对命令输出，rollout 里存的是 ②（和 ③）之后的文本，不是原始输出：5 万行的 rollout 里没有第 25000 行（`\n25000\n` 搜不到），最大一条记录 48 KB，不是 289 KB。只有 ④ 的截断才是「活历史截、rollout 留」。
- 进程退出后缓冲也没了。模型要看中间，只能重新跑命令（换成 grep / sed 范围 / 重定向到文件再分段读）。Codex 没有「读 rollout」的工具【源码 grep 未发现，未穷尽】。

**中文 / 估算偏差：** 3 万个「汉」= 90,001 B，估算 22,501 token；进入请求 40,210 B（约 1.3 万汉字）【实验 out/han30000-direct】。估算是字节数 ÷ 4，中文一字 3 字节 → 按 0.75 token 计；真实分词一个汉字常常不止 0.75 token，所以真实占用可能高于 1 万【推测：未用真实 tokenizer 测】。

**旧输出会不会被清掉：** `core/src` 里未发现「清空旧工具结果」的独立通道（grep `prune / Old tool result / microcompact / clear_old_tool` 无命中）【源码 grep，未穷尽，未做多轮实验】。所以进入历史的 1 万 token 之后每次请求都重发，直到压缩（U03）或新会话。

## 三、题与标准答案

分值：✅ 1 · 🟡 0.5 · ❌ 0。过关 ≥ 4 分，否则出 3 道补考。

### 第 1 题（列结构·复测 W1）
(a) 工具定义：**developer**（`additional_tools`，`input[0]`）。
(b) AGENTS.md：**user**（`input[5]`，和环境信息同一条）。
(c) system 角色：**没有**，只有 developer 和 user。
(d) 追加位置：**最后面**（在用户的话之后，按时间顺序追加：先模型的工具调用，后命令输出）。补讲：这两条不是带角色的消息，条目类型是 `function_call` / `function_call_output`（Lite 是 `custom_tool_call` / `custom_tool_call_output`）。
评分：4 个里对 ≥3 ✅；对 2 个 🟡；≤1 ❌。(a)(b)(c) 是 W1 本体，(c) 错就不给 ✅。
证据：U01 out/latest、out/tool-call（req-2 末尾三条）；本轮 out/seq50000-lite/req-2.json。

### 第 2 题（预测）
(a) 不会全部进入，只进一部分。
(b) **头和尾各留一半**，中间挖掉，换成 `…62224 tokens truncated…`；开头有说明头（原始 token 数、总行数）。
(c) 约 **1 万 token**（实测 10,040），不是 7.2 万。
评分：(a)(b)(c) 全对 ✅；对 2 个 🟡；≤1 ❌。(b) 答「只留开头」或「只留结尾」算错，答「两头」对；(c) 在 0.7～1.5 万算对。

### 第 3 题（预测·累计）
(a) 按他 2(c) 的数乘 10；标准是 **约 10 万 token**（10 × 1 万）。
(b) **还在**：历史每次整份重发，旧命令输出不会自己消失（U01 第 4 题的结论 + 本轮源码里未发现清理旧输出的通道）。补讲：11 次请求总量约 11.4 万，窗口够，但每一轮都在为这 10 万付费（U04）；窗口真满了靠压缩（U03）。
评分：两问都对 ✅；一问对 🟡；否则 ❌。(a) 以他第 2(c) 的答案为准算对错；他 2(c) 答「不知道」就按 1 万算。

### 第 4 题（诊断）
(a) 日志的**中间被截掉了**，第 25000 行正好在被挖掉的那段（头约到 4221 行，尾从约 46667 行开始）。agent 没撒谎，它看到的只是头和尾。
(b) 看工具输出本身：开头的说明头 `Warning: truncated output (original token count: …)` / `Total output lines: 50000`，以及中间的 `…N tokens truncated…`。
评分：(a) 对 + (b) 说到「输出里有截断说明/标记」✅；(a) 对、(b) 答不到 🟡；(a) 答「模型漏看/幻觉/日志没写全」❌。
注意：不要接受「文件没写进去」之类答案；他若说「agent 读漏了」要追问漏在哪一步。

### 第 5 题（取舍）
好答案（推荐）：**让命令自己缩小输出**——`grep -n ERROR`、`tail`、`sed -n 范围p`，或先重定向到文件再分段读。代价：要多跑一两次命令；需要知道找什么。
可接受但有坑：调大 `max_output_tokens`（模型每次调用传）；调大配置 `tool_output_token_limit`。代价：每条输出都会进历史，之后每次请求都重发（第 3 题）；且 Lite 路径有外层 `exec` 的 1 万默认和历史层 1.2 万的上限，调了不一定生效【实验 out/seq50000-lite-req50000、both30000】。
评分：(a) 至少 2 个办法 + (b) 选了推荐的 + (c) 代价说到「占上下文/重发」✅；选了调大上限并说出代价 🟡；选了调大上限但不提代价、或只有一个办法 ❌/🟡 酌情。
