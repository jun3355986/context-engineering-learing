## 二、保留、重组、补充清单

**保留（经复核仍然成立的质量基准）**
- 郊游 · 下午 4 点前返校主线；资料柜/工作桌隐喻（限定解释"保存与使用"的区别）。
- 四个阈值数字预设的演算思路（低于线/恰好到线/增长未到整段未到/增长未到但整段到）。
- 20K/64K 的"直接保留预算≠触发线≠请求总量"三组区分。
- 压缩方式（自动/手动）与观看方式（逐步/自动播放）分离的要求。
- 官方缓存原页入口 + 中文复现标注 + 实际可操作性验证（不用 load 事件代替）。
- "源码依据放章末""基础概念常显""术语先例子后定义"等修订纪律。

**重组（结构变化）**
- 十章 → 9 个单元 + 附录：把"源码索引"从独立一章降为各单元末尾的固定节与附录总索引（现有第 08 章只讲两行 Rust，本次把源码阅读均匀分布）。
- 缓存从第 09 章后置顺延为单元 08 之后直接进入收束单元 09（先机制后设计），并在缓存单元内补 CLI 字段证据。
- 状态与恢复（原 05）与失败（原 06）保持相邻但边界重划：U6 讲"正常路径的保存与恢复"，U7 讲"失败路径与手动路径"。
- 各单元统一采用"问题 → 例子/交互 → 人话定义 → 术语 → 伪代码 → 真实源码 → 自测"七拍。

**补充（本次新增内容）**
- 独立核查新增事实（见第三节），全部带固定行号链接。
- "剩余额度报告"与"触发判断"是两个输出（context_window.rs L88-95 vs L105-110）——现有证据未强调。
- `split_budget` 左右并非均分（左 floor 右 ceil，奇数预算差 1 字节）。
- OpenAI/Azure provider 默认 `RemoteCompactionSupport::V2`（capabilities.rs L31-52）+ 测试佐证。
- `Feature::RemoteCompactionV2` 的 Stage 为 Removed，仅用于无条件 advertise 请求头（session/mod.rs L1255-1273）。
- CLI 请求携带 `prompt_cache_key`（默认 = session_id），SSE 解析 `cached_tokens`/`cache_write_tokens` 进入 `TokenUsage`。
- 边界消息的"第三条注释"：`insert_initial_context_before_last_real_user_or_summary` 的三级插入点回退。
- 失败路径更精确的数字：本地重试上限=provider 设置（默认从 provider 取，最大 100 的配置上限见证据文档记载）、远端 v2 = min(provider, 2)。

## 四、写作执行决定

1. 单元命名采用"单元 01–09"，但内部叙述顺序、例子、伪代码与视觉独立设计。
2. 源码节选统一格式：先中文伪代码 → 真实 Rust 节选（标注固定 SHA 压缩版）→ 逐句解读，末尾给固定链接。
3. 所有教学数字分三类标注：演示数字 / 源码常量 / 测试样本；无实测处写"未运行"。
4. 交互组件 8 个（详见验收记录），全部离线可用；官方页面嵌入为可选折叠，另留外链。
