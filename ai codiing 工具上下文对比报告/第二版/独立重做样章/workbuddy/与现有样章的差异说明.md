# 与现有样章的差异说明（独立重做版）

> 交付物 5/5。对照对象：当前"Codex CLI 上下文管理 · 十章交互教程"（HTML + 配套说明 + 修订记录，2026-10-14 版）。
> 本文说明：保留了什么、重组了什么、补充了什么，以及每一处差异的理由。**默认覆盖现有十章的关键学习目标，不照搬章节标题、文案或视觉布局。**

## 0. 一句话总览

现有十章是"同一条主线不断加深"的迭代产物；本次独立重做把**教学骨架重新设计为"问题七拍 × 九单元"**，把**源码阅读从集中章节改为逐单元内联**，并补入**六项独立核查的新事实**（provider 默认 v2、缓存键与 usage 解析、插入点三级回退等）与**四个全新的交互形态**。两版共享同一质量基准（郊游主线、20K/64K 纪律、官方嵌入、模式纪律），但组织结构与信息呈现路径不同。

## 3. 实现（源码事实）差异——本次独立核查的新增与修正

| # | 现有表述 | 本次结论 | 性质 |
|---|---|---|---|
| 1 | "普通手动压缩按 provider 能力选择路径" | **OpenAI / Azure 系 provider 默认走远端 v2**（`capabilities.rs L31-51` + 官方测试断言）；`RemoteCompactionV2` feature 已是 `Stage::Removed`，只用于无条件广告请求头 | 新增事实（两处源码证据） |
| 2 | "缓存若要落到 CLI 需另查实际字段" | 已查：CLI **发** `prompt_cache_key`（默认=session_id）且**解析** `cached_tokens/cache_write_tokens` 进 `TokenUsage`；边界同步给出"不证明命中/不证明 UI 展示" | 新增事实 |
| 3 | "插入到当前上下文"（替代历史的插入点） | 精确为**三级回退**：最后真实用户消息前 → 摘要前 → 压缩条目前 → 追加 | 细化（`compact.rs L615-675`） |

## 5. 保留（两版共享的质量基准）

- 郊游·下午 4 点前返校主线；资料柜/工作桌隐喻（限定于"保存与使用"的解释）。
- 三个孩子般的实操纪律：20K/64K 直接保留预算 ≠ 触发线 ≠ 请求总量；压缩不删磁盘记录；恢复=替代历史+后缀。
- 压缩方式（自动/手动）与观看方式（逐步/播放）分离；条件不成立不假成功。
- 官方缓存原页入口 + 中文复现标注 + 实际可操作性验证（本次以真实鼠标操作复现 12,000↔11,264）。
- "术语先例子后定义""源码依据放章末""手机单章阅读"。
- 版本纪律：固定 SHA、不冒充当前发布版、未运行实验如实标注。

## 6. 为什么这样重做（判断与取舍）

1. **从"章"到"单元"**：章的数量是迭代痕迹（八章→十章），学习目标却是稳定的五级路线；按路线重编可以把"源码集中章"消肿、把"缓存"与"设计"两个终点单元放在正确的位置。
2. **源码阅读前置**：修订记录反复强调"读者不会 Rust 也要能懂"——最有效的做法不是集中补习，而是每单元都出现"伪代码→真码→逐句"的**小剂量重复**。
3. **事实先行**：独立核查发现的两处（provider 默认 v2、CLI 缓存字段）都直接影响读者对"我会看到什么产物"的预期，必须进正文而不是附录。
4. **交互收敛**：交互数量不追多，追"每个都改变内容可见性"——8 个组件都有定义好的观察目标（材料变化/数字变化/消失位置/状态分层），且全部通过自动断言与多宽度检查。
