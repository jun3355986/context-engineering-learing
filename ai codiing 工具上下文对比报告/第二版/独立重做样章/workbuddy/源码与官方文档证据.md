## 2. 官方缓存文档核查（2026-10-14）

来源：<https://developers.openai.com/api/docs/guides/prompt-caching>（当日实际打开）。关键规则（教程单元的引用出处）：

- 命中要求**完整渲染前缀**匹配；缓存保存的是 **KV tensors，不是 tokens**；
- 新代际最小可缓存 **1,024** 可见 token；隐藏系统内容不计入；
- 断点：新代际支持显式+隐式；5.5/5.5 Pro 隐式为固定 **2,048** 间隔；
- `cached_tokens` 上报：新代际精确；旧代际扣隐藏 token 后**向下取整 128 倍数**；
- 费率（新代际）：写 **1.25×**、读 **0.1×**（个别模型 0.05×）；1 写 1 读合计 **1.35×**；10 次（1 写 9 读）**2.15×**；不缓存两遍 **2×**；
- 生命周期：`ttl="30m"`（新，至少 30 分钟）；`in_memory` 5–10 分钟不活动（最长 1 小时）；`24h` 通常约 30 分钟（最长 24 小时）；ZDR 影响默认值；
- 每次请求最多 **4** 次缓存写入；查找范围：前 2 + 最新 50 显式断点（隐式模式另含隐式断点与最多 20 个更早合格端点）；
- 缓存不跨组织、不跨区域；计入 TPM；不可手动清除；
- 成本陷阱：`≤102 token` 前缀在给定假设下永不获益；`103` 需 ≥1,963 次请求；`≥221` 在 10 次请求内扩到 1,024 更便宜；
- **影响复用的变化**：model、tools、parallel_tool_calls、text.format、reasoning.effort、verbosity、context_management（压缩）等设置或内容变化——"从第一个变化的 token 起"。

**边界**：以上为 API 侧文档规则。**不能据此宣布固定 CLI 已启用新断点/30m TTL 等参数**（§1.5 的 CLI 证据只支持"发缓存键、认缓存明细"）。两者在教程中分开陈述。

## 3. 与旧证据的冲突与裁决

| 争议点 | 旧表述（现存证据/笔记） | 本次复核与裁决 |
|---|---|---|
| "90% 是触发阈值" | 旧学习笔记把 90%/95% 并列称"压缩阈值" | **90% 是范围线原料**（可被更低字段值按下），**95% 是整段线缺省比例**；两者 OR 判定。教程按裁决表述 |
| "20K 是压缩阈值" | 表格式笔记曾将 20,000 与阈值同列 | 20,000 为**直接保留预算**（本地路径）；与触发线无关 |
| "远端 v2 是否默认" | 旧证据只说"按 provider 能力选择" | 本次补充：**OpenAI/Azure 默认 V2**，且 `RemoteCompactionV2` feature 已是 Removed（仅广告头） |
| "压缩不可逆/可找回" | 第一版报告间互相矛盾 | 裁决：**存档追加不删旧记录**（D1）；**恢复只采用替代历史+后缀**（D3）。两者都为真、不矛盾 |
| "缓存与 CLI 无关" | 旧证据称"未另查 CLI 实际发送字段" | 本次核查：CLI **发** `prompt_cache_key`（默认 session_id）、**认** cached/write 明细（E3/E4）。边界见 E 表 |
| "边界消息均分头尾" | 旧表述"一半给开头、一半给末尾" | 精确为 split_budget：**左 floor、右 = 总数−左**（奇数差 1 字节归尾部） |
| 64K 混淆风险 | "64K 预算"多处出现 | 三个 64K 要区分：**64,000 token**（v2 保留预算）vs **64 KiB 字节**（持久化分片预算）——教程明确分开 |

## 4. 教程中数字的标注纪律
