# Grok Build · 证据导读

> **为什么这份文件不叫「源码导读」**：任务书 §4.3 给开源工具的产物是 `源码导读.md`（走一条代表链路：调用者 → 条件 → 处理 → 状态写回 → 下一次请求/恢复，含失败分支）。Grok Build **实现闭源**（预编译原生二进制，xAI 无公开实现仓库）。因此本文件改称**证据导读**：讲清"这个工具我们能证明什么、用什么方法证明、哪些永远不能证明"。
>
> **一句话边界**：可观测的只有**分发版本、随包文档与行为**；不可观测的是**内核实现与服务端**。任何把反混淆产物或二进制字符串当"源码"引用的做法，本包一律不采纳（任务卡明确禁止）。

## 3. 「代表链路」的闭源替代写法

开源工具写"调用者 → 条件 → 处理 → 状态写回 → 下次请求"，闭源工具改写成**可观测行为链**，每一步都注明证据：

**链 A：一次请求如何组装（CM-01 → CM-04 → CM-02 → CM-08）**
```
①【文档】系统提示词：默认提示词；--system-prompt-override 整体替换（用其文本）；
        --rules 追加，包在 <human_rules> 块里（1.0.52：追加在默认或 override 文本之后）
②【文档】AGENTS.md/项目规则：从 repo 根到 CWD 逐目录累积，深层文件在后、冲突时胜出
③【文档】技能：/skills <name> 注入；模型按 description 自动调用；技能体最多内联前 25,000 tokens
④【文档】记忆（默认关）：开启时系统提示词加 <memory> 段；每会话注入一次 MEMORY.md 索引（每 scope ≤8 KiB）
⑤【文档】工具定义：内置工具 + MCP（MCP 经 search_tool/use_tool 间接暴露，不进 tool_definitions.json 的 server__tool）
⑥【②分发件观察】落盘可核对：会话目录 system_prompt.txt（渲染后原文）、prompt_context.json（渲染输入）、
        tool_definitions.json（最新模型调用发送的函数工具）
```
**不可观测**：第 ①②④ 步在二进制内的**具体拼接字节序**与模板文本，闭源不可得；以上来自官方文档承诺，**未做端到端运行验证**（见 `过程观察.md` RUN-NOT_RUN-01）。

**链 B：一次自动压缩（CM-05 → CM-06 → CM-07 → CM-12）**
```
①【文档】用量接近触发线：auto_compact_threshold_percent（默认 85）× context_window（模型配置）
②【文档】自动压缩触发；TUI 给通知；两趟压缩 two_pass_compaction（默认 true）预发
③【文档】压缩策略 compaction_mode（summary/transcript/segments）+ compaction_detail（none..verbose）
④【文档】压缩产物：会话目录 compaction_checkpoints/（manual 或 auto 保存的状态）
⑤【②分发件观察】可观测读数：OTEL grok_code.compaction{duration_ms,tokens_before,tokens_after,model}；
        headless streaming-messages-json 的 system/compact_boundary 帧；signals.json 的 compactionCount
⑥【文档】压缩是一次独立模型调用（side-model），其用量**不计入**主 prompt 的 usage 合计
```
**不可观测**：第 ③ 步"segments 模式下逐字保留到什么程度"、第 ⑥ 步服务端摘要**真实内容与保真度**——**闭源/服务端**，标未决（见 `问题与审查.md` Q-02）。

**链 C：一次工具结果如何进入下一次请求（CM-04 → CM-07）**
```
①【②分发件观察】bash 输出被 `toolset.bash.output_byte_limit`（默认 65536 字节）截断
②【文档】MCP 输出经 `mcp.max_output_bytes` 限长；请求体经 `max_request_bytes`（messages 30 MB/其他 50 MiB），内联图片被驱逐
③【文档】工具结果剪枝 `[compaction.pruning]`：旧工具结果 >4000 字符 → 软裁保留头 1500 + 尾 1500 字符；
        超过 hard_clear_age_turns（10）轮 → 替换为占位符；最近 keep_last_n_turns（3）轮永不剪
④【文档】组装进下一次请求
⑤【②分发件观察】原文保留：会话目录 updates.jsonl / chat_history.jsonl 追加不删
```
**不可观测**：第 ①③ 步的**精确字节边界与顺序**（是否先按字节截断再按字符剪枝）——文档未明说，标未决。

## 4. 不可观测边界清单（本包总表）

| # | 不可观测项 | 原因 | 影响结论 |
|---|---|---|---|
| U-01 | 内核实现的常量名、公式与压缩算法（两趟压缩内部、segments 逐字规则、剪枝精确边界） | 闭源二进制；本轮**未下载反编译**、**未做**任何逆向 | grok-compact-02、grok-summary-02/03 只写"文档承诺级" |

| U-05 | 记忆捕获所用模型的**实际输出**与 Dream 折叠质量 | 后台模型调用；只暴露计数/字节 | grok-memory-03 只写机制与计数 |
