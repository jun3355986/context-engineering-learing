# Grok Build · 工具概览

> **本文件解决什么问题**：一页讲清 **Grok Build** 的身份、版本（双重口径）、语言、Stars、**12 机制覆盖表**、**默认 vs 扩展分列**、**客户端 vs 服务端分层**与适用范围，让课程（T15/T16）与比较（T14）有一个可引用、可定位、带证据等级的入口。
>
> **闭源纪律（贯穿本包全部文件）**：Grok Build 的**实现闭源**（xAI 官方预编译原生二进制，本机 `~/.grok/downloads/grok-<ver>-macos-aarch64`）。本包**不读实现源码、不反编译、不做字符串推测、不补造源码**。可核验的只有两类：①**官方文档承诺的行为**（一级证据；含随分发件提取的 `~/.grok/README.md` 与 `~/.grok/docs/user-guide/*`）；②**官方分发包与本地 CLI 的可观测项**（二级证据：版本、帮助文本、配置文件、目录布局、会话落盘结构、`grok inspect` 输出、运行行为）。社区线索一律**只作线索**（三级）。
>
> **命名纪律（T02 §G）**：正文统一用官方名 **「Grok Build」**（两词、无 `-er`）；**任务书作「Grok Builder」**。命令为 `grok`。本包**不混用其他 Grok 产品**（grok.com 网页版 / Grok API / Grok on X 均不在研究对象内；仅在 `cli-chat-proxy`/`grok.com` 作为**服务端**出现时按服务层标注）。

### 1.2 分发包性质（二级证据：分发件观察）

- 本机 `grok` 经 `~/.local/bin/grok → ~/.grok/bin/grok → ~/.grok/downloads/grok-<ver>-macos-aarch64` 两级软链；`file` 报 `Mach-O 64-bit executable arm64`。
- `~/.grok/` 为产品家目录（`GROK_HOME` 可覆盖），含：`config.toml`、`sessions/`、`memory-v2/`、`skills/`、`bundled/`、`docs/user-guide/`、`downloads/`、`README.md`、`version.json`、`marketplace-cache/`、`installed-plugins/`、`grove/`、`worktrees/` 等（完整清单见 `数据走查.md` DW-dist-01）。
- **随分发件提取的官方文档**：`~/.grok/README.md`（约 2,700 行，110,636 bytes）+ `~/.grok/docs/user-guide/01..27`（27 篇，合计约 11.2k 行）。`26-config-reference.md` 首行自述「This file ships with the CLI and is extracted to `~/.grok/docs/user-guide/26-config-reference.md` on launch.」

> **不能证明什么**：分发件目录/文档结构**不能**外推到内核实现。二进制内部常量名、压缩算法、服务端摘要内容**均不可得**（见 `证据导读.md §4` 不可观测总表）。

## 3. 客户端 vs 服务分层表（**可观测 / 不可观测**，逐条分列）

> **分界纪律（沿用 T09R 教训）**：**同源 ≠ 零耦合**；分层按**代码归属 + 证据可达性**逐条判定，不按"看起来像"二分。
> 「可观测」= 本包能用**官方文档 + 分发件/本地文件 + 运行输出**证明；「不可观测」= 落在 xAI 服务端（`cli-chat-proxy`/`grok.com`），CLI 侧只见字段或完全不可见。

| 环节 | 层 | 可观测证据 | 不可观测 / 不能证明 |
|---|---|---|---|
| 系统提示词渲染 / 组装 | **CLI** | `system_prompt.txt`、`prompt_context.json`、`--system-prompt-override`/`--rules`（17-sessions.md、12-project-rules.md） | 服务端如何解析该结构 |
| AGENTS.md / rules 发现与注入 | **CLI** | `grok inspect`（`projectInstructions`）、12-project-rules.md | — |
| 技能发现 / 激活 | **CLI** | `grok inspect`（`skills`）、08-skills.md、`grok_code.skill_activated` 事件 | 服务端技能包分发（`features.subagent_bundle`） |
| 工具定义发送（含 MCP） | **CLI** | `tool_definitions.json`（不含 MCP `server__tool`，走 `search_tool`/`use_tool`） | — |
| 工具输出限长 / 剪枝 | **CLI** | `toolset.bash.output_byte_limit`、`mcp.max_output_bytes`、`[compaction.pruning]` | 服务端是否二次处理请求体 |
| token 计量（窗口/用量） | **CLI 读数 / 服务端口径** | `signals.json`、`usage.json`、`/context`、`/session-info`、OTEL `grok_code.token.usage` | **真实分词/计费口径**由服务端决定 |
| 压缩触发判定（阈值比较） | **CLI** | `auto_compact_threshold_percent`、`context_window`、`compaction_at_tokens` | 服务端是否另设隐藏阈值 |
| 摘要生成（LLM 调用） | **CLI 发起 / 服务端执行** | `grok_code.compaction` 事件（tokens_before/after）、`compact_boundary` 帧、`compaction_checkpoints/` | **摘要文本内容与保真度**不可预知；不能证明"摘要一定保真" |
| 工具结果剪枝 / 硬清 | **CLI** | `[compaction.pruning]`（13-memory.md） | — |
| 长期记忆捕获 / Dream / 注入 | **CLI（本地模型调用）** | `memory-v2/` 布局、13-memory.md、`grok-shell-memory_injection` 事件、`memory_v2.daily_token_cap` | 捕获所用模型的**实际输出**；服务端是否有额外记忆侧 |
| 会话落盘 / 恢复 | **CLI** | `sessions/` 布局、17-sessions.md、`grok sessions`/`export`/`usage` | 远端 relay 同步（`relay.enabled`）的服务端行为 |
| 子 Agent 执行 | **CLI（本地执行器）** | `subagents/`、16-subagents.md、`grok_code.subagent` 事件 | 远端 Agent / `agent serve` 的服务端行为 |
| 重试与退避 | **CLI** | `models.max_retries`、`subagent_rate_limit_max_attempts`、`doom_loop_recovery` | 服务端限流策略 |
| **prompt cache 命中 / TTL / 缓存键** | **服务端（不可观测）** | CLI 仅读 `cache_read_input_tokens`/`cache_creation_input_tokens`/`cachedReadTokens`；OTEL `cache_read` 桶 | **命中率、存活期、缓存键、前缀断点** 全部 `UNOBSERVABLE` |
| **真实 cost / usage 计量** | **服务端** | `total_cost_usd_ticks`、`usage.json.costUsdTicks`、OTEL `grok_code.api_request` | 计费口径与"完整/不完整"判定由服务端盖章 |
| **模型窗口 / 模型元数据** | **CLI 配置 / 服务端目录** | `model.<id>.context_window`（配置或内置默认） | 实际服务端窗口若与配置不符，CLI 不可知 |

**分层结论**：Grok Build 的**上下文管理机制绝大部分落在 CLI 侧**（组装、规则/技能发现、限长、剪枝、触发判定、落盘、记忆捕获、恢复、重试）——**可观测**；**服务端承担**摘要执行、真实计量与**全部 prompt cache 行为**——**不可观测**。二者边界清晰。

## 5. 适用范围与边界

- **平台**：本包证据来自 macOS（darwin-arm64）+ 官方分发包 + 官方英文文档。Windows/Linux 行为未单独核验。
- **模型**：默认 `grok-4.6`（README 示例）/ `grok-build`；窗口由 `model.<id>.context_window` 或内置默认决定（本地实测某会话 `contextWindowTokens=500000`）。**不把某个模型的默认值外推为"Grok Build 的默认值"**。
- **入口**：TUI（`grok`）、无头（`grok -p`）、agent（`grok agent stdio/serve/headless/leader`）三种入口共享同一落盘与组装路径（17-sessions.md L3）。
