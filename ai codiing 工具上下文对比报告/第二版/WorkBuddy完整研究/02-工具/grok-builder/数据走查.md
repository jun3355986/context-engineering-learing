# Grok Build · 数据走查

> **本文件解决什么问题**：对每项机制给"**输入 → 处理顺序 → 前后对照（原样留下 / 变摘要 / 移除 / 落盘）→ 写回 → 找回入口**"，配**可算数字**（公式 + 代入值 + 结果 + 三类角标）与**边界例子**；失败分支给分类与是否有界。
> **数字角标**：【源码常量】本包用于"官方文档/配置给出的默认值"（闭源无源码，等价于"文档常量"）；【演示】教学代入值；【测试样本】来自本机真实文件（脱敏）。
> **单位纪律**：每个数字标单位（字节/字符/token）；**不把 token、字节、字符混用**。
> **数据地图四对象**：保存的记录 / 当前选中的材料 / 实际请求 / 外部记忆。

## DW-version-01｜版本漂移的判定（对应 grok-version-02）

- **输入**：本机 `grok` 可执行件 + `~/.grok/version.json`。
- **处理顺序**：① 会话起始 `grok --version` → ② 后续 `grok --version` → ③ `shasum -a 256` 两个 downloads 文件 → ④ `~/.grok/docs/user-guide/*` mtime。
- **前后对照**：

| 时点 | `grok --version` 自报 | `~/.grok/bin/grok` 指向 | 文档 mtime |
|---|---|---|---|
| 会话起始 | `grok 1.0.50 (c58f321264ba)` | `grok-1.0.50-macos-aarch64` | （旧） |
| 会话中（02:39 后） | `grok 1.0.52 (0920c8169e27)` | `grok-1.0.52-macos-aarch64` | `2026-10-15 02:39:57` |

- **可算数字**：
  - 冻结件 1.0.50 sha256 = `af41b1d65d4116ff649a689ad9d070d4c2abe255737d46ba0b3e8161345696e6`（**与版本表 §2 登记 `af41b1d6…696e6` 逐位一致**）。
  - 新件 1.0.52 sha256 = `c2caa9895dd763297a75e8fb6077e175d9c5304c53903e52cff8891a1384bbb9`。
  - 文档 diff 行数：`26-config-reference.md` 85 / `17-sessions.md` 37 / `14-headless-mode.md` 29 / `13-memory.md` 24 / `05-configuration.md` 18 / `12-project-rules.md` 3（其余多为 UI/工作树，与 CM 核心无关）。
- **写回/找回**：漂移登记进 `过程观察.md §1` 与版本表候选条目；冻结件仍在 `~/.grok/downloads/`，可复现 1.0.50。
- **失败分支**：若 auto_update 在观测中途替换二进制，则**同一观测批次的①口径可能跨版本**——本包已用"起始/后续两次 `--version`"锚定，避免混淆。
- **不能证明**：二进制内部行为差异（只有文档 diff）。

## DW-toolout-01｜bash 输出限长（对应 grok-toolout-01/02）

- **输入**：一条产生大输出的 bash 命令。
- **处理顺序**：命令输出流式捕获 → 按 `output_byte_limit` 截断 → 结果进消息。
- **前后对照**：**截断后**进请求；文档**未描述** bash 输出是否落盘全文（与 Claude Code 的"落盘+预览"**不同**）。
- **可算数字（边界例子）**：
  - 默认上限 **65,536 字节 = 64 KiB**【源码常量】。
  - 边界：输出 **65,536 字节** → 原样；**65,537 字节** → 超 1 字节即触发截断（文档未给"保头/保尾"规则 → 未决）。
  - 单位对照：64 KiB = 65,536 字节；**不等于** 64,000 字符，**不等于** 64,000 token。
- **写回/找回**：`mcp.max_output_bytes` 同理限 MCP 输出；请求体 `max_request_bytes`（messages 30 MB / 其他 50 MiB）。
- **失败分支**：命令超时 `timeout_secs` 默认 **120.0 秒**【源码常量】→ 命令被杀。
- **不能证明**：截断策略（头/头尾）；是否落盘。

## DW-toolout-02｜工具结果剪枝（对应 grok-toolout-03）

- **输入**：多轮会话中的旧工具结果。
- **处理顺序**：保留最近 `keep_last_n_turns`(3) 轮 → 更旧且 >`soft_trim_threshold`(4000 字符) 的**软裁**（留头 1500 + 尾 1500）→ 超过 `hard_clear_age_turns`(10) 轮的**硬清**（换占位符）。
- **前后对照**：软裁后 = 头 1500 字符 + 尾 1500 字符；硬清后 = 占位符（原文不再进请求）。
- **可算数字（边界例子）**：
  - 软裁阈值 4000 字符【源码常量】；保留 1500+1500=3000 字符。
  - 边界：结果 **4000 字符** → 不裁；**4001 字符** → 裁为 3000 字符（**奇数预算差 1 不切断**：头尾各 1500）。
  - 年龄边界：第 **10** 轮仍软裁；第 **11** 轮（>10）硬清【源码常量】。
- **写回/找回**：原文留在 `updates.jsonl`/`chat_history.jsonl`（追加不删）。
- **失败分支**：剪枝在压缩/组装中发生，原文**仍在磁盘**可找回。
- **不能证明**：剪枝与 bash 字节截断的先后顺序；软裁是否加省略标记。

## DW-trigger-01｜窗口与触发数字（对应 grok-trigger-01/02/03）

- **输入**：模型配置 `context_window` + `auto_compact_threshold_percent`。
- **处理顺序**：累计用量 → 与"阈值 × 窗口"比较 → 到线触发。
- **前后对照**：纯判定，无内容改动。
- **可算数字（公式 + 代入）**：
  - 触发线 = `auto_compact_threshold_percent` × `context_window`。
  - 代入（**演示**）：500,000 × 85% = **425,000 tokens**；若窗口 200,000 → 200,000 × 85% = **170,000 tokens**。
  - 对照 C-01「90%–95%」：Grok 默认 **85%**【源码常量】——**否证总括句**。
  - 本机实测（**测试样本**，脱敏）：某会话 `contextWindowTokens=500000`、`contextTokensUsed=137902`、`contextWindowUsage=27`（= 137902/500000 ≈ 27.6% → 显示 27）。
- **写回/找回**：`/context`、`/session-info`、`signals.json`、status-line 变量。
- **失败分支**：远端 pin 覆盖实际值（U-04）→ 观测到的阈值可能非 85。
- **不能证明**：分母是否含工具定义/系统提示词。

## DW-memory-01｜长期记忆的捕获与注入（对应 grok-memory-01/02/03/04）

## DW-fail-01｜失败分类与副作用（对应 grok-fail-01/02）

- **输入**：限流/超时/循环/压缩失败。
- **处理顺序**：分类 → 有界重试（`max_retries`=8）→ 限流等待（子 Agent 429 默认 8/上限 32）→ doom loop 重采样。
- **前后对照**：重试不改变历史；sandbox 一旦应用**不可逆**。
- **可算数字**：`models.max_retries` 默认 **8**【源码常量】；`subagent_rate_limit_max_attempts` 默认 **8**、上限 **32**、`0` 关闭【源码常量】；`inference_idle_timeout_secs` 默认 **600**【源码常量】。
- **写回/找回**：`signals.json`（errorCount/toolFailureCount/cancellationCount/doomLoopRecoveryAttempts）；`~/.grok/sandbox-events.jsonl`。
- **失败分支**：计量不完整时 headless 置 `usage_is_incomplete`（token 可能少计子 Agent）；cost 不完整时 `cost_is_partial` 并省略全部 cost 浮点。
- **不能证明**：退避算法；是否重复副作用。

## DW-cache-01｜缓存与成本的前后对照（对应 grok-cache-01/02）

- **输入**：一次模型响应。
- **处理顺序**：服务端返回 usage → CLI reshape 成三个不相交桶 → 写 `usage.json`。
- **前后对照**：

| 桶 | 含义 | 可观测入口 |
|---|---|---|
| `input_tokens` / `inputTokens` | **uncached** 输入 | `usage.json`、headless JSON、OTEL |
| `cache_read_input_tokens` / `cachedReadTokens` | 缓存命中 | 同上 |
| `cache_creation_input_tokens` / `cacheCreationTokens` | 缓存写入 | 同上 |
| `total_tokens` | = input + cache_read + cache_creation + output | 同上 |

- **可算数字（公式 + 代入）**：`total_tokens = input_tokens + cache_read_input_tokens + cache_creation_input_tokens + output_tokens`。代入文档示例（**演示**）：7,210 + 41,000 + 0 + 1,893 = **50,103**（与文档 `total_tokens: 50103` 一致）。
  - 成本口径：`total_cost_usd_ticks`，**1 USD = 10¹⁰ ticks**（文档示例 126,890,500 ticks = 0.01268905 USD）。
- **写回/找回**：`grok usage <session-id>`、`usage.json`、OTEL `grok_code.token.usage`/`api_request`。
- **失败分支**：服务端未报告完整 cost → 省略全部 cost 浮点（`cost_is_partial`）；"全零 usage"读作 **unknown 而非 free**。
- **不能证明**：命中率/TTL/缓存键（服务端 U-03）。

## 失败分支分类总览

| 类别 | 表现 | 是否有界 | 副作用可回退 | 证据 |
|---|---|---|---|---|
| 超窗 | 自动压缩触发；到线通知 | 有界（阈值） | 压缩改请求历史；磁盘不删 | grok-trigger-02、grok-summary-01 |
| 命令超时 | bash 被杀（默认 120s） | 有界 | 部分命令可能已执行 | grok-toolout-01 |

| 计量不完整 | `usage_is_incomplete`/`cost_is_partial` | 有界（省略字段） | — | grok-cache-02 |
| 沙箱 | 启动即应用 | 不可逆（设计） | **否** | grok-fail-02 |
