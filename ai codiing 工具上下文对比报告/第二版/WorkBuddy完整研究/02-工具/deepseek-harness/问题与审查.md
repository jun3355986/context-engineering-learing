## 3. 旧结论 / 冲突裁决（逐条）

| ID | 旧表述 | dsh 侧裁决 | 依据 |
|---|---|---|---|
| **C-01/C-02** | 三家触发阈值"90%–95%"总括 | **dsh 非 90–95%**：双上限公式 `floor(min(W×0.8, W−O−65536))`——**比例 0.8 ∧ 容量预留**；与各家（Codex 范围线/整段线、Gemini 0.5×窗口）均不同 | `dsh-trigger-01` |
| **C-03/C-12** | "压缩不可逆 / resume 绝不可能找回" | **支持"两事实并存"**：压缩只改 **surface（模型可见层）**，日志**追加式不删**；"找不回"**限制为默认模型可见层**——`shadowedSeqs` 指向原事件可找回 | `dsh-persist-01`、`dsh-recover-01` |
| **C-04/LQ-09** | "旧摘要只做字符串级 merge"（无损暗示） | **未决**：dsh 有**指令级增量合并**（"合并进同一结构"），但**保真度未实测**（依赖 T19）；不据此判成熟度 | `dsh-summary-03` |
| **C-05** | 桩函数被当作已实现能力 | **dsh 侧不适用**：上下文路径**无** `todo!()`/`unimplemented!()`/空实现（S5 复跑=0） | S5 |
| **C-06** | `len(text)//4` 对中文"保守" | **dsh 用 `ceil(len/4)`**（**按字符**，非字节）→ 对中文**低估**（与 pi/Codex 的 `ceil(bytes/4)` 口径不同；与 OpenCode 的 chars/4 同类）；**判为低估，非保守** | `dsh-trigger-02`；OBS-dsh-meter-01（400 汉字 = 108） |
| **C-07** | "零 API 调用的压缩" | **拆分裁决**：dsh 摘要**有**模型调用（**一次** `ctx.llm.stream()`）；pruner/spill **无**调用 | `dsh-summary-01`、`dsh-trunc-03/04` |
| **C-10** | 多层管道说法（层数非维度） | **dsh 不是层叠管道**：一阈值 + 一次摘要 + 可选剪裁/离载；支持"**层数不是维度**" | `dsh-compact-01`、`dsh-summary-01` |
| **LQ-04** | L1 是否保留源文？工具输出原文存哪？ | **保留**：会话 JSONL 追加不删；超限工具输出**落盘** `spill-local`（路径可找回）；压缩只改 surface | `dsh-persist-01`、`dsh-trunc-03` |
| **LQ-05** | 三家压缩阈值全表 | dsh 侧给出：**`floor(min(W×0.8, W−O−65536))`**（W=1,000,000、O=0 时 → **800,000**；O=256,000 时 → **678,464**） | `dsh-trigger-01`、DW-trigger-01 |
| **LQ-08** | 后台持续抽取会话记忆 | dsh 侧：**未发现**后台记忆提取（S3 复跑=0）；**无**长期记忆机制 | `dsh-memory-01` |
| **LQ-10** | resume 两条路线 | dsh = **持久化断点路线**（替换语义，恢复直接投影摘要+保留段） | `dsh-recover-01` |
| **T02 §G** | 工具专名与命名纪律 | **支持**；「区分 harness 实现与 DeepSeek 模型/API 能力」**已落实**（`harness实现-vs-模型API分列表.md`） | `dsh-layer-01` |
| **交接 §5 Q7 / 版本表 §4 Q6** | PyPI `deepseek-harness-sdk` 补核 | **存在**（pre-release，0.1.5rc1 检索日）；与 CLI = **同 harness 的 Python 子进程入口**（`--profile sdk`）；引用须标 pre-release | `dsh-version-03` |
| **术语表 §6** | "缓存键 = 已证（CLI 侧）" | **dsh 侧不成立**：**未发现** CLI 侧缓存键/断点（S4=1 为 Codex 样本）；dsh 只有 usage 明细字段 | `dsh-cache-02` |

## 4. harness vs 模型/API 分层（FB-07）

见 `harness实现-vs-模型API分列表.md`（**20 项逐条**）。**结论**：dsh 的上下文治理**全在 harness**（组装/计量口径/阈值/事务/剪裁/落盘/持久化/交接/重试/图像离载决策）；**模型/API 只提供**容量、真实分词与计费、缓存存储与命中/TTL、溢出真实判定、视觉定价、推理内容。**分界清晰**，无"同源难判定"问题（与 OpenCode v1/v2 的"同源≠零耦合"不同）。
