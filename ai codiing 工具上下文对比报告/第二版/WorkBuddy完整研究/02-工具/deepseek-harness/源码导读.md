# deepseek-harness · 源码导读

> 本文件解决什么问题：给出**代表性主链路**（调用者 → 条件 → 处理 → 状态写回 → 下一次请求/恢复，**含失败分支**）。
> 快照 `571902028a75c64c1d767f4ae5fd099485f0ddf0`（master）；**引用基址**：`https://github.com/deepseek-ai/deepseek-harness/blob/571902028a75c64c1d767f4ae5fd099485f0ddf0/<path>#L起-L止`。
> **语言桥接**：先给数据对象与条件，再给函数；真代码与教学伪代码分开标注。

## 0. 一句话架构（读源码前先看这个）

dsh 把"模型看到什么"定义为一个**事件溯源（event-sourced）日志**：`Session` 是一条**只追加**的 `SessionEvent` 序列；**模型可见的请求**由 `deriveMessages()` 从日志**投影**而来。上下文管理的一切动作 = **在日志上追加事件**（或追加一条带 `surfaceOp.replace` 的替换事件），**而不是就地改写历史**。

关键数据对象（全部来自 `dsh-session` / `dsh-llm`）：

| 对象 | 含义 | 备注 |
|---|---|---|
| `SessionEvent` | 日志一条事件（`system/message`、`user/message`、`assistant/message`、`tool/*`、`compaction/*`…） | `compaction/*` 是**log-only**（不进 surface） |
| surface | 日志投影出的**当前模型可见消息序列**（`session.surface.nodes` = 一串 seq） | 替换后 seq 可**非单调** |
| `SessionSeq` | 事件的稳定序号 | 替换时新事件 seq 更大但**占据旧位置** |
| `TokenMeasurement` | `ctx.tokenMeter.measure(session)` 的不可变快照：`totalTokens`、`surfaceTokens`、`nodes[].tokens`/`heuristicTokens` | O(surface) |
| `CompactionResult` | 一次压缩的结果（`shadowedSeqs`、`summary`、`shadowedTokenCount`…） | 见 `docs/subsystems/compaction.md` |

## 1. 主链路 A：自动压缩（pressure）——最核心的一条

**调用者**：`BasicCompactionEngine._registerAutomaticCompaction()` 注册的 `agent/pre-step` 监听器（`packages/compaction/compaction-basic/src/index.ts#L158-176`），在**请求派生之前**运行。

**条件 → 处理**：进入 `compactIfNeeded(agent, 'pressure', signal)`（`index.ts#L269-347`）：

```text
（教学伪代码，非真代码）
1. target = routedTarget(session)         // 最近一次durable路由的 provider/model；无则 return null
2. policy = resolveTargetPolicy(config, target)
3. measurement = tokenMeter.measure(session)
4. info = llm.resolveModelInfo(provider, model)   // 取适配器声明的窗口
5. spec = resolveCompactSpec(policy, info.context.contextWindow, reservedCompletionTokens)
        //  thresholdTokens = floor(min(W×0.8, W − O − 65536))；retainTokens = floor((W−O)×0.16)
6. if measurement.totalTokens < spec.thresholdTokens: return null   // 未到线，什么都不做
7. pruner?.pruneSession(session); 重新 measure()                     // 可选：先做无模型调用的工具剪裁
8. if 重新测量后 < thresholdTokens: return null                       // 剪裁已够，跳过摘要
9. for attempt in 0..compactionRetries(=1):
       range = selectCompactableRange(session, measurement, spec.retainTokens)
       if range == null: break/return
       result = compactRegion(range.start, range.end, agent, signal)
       重新 measure(); if < thresholdTokens: return result
10. throw "compaction still above threshold after N attempts"
```

**真代码关键点**（`index.ts`）：

- `#L319`：`if (measurement.totalTokens < spec.thresholdTokens) return null` —— **到线才动手**。
- `#L323-327`：`prune` 后**重新测量**；若已低于阈值，`return null`（**剪裁可完全替代摘要**，且**剪裁不调模型**）。
- `#L330-341`：`compactionRetries`（默认 **1**）决定重试次数；每次压缩后重新测量，达标即返回；否则抛错。
- `#L294-302`（overflow 分支）：**绕过**阈值与保留策略，`selectCompactableRange(..., retainTokens=0)` 做**一次最大化的平衡头部削减**。

**处理：选范围（`region.ts#L117-155`）**——从尾部往前累加 priced node 直到 `accumulated >= retainTokens`，得到 `keepFromIdx`；然后**向前退到 tool-call/result 配对平衡边界**（`toolPairingBalancedBefore`）；范围起点**永不含 surface node 0 的 `system/message`**（`#L131`）。若范围为空 → `null`（**不写任何东西**）。

**处理：事务（`region.ts#L173-276`）**——"**log-recorded bracket is the transaction**"：

```text
validateSurfaceRegion（范围合法 + 配对平衡）           #L183,337-358
inspectCompactionEntryState → assertCompactionInactive  #L184-189（孤儿锁检测）
session.append('compaction/start', {compactionId, turn})#L210（先落锁，同步紧邻校验）
prepared = prepareCompaction(...)                        #L222（定价快照 + 回放输入）
summarized = await summarizeCompaction(...)              #L223（异步，模型调用）
assertStable(...)                                        #L233（surface 未变）
commitCompactionBody → append('compaction/summary') + append('user/message', checkpoint, {surfaceOp:replace})  #L235,470-509
session.append('compaction/end', lifecycle)              #L237（恰一次）
```

**失败分支**（`#L240-251`）：任何异常 → 记 `failure`，若尚未收尾则**恰一次** `compaction/end`（带 `error`）；**收尾失败会刻意留下孤儿 `compaction/start`**（`#L125` 注释）——这正是"崩溃可检测"的设计：孤儿锁 = "上一次没干完"。

**状态写回**：`commitCompactionBody`（`region.ts#L470-522`）追加两条：
1. `compaction/summary`（log-only，含 `summary`、`shadowedRange`、`shadowedSeqs`、`shadowedTokenCount`、`provider/model/maxTokens/usage`）；
2. `user/message`（**替换**事件），`surfaceOp: { op:'replace', startSeq, endSeq }`，`sourceEventSeqs` 引用被遮蔽节点。

**下一次请求**：`agent-loop` 的 `deriveMessages()` 投影时，替换事件**占据被遮蔽区间的位置**，旧节点不再进入请求；前缀（`system/message` + 被遮蔽段之前的历史）**保持不变** → **KV cache 前缀可复用**（见 §5）。

**找回原文**：原始事件**仍在追加式日志里**（从未删除）——见 §4 与 `数据走查.md` DW-persist-01。

### 1.1 摘要调用（`summarizer.ts#L120-181`）

- **target 解析**：`config.summarizationProvider/Model`（非空）→ 最近一次路由请求目标 → `AgentOptions`（`#L127-142`）；三者皆无 → 抛 `no provider/model available for summarization`。
- **回放前缀**（`region.ts#L544-563` `buildSummarizationInput`）：把 `system/message`（surface node 0）派生消息 + 被遮蔽段消息**按 surface 顺序**拼成 `messages`，并带 `header.tools` → **让辅助调用成为对话的"真前缀"**，只多出**尾部指令**（`summarizer.ts#L144-151`）。
- **摘要指令**：`COMPACTION_INSTRUCTION`（`summarizer.ts#L32-67`）——要求输出**恰好 8 段** Markdown（Primary Request and Intent / Key Technical Concepts / Files and Code / Errors and Fixes / Pending Jobs / Current Work / Next Step / Critical Context），并含**增量规则**（"若已有 `<compacted-summary>`，是**上一份检查点**：保留仍真的事实、丢弃过期、合并新信息"）。
- **仅取文本**（`#L213-221`）：图像输出 → `UNSUPPORTED_CONTENT`（**不静默消失**）。
- **收缩校验**（`region.ts#L417-422`）：`framedSummaryTokenCount >= shadowedRouteTokenCount` → 抛错（"摘要不比被遮蔽内容小"）——**防止越压越大**。

### 1.2 检查点框架（`summarizer.ts#L188-194`）

`frameSummary()` 产出：`CHECKPOINT_PREAMBLE`（`#L70-71`，告诉模型"这是自动检查点，当作既定背景，别复述"） + `<compacted-summary>` + 摘要 + `</compacted-summary>`。

## 2. 主链路 B：上下文溢出恢复

**调用者**：`agent/request-error` 监听器（`index.ts#L190-234`）。

**条件**：`failure.code === CONTEXT_WINDOW_EXCEEDED_CODE` 且未取消（`#L194`）。

**处理**：
- 取 `generation = session.surface.replaceGeneration`（`#L202`）；
- `compactIfNeeded(agent, 'context-overflow', signal)`（`#L205`）→ 走 §1 的 overflow 分支（pruner + 最大化平衡削减）；
- **重试授权条件**：`surface.replaceGeneration > generation`（**surface 真的被替换了**）才返回 `{ kind:'retry' }`（`#L212,230`）；
- 计数：`overflowRetries` 达 `policy.maxOverflowRetries`（默认 **1**）则不再恢复（`#L199-200`）。

**失败分支**（`#L206-227`）：恢复抛错时，若 **prune 已落地**（`replaceGeneration` 已前进），仍算"有持久进展"并重试一次（`#L212-219`）；否则保留原始请求错误（`#L220-226`）。**取消始终优先**（`#L211,222`）。

## 3. 主链路 C：请求组装与系统提示词 reconciliation

**调用者**：`agent-loop` 的 turn/step 机（`packages/core/agent-loop/README.md#L118-122`）。

**要点**：
- 请求 = `header.config` + `deriveMessages()` + `header.tools`，**没有 `system` 字段**（`README#L120`）；提示词由 `system/message` 节点承载，取**最新非空**者（`README#L75,156`）。
- **reconciliation**：每次尝试**同步**核对渲染提示词与存活的 `system/message` 节点（`README#L122`）；**能力路由**或**新请求序列**时把非空渲染**合并到首个 system 节点**（后续 system 节点写"逐节点空替换"）；`in-history` 路由**在缓存历史之后追加**变更提示词（**保住前缀复用**）。
- **工具增删**：对比前后 header 的工具名，发一条 `developer/message`（`README#L156`）——**与模型能力无关**。

## 4. 主链路 D：持久化与恢复

**写入**：`session-persistence-jsonl`（`packages/session/session-persistence-jsonl/README.md`）——每会话一个**追加式** JSONL；默认 **zstd** 校验帧（`compression:'none'` 时是裸行文本）；`create(header)` **懒物化**（首条 `append` 才写 header+首批并 `fsync`）。

**崩溃语义**（同 README）：committed 前缀全保留；恢复时**不完整的尾行丢弃**；**撕裂的 zstd 帧只取完整解出的 JSONL 记录**；`session-checkpoint-policy` 在**每次模型请求前 / 顶层工具副作用前**做**语义检查点**（fail-closed：写不成功就不跑）。

**恢复**：`ctx.agents.resume()` → `persistence.open(id,'write')` 先取写权（排除并发同 id 恢复），读物理有效日志，为"中途崩溃的 turn"追加 `interruptedTurnClosers`。**语义崩溃修复属 agent 层**：未答工具调用得 `TOOL_OUTCOME_UNKNOWN`（提示只重试只读/幂等操作）；无开始记录的调用得 `TOOL_NOT_STARTED`（`agent-loop/README#L128-131,194-206`）。

**压缩与恢复的关系**：压缩是**替换**（`surfaceOp.replace`）——恢复后 `deriveMessages()` 直接投影出"摘要 + 保留段"，**不重放全部历史**（**持久化断点路线**，非重放路线；`dsh-recover-01`）。

**找回原文**：`compaction/*` 与原始事件**全在日志**；`shadowedSeqs` 给出被遮蔽节点。**无删除 API**（README "Nothing deletes session files"）。

## 5. 主链路 E：工具输出治理（进消息列表前）

三层，**按顺序**：

1. **工具自带上限**（进入结果时）：`read` → `readLimit` 2000 行 / `readMaxLineLength` 2000 字符 / `readMaxBytes` 51200 字节（`packages/fs/tool-fs/README.md#L65-68`）；bash → `maxOutputChars` 默认 16,000 字符（`packages/shell/tool-bash-persistent/README.md#L50`）。
2. **落盘策略**（`tools/post-execute`）：`spill-policy`——超 `maxInlineTokens`（默认装配 **12500**）时，保留**头/尾各半**预算 + 省略通知 + **全文落 `spill-local`**（路径 + `read`/`grep` 找回指引）；**存储失败则原文照旧可见**（best-effort，`spill-policy/README`）。
3. **压缩前剪裁**（仅到线后）：`tool-result-pruner`——超 `thresholdChars`（默认 **8192**）的文本结果替换为 `headChars`(4096) + `PRUNE_MARKER` + `tailChars`(1024)，**按 Unicode code point 切**（不劈代理对）；**只在压缩触发后运行**（`compaction-tool-result-pruner/src/config.ts#L7,10-14,27-29`）。

## 6. 与近亲/服务层的差异（详见 `harness实现-vs-模型API分列表.md`）

- **dsh ↔ 其自身 DeepSeek 适配器**：阈值/保留/事务/剪裁 = **harness**；窗口容量、真实分词、缓存命中与 TTL、溢出判定、视觉定价 = **模型/API**。
- **与 Codex 的差异（证据级）**：dsh 的 token 计量是**纯 harness 启发式**（4 字符/token），Codex 走 provider `usage` 锚定；dsh 阈值是**双上限 `min(W×ratio, W−O−B)`**，Codex 是 `min(M, 90%W)` 口径（术语表注①）；dsh 摘要是**一次结构化 8 段**，Codex 有远端加密压缩条目。**不得**因两者都叫"compact"而假定同构。
