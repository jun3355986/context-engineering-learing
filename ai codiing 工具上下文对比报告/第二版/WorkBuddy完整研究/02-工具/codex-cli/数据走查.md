# Codex CLI · 数据走查

> 本文件解决什么问题：用**可算数字**把机制讲清楚——输入什么、输出什么、什么被原样留下 / 变摘要 / 移除 / 落盘，边界例子在哪。
> **数字纪律（术语表 §12）**：`【源码常量】`=快照真实常量（给文件行号）；`【演示】`=教学假设数字；`【测试样本】`=仓库测试里的数，**未运行**。**无实测处写明 NOT_RUN**。
> 所有走查均为**静态走查**（读固定快照推算），**不是**模型实验。

## DW-trigger-01：两条触发线的算术（【演示】窗口 + 【源码常量】比例）

- **输入**：`W = 200,000`【演示】（模型窗口）；`p = 95`【源码常量】（`effective_context_window_percent` 缺省）；`M（模型字段 model_auto_compact_token_limit）= 150,000`【演示】。
- **计算（源码公式）**：

| 量 | 公式（来源） | 结果 |
|---|---|---|
| 整段线 H | `W × p / 100`（`openai_models.rs#L523-527`） | `200,000×95/100 = 190,000` |
| 90% 基础线 | `(W×9)/10`（`openai_models.rs#L530-532`） | `180,000` |
| 范围线 | `min(M, 90%基础线)`（`openai_models.rs#L534-538`） | `min(150,000, 180,000) = 150,000` |
| 到线 | `A ≥ 范围线` 或 `A ≥ 整段线`（`context_window.rs#L106-110`） | — |

- **边界例子**：
  - `A = 149,999` → 未到线（两条都不满足）。
  - `A = 150,000` → **范围线到线**（触发整理）。
  - `A = 185,000` 且 `M` 缺失 → 范围线退化为基础线 `180,000`，此时 `185,000 ≥ 180,000` 触发。
  - `A = 190,000` → **整段线到线**（硬检查）。
- **输出/写回**：到线 → 进入压缩流程；未到线 → 原样请求。
- **状态**：运行证据 `NOT_RUN`（静态走查；需 T03 合成任务数据 + 真实运行才能给出 A 的真实序列）。

## DW-trigger-02：90%/95%/20,000 三者不可混用

- **输入**：同 DW-trigger-01。
- **判断**：`90%` 只作**范围线原料**（可被更小的 M 按下）；`95%` 只作**整段线比例**；`20,000` 是**本地直接保留预算**，与触发**无关**。
- **反例（旧说法）**：把「90% 是统一压缩阈值」当结论 → 当 `M=150,000` 时实际范围线是 `150,000`（不是 `180,000`），阈值被高估 30,000 token。
- **状态**：`NOT_RUN`。

## DW-retain-01：本地保留（【源码常量】20,000）

- **输入**：旧历史候选（只收真用户消息，排除摘要前缀）；预算 `20,000`【源码常量】（`compact.rs#L64`）。
- **处理**：按 rev **从新到旧**累加候选 token；累到某条越界 → 该边界处 `break`；摘要**另加**（不计入 20,000）。
- **可算例子**（【演示】每条用户消息 = 3,000 token）：

| 累计 | 结果 |
|---|---|
| 1 条 = 3,000 | 保留 |
| … | … |
| 6 条 = 18,000 | 保留 |
| 7 条 = 21,000 > 20,000 | **越界** → 第 7 条不保留，`break` |

→ 原样保留 **6 条（18,000 token）**；更早的进入摘要。边界：正好第 7 条 = 20,000 时按 `<=` 保留（7 条）。
- **输出**：替代历史 = 摘要 + 保留的 6 条。
- **状态**：`NOT_RUN`。

## DW-retain-02：远端 v2 双预算（【源码常量】64,000 / 10,000）

- **输入**：候选集；共享预算 `64,000` token【源码常量】；单条 AgentMessage 上限 `10,000`【源码常量】（`compact_remote_v2.rs#L87-88`）。
- **处理**：逐条消耗共享预算；单条超 `10,000` 的 AgentMessage 被**截短**；`remaining==0` → `continue`（跳过构造，但组内 notice 一起计量）；特殊工具结果放不下 → `break`。
- **可算例子**：候选依次为 10,000 / 10,000 / 10,000 / 12,000(token 的 AgentMessage)：
  - 第 4 条 12,000 > 10,000 上限 → **先截到 10,000**；此时累计 40,000。
  - 后续继续累加，直到接近 64,000 时边界截短；剩余预算不足以放特殊工具结果则 `break`。
- **边界**：`remaining == 0` 时不报错，跳过该条继续。
- **状态**：`NOT_RUN`。

## DW-trunc-01：头尾裁剪算术（【源码常量】ceil(bytes/4)）

- **输入**：一段 UTF-8 文本，`s.len() = 40,096` 字节；`max_tokens = 2,000`。
- **计算**：

| 量 | 公式（`truncate.rs#L17-29,L142-145`） | 结果 |
|---|---|---|
| 允许字节 | `max_bytes = max_tokens × 4` | `8,000` |
| 是否截断 | `s.len() > max_bytes` → 是 | 截断 |
| 左预算 | `left = max_bytes / 2` | `4,000` |
| 右预算 | `right = max_bytes − left` | `4,000` |
| 被删 token 计数 | `ceil((s.len() − max_bytes) / 4)` | `ceil(32,096/4) = 8,024` |
| 标记 | `…8024 tokens truncated…` | 另占长度 |

- **边界**：
  - `max_tokens = 0` → `max_bytes = 0`，只返回标记 `…<全部估算>/4 tokens truncated…`。
  - 奇数预算例：`max_bytes = 8,001` → `left = 4,000`、`right = 4,001`（**奇数差 1 字节归尾部**）。
  - 中文边界：`floor_char_boundary / ceil_char_boundary` 保证不切断多字节字符。
- **状态**：`OBSERVED`（codex-run-2026-10-15-trunc-01，本地 0.152.0）：22,003 字节（≈5,501 token）未裁；384,079 字节（≈96,020 token）裁到头+尾、中间不可见、完整原文留档。**阈值取自模型元数据** `tokens(10_000)`（非 bytes）；观测为本地版行为、不外推快照（详见 `过程观察.md` 规程 3）。
- **与 E2 的三分**（运行观察时须分开记，勿混为一谈）：①**出口限长**（本条算术，管“进请求前被裁多少”）｜②**预览+落盘**（进请求的是否只头部预览、全文落盘到哪）｜③**中间原文能否取回**（裁剪后能否读回被删中段，入口/是否需重跑工具/重读次数）。三者对应 `过程观察.md` 规程 3 · E2 专项。**实测结论**：②进请求=头+尾+标记；③中间原文**可从会话存档找回**、无需重跑工具。

## DW-cache-01：缓存键可证 / 不可证边界

- **输入**：会话 `session_id = "s_abc"`；内部子会话来源 `"review"`，`parent_thread_id = "t_root"`。
- **输出（CLI 侧可证）**：

| 场景 | `prompt_cache_key`（`client.rs#L646-658`） |
|---|---|
| 主会话 | `s_abc` |
| 内部子会话 | `review:t_root` |
| 有 override | override 值优先 |

- **不可证**：是否命中、TTL、断点数量——**源码读不出**（`NOT_RUN`，服务端行为需 T19）。
- **边界**：`prompt_cache_key_changed` 只用于 websocket 增量复用判定，**不等于**「命中/未命中」。

## DW-persist-01：一次压缩的前后对照

- **输入（压缩前 live 历史）**：`[base, 规则, user×6, tool输出×4, assistant×3]`（示意）。
- **处理**：替换为替代历史。
- **输出**：

| 对象 | 去向 |
|---|---|
| 旧历史条目 | 内存中被**替换**；rollout 存档**原样追加保留**（不删） |
| 摘要 | 写进 `replacement_history` 头部 |
| 保留候选 | 进 `replacement_history`（本地路径 ≤20,000） |
| `CompactedItem` | 追加：`replacement_history` + window id + `latest_token_usage_record` + `resume_metadata` |

- **恢复**：读最新检查点 → 采用其 `replacement_history` → 回放其后条目（后缀回放）。
- **能否找回原文**：能——读 rollout 存档（旧记录仍在）。
- **状态**：`NOT_RUN`。

## DW-recover-01：断点恢复 vs 重放（对照）

- **路线 A（Codex 实际）**：持久化断点 + 后缀回放 → 恢复时**不重算**旧压缩，直接用存档的替代历史再回放后继。
- **路线 B（未被选用）**：把 100 轮从头重读重算。
- **可算差异**：若旧历史 100 轮=300,000 token，路线 A 只需读回摘要 + 少量保留 + 后缀；路线 B 需重读全部 300,000 token 的裁剪计算（**离线 CPU 成本**，非模型 token 成本）。
- **状态**：`NOT_RUN`。

## DW-fail-01：本地压缩失败有界性（【源码常量】）

- **输入**：`turn_input_len = N`；`max_retries = provider.stream_max_retries()`【源码常量，随 provider】。
- **分支**：

| 触发 | 动作（`compact.rs#L359-378`） | 有界性 |
|---|---|---|
| `ContextWindowExceeded` 且 `N>1` | `remove_first_item()` + `retries=0` 重试 | 每次至少减 1 条 → 有界 |
| `ContextWindowExceeded` 且 `N==1` | `set_total_tokens_full()` + `Err` | 终止 |
| 普通错误 | `retries++`（≤max_retries）+ backoff | 有界 |
| 中断/取消/预算耗尽 | 直接 `Err` | 终止 |

- **注意**：`retries=0` 是**缩副本循环**的计数归零，与**退避重试**是两个计数（样章「双计数语义」）。
- **状态**：`NOT_RUN`。

## DW-预算账：三个“64”与两个“32/64”不可混用

| 数字 | 单位 | 含义 | 来源 |
|---|---|---|---|
| `64,000` | **token** | 远端 v2 共享保留预算 | `compact_remote_v2.rs#L87` |
| `64 KiB` | **字节** | 分片命令输出 / MCP 结果的持久化预算 | `rollout/src/policy.rs#L16-19` |
| `32 KiB` | **字节** | `AGENTS.md` 共享字节预算 | `core/src/config/mod.rs#L253` |
| `20,000` | **token** | 本地直接保留预算 | `compact.rs#L64` |
| `10,000` | **token** | 远端 v2 单条 AgentMessage 上限 | `compact_remote_v2.rs#L88` |

- **反例**：把「64K 预算」统一当一个数 → 会把 v2 的 64,000 **token** 与持久化的 64 **KiB 字节**混为一谈（后者按 UTF-8 字节计，对中文差约 3 倍）。
