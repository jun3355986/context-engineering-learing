## 0. 阅读地图

### 0.1 一次任务的主骨架（v2）

```text
用户输入 / inbox 项
  └─ SessionRunner.drain()                          # runner/llm.ts:57-199
       ├─ settleStaleCompactions / settleStaleToolCalls   # 崩溃遗留结算（llm.ts:332-385）
       └─ advanceToStep()  while(true)              # 步边界：消费 inbox 控制项（llm.ts:74-189）
            ├─ inbox "compaction" → compaction.compact({reason:"manual"})  # llm.ts:115-163
            └─ Ready → context.load(selected)        # 投影历史 + 指令基线（context.ts:163-179）
       └─ runStep(context, step)  while(true)        # ★步循环（llm.ts:209-330）
            ├─ compaction.compact({reason:"auto"})   # 到线即压缩（llm.ts:220-225）
            ├─ baseTranscript() → system + messages  # model-request.ts:100-120
            ├─ context.request.primary()             # 请求装配 + 插件钩子（model-request.ts:236-420）
            └─ SessionStep.attempt() → llm.stream()  # 单步流处理（runner/step.ts:73-286）
                 ├─ 工具调用 → ToolOutput.truncate()  # step.ts:127
                 ├─ 溢出（未输出前）→ Outcome.Compacted → recoverOverflow  # step.ts:155-167
                 └─ step-finish: 记 tokens/usage      # step.ts:246-260
```

## 1. 主链路 A · 请求组装与角色（CM-01）

### 1.1 调用者与入口

`runStep`（`llm.ts:209`）在每步：

```ts
// llm.ts:220-233
const compacted = yield* compaction.compact({ reason: "auto", context: loaded })
if (compacted.status === "completed") { assistantMessageID = SessionMessage.ID.create(); continue }
const stepLimitReached = loaded.agent.info.steps !== undefined && step >= loaded.agent.info.steps
const transcript = SessionModelRequest.baseTranscript({
  agent: loaded.agent.info, model: loaded.model, tools: loaded.tools,
  initial: loaded.initial, messages: loaded.messages,

```

**中文解读**：每步先判"是否该自动压缩"（到线则压完 `continue`，下一轮用压缩条目重建）；再按"是否已达步数上限"决定要不要追加末步提示；然后 `baseTranscript` 把"历史消息 + 指令基线"投影成请求骨架。

### 1.2 system 的最终合成（`baseTranscript`）

```ts
// model-request.ts:100-120
return {
  providerMetadataKey,
  system: [
    input.agent.system
      ? input.agent.system
      : SessionSystemPrompt.make(input.tools.definitions.map((tool) => tool.name)),
    input.initial,
  ].filter((part) => part.length > 0).map(SystemPart.make),
  messages: toLLMMessages(input.messages, input.model.ref, providerMetadataKey),
}
```

- **只有 2 条 system 段**：`[agent.system 或 基础提示词, initial]`。
  - `SessionSystemPrompt.make`（`system-prompt.ts:5-28`）渲染 `runner/prompt/system.txt`，按"当前工具名"注入 `${OPENCODE_TOOL_GUIDANCE}`（含 shell/write/edit 的用法提示）。
  - `agent.system` 是 agent 自定义系统提示词（`schema/src/agent.ts:28`），有则**整段替换**基础提示词。
  - `initial` = **指令基线**（`InstructionState.initial`，见 §2）。**v1 的"环境块 / 规则指令 / MCP 指令 / 技能清单"四类块在 v2 被折叠进 `initial` 与后续指令增量**——这是 v2 与 v1 请求组装的核心结构差异。
- 模型专属系统提示词由**插件钩子**注入（`plugin/optimize.ts:16-62`）：gpt/claude/kimi/trinity/muse 各有模板，`override`（gpt/kimi/…）或 `append`（claude）。

### 1.3 工具与角色

- 工具集经 `context` 钩子塑形后按 `Object.entries` 顺序入请求（`model-request.ts:298`）；钩子可改名/删工具（`model-request.ts:266-274`：按对象身份或 key 匹配，凭空新增的丢弃）。
- 角色：`user`/`assistant`/`tool-result`/`system`（`to-llm-message.ts:253-334`）；工具调用与结果由 `ToolCallPart`/`ToolResultPart` 配对。
- 消息投影要点：`compaction` 消息 → `<conversation-checkpoint>`（§4）；`shell` 后台结果不进（`to-llm-message.ts:293-295`）；模型切换时 reasoning/工具元数据按"是否同一模型"决定是否可重放（`:153-210`）。

### 1.4 写回与下一次请求

组装结果经 `SessionStep.attempt`（`step.ts:73`）交给 `llm.stream`；模型事件写回消息部件，下一次循环**重新** `context.load` 投影，故**每次请求都是重算**。

**失败分支**：无 agent → `AgentNotFoundError`（`context.ts:129`）；会话 location 不匹配 → `Effect.interrupt`（`:124-125`）。

## 4. 主链路 D · 计量、触发与压缩（CM-05 / CM-06 / CM-07）

### 4.1 触发上限（`calculateCeiling`）

```ts
// compaction.ts:905-912
const calculateCeiling = (limit, buffer) => {
  const window = limit.input || limit.context
  if (window <= 0) return Number.POSITIVE_INFINITY            // 未知窗口永不自动触发
  if (buffer !== undefined) return window - buffer
  return window - Math.max(Math.floor(window * 0.1), window >= 2 * RESERVE_MIN ? RESERVE_MIN : 0)
}   // RESERVE_MIN = 16_000
```

**中文解读**：v2 预留 = `max(10%W, 16000)`（窗口 ≥32000 时保 10%，小窗口保 16000 下限）；**v1 为绝对预留 `min(20000, maxOutputTokens)`**——**口径变化**。

### 4.2 到线判定（`due`）

```ts
// compaction.ts:242-251
const due = (context, ceiling) => {
  const messages = context.messages
  const last = messages.at(-1)
  if (last?.type === "compaction" && last.status === "completed") return false   // 刚压完，等重建
  const measured = messages.findLastIndex((m) => hasMeasuredPrompt(m, context.model.ref))
  if (measured < messages.findLastIndex(SessionProviderContext.isCheckpoint)) return false
  return estimateContext(context) >= ceiling
}
```

`estimateContext = measured + estimated`（`compaction.ts:868-898`）：`measured` 取最近一次 provider 回报的 `input+cache.read+cache.write+output+reasoning`；`estimated` 为锚点之后本地 `Token.estimate`（chars/4）累加。

### 4.3 三种压缩触发

| reason | 入口 | 预算/行为 |
|---|---|---|
| `auto` | `runStep` 每步开头（`llm.ts:220`），仅 `auto && due` | `budget = cap = calculateCeiling` |
| `overflow` | provider 报 context-overflow 且未输出 → `Outcome.Compacted` → `recoverOverflow`（`step.ts:155-167`、`llm.ts:265-271`） | `budget = min(cap, floor(estimateContext × 0.7))`（`compaction.ts:226-228`） |
| `manual` | `/compact` inbox 项在步边界消费（`llm.ts:91-163`） | `budget = cap`；结算走 `/compact` inbox 项 |

### 4.4 摘要路径（`summarize`）

```ts
// compaction.ts:272-310（要点）
const split = splitConversation(context.messages, keep)        // older / recent
const previous = previousCompaction(context.messages)          // 第一条即上次压缩
const prompt = buildPrompt(previous !== undefined, previous?.summary.includes(LEGACY_HEADING) ?? false)
const prepared = yield* prepare(context, split.older, budget)
const send = (request) => {                                    // 模板校验 + 一次 NUDGE
  const reply = yield* stream(context, update(request, {messages:[..., Message.user(prompt)]}), options)
  if (filled(reply.text)) return { ...reply, recent: split.recent }
  const retry = yield* stream(context, nudged, options)
  if (filled(retry.text)) return { ...retry, recent: split.recent }
  return yield* Effect.fail({ error: { type: "compaction.failed", ... } })
}
return yield* deliver(trigger, prepared, split.recent, budget - overhead, send)
```

- 摘要模板（`compaction.ts:104-143`）：`Objective / Requirements / Decisions / Work State{Completed/Active/Blocked} / Next Move / Relevant Files / Important Context`（**v1 为 Objective / Important Details / Work State / Next Move / Relevant Files**）。
- 增量规则（`:159-175`）："**新历史优先**；除非明确矛盾/取代/解决/过期，否则保留旧信息"（**v1 为"未带过来即丢失、冲突以新对话为准"**）。
- 保留预算 = `settings.keep`（**默认 15_000 固定**；v1 为 `usable×0.25` 夹 `[2000,15000]`）；`recent` 以**文本**存入 checkpoint。
- **模板校验 + 一次 NUDGE** 是 v2 新增（v1 无）。

### 4.5 请求过大时的收缩（`deliver` / `flattenAndDropOldest`）

```ts
// compaction.ts:403-454（收缩循环）
while (true) {
  const fits = !asText && estimateRequest(prepared.request) <= target
  const request = fits ? prepared.request
    : (flattenAndDropOldest(prepared.request, context, target) ?? ...)
  const attempt = yield* Effect.result(send(request))
  if (Result.isSuccess(attempt)) return attempt.success
  if (tooLarge || isContextOverflowFailure(cause)) {
    const step = SHRINK_STEPS[rejections]           // [0.7, 0.5, 0.35]
    if (step === undefined) return fail
    rejected ??= estimateRequest(request); target = Math.floor(rejected * step); rejections++; continue
  }
  // 其他错误按会话重试策略
}
```

`flattenAndDropOldest`（`:465-504`）：把历史**文本化**（丢 reasoning/媒体/指令更新、切长工具输出），旧摘要在前、其 `recent` 变最旧 transcript 项，按 **exchange** 整块丢最旧，加 `[N older exchanges omitted]`；只在仍装不下时才丢。

### 4.7 原生（provider）压缩（v2 新增）

```ts
// compaction.ts:324-372（要点）
```

**失败分支**：`splitConversation` 无内容 → `Nothing to compact yet`（`compaction.ts:279`）；摘要模板两次都不合格 → `compaction.failed`（`:298-305`）；无法再缩减 → `compaction.failed`（`:413-421`）。

### 5.2 fork

```ts
  boundary: { type: input.before ? "before" : "through", messageID: boundary.id }, ...inherited })
```

**中文解读**：fork 复制边界内消息到新会话，并**继承父的最新指令基线**（而非边界时的基线）；boundary 用 `before`/`through` 表达（**v1 用 `tail_start_id` 重映射**）。

### 5.3 恢复与崩溃 claim

```ts
// execution.ts:76-86（注释）
// Write-ahead claim: 开始执行时在同一事务写 time_suspended；终态释放——shutdown 中断保留，
```

## 6. 主链路 F · 错误与副作用（CM-11）

### 6.1 重试（`retry.ts`）

```ts
// retry.ts:42-56
const schedule = Schedule.max([
  Schedule.min([Schedule.exponential("2 seconds"), Schedule.spaced("10 seconds")]),
  Schedule.recurs(10),
]).pipe(Schedule.jittered, Schedule.modifyDelay(({input, duration: delay}) => {
  const minimum = retryAfter(input)          // ≤ 15 分钟
  return Effect.succeed(Duration.millis(Math.ceil(Duration.toMillis(minimum === undefined ? delay : Duration.max(delay, Duration.millis(minimum))))))
}))
```

- 最多 **10** 次；每间隔退避上限 **10s**；`retryAfter` 夹 **≤15 分钟**；超时类额外上限 **3** 次（`MAX_TIMEOUT_RETRIES`）。
- `session.retry` 钩子可改 `attempt`/`delay`。

### 6.2 失败分类与副作用

- **输出超限**（`finish==="length"`）：最多**连续 2 次**续跑（合成 `CONTINUE_AFTER_OUTPUT_LIMIT`），第 3 次连续 → `output-limit` 失败（`runner/llm.ts:290-319`）。
- **不完整流**：合成 `CONTINUE_AFTER_INCOMPLETE_STREAM` 续跑（`:281-289`）。
- **工具中断/拒绝**：未结算工具标 `aborted`、assistant 标 `Step interrupted`（`step.ts:207-232`）。
- **压缩中断**：`compaction.interrupted`（`compaction.ts:666-670`）。
- **副作用**：压缩/工具执行**已写盘动作不回退**（本包未读到自动回滚）。
- **注意**：**v2 出货路径（`core/src/session/*`、`core/src/tool/*`）未发现 `doom_loop` 阈值判定逻辑**（检索 `doom|consecutive|repeated` 无阈值判定，**推断**）；`doom_loop` 作为**权限动作名**仍在 `core/src/v1/config/permission.ts:27,38`（v1 迁移子集），且全仓（排除 node_modules）**169 命中**（app 126 / web 37 / tui 3 / console 1 / core 2）——**非"全仓零命中"**。v1 有 `DOOM_LOOP_THRESHOLD=3`（`ocv1-fail-02`）。

## 7. 主链路 G · 缓存与扩展点（CM-12 / 扩展点）

### 7.1 缓存（`ai/src/cache-policy.ts`）

```ts
// cache-policy.ts:17-24
const AUTO = { tools: true, system: true, messages: { tail: 1 } }
```
