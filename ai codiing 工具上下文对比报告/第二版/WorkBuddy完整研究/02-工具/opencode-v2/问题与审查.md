## 5. v1↔v2 对照（5 字段，v2 侧独立证据 + 变化/未变/兼容与迁移条件）

> **对照纪律**：v1 侧字段**只引 T09 已交付 `ocv1-*`**；v2 侧字段**只引本包 `ocv2-*`**；**不得反向用 v2 推断 v1**。界面/名称不同**不自动**算机制差异（须落到行为）。
> **分界方法（依 T09R 提醒）**：v1/v2 分界按**"包是否出货" + 引用关系**判定，**不得按目录或服务标签后缀二分**——本快照 `packages/core/src/session/*` 标签为 `@opencode/<Name>`（仅 `formatter.ts:25` 残留 `@opencode/v2/Formatter`）。T09R 发现 **v1 快照的 `packages/core/src/session/*` 为混合目录且 v1 确引用 v2 命名空间内容**（`MAX_STEPS_PROMPT`/`SessionExecution`/`SessionV2.node`）——**属 v1 侧事实，不改变本包对 v2 快照的判定**。

### 5.1 请求组装

| 项 | v1（T09 已交付，`ocv1-assembly-01/02`） | v2（本包独立证据） |
|---|---|---|
| system | **一条合成字符串**：`agent.prompt`/`SystemPrompt.provider(model)` + env + instructions + mcp + skills + user.system | **2 段 `SystemPart`**：`[agent.system ?? 基础提示词, initial]`（`ocv2-assembly-01`） |
| messages | `[system 消息, 投影消息, (末步)MAX_STEPS_PROMPT]` | `toLLMMessages(投影消息)`；末步把 `MAX_STEPS_PROMPT` 作为 **assistant** 消息 + `toolChoice:"none"`（`ocv2-assembly-02`） |
| 工具顺序 | 按名排序 | `Object.entries` 顺序（钩子可改名/删） |

- **变化**：① v1 的四类 system 块（env/instructions/mcp/skills）在 v2 **折叠进 `initial` 指令基线**（+ 后续指令增量）；② v2 末步提示**角色与工具禁用**方式不同；③ v2 模型专属提示词经**插件钩子**注入；④ 工具顺序口径不同。
- **未变**：system-first；`messages = system + 投影消息`；每步**重新投影重算**；模型专属提示词存在。
- **兼容与迁移条件**：`opencode.json` 经 `packages/core/src/v1/config/migrate.ts` 迁移；**自定义 agent 的 `system` 语义等价**（有则整段替换）；依赖"env/instructions/mcp/skills 四块顺序"的插件须改挂 `session.context` 钩子。

### 5.2 裁剪

| 项 | v1（`ocv1-trunc-01/02`、`ocv1-summary-03`） | v2（本包独立证据） |
|---|---|---|
| 工具输出上限 | **2000 行 / 51200 字节**先到者；`head`/`tail` 双向 | **2000 行 / 51200 字节**先到者；**仅 head**（`ocv2-trunc-01`） |

> 【T19 实测更正（2026-10-15）】产品 shell 路径实测为**纯 tail**（与 v1 同向）；「仅 head（无 tail）」**不成立于 shell 路径**；落盘实为 `shell/<hash>/sh_<id>.out`。原函数级观察（`tool-output.ts` 头向通用通道）保留——head 仅在 read 分页与通用默认（证据：`05-实验/T19/记录/08-ocv2.md` §五/§2.7；`T19-结果总表.md` §5 #14）。
| 落盘 | 截断目录（文件名 `tool_*`），保留 **7 天** | `global.data/tool-output/`（`tool_<hex>`），保留 **7 天**（`ocv2-trunc-01`） |
| 压缩序列化限长 | **2000 字符**（`TOOL_OUTPUT_MAX_CHARS=2000`） | **1250 字符**，**码点安全**（`ocv2-trunc-02`） |
| 压缩前擦旧工具输出 | `prune`（**默认关**，保护 40000/最小节省 20000，`skill` 受保护） | **未见 `prune`**；配置层标 **unsupported**（`ocv2-summary-03`） |

- **变化**：① 压缩序列化限长 **2000→1250 字符**；② 工具输出**去掉 tail 方向**；③ **`prune` 移除**（配置层 unsupported），旧工具输出治理改为"文本化 + 丢 exchange"。
- **未变**：工具输出入口限长的**行/字节/保留期数值**；落盘 + 标记 + 预览范式；"落盘 ≠ 摘要"边界。
- **兼容与迁移条件**：依赖 `direction: "tail"` 的调用方在 v2 无对应参数（需自行处理）；配置 `compaction.prune`/`tail_turns` 在 v2 会**触发诊断**（须移除）；`preserve_recent_tokens` 自动迁移为 `keep.tokens`。

|---|---|---|
| 模板 | `Objective / Important Details / Work State / Next Move / Relevant Files` | `Objective / Requirements / Decisions / Work State / Next Move / Relevant Files / Important Context`（`ocv2-summary-01`） |
| 增量 | `<prior-summary>`：**未带过来即丢失、冲突以新对话为准** | "**更新现有 checkpoint**"：**新历史优先、除非明确矛盾否则保留**（`ocv2-summary-01`） |
| 保留预算 | `usable×0.25` 夹 `[2000,15000]`（**随窗口浮动**） | `settings.keep`（**默认固定 15000**）（`ocv2-summary-02`） |
| 保留段形式 | `tail_start_id` 起原样段 | `recent` **文本**（`<recent-context>`）（`ocv2-summary-02`） |
| 重建 | `filterCompacted` **重排**"压缩条目 + 摘要 + 保留段 + 后续" | `SessionHistory` 按 **seq 边界**取"最近完成压缩起"（`ocv2-summary-04`） |
| 兜底 | —（无模板校验） | 模板校验 + **一次 NUDGE**；请求过大 → 文本化 + 丢 exchange（`ocv2-summary-01/03`） |

- **变化**：① 模板**新增三节**；② 增量语义从"丢失式"变"**保留式 + 新历史优先**"；③ 保留预算从"浮动"变"**固定默认 15000**"；④ 重建从"**重排**"变"**seq 边界连续段**"；⑤ **新增模板校验/一次 NUDGE** 与**请求过大收缩**。
- **未变**：结构化模板范式；保留尾段原样；增量合并；摘要替代历史（两事实并存）；**均判有损**。
- **兼容与迁移条件**：旧格式 checkpoint 由 `legacy` 分支**重写一次**（`## Additional Context` → 新模板）；`preserve_recent_tokens`→`keep.tokens`；`tail_turns` unsupported。

### 5.4 恢复

| 项 | v1（`ocv1-persist-01`、`ocv1-recover-01`） | v2（本包独立证据） |
|---|---|---|
| 存储 | **SQLite**（事件溯源 + 投影） | **SQLite**（drizzle + 事件溯源）（`ocv2-persist-01`） |
| 断点重建 | `filterCompacted`（`tail_start_id`） | `SessionHistory.messageEntries`（**seq 边界**）（`ocv2-recover-01`） |
| 入口 | `--continue`/`--session`/`--fork` | `--continue`/`--session`/`--fork`（`--fork` 需配前两者）（`ocv2-recover-01`） |
| fork | 复制 + **`tail_start_id` 重映射** | boundary `before/through` + **继承指令基线**（`ocv2-recover-01`） |
| 崩溃恢复 | **未见**跨进程 claim（进程内中断清理） | **write-ahead claim**（`time_suspended`）+ 遗留压缩/工具结算（`ocv2-recover-02`） |

- **变化**：① 断点表达从 `tail_start_id` 变 **seq 边界**；② fork 语义改为 **boundary + 指令基线继承**；③ **新增崩溃 claim 与遗留结算**；④ native checkpoint 引入**可重放性**校验（`replayable`）。
- **未变**：SQLite 持久化；**持久化断点路线**；三个恢复入口；原始消息**不删**；"压缩 ≠ 删除"。
- **兼容与迁移条件**：v1 会话数据经 `packages/core/src/database/v1-migration.*` 迁移；依赖 `tail_start_id` 的插件/工具须改用 v2 的 checkpoint/seq 语义。

### 5.5 扩展点

| 项 | v1（`ocv1-ext-01`） | v2（本包独立证据） |
|---|---|---|
| 钩子域 | `chat.*` / `tool.execute.*` / `shell.env` / `experimental.chat.*` / `experimental.session.compacting` / `experimental.compaction.autocontinue` / `experimental.text.complete` / `tool.definition`（**缩写，全集另含 `experimental.provider.small_model`，见 `ocv1-ext-01`**） | `session.prompt/context/compaction/generate/title/model.request/http.request/http.response/experimental.ws.*/retry` + 工具 `execute.before|after`（`ocv2-ext-01`） |
| 摘要钩子 | `experimental.session.compacting` 可注入 context / **替换 prompt** | `session.compaction` 可**直接提供摘要**（`fromHook` 跳过模型调用）（`ocv2-ext-01`） |
| 配置 | `opencode.json` | `opencode.json`（`compaction.{auto,keep.tokens,buffer}`） |

- **变化**：① 钩子名与域**重组**（`chat.*`→`session.*`；`experimental.session.compacting`→`session.compaction`；新增 `model.request`/`http.*`/`ws.*`/`retry`）；② 摘要钩子从"替换提示词"升级为"**可直接产出摘要**"；③ 配置项改名/移除（`reserved`→`buffer`、`preserve_recent_tokens`→`keep.tokens`、`prune`/`tail_turns` 移除）。
- **未变**：插件可改写**请求/系统提示词/压缩**；有配置文件；扩展点分"默认 vs 插件态"。
- **兼容与迁移条件**：v1 插件须**改钩子名**（无兼容别名证据）；配置须按新名迁移（部分旧名有 `prefer(legacy, native)` 自动迁移：`preserve_recent_tokens`/`reserved`；`prune`/`tail_turns` 则报 unsupported）。

> **对照小结（一句话）**：v1→v2 是**同工具的代际重构**——**请求组装**从"四类块合成一条 system"变为"2 段 + 指令基线/增量"；**裁剪**数值基本未变但**去掉 tail、序列化限长收紧、移除 `prune`**；**摘要**模板/增量语义/预算/重建**四处变化**并新增校验与收缩；**恢复**保留持久化断点路线但断点表达与 fork 语义变化并新增崩溃 claim；**扩展点**钩子域整体重组。**界面/名称差异不计为机制差异**（如 `task`→`subagent`、`summarize`→inbox `compaction` 已按行为核对）。

### 7.3 术语增补候选（并入 `00-管理/术语表.md`，主 Agent 合并）
- **指令基线（instruction epoch baseline / `initial`）**：v2 每次请求开头渲染的指令纪元基线（`InstructionState.initial`）。
- **指令增量（instruction delta / `InstructionsUpdated`）**：指令源变化时冻结进持久事件的差分更新。
- **压缩检查点（conversation-checkpoint）**：v2 文本压缩条目在模型可见层的封装（`<summary>` + `<recent-context>`）。
- **原生压缩（native compaction / `providerContext`）**：provider 返回的加密替换窗口，带 endpoint provenance，仅同 endpoint 可重放。
- **保留预算（`keep`，默认 15000）**：v2 压缩后原样保留的最近 token 预算（固定值）。
- **崩溃认领（write-ahead claim / `time_suspended`）**：v2 记录"某轮在飞行中"的持久意图，供重启恢复。
- **丢弃最旧 exchange（`flattenAndDropOldest`）**：v2 压缩请求过大时把历史文本化并整块丢弃最旧 exchange 的收缩机制。

### 7.4 供后续任务的可复用经验
1. **"同仓库两条 tag 线"必须先定出货路径**：v2 的 `packages/opencode` **不存在**，出货主体在 `packages/core/src/session/*`；`packages/core/src/v1/*` 只是**迁移子集**——引用行号前先确认包与命名空间。
   - **补充（依 T09R，2026-10-15）**：**不得按目录/服务标签后缀二分**——v2 快照的 `session/*` 标签是 `@opencode/*`（`/v2/` 后缀仅剩 `formatter.ts:25`）；且 v1 快照的 `packages/core/src/session/*` 是**混合目录**、v1 出货代码**确引用** v2 命名空间内容。**v1 侧结论以 T09/T09R 为准，不得据其反推 v2**。
2. **文档与实现可能分叉**：v2 快照的 `config.mdx` 仍写 v1 配置项（`prune`/`reserved`），而代码已改——**配置项以 schema + `config/normalize.ts` 为准**（对应 T07 §5"数值来源错认"坑）。
3. **"移除"类断言走配置层证据**：`prune`/`tail_turns` 的 unsupported 由 `unsupportedIfPresent` 显式给出，比"全仓零命中"更硬；仍须标**推断**（无官方声明）。
4. **函数级观察**：v2 `util/token.ts` 无 import，可 `bun` 直接跑快照文件；检查器必带**负例**，退出码为准。
5. **"零命中/未发现"类断言的三条硬纪律（2026-10-15 依 T10R 复核新增）**：本包初稿有两处"全仓零命中"**不成立**——① `prune` 在 `core/src` 实为 **6 命中**（1 相关 + 5 为 `git.ts`）；② `doom_loop` 全仓 **169 命中**（`core` 2 处为 v1 迁移子集的权限动作名）。**根因**：(a) macOS BSD `grep` 对 BRE 的 `\|` 交替**不支持** → 假空；(b) 一次 ripgrep 结果被 `head_limit` **截断**却被误当全集。**纪律**：交替模式一律 `grep -E`（或逐个模式跑）；带上限的检索必须确认未截断；**提交前必复跑登记命令并贴真实输出**；结论句须限定范围（如"**出货路径**未发现 X"而非"全仓无 X"），并给三要素（查的路径 + 凭什么 + 官方怎么说）。
