```yaml
结论ID: claude-assembly-01
结论: Claude Code 把每次请求按「变化频率」排成三层，顺序固定：①System prompt 层（核心指令、工具定义）→ ②Project context 层（CLAUDE.md、auto memory、无作用域规则）→ ③Conversation 层（消息、回复、工具结果）。此排序是为前缀缓存优化。
性质: 事实
范围: 当前官方文档；所有模型/平台
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（"Claude Code orders each request so content that rarely changes between turns comes first"；三层表）
数据走查: 见 数据走查.md §3（前缀失效推演）
运行证据: NOT_RUN（不需运行即可读文档；但未做真实请求抓取验证）
```

```yaml
结论ID: claude-assembly-02
结论: 系统提示词默认在「对话的首次请求」构建一次并记入会话；**直到会话被压缩之前**，后续每个请求（含 --resume/--continue 后）都用这份记录的提示词。传入不同的 system prompt 标志文本，要等会话被压缩或开新会话才生效。
性质: 事实
范围: 当前官方文档；`--system-prompt[-file]`、`--append-system-prompt[-file]`、`--system-prompt-snapshot`（off 可每次重建，需 v2.1.257+）
实现状态: 默认（on）
来源: ① https://code.claude.com/docs/en/cli-reference.md（"By default, Claude Code builds the system prompt once, on a conversation's first request… Until the conversation is compacted, every later request uses that recorded prompt"）
数据走查: 见 数据走查.md §3
运行证据: NOT_RUN
不能证明: ①记录的提示词在磁盘上的存储位置（应在会话状态内，文档未给字段名）；②「压缩后重建」是否也重建工具定义集合（文档只说 system prompt 那次切换）。
冲突裁决: 与题面「压缩是重置点」呼应——压缩不仅换历史，也是**系统提示词重算点**。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-rules-01
结论: 规则以 CLAUDE.md 家族按四级作用域加载（Managed policy → 用户 ~/.claude/CLAUDE.md → 项目 ./CLAUDE.md 或 ./.claude/CLAUDE.md → 本地 ./CLAUDE.local.md），工作目录及其以上各级目录都被拼接进上下文（不互相覆盖）；`@path` 导入**递归最多 4 跳**；单文件超过 **4 MiB 被跳过**；建议每文件 <200 行。块级 HTML 注释在注入前被剥离。
性质: 事实
范围: 当前官方文档；AGENTS.md 直读需 v2.1.277+
实现状态: 默认
来源: ① https://code.claude.com/docs/en/memory.md
数据走查: 见 数据走查.md §4（规则预算）
运行证据: NOT_RUN
不能证明: ①合并后的字节预算上限（文档只给单文件 4 MiB 与"合并超限会告警"）；②四级作用域冲突时的**裁定规则**（文档明说"Neither set overrides the other"，互相不覆盖，靠位置/顺序）。
冲突裁决: 澄清 T02 例②「规则冲突」——Claude 侧是**拼接不覆盖**，故新旧规则并存时由模型判断，不是程序裁定。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-rules-02
结论: 带 `paths:` frontmatter 的规则**按需加载**：只有当 Claude 用 Read/Write/Edit 命中匹配文件时才进入消息历史；子目录中的 CLAUDE.md 同理按需加载。无 `paths` 的规则在启动时随 `.claude/CLAUDE.md` 同优先级加载。
性质: 事实
范围: 当前官方文档；一个规则的 `paths` 列表共享 **1,000 个展开模式 + 4 MiB** 预算（无花括号的模式不计入）
实现状态: 默认
来源: ① https://code.claude.com/docs/en/memory.md；https://code.claude.com/docs/en/context-window.md（0.35/0.44 事件：path-scoped rule 在读取匹配文件时加载）
数据走查: 见 数据走查.md §4
运行证据: NOT_RUN
不能证明: ①命中判定的 glob 实现细节；②按需加载的规则若被压缩摘要掉，是否真的"不再自动回流"（文档说需去掉 `paths:` 或移到 project-root CLAUDE.md 才能跨压缩持久）。
冲突裁决: 支持 CM-03「按需检索 vs 整块装填」——Claude 侧规则/子目录记忆是**按需**，全局 CLAUDE.md 是**装填**。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-skill-01
结论: 技能采用「分层加载」：普通会话启动时把**技能描述**装入上下文（`description` + `when_to_use` 合并后在技能列表中**截断于 1,536 字符**），完整正文只在被调用时加载；`disable-model-invocation: true` 让描述完全不进上下文，你手动 `/name` 调用才加载。
性质: 事实
范围: 当前官方文档；压缩后不计入描述（见 claude-skill-02 与 claude-compact-06）
实现状态: 默认
来源: ① https://code.claude.com/docs/en/skills.md（"combined description and when_to_use text is truncated at 1,536 characters"）；https://code.claude.com/docs/en/context-window.md（0.10 skill descriptions 450 tokens；`noSurviveCompact: true`）
数据走查: 见 数据走查.md §4
运行证据: NOT_RUN
不能证明: ①`skillListingBudgetFraction`/`skillListingMaxDescChars` 两个设置键在 settings-reference 索引表中出现，但 skills 页**未**采用；两处口径需 T07/后续核对（**未决**，见 问题与审查.md Q-06）；②技能列表总预算的具体 token 数未给出。
冲突裁决: 澄清学习笔记 §2「skills（渐进式披露）」——机制成立，但"渐进式披露"是社区叫法，官方文档用"描述/正文分层加载"。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-skill-02
结论: 压缩后被调用过的技能正文会被**重新附加**：每个技能保留**前 5,000 tokens**（超出从头截断），所有重附加技能共享 **25,000 tokens** 合计预算，从最近调用的技能开始填充，旧的可能被整体丢弃。
性质: 事实
范围: 当前官方文档；auto-compaction 场景
实现状态: 默认
来源: ① https://code.claude.com/docs/en/skills.md（"keeping the first 5,000 tokens of each. Re-attached skills share a combined budget of 25,000 tokens"）；https://code.claude.com/docs/en/context-window.md（同数字）
数据走查: 见 数据走查.md §4
运行证据: NOT_RUN
不能证明: ①"截断保留文件开头"是否对所有技能文件类型成立（文档说要紧指令放 SKILL.md 顶部）；②技能描述列表是否重注入（明确：不重注入）。
冲突裁决: 支持 CM-07「哪些原样留下 / 变成摘要 / 移除」的清单化。
核验日期: 2026-10-15
```
