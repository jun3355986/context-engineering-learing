# 证据卡 · 缓存及总成本（CM-12）

> 一级证据（官方文档）。**区分客户端可观测部分 vs 服务端行为边界**是本卡的主线。

---

```yaml
结论ID: claude-cache-01
结论: 缓存按请求**前缀**精确匹配，无"按文件/按段"缓存；前缀任一字节变化都会**重算其后全部**。Claude Code 因此把请求排成三层（system prompt → project context → conversation）。**改对话层不影响前两层缓存；改 system prompt 层会使全部失效**（其后所有内容前缀都变了）。plan mode 与技能加载以**追加会话消息**方式进入，故缓存前缀保持完整。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（"The API caches by matching the start of each request, called the prefix … There is no per-file or per-segment caching."；三层表；"[Plan mode] and [skill loading] append their instructions as conversation messages, so the cached prefix stays intact."）
数据走查: 见 数据走查.md §3（D-23）
运行证据: NOT_RUN（缓存命中需真实请求读 `cache_read_input_tokens`）
不能证明: ①服务端 KV 张量实现（**U-03**，永久不可观测）；②前缀匹配的精确断点位置（客户端只能读到计数）。
冲突裁决: 支持 T02 红线「缓存的 KV 张量不是摘要」——缓存不改文本、不改内容选择。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-cache-02
结论: 缓存 TTL 两档：**5 分钟**与 **1 小时**（后者写入费率更高）。每个请求按**两个固定桶**分配：①"主对话"（交互轮次、`-p` 运行、Agent SDK 轮次、内联 helpers）；②"其它"（子代理、workflows、in-process teammates、forks、**压缩**、会话标题）。在 Claude 订阅的套餐用量内，主对话用 1 小时、其它用 5 分钟；走**用量积分/API key/云服务商**时都降到 5 分钟。可显式设：主对话 `promptCacheTtl`/`CLAUDE_CODE_PROMPT_CACHE_TTL`，其它 `subagentPromptCacheTtl`/`CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL`（均 v2.1.242+）。每次命中会重置计时器。
性质: 事实
范围: 当前官方文档；TTL 与预算桶按订阅类型不同
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（Cache lifetime 全节：两桶表、优先级顺序 FORCE_PROMPT_CACHING_5M > 桶环境变量 > 桶设置 > subagent frontmatter cacheTtl(v2.1.248+) > ENABLE_PROMPT_CACHING_1H > 桶默认）
数据走查: 见 数据走查.md §3（D-24）
运行证据: NOT_RUN；**可验证入口**：`claude -p "hello" --output-format json` 读 `usage.cache_creation`（1 小时写记为 `ephemeral_1h_input_tokens`，5 分钟写记为 `ephemeral_5m_input_tokens`）——留作 T19 运行项
不能证明: ①服务端缓存的物理位置（随 provider 不同，见文档"Where the cache lives"）；②`ephemeral_*` 之外的计费口径。
冲突裁决: 无
核验日期: 2026-10-15
```

```yaml
结论ID: claude-cache-03
结论: 文档给出**失效清单**（会造成一次更慢更贵的请求）：切模型（`/model`，整段历史无命中；`opusplan` 每次 plan 切换即一次模型切换）、改 effort level、开启 fast mode、连接/移除 MCP 服务器（取决于 tool search 是否启用）、启停插件、整体 deny 一个工具（无 tool search 时）、**压缩对话**、累积过多图像（超限移除最旧一批）、升级 Claude Code。整体 deny 仅指"在工具名位置匹配"的规则（裸名、`Bash(*)`、`"*"`）；`Bash(rm *)` 这类**作用域 deny 不改工具可见集**。插件的 skills/commands/agents/hooks/monitors/themes **永不**使缓存失效（其内容追加在既有对话之后）。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（What invalidates cache 全节）
数据走查: 见 数据走查.md §3（D-25）
运行证据: NOT_RUN
不能证明: 各类失效的**代价量级**（文档只给方向"一次更慢更贵"）。
冲突裁决: 支持 CM-12「缓存省了什么、没省什么」；并提示课程须把"改规则/加 MCP"讲成**可能触发缓存重建**。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-cache-04
结论: **压缩按设计使"对话层"缓存失效**（新历史更短，与旧前缀不共享前缀）；system prompt 层通常复用（除非会话恢复时保留了本应变化的提示词，则首次压缩切换并重建该层一次）。**摘要请求本身复用缓存**（暖时读前缀），冷时重处理全文。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（"Compacting the conversation — By design, this invalidates the conversation layer…"；"To produce the summary, Claude Code sends a separate request with the same system prompt, tools, and history…"）
数据走查: 见 数据走查.md §3（D-14/D-26）
运行证据: NOT_RUN
不能证明: 压缩"恢复"对话层缓存需要几轮（文档说压缩后那一轮只重建更短的摘要历史，"不是慢的部分"）。
冲突裁决: 与 claude-compact-07 同源；共同支撑 V-05（C-07 拆开裁决）。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-cache-05
结论: 保持缓存的动作：编辑仓库文件（追加 `<system-reminder>` 提示变更）、编辑 CLAUDE.md（**不清缓存但也不生效**，需 `/clear`、`/compact` 或重启）、改权限模式、改输出风格、调用 skills/commands、`/recap`（追加为命令输出）、`/rewind`（**截断回已缓存的前缀**）、生成子代理（父级缓存不受影响）。缓存**作用域**实际是"一台机器 + 一个目录"：system prompt 内嵌 auto memory 路径，对话开头声明工作目录/平台/shell/OS，故不同目录的会话前缀不同、互不命中；同目录并行会话前缀匹配、可互读；串行会话仅当**启动时 git status 快照一致**才共享前缀。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（Actions that keep the cache；Cache scope）
数据走查: 见 数据走查.md §3（D-27）
运行证据: NOT_RUN
```

## 附：客户端可观测 vs 服务端边界

| 项 | 客户端可观测 | 服务端/不可观测 |
|---|---|---|
| 缓存命中 | `cache_read_input_tokens` / `cache_creation_input_tokens`；statusline `prompt_cache` 对象；`/usage` 的 `Prompt cache (main)` 行（需 v2.1.251+；likely-cause 需 v2.1.260+） | KV 张量、断点位置、跨组织隔离细节 |
| TTL | 请求里带的 TTL；`usage.cache_creation.ephemeral_1h/5m_input_tokens` | 服务端计时器与过期实现 |
| 失效 | 由"哪些动作导致 miss"从计数侧推断 | 精确重算范围 |
| 压缩成本 | 压缩前后 token 面板、`/usage` | 摘要请求的精确计费与耗时分布 |
