# 证据卡 · 子 Agent 交接与错误/副作用（CM-09 / CM-11）

> 一级证据（官方文档）。

---

```yaml
结论ID: claude-subagent-01
结论: 子代理默认**全新独立上下文窗口**：看不到主对话历史、已调用的技能、已读文件；由 Claude 写一条委派消息（含任务摘要）给它起步。**fork** 则相反——继承主对话的 system prompt、工具、模型与全部消息历史（首请求**读父级缓存**），故牺牲了输入隔离。子代理有**自己的** system prompt（替换默认 Claude Code 提示，除非为空），不继承输出风格与主对话 auto memory；上下文窗口大小由**它自己的模型**决定。
性质: 事实
范围: 当前官方文档
实现状态: 默认（fork 需显式 `/fork`、`/branch` 或 `--fork-session`）
来源: ① https://code.claude.com/docs/en/sub-agents.md（"Each subagent starts with a fresh, isolated context window…"；Fork vs 非 Fork 对比表）；https://code.claude.com/docs/en/context-window.md（子代理独立窗口）
数据走查: 见 数据走查.md §4（D-28：6,100 → 420 tokens 示例）
运行证据: NOT_RUN
不能证明: ①委派消息的具体长度上限（文档提到子代理**描述合并** token 上限 15,000 会触发启动警告，属另一项）；②fork 是否也跳过工具过滤（文档说 fork **跳过**两个过滤器，拿主对话的**完整**工具池）。
冲突裁决: 支持 CM-09「子 Agent 继承多少上下文」——两条路线（fresh / fork）必须分列。
核验日期: 2026-10-15
```

性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/sub-agents.md；https://code.claude.com/docs/en/how-claude-code-works.md（"the subagent's tool calls stay out of your context, and Claude gets back a summary"）
数据走查: 见 数据走查.md §4（D-28）
运行证据: NOT_RUN
不能证明: 摘要的**长度上限**；"只回摘要"是否包含子代理的最终文本之外的图像/附件。
冲突裁决: 支持 CM-09 SP-05/SP-08（交接材料生成与边界）；回应 FB-06「有历史 / 看得到 / 能找回」是不同对象——子代理历史不在主会话里。
核验日期: 2026-10-15

```yaml
结论ID: claude-error-01
结论: 上下文到线时出现阻塞型错误消息：`Context limit reached · /compact or /clear to continue`（或只能 `/clear` 的变体 `Context limit reached · /clear to continue`）；`/context` 输出会给出 `Context exceeds the ...-token limit by ... tokens`。相关错误还有 `Prompt is too long`、`Input is too long for requested model`、`Prompt is too long · automatic compaction failed:`、`Prompt is too long · this conversation is a single exchange`/`A single-exchange conversation cannot be compacted`。
性质: 事实
范围: 当前官方文档（errors 页错误检索表）
实现状态: 默认
来源: ① https://code.claude.com/docs/en/errors.md（错误查找表与锚点 `#prompt-is-too-long`、`#context-exceeds-the-token-limit`）
数据走查: —
运行证据: NOT_RUN
不能证明: **硬上限的精确数值**——文档**未给出**具体 token 硬顶（如"-3,000"）；只给消息与"用 /compact 或 /clear"。故 LQ-11 的"硬上限 = effectiveWindow − 3,000（177K）"**无一级出处**（U-01）。
冲突裁决: **限制**旧报告的具体硬顶公式；**支持**"存在阻塞线 + 提示入口"这一机制。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-error-02
结论: 当请求因 `输入 + max_tokens` 超上下文限制被拒时，重发同样请求会同样失败，故 Claude Code **降低 `max_tokens` 重试**；在两种情况**停止重试并转为压缩**：①无法再缩减以适配（如对话本身几乎填满窗口）；②`max_tokens` 已无法再缩小。v2.1.218 之前可能重发一个仍不合适的缩减请求（如 extended thinking 预算超过剩余上下文）直到重试预算耗尽。
性质: 事实
范围: 当前官方文档；与 v2.1.218 分界
实现状态: 默认
来源: ① https://code.claude.com/docs/en/errors.md（Automatic retries 段）
数据走查: —
运行证据: NOT_RUN
不能证明: 重试次数上限与 `max_tokens` 缩减步长。
冲突裁决: 支撑 CM-11 SP-07（失败分类、重试、回退）。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-error-03
结论: 恢复会话时，**进程结束时仍在运行的工具不会重新完成或再次运行**（除非设 `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`）；未过期的计划任务会恢复，但后台 Bash 与 monitor 任务不会；结束于上一进程的后台子代理/后台命令/工作流会在恢复记录中显示为"未完成"备注。不恢复的启动标志：`--mcp-config`、`--settings`、`--plugin-dir`、`--fallback-model`、`--add-dir` 添加的目录（`/add-dir` 中途加入的也不恢复）。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/sessions.md（restore 列表）
数据走查: —
运行证据: NOT_RUN
不能证明: 恢复时"未完成"备注如何影响模型的下一步决策。
冲突裁决: 直接支撑 CM-11「哪些动作已发生，会不会重复副作用」——**默认不重跑**在途工具，避免重复副作用。
核验日期: 2026-10-15
```
