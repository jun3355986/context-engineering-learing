# 证据卡 · 长期记忆与保存/恢复（CM-08 / CM-10）

> 一级证据（官方文档）+ 二级证据（本地目录观察）。**涉及 LQ-08、LQ-10 与 C-03 / C-12 的裁决基础。**

```yaml
结论ID: claude-memory-01
结论: auto memory 每个项目一个目录 `~/.claude/projects/<project>/memory/`（`<project>` 由 git 仓库派生，同仓库的 worktree 与子目录共享）；索引文件 `MEMORY.md` 在**每次会话开始时注入前 200 行或前 25 KB（先到者为准）**，超出部分**下次加载被丢弃**，写入超限时 Claude Code 会提醒 Claude 重写索引。主题文件（如 `user_role.md`）**不随启动加载**、由 Claude 按需用文件工具读。记忆是**机器本地**的，不跨机器/云环境同步。`memory` 文件的 `modified` 字段需 v2.1.214+。
性质: 事实
范围: 当前官方文档；auto memory 默认在本地会话开启
实现状态: 默认（on；`autoMemoryEnabled`/`CLAUDE_CODE_DISABLE_AUTO_MEMORY` 可关）
来源: ① https://code.claude.com/docs/en/memory.md（auto memory 段、200 行/25 KB、按需读主题文件、机器本地）；https://code.claude.com/docs/en/context-window.md（0.035 Auto memory 680 tokens，"前 200 行或 25KB"）
数据走查: 见 数据走查.md §4（D-16）
运行证据: 本地只读观察（存在 `~/.claude/` 但**本机未见 `projects/` 目录**，见 claude-dist-03）；**未做运行**
不能证明: ①200 行/25 KB 是**加载上限**，不是"记忆容量上限"（主题文件可更多，只是不全进上下文）；②写入超限时"提醒"的触发阈值（"near a limit" 未给数值）。
冲突裁决: 支持 CM-08「保存 ≠ 用上」：MEMORY.md 超限部分**存着但不进请求**。
核验日期: 2026-10-15
```

```yaml
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/memory.md（"Two mechanisms carry knowledge across sessions"；CLAUDE.md vs auto memory 对比表；`type` 字段四类）
数据走查: 见 数据走查.md §4（D-17：两条线对照）

核验日期: 2026-10-15
```

```yaml
结论ID: claude-memory-03
结论: 关于"**后台持续抽取会话记忆**"（学习笔记 §8 / LQ-08）：官方文档**只**描述"Claude 在你的会话中读写记忆文件"（界面出现 `Saved N memories`/`Recalled N memories` 即对应 `~/.claude/projects/<project>/memory/`），并提供按需（惰性）加载；**没有**任何"后台多次小请求、每条从历史抽关键信息"的机制描述。最接近的 API 侧特性是 memory tool 在接近清除阈值时给 Claude 一个自动提醒，让其先把重要信息写进记忆文件。
性质: 推断（"文档未描述"为事实；"不存在"为推断）
范围: 当前官方文档
实现状态: 未证实（后台抽取）；**文档可证**（会话内读写）
来源: ① https://code.claude.com/docs/en/memory.md（全文检索无 "background extraction"/"session memory" 独立机制）；https://code.claude.com/docs/en/how-claude-code-works.md（"Claude reads and writes memory files during your session"）；https://platform.claude.com/docs/en/build-with-claude/context-editing（memory tool 的清除前自动提醒）
数据走查: —
运行证据: NOT_RUN（无运行则无法证伪"后台小请求"；且此类请求在服务端也难观测）
不能证明: "**不存在**后台抽取"——文档不写 ≠ 不存在。故本包**不支持**旧报告的"后台多次小请求持续抽取"表述，但也**不判定其不存在**，标"未证实 + 文档未描述"。见 问题与审查.md V-06。
冲突裁决: **限制** LQ-08 的旧表述：把"后台持续抽取的独立小请求线"改为"由模型在会话中按需读写记忆文件 + 会话启动注入一次"。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-resume-01
结论: 会话 transcript 是**明文 JSONL**，默认路径 `~/.claude/projects/<project>/<session-id>.jsonl`，`<project>` = 工作目录路径的非字母数字字符替换为 `-`（转换后 >200 字符则截断到 200 + 追加路径哈希）。每行是一个 JSON 对象（消息 / 工具调用 / 元数据）。**格式是内部格式、版本间会变**，官方不建议脚本直接解析，推荐 `/export` 或脚本接口。会话**持续保存**，可用 `--resume`/`--continue` 恢复。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/sessions.md；CLAUDE_CONFIG_DIR / CLAUDE_CODE_PROJECT_DIR_NAME（v2.1.234+）可改位置与目录名
数据走查: 见 数据走查.md §5（D-19）
运行证据: 本地只读观察（官方路径 `~/.claude/projects/` **本机不存在**；存在的是非原生 `~/.claude/transcripts/`，见 claude-dist-03）；**未做运行**
不能证明: ①每行的字段语义（官方明说格式不定，且本机没有原生样例）；②本机为何没有 `projects/`（未决 Q-05）。
冲突裁决: 澄清"transcript = 物理保留的记录"——它是 C-03/C-12 的"物理保留"落点。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-resume-03
结论: 本地会话记录默认保留 **30 天**（`cleanupPeriodDays`，最小 1、设 0 报错）；**auto memory 目录**（`projects/<project>/memory/`）**不随清理删除**（仅当整个保留期内一直为空才移除；v2.1.228 之前会误删）。Claude Desktop / Cowork 的 transcript 默认**豁免**该期限（可用 `desktopSessionCleanupPeriodDays`，需 v2.1.248+）。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/claude-directory.md（§3.1/§3.2 清理规则）；https://code.claude.com/docs/en/data-usage.md（"30 days by default"）；https://code.claude.com/docs/en/sessions.md
数据走查: 见 数据走查.md §5（D-21）
运行证据: 本地只读观察（`~/.claude/backups/` 有 3 个 `.claude.json.backup.*`；未见 30 天清理痕迹）
不能证明: 清理扫描的精确触发时机（文档说"无法安全确定保留期时暂停"，`retention_sweep` 事件会列出原因）。
冲突裁决: 关键——**"物理保留"有时间边界（默认 30 天）**，故 C-12 的"绝不可能找回"应改为"在当前会话内可查；跨 30 天后可能已被清理"。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-resume-05
结论: **压缩不改变磁盘文件；原始消息留在会话 transcript 中，Claude 仍能引用细节。** 另外 Claude Code 的 checkpointing 记录 Claude 文件编辑工具的改动：每个"开始一个轮次"的提示创建一个 checkpoint，保留**最近 100 个** checkpoint 的文件快照（每个文件的第一个快照除外，供 VS Code 扩展做会话 diff 基线）；快照随会话保存，`/resume` 后仍可 `/rewind`；默认约 **30 天**后被保留清理删除（快照没了时回溯会报 `No files were restored`）。checkpointing **不**跟踪 Bash 命令的改动、通常也不跟踪子代理的编辑。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/checkpointing.md（"Summarizing doesn't change files on disk, and the original messages stay in the session transcript, so Claude can still reference the details."；100 checkpoint；30 天；不跟踪 Bash/子代理）；https://code.claude.com/docs/en/context-window.md（同句）
数据走查: 见 数据走查.md §5（D-22）
运行证据: NOT_RUN
不能证明: ①"Claude 仍能引用细节"的**具体入口**（是自动重读 transcript 还是仅 `/rewind` 可见？文档未给）；②用户能否**手动展开**取回被摘要内容（文档未明说，只说明仍存在于记录中）。
冲突裁决: **这是 C-03 / C-12 的核心一级证据**：压缩（改内存/当前请求历史）与物理保留（磁盘 transcript 不动）**两个事实并存不矛盾**。学习笔记 §10 "resume 绝不可能找回" 属**过度绝对化**：在 30 天保留期内、通过 transcript/`/rewind`/`/export` 仍可查证。详见 V-07。
核验日期: 2026-10-15
```
