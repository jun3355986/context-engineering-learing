# 证据卡 · 单条工具输出治理（CM-04）

> 一级证据（官方文档）+ 二级证据（本地帮助文本）。**这是对学习笔记「保头 2KB + 全量落盘」说法的核验主战场。**

---

```yaml
结论ID: claude-toolout-01
结论: Bash（及命令行类）工具的**有效结果**默认内联约 **30,000 字符**；超过内联上限时，模型拿到的是**「保存文件路径 + 最多前 2,000 字符预览」**，文件写入 session 目录、**超过 64 MiB 则截断**。读回字符数由 `BASH_MAX_OUTPUT_LENGTH`（默认 30,000，硬顶 150,000）或 `bashOutputMaxChars` 设置（≤128,000，需 v2.1.261+）控制。
性质: 事实
范围: 当前官方文档；Bash 工具；默认配置
实现状态: 默认
来源: ① https://code.claude.com/docs/en/tools-reference.md（Output limits：streams 到 working file，>5 GB 被杀；valid 约 30,000 字符内联，"capped at 64 MiB" 截断；"up to the first 2,000 characters" 预览）；https://code.claude.com/docs/en/env-vars.md（BASH_MAX_OUTPUT_LENGTH 30000/150000）
数据走查: 见 数据走查.md §2（D-01）
运行证据: NOT_RUN（见 过程观察.md RUN-NOT_RUN-01；未做真实大输出运行）
不能证明: ①「30,000 字符」是**字符**不是字节，也**不是** token——不能直接换算成上下文占比（要按 tokenizer，且模型而变）；②"全量落盘"是**近似**：文件有 64 MiB 截断，且失败路径根本不给文件（claude-toolout-02）；③未验证 2,000 字符预览是否含截断标记文本。
冲突裁决: **部分支持**学习笔记「>30k 字符 → 保头 2KB 预览 + 全量落盘」：阈值与预览量级一致，但须修正为（a）单位是字符；（b）预览是"最多前 2,000 字符"；（c）落盘有 64 MiB 上限；（d）失败结果不走这套。详见 问题与审查.md V-01。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-toolout-02
结论: 命令被判定为**失败结果**时，内联约 **10,000 字符**；超过则给**头尾摘录（head-and-tail excerpt）**且**不提供文件路径**。「有效/失败」判定排除一组良性退出码 1 的命令（grep/rg/find/diff/test/`[`、git diff、git grep），其余退出码 1 一律算失败。
性质: 事实
范围: 当前官方文档；Bash 工具
实现状态: 默认
来源: ① https://code.claude.com/docs/en/tools-reference.md（"Failure: 约 10,000 字符；超出给 head-and-tail excerpt，无文件路径"；良性退出码 1 列表）
数据走查: 见 数据走查.md §2（D-02）
运行证据: NOT_RUN
不能证明: ①头尾各取多少字符（文档未给比例）；②失败判定的其它启发式（如 stderr 关键字）。
冲突裁决: **限制**旧报告的"三家都保头/全量落盘"一律概括——Claude 侧失败路径**不落盘**，与成功路径不同。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-toolout-03
结论: Read 工具默认单次最多返回 **25,000 tokens**（或 `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` 设定值）；整文件超过 **256 KB** 被拒绝；`allow_large: true`（需 v2.1.296+）可整读、按会话剩余窗口算大小（图像/PDF/notebook 仍受限）。文件超 token 限制时给第一页 + `PARTIAL view` 通知，提示用 `offset`/`limit`。
性质: 事实
范围: 当前官方文档；Read 工具
实现状态: 默认
来源: ① https://code.claude.com/docs/en/tools-reference.md；https://code.claude.com/docs/en/env-vars.md（CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS 默认 25,000）
数据走查: 见 数据走查.md §2（D-03）
运行证据: NOT_RUN
不能证明: ①25,000 tokens 对应的字符数（依文件内容与 tokenizer）；②`allow_large` 的边界计算细节。
冲突裁决: 无（补全 CM-04 的"读入侧"限长，旧报告只讲"输出侧"）。
核验日期: 2026-10-15
```

数据走查: 见 数据走查.md §2（D-04）

```yaml
结论ID: claude-toolout-05
结论: 工具输出与 hook 输出超过 **10,000 字符**时会保存到文件，模型只拿到**预览与文件路径**；PostToolUse hook 的普通 stdout 在 exit 0 时**不进上下文**（只写 debug log），只有 `hookSpecificOutput.additionalContext` 字段进上下文；exit code 2 时 stderr 作为错误呈现但不能阻止已运行的工具。
性质: 事实
范围: 当前官方文档（context-window 页）；hook 机制
实现状态: 默认
来源: ① https://code.claude.com/docs/en/context-window.md（"输出超过 10,000 字符时会保存到文件；Claude 只得到预览和文件路径"；hook 段）
数据走查: 见 数据走查.md §2（D-05）
运行证据: NOT_RUN
不能证明: ①10,000 与 30,000 两个阈值的关系（一个来自 hook/tool 通用段，一个来自 Bash 有效结果段）——本包按"不同上下文/不同来源"分别登记，**不合并**；②`additionalContext` 的字节上限。
冲突裁决: 无
核验日期: 2026-10-15
```

## 附：其它工具的限长（同一页文档，供横向比较时引用）

| 工具 | 限制 |
|---|---|
| Glob | 结果按修改时间排序、**上限 100 个文件**，命中上限时结果带截断标志 |
| WebFetch | 每次最多读取页面 **100,000 字符**；缓存 TTL 默认 **15 分钟**；下载超时 **5 分钟** |
| WebSearch | 交互式终端会话 **200 次**上限（主对话与子代理共用），可按小时约 100 次回填，**不能关闭** |
| Bash 超时 | `BASH_DEFAULT_TIMEOUT_MS` 默认 2 分钟；`BASH_MAX_TIMEOUT_MS` 默认 10 分钟 |
| PDF | 短 PDF 整读；超 10 页按范围读，一次最多 **20 页** |
| 图片 | 重缩放后 > **500 KB** 的转成降质 JPEG |
| notebook | 单元格超 **256 KB** 或超 token 限报错；**>100 MB 拒绝读取** |
