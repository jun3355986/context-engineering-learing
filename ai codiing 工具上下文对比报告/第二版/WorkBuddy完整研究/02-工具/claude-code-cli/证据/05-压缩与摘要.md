```yaml
结论ID: claude-compact-03
结论: 存在四类"缩短历史"的动作，语义不同，不能混用：
① `/compact`：压缩**全部**到当前；
② `/rewind` 菜单的 **Summarize from here** / **Summarize up to here**：只压某一段（"从这点往后"/"到这点为止"），可加可选说明；选择后原消息的 prompt 会回到输入框可再发送；
③ `/clear`：**空上下文**开新对话（零成本，不做摘要，旧对话仍存盘可 `/resume`）；
④ `/recap`：**追加**一行摘要作为命令输出（**不替换**历史，保持前缀缓存）。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/checkpointing.md（两种 Summarize）；https://code.claude.com/docs/en/commands.md（/clear、/recap、/rewind）；https://code.claude.com/docs/en/prompt-caching.md（/recap "appends the summary as command output rather than replacing your message history, so the cached prefix stays intact"）
数据走查: 见 数据走查.md §3（D-11）
运行证据: NOT_RUN
不能证明: ①Summarize 段落的边界如何映射到消息 ID；②`/recap` 的自动版本（离开后回来显示）触发条件细节。
冲突裁决: 澄清 CM-06「自动/手动压缩」不止一种手动入口——课程若只讲 `/compact` 会漏掉分段摘要与 `/recap`。
```

```yaml
结论ID: claude-compact-07
结论: 生成摘要**不是"零 API 调用"**：Claude Code 会发一次**独立请求**，内容 = 与主对话**相同的 system prompt、工具、历史**，再在末尾**追加一条摘要指令**作为 user 消息。缓存暖时该请求**复用前缀**，成本远低于上下文大小；缓存冷（休息超过 TTL）时**重处理全文为未缓存输入**——这正是"恢复旧会话后 `/compact` 最贵"的原因。costs 页明确："`/compact` 会读取它要总结的对话，**压缩大上下文本身就是一次大请求**"。
性质: 事实
范围: 当前官方文档
实现状态: 默认
来源: ① https://code.claude.com/docs/en/prompt-caching.md（"a separate request with the same system prompt, tools, and history … plus a summarization instruction appended as a final user message"；暖/冷两种情况）；https://code.claude.com/docs/en/costs.md（"Compaction：`/compact` 会读取它要总结的对话，压缩大上下文本身就是一次大请求"）
数据走查: 见 数据走查.md §3（D-14：暖/冷成本差异推演）
运行证据: NOT_RUN
不能证明: ①摘要请求的 `max_tokens`；②"同历史"是否包含被清工具输出之后的历史（时序未明）。
冲突裁决: **裁决 C-07（零 API 调用压缩）**：分两种情况——(a) **对话摘要/压缩**会**新增一次模型调用**（本卡证据），"零 API 调用"**不成立**；(b) **服务端工具结果清除**（claude-compact-08）**不新增调用**（在到达模型的同一请求内服务端应用），此处"零调用"**成立**。故 C-07 须按机制拆开裁决。详见 V-05。
核验日期: 2026-10-15
```

```yaml
结论ID: claude-compact-08
结论: Anthropic API 提供**服务端 context editing**（beta 头 `context-management-2025-06-27`）：`clear_tool_uses_20250919` 在**提示到达 Claude 之前**由 API 自动清除最旧的工具结果（以占位文本替换），配置项：`trigger` 默认 **100,000 input tokens**、`keep` 默认 **3 tool uses**、`clear_at_least` 默认无、`clear_tool_inputs` 默认 `false`、`exclude_tools` 可选；`clear_thinking_20251015` 管理 thinking 块。客户端**保留完整未修改的历史**，无需与服务端状态同步。清除会**使缓存前缀失效**，故建议用 `clear_at_least` 保证"清得够多"。
性质: 事实（**API 能力**）
范围: Anthropic API（platform.claude.com）；**不等于** Claude Code CLI 默认启用
实现状态: API 默认关闭（需 beta 头与 `context_management` 参数）
来源: ① https://platform.claude.com/docs/en/build-with-claude/context-editing
数据走查: 见 数据走查.md §3（D-15）
运行证据: NOT_RUN
不能证明: **Claude Code CLI 是否、以及在什么条件下启用该 API 策略**——这是 FB-07 的核心（"API 支持 ≠ 某 CLI 默认启用"）。CLI 侧文档只说"clears older tool outputs first"（claude-compact-05），**未指名**走该 API。→ 标 未决（Q-03）。
冲突裁决: 支持 C-07 的"区分此刻复用不新增 vs 此前已产生"；并把"零 API 调用"限定到**服务端清除**这一种。
```
