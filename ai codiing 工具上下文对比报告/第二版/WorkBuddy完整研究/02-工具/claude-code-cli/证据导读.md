# Claude Code CLI · 证据导读

> **为什么这份文件不叫「源码导读」**：任务书 §4.3 给开源工具的产物是 `源码导读.md`（走一条代表链路：调用者 → 条件 → 处理 → 状态写回 → 下一次请求/恢复，含失败分支）。Claude Code **实现闭源**（预编译原生二进制），**没有可读源码**。因此本文件改称**证据导读**：讲清"这个工具我们能证明什么、用什么方法证明、哪些永远不能证明"。
>
> **一句话边界**：可观测的只有**分发版本**与**行为**；不可观测的是**内核实现**。任何把反混淆产物或二进制字符串当"源码"引用的做法，本包一律不采纳（任务卡明确禁止）。

## 1. 三类证据与角标

| 等级 | 名称 | 本包中的具体来源 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|
| **①** | 官方文档 / 发布说明（**承诺行为**） | `code.claude.com/docs/en/*`（context-window、memory、prompt-caching、model-config、tools-reference、sessions、checkpointing、claude-directory、sub-agents、skills、costs、errors、env-vars、commands、cli-reference、data-usage）；`platform.claude.com/docs/en/build-with-claude/context-editing`；Claude Academy 课程页 | 产品**承诺**的默认行为、配置键名、单位与边界 | 承诺 ≠ 该版本**实际**这样跑；文档不写的实现细节不可得 |
| **②** | 官方分发件 / 本地 CLI 可观测项（**标注观察方法**） | 分发包 `2.1.299` tarball（包结构、`package.json`、`install.cjs`、`cli-wrapper.cjs`）；本地 CLI `2.1.296` 的 `--version`/`--help`/`--autocompact`/`purge --help`；本地配置文件（`~/.claude.json`、`~/.claude/settings.json`、目录清单） | 特定版本**确实**存在哪些标志、配置键、目录与文件 | 标志存在 ≠ 该机制默认启用；帮助文本不列全部标志（官方明说 `claude --help` 不列全）；本机残留 ≠ 官方默认布局 |
| **③** | 社区线索 | 社区还原/反混淆目录、第三方博客、旧报告 `LONG_CONTEXT_SOURCE_DEEP_DIVE`（`claude-ds`）、`ant-opus` 等 | **只是线索**，用于提出待核验问题 | **不得**独立证明任何默认行为；不得写成"源码" |

**角标写法**：正文引用处标 `【①文档】`、`【②分发件观察】`、`【③社区线索】`。**高风险主张**（触发阈值、落盘行为、压缩不可逆性）必须同时给等级与"不能证明"。

## 3. 「代表链路」的闭源替代写法

开源工具写"调用者 → 条件 → 处理 → 状态写回 → 下次请求"，闭源工具改写成**可观测行为链**，每一步都注明证据：

**链 A：一次工具调用结果如何进入下一次请求（CM-04 → CM-01）**
```
①【文档】Bash 命令输出流式写入 working file（>5GB 被杀）
②【文档】命令结束，从 working file 读回，内联上限约 30,000 字符（BASH_MAX_OUTPUT_LENGTH 默认 30000，硬顶 150,000；或 bashOutputMaxChars ≤128,000）
③【文档】超限：给"文件路径 + 最多前 2,000 字符预览"，文件存 session 目录，>64 MiB 截断
   ——失败结果不同：约 10,000 字符内联，超限给头尾摘录，且【无文件路径】
④【文档】请求组装：把该消息与其余"对话层"内容一起序列化进下一次请求
⑤【文档】大型工具输出与 MCP 图像外溢到 ~/.claude/projects/<project>/<session>/tool-results/
⑥【文档】清理：随会话 transcript 一起按 cleanupPeriodDays（默认 30 天）到期删除
```
**不可观测**：第 ② 步"读回"的内部实现、第 ④ 步序列化的精确字节序，闭源不可得；以上全部来自官方文档承诺，**未做运行验证**（见 `过程观察.md` RUN-NOT_RUN-01）。

**链 B：一次自动压缩（CM-05 → CM-06 → CM-07 → CM-12）**
```
①【文档】当前用量达到 auto-compact 窗口的触发百分比（可用 CLAUDE_AUTOCOMPACT_PCT_OVERRIDE 调低）
②【文档+分发件】窗口由 autoCompactWindow / /autocompact / --autocompact / CLAUDE_CODE_AUTO_COMPACT_WINDOW 决定
③【文档】"先清理较旧工具输出，再按需摘要对话"（两段式）
④【文档】摘要 = 一次与主对话"同 system prompt、同工具、同历史 + 末尾附摘要指令"的独立请求
⑤【文档】压缩按设计使对话层缓存失效；system prompt 层通常复用
⑥【文档】压缩后重载：系统提示/CLAUDE.md/auto memory/plan/被调用技能正文（每技能 ≤5,000、合计 ≤25,000 tokens）/最近最多 5 个文件
```
**不可观测**：第 ③ 步"清理旧工具输出"是否走服务端 `clear_tool_uses_20250919`（API 能力）还是客户端实现——**文档未明说**，标未决（见 `问题与审查.md` Q-03）。
