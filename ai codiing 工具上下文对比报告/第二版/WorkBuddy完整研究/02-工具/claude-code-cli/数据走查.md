# Claude Code CLI · 数据走查

> **口径**：每个走查给"输入 → 处理 → 保留/丢失/落盘 → 边界例子"，凡能算的给数字与算式。所有数字**必须带适用条件**（版本/模型/配置）。
> **数字类别角标**（沿用 T02 数字纪律）：【文档常量】官方文档给出的固定值｜【官方示例】官方文档的示意值（非保证）｜【推算】本包按前两者算出的派生值｜【未知】不可观测。
> **红线**：本文所有 token 数字都是**示意/推算**，不是本机实测；本包**未运行真实模型**（见 `过程观察.md`）。

## §2 单条工具输出（CM-04）

**D-03｜Bash 有效输出（对照学习笔记"保头 2KB + 全量落盘"）**
- 输入：一条 Bash 命令，输出 `N` 字符
- 处理【文档】：
  - `N ≤ 30,000` → 全量内联进模型
  - `N > 30,000` → 模型得到"文件路径 + 最多前 **2,000** 字符预览"
  - 落盘文件 > **64 MiB** → 截断
  - 输出流 > **5 GB** → 命令被杀
- **算式（举例 N = 100,000 字符）**：
  - 进请求字符 ≈ `2,000`（预览）；落盘字符 ≈ `100,000`（未超 64 MiB）
  - 进请求占比 ≈ `2,000 / 100,000 = 2.0%`【推算】
- **保留**：全量在磁盘（≤64 MiB）；**丢失**：模型视野里 98% 内容（除非模型主动 Read 回读）
- **边界例子（三个反例）**：
  1. `N = 30,001`：刚好越线 → 从"全量"跳到"2,000 预览"，**阶跃**而非渐变【文档】
  2. `N = 70 MiB`：落盘被 64 MiB 截断 → "全量落盘"**不成立**
  3. **失败结果**：内联约 10,000 字符，超限给头尾摘录、**无文件路径** → 既没全文也没路径 → claude-toolout-02
- **单位警告**：【文档】给的是**字符**；换算 token 依赖 tokenizer 与内容（英文/中文/代码差异大），本包**不做字符→token 换算**。→ claude-toolout-01

**D-04｜Read 输出**
- 默认单次 ≤ **25,000 tokens**；整文件 > **256 KB** 直接拒绝；超 token 限给第一页 + `PARTIAL view` 并提示 `offset`/`limit`
- 边界例子：一个 300 KB 源码文件 → 直接报错（不给部分内容）；一个 200 KB、60,000 tokens 的文件 → 给第一页 + PARTIAL 通知【文档】
- 注：有 `/workspace` 之外的文件走 `--add-dir`，不改变输出限长。→ claude-toolout-03

**D-05｜工具/hook 输出落盘**
- 规则【文档】：工具输出 / hook 输出 > **10,000 字符** → 存文件，模型拿预览 + 路径
- 与 D-03 的关系：D-03 是 **Bash 有效结果**的 30,000（可经 `BASH_MAX_OUTPUT_LENGTH`/`bashOutputMaxChars` 调），D-05 是 **hook/tool 通用段**的 10,000。**两者不同来源，本包不合并**。→ claude-toolout-05

**D-06｜落盘位置与清理**
- 大型工具输出 → `~/.claude/projects/<project>/<session>/tool-results/`【文档】
- 随父 transcript 按 `cleanupPeriodDays`（默认 **30 天**）到期移除【文档】
- **保留**：磁盘 30 天；**丢失**：30 天后（自动清理）
- 边界例子：本机 2.1.296 下 **`~/.claude/projects/` 与 `tool-results/` 均不存在**（见 §5）→ 无法用本机佐证；归因未决（Q-05）。→ claude-toolout-04

## §3 窗口、触发、压缩与缓存（CM-05/06/07/12）

**D-07｜窗口口径（绝对 token）**
- 入口与范围【文档】：`CLAUDE_CODE_AUTO_COMPACT_WINDOW` / `--autocompact` / `/autocompact` / `autoCompactWindow`，取值 **100,000 – 1,000,000**，且被钳制在模型窗口内
- 优先级【文档】：env > flag > `/autocompact`（按模型）> `autoCompactWindow`（所有模型）
- 边界例子：`CLAUDE_CODE_AUTO_COMPACT_WINDOW=500k` → 被读作 `500` 并被钳到下限 **100K**（变量**只接受纯整数**，`500k`/`1M` 形式在**命令/标志**可用、在**环境变量**不可用）→ 常见配置陷阱。→ claude-trigger-01

**D-08｜触发口径（百分比）**
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` ∈ **[1, 100]**；**低于默认值才生效**，高于默认被忽略；仅对"会在模型上限前压缩"的会话生效；主对话与子代理同用【文档】
- **可算的只有区间**，默认值【未知】。若某会话窗口 = 200,000：
  - 取覆盖率 50 → 触发点 ≈ 100,000
  - 若观测到的触发点 = 167,189 → 覆盖率 ≈ `167,189 / 200,000 = 83.59%`（这正是 claude-trigger-04 示例的算法）【推算】
- **红线**：83.59% 是**由示例值反算**，**不是**"默认 83.5%"。文档未给默认百分比。→ claude-trigger-02

**D-09｜默认阈值（按模型）**
| 情形 | 默认压缩点【文档】 | 若窗口 200K 的占比【推算】 |
|---|---|---|
| 不设窗口、普通模型 | 模型上下文上限 | ≈100% |
| Sonnet 4.6 / Opus 4.6（无扩展） | 200K 边界 | 100%（窗口本身 200K） |
| `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` 的原生 1M 模型 | 200K 边界 | 20% of 1M |
| 原生 1M 模型（Fable / Sonnet 5+ / Haiku 5.5 / Opus 4.7+） | 约 **967K** | ≈96.7% |
- 边界例子：Haiku 5.5（原生 1M）默认约 967K 触发；但若设 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` 则落到 200K 边界，且**把 auto-compact 窗口设到 200K 以上也不解除**该限制【文档】。→ claude-trigger-03

**D-10｜官方压缩事件示例**
- 示例【官方示例】：`compactMetadata = {trigger: "auto", preTokens: 167189}`
- 关系：`167,189 / 200,000 = 83.59%`；与旧报告"≈167K（83.5%）"**量级一致**
- **不能**读成默认值；示例未注明模型。→ claude-trigger-04

**D-11｜`/compact` 摘要系数（教学示意）**
- context-window 时间线组件用 `Math.round(sumTokens * 0.12)` 表示摘要块大小【官方示例】
- 举例：被摘要事件合计 20,000 tokens → 摘要块 ≈ `20,000 × 0.12 = 2,400` tokens【推算】
- **红线**：这是**教学示意系数**，不是保真度或压缩率保证；不得当"压缩率 12%"引用。→ claude-compact-02

**D-12｜两段式缩短**
- 【文档】"clears older tool outputs first, then summarizes the conversation if needed" + Academy"removes unnecessary tool call results"
- 可写层数 = **2**（清工具输出 + 摘要）。"六层压缩"**无以支撑**。→ claude-compact-05、V-04

**D-13｜压缩前后对照（200K 窗口、示意）**
| 层 | 压缩前 | 压缩后 | 来源 |
|---|---|---|---|
| 系统提示 | 在 | 在（在消息历史之外，压缩后重载） | 【文档】 |
| project-root CLAUDE.md | 在 | 从磁盘重注入 | 【文档】 |
| auto memory | 前 200 行/25KB | 从磁盘重注入 | 【文档】 |
| 对话逐字历史 | 在 | → **一段结构化摘要**（原工具输出与中间推理消失） | 【文档】 |
| 被读/编辑的文件 | 在 | **重读最多 5 个**（最近修改优先；单文件 >5,000 tokens 只给路径） | 【文档】 |
| 被调用技能正文 | 在 | 重注入（每技能 ≤5,000、合计 ≤25,000 tokens；超则丢最旧） | 【文档】 |
| 技能描述列表 | 在 | **不重注入** | 【文档】 |
| git status | 快照 | 重新读一份 | 【文档】 |
- 边界例子：会话调用 7 个技能、每个正文 6,000 tokens → 想全留需 42,000 > 25,000 预算 → 最旧的被丢；每个只留前 5,000（共丢 ≥7,000）【推算】。→ claude-compact-06、claude-skill-02

**D-14｜摘要请求的成本（暖 vs 冷）**
- 【文档】摘要 = 一次与主对话"同 system prompt / 工具 / 历史 + 末尾摘要指令"的独立请求
- 暖缓存：读前缀（`cache_read` 费率，**低于**标准输入）→ "成本远低于上下文大小"
- 冷缓存（休息超过 TTL）：前缀 **重处理为未缓存输入** → "恢复旧会话后 `/compact` 最贵"
- 结论：**压缩 ≠ 零 API 调用**（一次模型调用）→ V-05

**D-15｜API 服务端工具结果清除（API 能力，不写 CLI 默认）**
- 【文档】`clear_tool_uses_20250919`：`trigger` 默认 **100,000 input tokens**、`keep` 默认 **3 tool uses**、`clear_at_least` 默认无、`clear_tool_inputs` 默认 `false`
- 举例：设 `trigger=30,000`、`keep=3`、`clear_at_least=5,000` → 超过 3 万 token 后按时间清最旧工具结果，保留最近 3 个，且每次至少清 5,000 tokens（否则不应用），以让缓存失效"值回票价"
- 缓存代价【文档】：清除会使缓存前缀失效 → 用 `clear_at_least` 控制"清得够多"
- **不新增模型调用**（服务端在提示到达 Claude 前应用）→ 这一层"零 API 调用"成立。→ claude-compact-08

**D-16｜缓存三层与前缀失效**
- 层序【文档】：system prompt → project context → conversation
- 失效推演：
  - 改对话层（新消息）→ 前两层命中，只重算新增【文档】
  - 改 project context（`/clear`、`/compact`）→ 重算 project context + 对话层【文档】
  - 改 system prompt（如升级、工具定义集合变化）→ **全部重算**【文档】
- 举例：稳定前缀 150,000 tokens，某轮只加 2,000 tokens 新对话 → 命中 150,000、只全量处理 2,000【推算，按文档机制】。→ claude-cache-01

**D-17｜TTL 与请求桶**
- 桶【文档】：主对话 vs 其它（子代理/fork/压缩/会话标题等）
- 订阅套餐用量内：主对话 1 小时、其它 5 分钟；走积分/API key/云 → 都 5 分钟
- 验证入口【文档】：`claude -p "hello" --output-format json` 读 `usage.cache_creation`；1 小时写 → `ephemeral_1h_input_tokens`，5 分钟写 → `ephemeral_5m_input_tokens`（**留作 T19 运行项**）。→ claude-cache-02

**D-18｜缓存失效清单（计数侧可观测）**
- 【文档】切模型 → `no cache hits`（整段历史无命中）；压缩 → 对话层失效；插件 skills/commands/agents/hooks **永不**失效（追加在对话之后）
- 边界例子：`opusplan` 每次 plan 切换 = 一次模型切换 = 一次全新缓存 → plan 密集会话缓存命中率显著下降【推算，按文档】。→ claude-cache-03/04

## §4 记忆、规则、技能、子代理（CM-02/03/08/09）

**D-19｜MEMORY.md 注入上限**
- 输入：`MEMORY.md` 共 320 行 / 30 KB
- 处理【文档】：注入前 **200 行或前 25 KB（先到者）** → 取前 200 行（若 200 行 < 25 KB）
- **保留**：前 200 行进请求；**丢失**：第 201 行起**不进请求**（文件仍在磁盘；主题文件按需读）
- 边界例子：前 200 行已 26 KB（长行）→ 取 25 KB（先到的 KB 限）→ 第 200 行可能被腰斩。→ claude-memory-01

**D-20｜CLAUDE.md 预算**
- 四级层次**拼接**（不覆盖）；单文件 > **4 MiB** 跳过；导入**最多 4 跳**；建议 <200 行/文件
- 规则 `paths` 预算：**1,000 个展开模式 + 4 MiB**（无花括号模式不计）
- 边界例子：根 CLAUDE.md 引 `@AGENTS.md` 引 `@docs/x.md` 引 … 第 5 跳**不再展开**（超 4 跳）【文档】。→ claude-rules-01

**D-21｜技能描述预算**
- `description` + `when_to_use` 合并后在技能列表**截断于 1,536 字符**；`disable-model-invocation: true` 则描述**完全不进**上下文
- 举例：10 个技能、每个描述满 1,536 字符 → 列表 ≈ 15,360 字符（约）【推算；token 未给】
- ⚠ 与 settings-reference 索引表出现的 `skillListingMaxDescChars` / `skillListingBudgetFraction` 口径**未对齐** → Q-06。→ claude-skill-01

**D-22｜子代理节省（官方示例）**
- 【官方示例】子代理读了 2,200 + 800 + 3,100 = **6,100 tokens** 的文件，主上下文只得到 **420 tokens** 结果
- 节省比 ≈ `(6,100 − 420) / 6,100 = 93.1%`【推算】
- **红线**：这是**单次教学示例**，不是性能基准（T02/LQ-03：未实测不得作效果结论）。→ claude-subagent-01/02

**D-23｜子代理记忆与规模上限**- 子代理记忆：MEMORY.md 前 200 行/25 KB；`project` 为推荐 scope
- 规模【文档】：并发子代理默认 **20**、嵌套默认 **3 层**、预加载技能上限 **32** 个不同名、子代理描述合并 token 上限 **15,000**（触发启动警告）
- 边界例子：fork **不能**再 fork；fork 跳过工具过滤器，拿主对话**完整**工具池。→ claude-memory-04、claude-subagent-03

**D-30｜启动装配清单磁盘侧实测（attachment 枚举）**
- 输入：一次 `claude -p`（未登录）产生的原生 transcript
- 观测到 `attachment.type` 枚举 11 种：`environment`、`model`、`deferred_tools_delta`、`agent_listing_delta`、`skill_listing`、`total_tokens_reminder`、`instructions`、`session_context`、`date`、`remote_session_change`、`prompt_snapshot`
- 与官方 context-window 文档的"启动加载"逐项对应：environment(环境) / deferred_tools_delta(MCP 工具延迟) / skill_listing(技能描述, 本机 `skillCount=19`) / instructions(CLAUDE.md) / date(日期) / prompt_snapshot(系统提示词快照, `systemPrompt` 对象长度 8,455)
- **可算**：本机技能列表 **19** 个技能；系统提示词快照约 **8,455 字符**（是对象序列化长度，**非** token）
- **不能证明**：①`total_tokens_reminder`/`atis-latch`/`queue-operation` 的语义（文档未命名，**不猜测**）；②枚举完整性（单次未登录样本）；③attachment 是**会话记录**，**不等于实际请求体**。→ claude-dist-05

## §5 保存与恢复（CM-10）

**D-24｜transcript 路径映射（文档）**
- 【文档】`~/.claude/projects/<project>/<session-id>.jsonl`，`<project>` = 工作目录的非字母数字 → `-`；转换后 >200 字符 → 截到 200 + 路径哈希

**D-24b｜原生 transcript 实测落盘（真实运行，未登录失败路径）**

- 边界例子：**一个未登录、无模型回合的会话也占 46.8 KB 磁盘**——"落盘量 ≠ token 量"。→ claude-dist-04、claude-resume-01

**D-24c｜`--no-session-persistence` 实测**

- `skill_listing`：`skillCount=19`、`isInitial=true`
- `cost-state`：`totalCostUSD=0`、`modelUsage={}`（因未登录无模型回合）
- **与官方文档对照**：`environment`/`deferred_tools_delta`(MCP 延迟)/`skill_listing`(技能描述)/`instructions`(CLAUDE.md)/`date` 与 context-window 文档的启动加载清单**一一对应**；`prompt_snapshot.systemPrompt` 支持 claude-assembly-02（系统提示词记录一次）
- **不能证明**：`total_tokens_reminder`/`atis-latch`/`queue-operation` 语义（文档未命名，本包不猜测）；枚举是否完整（单次未登录样本）→ claude-dist-05

**D-25｜物理保留的两个证据**
- 【文档】旧 transcript 以 `.superseded-<timestamp>` / `.orphaned-<timestamp>-<suffix>` **搁置保留**，不删不覆盖
- 【文档】"Summarizing doesn't change files on disk, and the original messages stay in the session transcript"
- 边界（时间上限）：`cleanupPeriodDays` 默认 **30 天**；auto memory 目录**不**随清理删；Desktop/Cowork transcript 默认豁免
- 结论：**压缩（改请求历史）与物理保留（磁盘不动）并存不矛盾** → V-07

**D-26｜checkpoint 快照**
- 每个"开始轮次"的提示建一个 checkpoint；保留**最近 100 个**；每个文件的**第一个**快照保留（VS Code 基线）
- 边界例子：120 个 checkpoint 的会话 → 最早 20 个被丢；回溯到已丢 checkpoint → `No files were restored`【文档】
- 不跟踪：Bash 命令改动、通常不跟踪子代理编辑、符号/硬链接

**D-27｜关闭落盘**
- `--no-session-persistence`（仅 `claude -p`）/ `CLAUDE_CODE_SKIP_PROMPT_HISTORY`（所有模式）→ 不写 transcript、不能 resume【文档+帮助文本】

## §6 「同一份数据在四个对象里的位置」（对齐 T02 数据地图四对象）

| 走查 | 保存的记录（磁盘） | 当前选中的材料（内存消息列表） | 实际请求 | 外部记忆 |
|---|---|---|---|---|
| D-03 Bash 大输出 | 全量文件（≤64 MiB，`tool-results/` 或 session 目录） | 预览 + 路径 | 预览 + 路径 | — |
| D-13 压缩 | transcript **不动** | 被替换为摘要 + 重载项 | 摘要 + 重载项 | CLAUDE.md / auto memory 从磁盘重注入 |
| D-19 AUTO MEMORY | `memory/MEMORY.md` 全文 | 前 200 行/25 KB | 同上 | 主题文件按需读 |
| D-21 技能 | `SKILL.md` | 描述（≤1,536 字符）；正文仅调用后 | 描述 + 已调用正文 | — |
| D-26 checkpoint | `file-history/<session>/` 快照 | 不直接进请求 | 不直接进请求 | — |
| D-16 缓存 | — | — | 服务端前缀复用（不改文本） | — |

> **一句话**：**"存着"（磁盘）与"进请求"（当前材料经组装）永远不是一回事**——对应 T02 两条红线。
