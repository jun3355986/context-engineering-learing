# Claude Code CLI · 工具概览

> **这份文件解决什么**：一页讲清 Claude Code CLI 的身份、版本、语言、闭源边界、能力覆盖与适用范围，让后续课程（T15/T16）与比较（T14）有一个可引用、可定位、带证据等级的入口。
>
> **闭源纪律（贯穿本包全部文件）**：Claude Code 的**实现是闭源原生二进制**（本机 `~/.local/share/claude/versions/2.1.296`，约 248 MB）。本包**不读实现源码、不反编译、不做字符串推测、不补造源码**。可核验的只有两类：①**官方文档承诺的行为**（一级证据）；②**官方分发包与本地 CLI 的可观测项**（二级证据：版本、包结构、帮助文本、配置文件、运行行为）。社区还原/反混淆目录一律**只作线索**（三级）。

### 1.1 分发包性质（二级证据：分发件观察）

对冻结的 `2.1.299` tarball 做非侵入观察（`tar -tzvf` + 解包到 `workbuddy-sources/claude-code-cli/pkg/`，未改动既有登记）：

- 包内 **7 个文件**：`cli-wrapper.cjs`、`install.cjs`、`bin/claude.exe`、`package.json`、`LICENSE.md`、`README.md`、`sdk-tools.d.ts`。包体 29,068 bytes。
- `package.json` 声明：`"version": "2.1.299"`、`"bin": {"claude": "bin/claude.exe"}`、`"postinstall": "node install.cjs"`、`"engines": {"node": ">=22.0.0"}`、`dependencies: {}`，以及 8 个平台原生包 `optionalDependencies`（darwin-arm64 / darwin-x64 / linux-x64 / linux-arm64 / linux-x64-musl / linux-arm64-musl / win32-x64 / win32-arm64，均锁 `2.1.299`）。
- `bin/claude.exe` **不是可执行文件**，是一段 shell 占位脚本（打印 "claude native binary not installed" 并 `exit 1`）；`install.cjs` 在 postinstall 时把平台原生二进制**硬链接/复制**覆盖到 `bin/claude.exe`。
- **结论**：npm 包是**安装包装层**；真正实现为 `@anthropic-ai/claude-code-<platform>@2.1.299` 原生二进制（darwin-arm64 解包 247,932,273 bytes，本包**未落地**，仅登记 integrity）。

> **不能证明什么**：包装层代码结构**不能**外推到内核实现。`cli-wrapper.cjs` 里的平台探测与 `PLATFORMS` 映射只是安装器逻辑，与上下文管理机制无关；不得据此推断内核行为。

## 3. 适用范围与边界

- **平台**：本包证据来自 macOS（darwin-arm64）+ npm 分发包 + 官方英文文档。Windows/Linux 行为未单独核验。
- **模型**：官方文档中的默认阈值**依模型类别不同**（Sonnet 4.6/Opus 4.6 无扩展上下文 = 200K 边界；原生 1M 模型 ≈ 967K）。本包所有数字均标注适用模型/版本条件；**不把某个模型的默认值外推为"Claude Code 的默认值"**。
- **订阅/provider**：缓存 TTL、1M 上下文可用性依赖 Claude 订阅或 API key 与云服务商；对 Bedrock/Google Agent Platform/Foundry/gateway 的差异有部分文档说明（claude-cache-02）。
- **不可观测边界（总表见 `证据导读.md` §4 与 `问题与审查.md` §4）**：内核常量名与公式（如旧报告 `effectiveWindow − 13_000`）、服务端摘要真实内容与保真度、缓存命中在服务端的具体实现、auto memory "后台抽取"是否真有一次独立小请求——**均不可观测**，如实标注。

## 4. 与课程/比较的接口

- **机制名**：全部使用 `03-课程/T02/问题地图.md §E` 的统一术语（触发线/范围线/整段线、替代历史、长期记忆、退出归档等），本包不另起名字。
- **数据地图四对象**：本包 `数据走查.md` 按"保存的记录 / 当前选中的材料 / 实际请求 / 外部记忆"四对象标注每次对照落在哪一层。
- **结论ID 命名**：`claude-<机制>-<序号>`，形如 `claude-trigger-02`、`claude-toolout-01`；冲突裁决 ID 沿用 `C-xx`/`LQ-xx`。
