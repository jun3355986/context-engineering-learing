## 3. 能力覆盖（一句话版；逐项判定见 `问题与审查.md` §1 十二机制表）

- **请求组装与角色**：主循环 `runLoop` 每步先 `MessageV2.filterCompactedEffect` 取"替代历史"，再拼 `system = [环境块, 指令块, MCP 指令, 技能清单]`，`messages = toModelMessages(msgs) (+ MAX_STEPS_PROMPT)`；`LLMRequestPrep.prepare` 把 `agent.prompt|SystemPrompt.provider(model)` + `system` + `user.system` 合成一条 system，并在最前插入（`ocv1-assembly-01/02`）。
- **项目规则 / 技能**：规则文件 `AGENTS.md`（+ `CLAUDE.md`、废弃 `CONTEXT.md`）——全局取首个命中、项目层 `findUp` 首个命中、`config.instructions` 可加文件与 **URL**；读取时沿目录向上附"就近规则"（每消息一次）。技能走**渐进式披露**：`skills/**/SKILL.md` 发现、系统提示词只放 `name/description/location`，正文经 `skill` 工具按需读（`ocv1-rule-01`、`ocv1-skill-01`）。
- **资料选择与代码检索**：`read/grep/glob/list` 按需检索；`read` 分页 `offset/limit`（默认 2000 行、单行 2000 字符、50 KiB 上限），并在结果里追加 `<system-reminder>` 就近规则（`ocv1-retrieval-01`）。
- **单条工具输出治理**：统一入口 `Truncate.output`——**2000 行 / 51200 字节先到者**、`head`/`tail` 分流；**超限原文落盘**到截断目录（文件名 `tool_*`，**保留 7 天**）并返回预览 + 提示（`ocv1-trunc-01`）；压缩序列化时对工具结果再按 **2000 字符**限长（`ocv1-trunc-02`）。
- **窗口计量与触发**：`usable = limit.input − reserved`，`reserved = cfg.compaction.reserved ?? min(20000, maxOutputTokens)`；`isOverflow = (total || input+output+cache.read+cache.write) ≥ usable`，且 `compaction.auto===false` 直接不触发（`ocv1-trigger-01/02`）。
- **自动 / 手动压缩**：自动——主循环在"上一轮已结束且 `isOverflow`"时 `compaction.create({auto:true})`，处理器在 `step-finish` 溢出或收到 `ContextOverflowError` 时置 `needsCompaction`；手动——用户命令 **`/compact`**（TUI 斜杠 / ACP）映射到 HTTP `session.summarize`，以 `auto:false` 建压缩条目再 `loop`（`ocv1-compact-01/02`）。
- **摘要 / 裁剪 / 重建**：压缩取"尾部若干 turn"到**保留预算**（`preserve_recent_tokens ?? min(15000, max(2000, floor(usable×0.25)))`，可 `tail_turns` 限制）；旧摘要经 `<prior-summary>` **增量合并**（有损，模型侧）；摘要后**先跑 `prune` 擦旧工具输出**（保护最近 40000 token、最小节省 20000 token、`skill` 工具不擦）；重建由 `filterCompacted` 把"压缩条目 + 摘要 + `tail_start_id` 保留段 + 后续"重排（`ocv1-summary-01..04`）。
- **长期记忆**：**未发现默认实现（推断）**——v1 出货路径无 memory 模块；`grep` 全仓 `packages/opencode/src`、`packages/core/src/v1` 零命中（`ocv1-memory-01`）。
- **子 Agent 交接**：**支持**——`task` 工具为子 agent 建**独立子会话**（自带 systemPrompt），结果以 `<task_result>` 文本回父；`subagent_depth` 默认 **1**（禁嵌套）；可选后台子代理（`OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`）（`ocv1-cm09-01`）。
- **保存 / fork / 恢复**：会话消息/部件持久化到 **SQLite（事件溯源 + 投影）**；恢复由 `--continue` / `--session <id>` 载入并按 `filterCompacted` 重建模型可见历史；`--fork` / `session.fork` 复制到新会话（含 `tail_start_id` 重映射）（`ocv1-persist-01`、`ocv1-recover-01`）。
- **错误与副作用**：重试 `RETRY_MAX_RETRIES=5`、退避 2000ms×2ⁿ（抖动 0.25、无头上限 30s）；`ContextOverflowError` **不重试**、转压缩；`DOOM_LOOP_THRESHOLD=3` 触发 `doom_loop` 询问；中断/中止的工具标 `interrupted` 清理（`ocv1-fail-01/02`）。
- **缓存及总成本**：CLI 侧可证——`applyCaching` 给"前 2 条 system + 后 2 条**非 system** 消息"打 provider 级 ephemeral 缓存标记，OpenAI 兼容系 `prompt_cache_key = sessionID`，请求头带 `x-session-affinity`/`X-Session-Id`；**服务端命中率/TTL = `UNOBSERVABLE`**（`ocv1-cache-01`）。

## 4. "默认" vs "开配置/装插件以后"（分列）

> 扩展点：插件 `Hooks`（`packages/plugin/src/index.ts` §Hooks）+ `opencode.json` 配置。**默认分发（未改配置、未装插件）不含下列"条件/实验"态行为。**

| 维度 | 默认（v1 本体） | 条件/配置/插件态能改什么 | 证据 |
|---|---|---|---|
| 自动压缩 | `compaction.auto = true`（默认开） | 设 `false` 后溢出不再自动压缩（转报错/手动） | `ocv1-compact-01`、`ocv1-trigger-02` |
| 工具输出裁剪 | `tool_output.max_lines=2000` / `max_bytes=51200` | `tool_output` 可改两上限 | `ocv1-trunc-01` |
| 旧工具输出擦除 | `compaction.prune = false`（默认关） | 设 `true` 后启用 `prune`（擦旧工具输出） | `ocv1-summary-03` |
| 保留预算/尾 turn | `preserve_recent_tokens` 未设→按 `usable×0.25` 夹 `[2000,15000]`；`tail_turns` 未设→不限 | 可显式设 `preserve_recent_tokens` / `tail_turns` / `reserved` | `ocv1-summary-02`、`ocv1-trigger-01` |
| 压缩提示词 | 内置 `SUMMARY_TEMPLATE` + `compaction` agent 提示词 | 插件 `experimental.session.compacting` 可注入 context / **整体替换 prompt** | `ocv1-summary-01`、`ocv1-ext-01` |
| 自动续跑 | 压缩成功后追加合成"continue"用户消息（`enabled=true`） | 插件 `experimental.compaction.autocontinue` 置 `enabled=false` 可跳过 | `ocv1-compact-01`、`ocv1-ext-01` |
| 请求消息 | 投影消息 + 系统块 + 工具声明 | 插件 `experimental.chat.messages.transform` / `experimental.chat.system.transform` 可改写 | `ocv1-assembly-01/02`、`ocv1-ext-01` |
| 子 Agent | 内置 `task` 工具（默认可用），深度上限 1 | `subagent_depth` 可增；后台子代理需实验开关 | `ocv1-cm09-01` |
| 长期记忆 | **无**（推断） | 未见 v1 内置记忆开关 | `ocv1-memory-01` |
| 原生 LLM 运行时 | AI SDK 路径（默认） | `experimentalNativeLlm` 开 → 尝试 `@opencode-ai/llm` 原生适配 | `ocv1-assembly-01` |

**一句话边界**：v1 的"默认"是**中等内核**——含子代理、自动压缩、插件钩子；**不含长期记忆**；`prune`、`tail_turns`、`reserved` 等为**配置态**，报告必须分列。
