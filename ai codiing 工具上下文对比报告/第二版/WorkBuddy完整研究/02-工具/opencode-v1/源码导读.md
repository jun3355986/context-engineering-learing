# OpenCode v1 · 源码导读

> 本文件解决什么问题：把 v1 出货路径（`packages/opencode/src/session/*`）的**代表主链路**走完"**调用者 → 条件 → 处理 → 状态写回 → 下一次请求/恢复**"，并给**失败分支**；核心片段配**中文解读**。
> **引用纪律**：行号一律对快照 `733b2c6`；链接基址 `https://github.com/anomalyco/opencode/blob/733b2c627e5aec39cb33cc22373bdce33053ef2c/`。
> **v1/v2 分界**：本文件**只**读 `packages/opencode/src/*`（v1）与 `packages/core/src/v1/*`（v1 命名空间）。`packages/core/src/session/*` 为**混合目录**：带 `@opencode/v2/*` 标签部分**只在** §0.3 作为边界声明出现；**无标签且被 v1 实际使用**的文件（如 `compaction.ts` 的 `buildPrompt`，见 §4）正常引用并标注定义位置。

## 0. 阅读地图

### 0.1 一次任务的主骨架（v1）

```text
用户输入
  └─ SessionPrompt.prompt()                       # prompt.ts:1052-1071
       └─ createUserMessage()                      # 落盘用户消息/部件（prompt.ts:635-1050）
       └─ SessionPrompt.loop()                     # run-state 串行化（prompt.ts:1343-1347）
            └─ runLoop()  while(true)              # ★主循环（prompt.ts:1081-1341）
                 ├─ MessageV2.filterCompactedEffect()   # 取"替代历史"（message-v2.ts:534-589）
                 ├─ 溢出判定 → compaction.create(auto)  # prompt.ts:1161-1168
                 ├─ 压缩任务 → compaction.process()     # prompt.ts:1149-1159
                 ├─ SessionReminders.apply()            # 轮前注入（reminders.ts:15-90）
                 ├─ 组装 system + toModelMessages()     # prompt.ts:1257-1269
                 └─ processor.process() → llm.stream()  # processor.ts:641-697 / llm.ts:85-355
                      └─ step-finish: 记 tokens + 溢出判定（processor.ts:435-498）
```

### 0.3 v1/v2 边界声明（一句话）

`packages/core/src/session/runner/index.ts` 与 `packages/core/src/session.ts` 的服务标签是 **`@opencode/v2/*`**；`packages/opencode` 全包**零引用**该 runner。故 **v1 出货路径 = `packages/opencode/src/session/*`**；`packages/core/src/session/*` 属 v2，**本文件不引用其行为**。`packages/opencode/src/session/session.ts:13-14` 对 `SessionV2`/`SessionExecutionLocal` 的导入**全文件未使用**（死导入），不得据此推断 v1 使用 v2 代码。

## 1. 主链路 A · 请求组装与角色（CM-01）

### 1.1 调用者与入口

`runLoop`（`prompt.ts:1081`）在每步：

```ts
// prompt.ts:1092
let msgs = yield* MessageV2.filterCompactedEffect(sessionID)   // ① 取"替代历史"
...
// prompt.ts:1180
msgs = yield* SessionReminders.apply({ messages: msgs, agent, session })  // ② 轮前提醒
...
// prompt.ts:1255-1269
yield* plugin.trigger("experimental.chat.messages.transform", {}, { messages: msgs })  // ③ 插件可改写
const [skills, env, instructions, mcpInstructions, modelMsgs] = yield* Effect.all([
  sys.skills(agent), sys.environment(model), instruction.system(), sys.mcp(agent, session.permission),
  MessageV2.toModelMessagesEffect(msgs, model),
])
const system = [...env, ...instructions, ...(mcpInstructions ? [mcpInstructions] : []), ...(skills ? [skills] : [])]
```

**中文解读**：每步先把**磁盘上的全部消息**投影成"模型这次该看到的列表"（`filterCompacted`，见 §4）；再注入"计划/构建模式提醒"；再让插件有机会改消息；最后把**四类系统块**（环境 / 规则指令 / MCP 指令 / 技能清单）按固定顺序拼成 `system` 数组，并把消息转成 AI SDK 的 `ModelMessage[]`。

### 1.2 system 的最终合成（`LLMRequestPrep.prepare`）

```ts
// session/llm/request.ts:58-66
const system = [
  [ ...(input.agent.prompt ? [input.agent.prompt] : SystemPrompt.provider(input.model)),
    ...input.system,
    ...(input.user.system ? [input.user.system] : []) ].filter(Boolean).join("\n"),
]
```

- `agent.prompt`：内置 agent 专属提示词（如 `explore`→`PROMPT_EXPLORE`）；无则用 `SystemPrompt.provider(model)` 按模型挑提示词（`system.ts:28-51`：gpt→`PROMPT_GPT`、claude→`PROMPT_ANTHROPIC`、gemini→`PROMPT_GEMINI`…）。
- `input.system`：即 §1.1 的 env+instructions+mcp+skills。
- `input.user.system`：单条用户消息可带的额外 system。
- 组装后由 `messages = [...system.map(x => ({role:"system",content:x})), ...input.messages]`（`request.ts:101-112`）——**system 作为最前的 system 消息**；若 provider 是 OpenAI OAuth 或 workflow，则改用 `instructions`/原生 `systemPrompt`。

### 1.3 工具与角色

- 工具集由 `resolveTools`（`request.ts:210-216`）按权限与 `user.tools` 过滤后**按名排序**。
- 角色：`user` / `assistant` / `tool`（AI SDK 的 `tool-<name>` 部件）/ `system`；`toModelMessagesEffect`（`message-v2.ts:131-428`）负责映射，并处理**配对不变量**——把 `pending/running` 的工具补成 `output-error`（`errorText:"[Tool execution was interrupted]"`，`message-v2.ts:364-373`），避免 Anthropic 因悬空 `tool_use` 报错。

### 1.4 写回与下一次请求

组装结果经 `processor.process()`（`processor.ts:641`）交给 `llm.stream()`；模型流事件写回**消息部件**（文本/推理/工具/`step-finish`），下一次循环**重新**从磁盘投影，故**每次请求都是重算**。

**失败分支**：`filterCompactedEffect` 找不到会话 → `stream()` 逐页读，空则返回空列表（不抛）；`toModelMessages` 中带 `error` 的 assistant（非中止型）**整条跳过**（`message-v2.ts:258-266`）。

## 2. 主链路 B · 工具输出治理（CM-04）

### 2.1 调用者与条件

工具执行完成后，调用方（各工具如 `read`/`bash`/`grep`）把原始文本交给 `Truncate.output(text, options?, agent?)`（`tool/truncate.ts:85`）。

```ts
// tool/truncate.ts:14-15
export const MAX_LINES = 2000
export const MAX_BYTES = 50 * 1024          // = 51200 字节
// tool/truncate.ts:93-95
if (lines.length <= maxLines && totalBytes <= maxBytes) return { content: text, truncated: false }
```

### 2.2 处理顺序（head 分支）

```ts
// tool/truncate.ts:102-122（摘要）
for (i = 0; i < lines.length && i < maxLines; i++) {
  const size = Buffer.byteLength(lines[i], "utf-8") + (i > 0 ? 1 : 0)
  if (bytes + size > maxBytes) { hitBytes = true; break }   // 先到者：行数或字节
  out.push(lines[i]); bytes += size
}
```

- **先到者**：行数达 `maxLines` **或** 字节达 `maxBytes` 即停；`removed`/`unit` 随之在 `bytes`/`lines` 间切换（`truncate.ts:124-125`）。
- `direction`：默认 `head`（保头），`tail` 保尾（`bash` 等用）。
- **多字节安全**：按**整行**累加字节，不会切断半个 UTF-8 字符。

### 2.3 落盘与写回

```ts
// tool/truncate.ts:127-140
const file = yield* write(text)     // 原文写入截断目录，文件名 ToolID.ascending()
const hint = hasTaskTool(agent)
  ? `... Full output saved to: ${file}\nUse the Task tool to have explore agent process this file ...`
  : `... Full output saved to: ${file}\nUse Grep to search the full content or Read with offset/limit ...`
return { content: `${preview}\n\n...${removed} ${unit} truncated...\n\n${hint}`, truncated: true, outputPath: file }
```

- **写回**：返回 `content`（预览 + 截断标记 + 提示）进入消息列表；`outputPath` 供 UI/后续工具取回。
- **保留期**：截断目录条目保留 **7 天**（`RETENTION = Duration.days(7)`，`truncate.ts:12`），后台每小时清理一次（`truncate.ts:143-148`）。
- **配置覆盖**：`tool_output.max_lines` / `max_bytes`（`v1/config/config.ts:136-148`）。

### 2.4 压缩期再限长（第二道）

压缩序列化时对工具结果**再按 2000 字符**限长：`TOOL_OUTPUT_MAX_CHARS = 2_000`（`compaction.ts:30`），`truncate()` 追加 `\n[truncated]`（`compaction.ts:51-52`）；已被 `prune` 擦除的结果显示 `[Old tool result content cleared]`（`compaction.ts:76-78`）。

**失败分支**：`write` 失败走 `Effect.orDie`（进程级失败）；截断目录不可读时 `cleanup` 用 `catch(() => [])` 静默（`truncate.ts:55-57`）。

## 3. 主链路 C · 窗口计量、触发与自动压缩（CM-05 / CM-06）

### 3.1 有效窗口（`overflow.ts`）

```ts
// session/overflow.ts:8-20
const COMPACTION_BUFFER = 20_000
export function usable({cfg, model, outputTokenMax}) {
  const context = model.limit.context
  if (context === 0) return 0
  const reserved = cfg.compaction?.reserved
    ?? Math.min(COMPACTION_BUFFER, ProviderTransform.maxOutputTokens(model, outputTokenMax))
  return model.limit.input
    ? Math.max(0, model.limit.input - reserved)     // 有 input 上限：用 input − 预留
    : Math.max(0, context - ProviderTransform.maxOutputTokens(model, outputTokenMax))  // 否则：context − 输出上限
}
```

### 3.2 溢出判定（`overflow.ts`）

```ts
// session/overflow.ts:22-34
export function isOverflow({cfg, tokens, model, outputTokenMax}) {
  if (cfg.compaction?.auto === false) return false          // 手动关 → 永不自动触发
  if (model.limit.context === 0) return false
  const count = tokens.total || tokens.input + tokens.output + tokens.cache.read + tokens.cache.write
  return count >= usable({cfg, model, outputTokenMax})
}
```

**中文解读**：`count` 优先用服务端返回的 `total`，缺失则**四项相加**（input+output+cache.read+cache.write）；`≥ usable` 即"到线"。注意 `usable` 是**整段线**（全部材料不得超过），v1 **没有** Codex 式"范围线 / 整段线"两线结构——这是 v1 与 Codex 的**机制差异**（不按数量比成熟度）。

### 3.3 自动压缩触发（两处入口）

1. **主循环轮后**（`prompt.ts:1161-1168`）：上一轮 `lastFinished.summary!==true` 且 `isOverflow` 为真 → `compaction.create({auto:true})` → 下一轮 `runLoop` 走压缩任务分支（`prompt.ts:1149-1159`）。
2. **处理器 `step-finish`**（`processor.ts:491-496`）：非摘要轮且 `isOverflow` → `ctx.needsCompaction=true` → `process()` 返回 `"compact"`（`processor.ts:693`）→ 主循环 `compaction.create({auto:true, overflow:!finish})`（`prompt.ts:1320-1328`）。

### 3.4 手动压缩（CM-06）

用户命令 **`/compact`**（TUI 斜杠命令 `app/src/pages/session/use-session-commands.tsx:482`；官方文档 `web/src/content/docs/tui.mdx:93`；ACP `acp/service.ts:570-574` `command.name==="compact"`）映射到 HTTP **`POST /api/session/:sessionID/summarize`**（`groups/session.ts:94,303`）。处理（`handlers/session.ts:273-293`）：

```ts
yield* compactSvc.create({ sessionID, agent: currentAgent, model, auto: ctx.payload.auto ?? false })
yield* promptSvc.loop({ sessionID })
```

即**同一套** `compaction.process`，仅 `auto=false` 且不经 `isOverflow`。路由描述："Generate a concise summary of the session using AI compaction…"（`groups/session.ts:313`）。> **注**：`packages/protocol` 另有 `v2.session.compact`（`/api/session/:sessionID/compact`），属 **v2 协议**，**不计入 v1**。

**失败分支**：`compaction.auto===false` 且 `!summary` 时收到 `ContextOverflowError` → 处理器直接报错并置 idle（`processor.ts:621-628`），**不自动压缩**。

## 4. 主链路 D · 摘要 / 裁剪 / 重建（CM-07）

### 4.1 选尾（`select`）

```ts
// session/compaction.ts:115-120
function preserveRecentBudget({cfg, model}) {
  return cfg.compaction?.preserve_recent_tokens
    ?? Math.min(MAX_PRESERVE_RECENT_TOKENS, Math.max(MIN_PRESERVE_RECENT_TOKENS, Math.floor(usable({cfg,model}) * 0.25)))
}   // MIN=2000, MAX=15000（compaction.ts:32-33）
```

`select`（`compaction.ts:223-269`）从**最新 turn 往回**累加估算 token，直到 `budget` 用完；不足一个整 turn 时用 `splitTurn`（`compaction.ts:140-163`）在 turn 内部找切点；`tail_turns` 可限制候选 turn 数。切点**只落在 turn 的 message 边界**（`turns()` 只以 user 消息为界，`compaction.ts:122-138`）。

### 4.2 摘要提示词（增量）

```ts
// session/compaction.ts:381-391
const nextPrompt = compacting.prompt ?? [
  buildPrompt({ previousSummary, context: [conversation] }),
  ...compacting.context,
].filter(Boolean).join("\n\n")
```

`buildPrompt`（`packages/core/src/session/compaction.ts:160-174`，**v1 引用的共享函数**）：

```ts
export const buildPrompt = ({ previousSummary, context }) => {
  const conversation = `Here is the conversation so far:\n\n<conversation>\n${context.join("\n\n")}\n</conversation>`
  if (!previousSummary) return [conversation, "Create a new anchored summary ...", SUMMARY_TEMPLATE].join("\n\n")
  return [conversation, `...<prior-summary>\n${previousSummary}\n</prior-summary>`,
          SUMMARY_UPDATE_INSTRUCTIONS, SUMMARY_TEMPLATE].join("\n\n")
}
```

- `SUMMARY_TEMPLATE`（`core/.../compaction.ts:16-46`）：固定章节 `Objective / Important Details / Work State(Completed/Active/Blocked) / Next Move / Relevant Files`，要求"保留精确路径/命令/错误串，不要提压缩过程"。
- `SUMMARY_UPDATE_INSTRUCTIONS`（`:47-55`）：**增量合并规则**——"prior-summary 之后被丢弃，没带过来的就丢了；冲突时以 conversation 为准"。→ **有损**（模型侧）。

### 4.3 压缩前裁剪（`prune`，默认关）

```ts
// session/compaction.ts:28-31
export const PRUNE_MINIMUM = 20_000
export const PRUNE_PROTECT = 40_000
const PRUNE_PROTECTED_TOOLS = ["skill"]
// session/compaction.ts:273-317（摘要）
if (!cfg.compaction?.prune) return
loop: for (msgIndex 从后往前) {
  if (user) turns++
  if (turns < 2) continue
  if (assistant && summary) break loop
  for (part 从后往前) {
    if (part.tool 在 PRUNE_PROTECTED_TOOLS) continue
    if (part.state.time.compacted) break loop
    total += estimate(output); if (total <= PRUNE_PROTECT) continue
    pruned += estimate(output); toPrune.push(part)
  }
}
if (pruned > PRUNE_MINIMUM) { 把 toPrune 的 part.state.time.compacted = Date.now(); 写回 }
```

**中文解读**：从最新往回数，**保留最近 40000 token 的工具输出不动**；超过部分累计，若可擦总量 **> 20000 token** 才真正擦（否则不划算）；被擦的部件只打 `time.compacted` 时间戳，**原文仍在库里**（只是不再进请求）。`skill` 工具输出受保护。

### 4.4 重建 / 替代历史（`filterCompacted`）

```ts
// message-v2.ts:534-585（要点）
// ① 从后往前扫，找到"已完成压缩"的用户消息（带 compaction 部件）
// ② 用 part.tail_start_id 记保留起点；把 [压缩条目, 摘要, 保留段, 后续] 重排
if (tailIndex >= 0 && tailIndex < compactionIndex && summaryIndex > compactionIndex) {
  return [...result.slice(compactionIndex, summaryIndex + 1),
          ...result.slice(tailIndex, compactionIndex),
          ...result.slice(summaryIndex + 1)]
}
```

**中文解读**：磁盘上**从未删除**原始消息；模型可见层由"压缩用户消息（`type:"compaction"`）+ 摘要 assistant 消息（`summary:true`）+ `tail_start_id` 起的保留段 + 后续消息"重新拼成。压缩用户消息在转换时会变成文本 `"What did we do so far?"`（`message-v2.ts:238-243`）。→ **两事实并存**：磁盘保留原文 + 模型只见替代历史。

**失败分支**：压缩失败/超限 → 处理器写 `ContextOverflowError` 并 `return "stop"`（`compaction.ts:450-459`）。

## 5. 主链路 E · 保存 / fork / 恢复（CM-10）

### 5.1 持久化

- 会话消息/部件通过**事件**（`SessionV1.Event.MessageUpdated/PartUpdated`，`session.ts:629-643`）进入 EventV2 存储，再由投影器落 **SQLite**（`packages/core/src/session/projector.ts` 定义行结构；`MessageTable`/`PartTable`）。
- 读取：`MessageV2.page`（`message-v2.ts:438-480`）按 `time_created` 倒序分页，`stream()` 逐页取回再正序（`message-v2.ts:482-503`）。
- 旧版 JSON 文件存储（`storage/storage.ts`）保留**仅为迁移**（`MIGRATIONS`，`storage.ts:81-211`）。

### 5.2 fork

`Session.fork`（`session.ts:691-732`）：新建会话，逐条复制消息并**重映射 ID**，其中 `compaction` 部件的 `tail_start_id` **一并重映射**（`session.ts:725-727`）。

### 5.3 恢复

CLI `opencode run --continue` / `--session <id>`（`cli/cmd/run.ts:147-158`）载入既有会话；`runLoop` 首步 `filterCompactedEffect` 即"**持久化断点路线**"——**不重放全部历史重算压缩**，而是直接用存档的 `compaction` 条目 + `tail_start_id` 重建（§4.4）。`--fork` 先 fork 再续（`run.ts:157-158`）。

**失败分支**：会话不存在 → `NotFoundError`；分页读空 → 返回空列表。

## 6. 主链路 F · 错误与副作用（CM-11）

### 6.1 重试（`retry.ts`）

```ts
// session/retry.ts:26-31
export const RETRY_INITIAL_DELAY = 2000
export const RETRY_BACKOFF_FACTOR = 2
export const RETRY_JITTER_FACTOR = 0.25
export const RETRY_MAX_DELAY_NO_HEADERS = 30_000
export const RETRY_MAX_RETRIES = 5
```

- `retryable`（`retry.ts:85-155`）：`ContextOverflowError` **不重试**；`APIError` 5xx / 命中可重试消息模式才重试；`retry-after`/`retry-after-ms` 头优先。
- `policy`（`retry.ts:183-207`）：`attempt > RETRY_MAX_RETRIES` 即停；退避 = `2000×2^(n-1)×(1+0.25·rand)`。

### 6.2 失败分类与副作用

- `step-finish` 溢出 → `needsCompaction`（§3.3）；`ContextOverflowError` → 压缩或报错（§3.4）。
- `halt`（`processor.ts:613-639`）：记录错误、发 `Session.Event.Error`、置 idle；非溢出错误直接落 `assistant.error`。
- `doom_loop`（`processor.ts:29,356-380`）：连续 **3** 次相同工具+相同输入的调用 → 触发 `doom_loop` 权限询问（默认 `ask`）。
- **中断清理**（`processor.ts:553-611`）：未结算的工具标 `status:"error"`、`metadata.interrupted=true`，并把 `time.completed` 落盘。
- **副作用**：压缩/工具执行**已写盘的动作不回退**（如已 `edit` 的文件）；`revert` 机制（`session/revert.ts`）单独处理文件回滚，与压缩失败无关。
