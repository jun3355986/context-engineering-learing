## 1. 主链路 A：一次模型请求怎么被拼出来 / 恢复时怎么重建

**调用者**：`SessionManager.buildSessionContext()`（`session-manager.ts#L3749-3755`）→ 委托 `buildSessionContext(entries, leafId, byId, options)`（`session-context.ts#L238`）。

**条件**：每次要发模型请求、恢复会话、`/shake`、reload、丢图重建时都走这里。

**处理顺序**（`session-context.ts#L281-644`）【源码】：

1. **从 leaf 向 root 回溯**，按 `parentId` 收集路径 `path`（遇重复 id 即停，防环）（`#L281-291`）。
2. 沿路径扫描设置类条目：`thinking_level_change` / `model_change` / `service_tier_change` / `ttsr_injection` / `mode_change`，并记下**最新一条 `compaction`**（`#L311-346`）。
3. 定位最新 `/clear` 的 `reset_boundary` 下标（`#L354`）。
4. 三分支发射：
   - **transcript 模式**（`options.transcript && !collapseCompactedHistory`）：按时间序**每条都在**，压缩只作为内联分隔条（`#L422-462`）。
   - **有 reset 边界且晚于最新压缩**：只发射 reset 之后的条目（`#L463-482`）。
   - **有压缩**（模型上下文主路径，`#L483-638`）：
     - 取 provider 原生载荷（`getOpenAiRemoteCompactionPayload` / `getAnthropicCompactionPayload`）；
     - **先 push 摘要消息**（`createCompactionSummaryMessage`，携带 `providerPayload` / snapcompact blocks / `historyRewriteAt`）（`#L526-545`）；
     - 再发射**保留段**：从 `firstKeptEntryId` 到压缩点（`#L576-614`）；
     - 再发射**压缩后消息**（`#L634-638`）。
   - **无压缩**：发射全部路径消息（`#L639-644`）。
5. **上下文笔记**（实验性）：`getContextNotes`/`renderContextNotes` 渲染后插入（Anthropic 原生压缩块后）（`#L646-671`）。
6. **剥离悬挂 tool_use**：assistant 轮里没有配对 `toolResult` 的 `toolCall` 块被剔除，并中和其受保护推理签名（`#L673-734`）。
7. **丢弃失败/中止的 assistant 轮**：`stopReason` 为 `aborted`/`error` 的 assistant 及其配对的合成 toolResult 一并移除（`#L744-769`）。

**写回/下一次请求**：结果 `SessionContext.messages` 被 `agent.replaceMessages(...)` 采用；压缩后每次重建都**从摘要 + `firstKeptEntryId`** 起，不重放被压掉的前缀。

**教学伪代码（非正式代码）**：
```text
path = walk_leaf_to_root(leafId)                 # 成树回溯
latest_compaction = last(path where type==compaction)
if latest_compaction:
    emit(summary_message(latest_compaction))     # 摘要在前
    emit(kept entries from firstKeptEntryId .. compaction)  # 保留段
    emit(entries after compaction)               # 之后
else:
    emit(all path messages)
strip_dangling_tool_calls(messages)
drop_error_or_aborted_assistant_turns(messages)
```

## 2. 主链路 B：自动压缩"触发 → 准备 → 方法链 → 提交"

**调用者**：`SessionMaintenance`（`session-maintenance.ts`）在六条路径上调用；核心判定函数是引擎侧纯函数。

### 2.1 触发判定【源码】

```ts
// packages/agent/src/compaction/compaction.ts
export function shouldCompact(contextTokens, contextWindow, settings) {   // #L350-354
  if (!settings.enabled || settings.strategy === "off" || contextWindow <= 0) return false;
  const thresholdTokens = resolveThresholdTokens(contextWindow, settings);
  return contextTokens > thresholdTokens;
}
export function resolveThresholdTokens(contextWindow, settings) {          // #L384-414
  // thresholdTokens>0 优先（固定点，≥window 时退化为 promptBudget）
  // 否则 thresholdPercent>0 → floor(window × clamp(pct,1,99)/100)
  // 否则（默认 -1/-1）→ promptBudgetTokens = window - resolveBudgetReserveTokens(...)
}
export function effectiveReserveTokens(contextWindow, settings) {         // #L320-322
  return Math.max(Math.floor(contextWindow * 0.15), settings.reserveTokens ?? DEFAULT_RESERVE_TOKENS);
}
```
- `DEFAULT_RESERVE_TOKENS = 16384`（`#L199`）；`MAX_SUMMARY_TOKENS = 16384`（`#L211`）。
- 默认设置 `thresholdPercent=-1`、`thresholdTokens=-1`、`reserveTokens=undefined`、`keepRecentTokens=20000`（`context-settings.ts#L275-285`、`compaction.ts#L216-227`）。

**用量口径**【源码】：`calculateContextTokens(usage)`（`compaction.ts#L257-267`）优先 `usage.contextTokens`，否则 `totalTokens` 或 `input+output+cacheRead+cacheWrite`，并**减去服务端编排 token** `usage.orchestration`；触发前再用本地存量估算**取大兜底** `compactionContextTokens(providerTokens, storedEstimate)`（`#L371-373`），在 `session-maintenance.ts#L2723-2726` 调用。

### 2.2 六条触发路径【文档+源码】

| # | 路径 | 入口 | 依据 |
|---|---|---|---|
| 1 | 手动 `/compact [指令]` | `AgentSession.compact(...)` | `docs/compaction.md#L72` |
| 2 | 溢出恢复 | 同模型 assistant 报错且判定为上下文溢出 | `docs/compaction.md#L73,117-122` |
| 3 | 输出未完成恢复 | `stopReason==="length"` | `docs/compaction.md#L74,124-131` |
| 4 | 轮后阈值 | 成功轮后 `contextTokens > resolveThresholdTokens` | `docs/compaction.md#L75,133-140` |
| 5 | 轮中阈值 | 下一次 provider 请求前的安全工具循环边界，`compaction.midTurnEnabled !== false` | `docs/compaction.md#L76`；`session-maintenance.ts#L2713-2805` |
| 6 | 空闲维护 | `runIdleCompaction()`（`idleEnabled` 默认 false） | `session-maintenance.ts#L2043`；`docs/compaction.md#L77` |

### 2.3 准备与切点【源码】

`prepareCompaction()`（引擎）→ `findCutPoint()`（`compaction.ts#L521-574`）：
- 合法切点 = `user / assistant / bashExecution / hookMessage / branchSummary / compactionSummary / custom_message / branch_summary`；**绝不切在 `toolResult`**（`findValidCutPoints` `#L427-462`）。
- 从最新往回按**整组**累加 token，累加超过 `keepRecentTokens` 即停，取最接近的合法切点；切到 assistant 时其 toolResult 跟随保留（`#L537-549`）。
- 若切点不在轮首 → `isSplitTurn=true`，生成"历史摘要 + 轮前缀摘要"再合并（`docs/compaction.md#L277-303`）。

### 2.4 方法链与提交【源码+文档】

`compaction.methodOrder` 默认 `["remote","snapcompact","handoff","shake","soft"]`（`compaction-methods.ts#L44-50`）；`remote` 不可用/失败则**逐级回退**。提交：`appendCompaction(...)` 追加一条 `CompactionEntry{summary, firstKeptEntryId, tokensBefore, ...}`（`session-manager.ts#L3530`；条目结构 `packages/agent/src/compaction/entries.ts#L34-54`），**不删除任何原始条目**。

**写回**（`docs/compaction.md#L384-390`）：追加 `CompactionEntry` → `buildDisplaySessionContext()` 重建 → 替换实时 agent 消息 → 同步 todo/关闭被改写历史的 provider 会话 → 发 `session_compact`。

## 3. 主链路 C：单条工具输出治理（限长 + 落盘）

**调用者**：各工具（`read`/`bash`/`grep`/`fetch`…）经 `OutputSink` / `truncateHead` / `truncateTail`（`packages/tui/src/tools/streaming-output.ts`）。

**条件与常量**【源码】（`streaming-output.ts#L10-26`）：
```ts
export const DEFAULT_MAX_LINES = 3000;         // 行上限
export const DEFAULT_MAX_BYTES = 50 * 1024;    // 字节上限（51200）
export const DEFAULT_MAX_COLUMN = 512;         // 单行字节上限
export const ARTIFACT_DEFAULT_MAX_BYTES = 16 * 1024 * 1024;  // 落盘 16 MiB
export const ARTIFACT_DEFAULT_HEAD_BYTES = 3 * 1024 * 1024;  // 落盘头 3 MiB
```

**处理顺序**（`truncateHead` `#L345-441`）【源码】：
1. 先算 `totalLines`/`totalBytes`；**两者都未到线 → 原样返回**（`noTruncResult`）。
2. 逐行累加，任一超限即停；**不返回半行**；首行就超字节上限时返回空内容 + `firstLineExceedsLimit=true`。
3. `truncateTail` 同理但保尾，且**可能返回半行**（尾部截断到字节）。

**落盘**【源码】：超限时原文写入 artifact 文件，上下文里只留预览 + `artifact://<id>`；artifact 有独立上限（16 MiB，头 3 MiB 保留 + 滚动尾），触顶写 `[ARTIFACT TRUNCATED: …]`（`streaming-output.ts#L74-116,961-966`；`tools/bash.ts#L1506-1507`（落盘分配 `allocateOutputArtifact`））。

**观察佐证**【观察】：`OBS-ohmy-trunc-01`（对已发布 `@oh-my-pi/pi-tui@18.10.4` 的 `truncateHead` 真实执行）——未到线原样、3500 行→保 3000 行、单行 60000 字节→`firstLineExceedsLimit`、CJK 截断保持合法 UTF-8 且 ≤51200 字节；退出码 0。

## 4. 失败分支总表（CM-11 素材）

| 场景 | 处理 | 是否有界 | 副作用是否可回退 | 依据 |
|---|---|---|---|---|
| 上下文溢出 | **不进**通用重试；先"升级更大模型"，否则走方法链压缩并重试 | 一次恢复 | 失败 assistant 从运行时上下文移除 | `docs/compaction.md#L117-122`；`docs/non-compaction-retry-policy.md#L24-28` |
| 输出未完成（`length`） | 阈值下且已产出 → 保留并告警；否则移除 + 升级/压缩；**连续无产出恢复上限 3 次** | 3 次 | 是（保留/移除可控） | `docs/compaction.md#L124-131` |
| 载荷被拒（413 等） | **不**自动当 token 溢出；有 ≥10% 余量则阻止自动续跑并告警 | 有界 | — | `docs/compaction.md#L146-150` |
| 通用 API 错误 | 分类→有界重试；`retry.maxRetries=10`，退避 500→8000ms（抖动 75–100%），可切凭据/模型 | 10 次/模型 | 失败 assistant 移出运行时但**日志保留**并标 `retryRecovery` | `docs/non-compaction-retry-policy.md#L106-134,272-277` |
| 压缩无进展 | 进度守卫：重写后需降到阈值 ~80% 以下才续跑，否则告警并阻止自动续跑 | 有界 | 本地救援（重渲 archive/省略重块/丢图） | `docs/compaction.md#L219-221` |
| 手动压缩中断 | 先 abort 当前操作，摘要提交后按需恢复该轮 | — | 取消/失败不续跑 | `docs/compaction.md#L495` |
| handoff 失败 | 手动抛错；自动返回 undefined → 方法链推进到下一个 | 有界 | — | `docs/handoff-generation-pipeline.md#L92-99` |

## 5. 中文解读要点（先例子/数据对象，再条件/循环/写回）

- **数据对象先讲清**：会话不是"消息数组"，而是**只追加的条目日志**（每行一条 `SessionEntry`，靠 `id`/`parentId` 成树）。`CompactionEntry` 是一条**一等条目**，不是普通消息；它记 `summary` 与 `firstKeptEntryId`（"从这里开始保留"）与 `tokensBefore`。
- **"投影"直觉**：模型看到的上下文是**当前分支路径的一次投影**——压缩没有删历史，只是让投影从"摘要 + 保留段"开始。
- **条件的单位**：`contextTokens` 与 `contextWindow`、`reserveTokens`、`keepRecentTokens` 都是 **token**；`DEFAULT_MAX_BYTES` 是 **UTF-8 字节**（51200），两者**不可混用**（规范 §5 坑）。
- **循环/顺序**：`findCutPoint` 是"**从最新往回**按整组累加"；`truncateHead` 是"**从头往尾**逐行累加"。方向相反，别记混。
- **写回时机**：压缩是"**成功才提交**"——`appendCompaction` 在摘要生成之后；失败/取消不追加、不重试（`docs/compaction.md#L493-504`）。
