## 第 1 组：OpenCode v1 / v2 的版本与代际定义

**结论：`已解决但需口径确认`。v1 与 v2 是同一仓库 `anomalyco/opencode` 的两条 tag 线，不是两个独立仓库。**

### 已查到什么
- **仓库唯一**：`https://github.com/anomalyco/opencode`（原 `sst/opencode`，`gh api repos/sst/opencode` 已 302 到 `anomalyco/opencode`）。MIT，TypeScript，默认分支 `dev`。
- **两条 tag 线并存**（`git ls-remote` 核验）：
  - v1 线：`v1.19.0`（2026-10-11），也是仓库当前的 GitHub「latest release」。
  - v2 线：`v2.0.0`（2026-09-11）→ `v2.0.29`（2026-10-14，最新 tag）。v2 仍处 **beta**，未列为 latest release。
- **两个 npm 包**：v1 = `opencode-ai`（latest 1.19.0）；v2 = `@opencode/cli`（latest 2.0.29）。
- **代际差异（源码树证据）**：v2 树根含 `V2_HTTP_API_AUDIT.md`，`packages/` 新增 v1 无有的 `ai`、`merman`、`plugin-browser`、`simulation`、`theme`、`util`、`gui-extensions`、`posts`；v1 树含 `packages/opencode`、`llm`、`sdk-next`。
- **官方代际口径**（官方迁移文档 `https://opencode.ai/v2/docs/migrate-v1`）：V1 是独立 TUI；V2 改为「单一共享后台（Hono/SQLite 服务）同时支撑终端 / 桌面 / 网页」。三处**有意破坏性变更**：① 插件 API 重写；② 服务端 API 与客户端契约变更；③ 终端配置从分层 `tui.json(c)` 收敛为单一全局 `cli.json`。
- **升级路径**：v1.19.0 起提供 `opencode upgrade --major` 与 TUI `/update` 迁移到 v2；v1/v2 命令名同为 `opencode`，默认不再并排安装（beta 期曾用 `opencode2` 并存）。

### 还差什么
- **教学口径未定**：九工具对比里「OpenCode v1」「OpenCode v2」两行分别固定到哪条 tag？本任务已按「各取研究日最新」冻结：v1 = `v1.19.0`，v2 = `v2.0.29`。
- **beta 可接受性未定**：v2 仍为 beta，是否接受用 beta 版本参与横向对比、如何标注。

### 是否需要用户确认
**需要（口径级，非身份级）**。建议默认：v1=`v1.19.0`、v2=`v2.0.29`，两目录 `opencode-v1/`、`opencode-v2/` 已就绪；正文明确标注 v2 为 beta。若用户希望固定其它具体版本，需在正文写作前指定。

## 第 2 组：pi 与 oh-my-pi 的来源关系

**结论：`已解决`。oh-my-pi 是 pi 的**派生（fork）项目**，二者已是不同仓库、不同包、不同版本线的两个独立产品。**

### 已查到什么
- **pi**：
  - 官方主页 `https://pi.dev`；官方仓库 `https://github.com/earendil-works/pi`；官方 npm 包 `@earendil-works/pi-coding-agent`（1.2.0）。
  - 作者 Mario Zechner（GitHub `@mariozechner` / `badlogic`）；**旧仓库名为 `badlogic/pi-mono`**，现仓库为 `earendil-works/pi`。
  - 官方自我定位：「a minimal, extensible agent harness that you can make your own」，**刻意不含 sub-agents 与 plan mode**。
  - 本地证据：`/opt/homebrew/bin/pi → @earendil-works/pi-coding-agent/dist/bundle/cli.js`，版本 1.2.0；`~/.pi/agent/` 有 sessions/skills/extensions。
- **oh-my-pi**：
  - 官方主页 `https://omp.sh`；官方仓库 `https://github.com/can1357/oh-my-pi`；官方 npm 包 `@oh-my-pi/pi-coding-agent`（18.10.4）。
  - 作者 Can Bölük，隶属 **Stencil Labs**。
  - README 明确声明：**「Fork of [Pi](https://github.com/badlogic/pi-mono) by @mariozechner」**——即官方自述为 pi 的分支。
  - 定位「A coding agent with the IDE wired in」，在 pi 基础上加入 LSP、DAP 调试、内置浏览器、子代理、Python 内核、hindsight 记忆等；技术栈 TS + Rust（`crates/pi-*`）。
- **共享代码来源 ≠ 默认行为相同**：二者已分叉出不同功能集与版本线（pi 1.x vs omp 18.x），必须分别研究（任务书要求，已按此执行）。

### 残留命名风险（需注意）
- npm 上另有一个**完全无关的同名包** `oh-my-pi@0.2.0`（作者 `acidsugarx`，描述「Enhancement framework for Pi CLI coding agent」）。其声明的仓库 `github.com/acidsugarx/oh-my-pi` **已 404**（不可访问），且与 can1357/oh-my-pi 无任何关联。
- 判断：任务书所指「oh-my-pi」**几乎可以确定**是 `can1357/oh-my-pi`（官网 omp.sh、35k★、活跃维护），而非 acidsugarx 的同名第三方包。但该同名包构成潜在混淆，需在正文中一句澄清。

### 还差什么
- 无身份层面缺口。仅需在正文澄清「oh-my-pi 专指 can1357/oh-my-pi（omp）」。

### 是否需要用户确认
**建议确认（低风险）**：确认「oh-my-pi = can1357/oh-my-pi（omp.sh）」，并在术语表注明 acidsugarx 同名包为无关第三方，避免读者混淆。

## 第 4 组：deepseek-harness 的定位

**结论：`已解决但需范围确认`。已定位为 DeepSeek 官方开源 Agent 运行框架，CLI 命令名 `dsh`。**

### 已查到什么
- **官方仓库**：`https://github.com/deepseek-ai/deepseek-harness`，description「DeepSeek Harness: Everything is a Plugin.」，MIT，默认分支 **`master`**（非 main），TypeScript，249,560★（2026-10-14 23:45 CST）。
- **官方站点**：`https://deepseek.com/harness`（仓库 `homepage` 字段同址；宣传语「AGENT = MODEL + HARNESS」）。本次 curl 该站点返回 HTTP 429（限流），但仓库字段与检索结果一致，可确认。
- **官方 CLI 包**：npm `@deepseek-ai/dsh`（latest `0.2.0-rc.2`，描述「dsh CLI: profile launch, plugin management, and configuration inspection」）。
- **运行入口**：`npx @deepseek-ai/dsh web`（Web UI，127.0.0.1:3080）；profile 化启动 `dsh --profile tui/headless`；源码 `pnpm dsh web`。
- **架构**：pnpm monorepo，「一切皆插件」，Cordis 内核；`apps/`（cli、web）、`packages/`（200+ 个 `@deepseek-ai/dsh-*`）、`native/`（Rust）、`python/`。
- **状态**：Developer Preview，版本可能快速迭代。
- **已冻结源码快照**：`workbuddy-sources/deepseek-harness/`，SHA `571902028a75c64c1d767f4ae5fd099485f0ddf0`（master，2026-10-14）。

### 还差什么
- **Python SDK 未核验**：检索显示存在 `pip install deepseek-harness-sdk`，但本任务未核验 PyPI（npm 上不存在该包名属正常，因其非 npm 包）。标记为**待补**，不写入结论。
- **研究范围未定**：研究对象是仅 `dsh` CLI，还是含 Web UI / Python SDK / TS SDK？任务书要求「工具本身」，但 dsh 的默认入口是 Web UI。
- **版本口径未定**：固定到 npm `0.2.0-rc.2` 还是 master 快照（已取 master 快照）。

### 是否需要用户确认
**需要（范围级）**：① 研究是否以 `dsh` CLI 为主入口（默认 Web UI 是否纳入）；② 是否纳入 Python/TS SDK；③ 是否需要补核 PyPI 的 `deepseek-harness-sdk`。身份本身无需确认。
