# Gemini CLI · 过程观察

> 本文件解决什么问题：给出**可运行机制的最小一次真实观察**（命令 / 预期事件 / 判据 / 停止条件）或**确切不可运行原因**。
> **纪律**（规范 §4）：退出码为准 + 至少一次负例；版本双重口径三行；污染登记；`UNOBSERVABLE ≠ 没有实现`；不把源码阅读当实验通过；归因限制必写。

## 0. 观察策略：为什么走"函数级真实执行"路线

- **产品入口 `gemini` 本机未安装**（`which gemini` = not found，版本表 §3）→ **端到端产品观察 `NOT_RUN`**，原因：缺可执行件（官方 release v0.64.0 未安装；无登录凭据）。
- 按 T08 可复用经验 §6.4-2：产品入口不可用时，可对**官方已发布快照**的出货代码做**函数级真实执行**（用 bun 直接跑快照 `.ts`，只读导入，不修改快照），记"**出货代码行为**"，并**显式声明不能外推到产品端到端**。
- **选点**：`OBS-gemini-trunc-01` 选**纯函数**（`truncation.ts` / `tokenCalculation.ts` / `tokenLimits.ts`），因这些是"单条工具输出治理"与"窗口计量"的**出货常量与公式**，且**无网络依赖**、可确定性验证。

### 1.4 实际结果（已运行）

**正向**（`OBS-gemini-trunc-01-run-PASS`）：**28 条断言全部 PASS**，`EXIT_CODE=0`。

| 组 | 验证内容 | 结果 |
|---|---|---|
| A | `truncation.ts` 出货常量：`MIN_TARGET_TOKENS=10`、`MIN_CHARS_FOR_TRUNCATION=100`、两个截断前缀 | PASS |
| B | `tokenCalculation.ts` 常量与公式：`ASCII_TOKENS_PER_CHAR=0.33`、`NON_ASCII_TOKENS_PER_CHAR=1.5`；`est([a×100])=25`、`est([中×4])=6`、`est([ab])=0`（边界 <1） | PASS |
| C | `tokenLimits.ts`：`DEFAULT_TOKEN_LIMIT=1048576`、`GEMMA_4_TOKEN_LIMIT=256000`、`tokenLimit('gemini-2.5-pro')=1048576`、未知模型回退 1048576 | PASS |
| D | `estimateCharsFromTokens` 公式：`chars(ascii1000,250t)=757`、`chars(cjk1000,300t)=200`、空串=0 | PASS |
| E | `truncateProportionally` 头尾比例与边界：总长 50、头 8 / 尾 33、`\n...\n`、不到线原样、极小目标仅返回前缀 | PASS |

### 1.5 归因限制（必写，规范 §4.6）

1. **不涉及模型**：本观察**无**任何模型调用，故**不能**说明"压缩/摘要是否保真""模型是否遵守约束"。
2. **不证明产品默认参数**：验证的是**快照出货代码**的常量/公式，**不是**发行版 v0.64.0 或远端 flag 生效后的**运行时值**。
3. **不能外推到端到端**：**不能**证明 `usable`/溢出/压缩触发在真实会话的行为；阈值是否被远端 `CONTEXT_COMPRESSION_THRESHOLD` 改写**不可观测**。
4. **可外推的部分**：出货常量（10/100/0.33/1.5/1,048,576/256,000）与纯函数公式（`estimateCharsFromTokens`、`truncateProportionally`）**在快照层成立**，可用于佐证证据卡 `gemini-trunc-01`、`gemini-trigger-01`、`gemini-trigger-02`。

### 1.6 不能证明（规范 §4.4）

- **不证明**"产品端到端压缩行为"；**不证明**服务端缓存；**不证明**GEMINI.md 加载；**不证明**会话恢复。
- **不把源码阅读冒充实验通过**：本观察是**出货代码真实执行**（非"模型说它记住了"），且已明确其边界。

## 2. 未运行项（NOT_RUN + 确切原因，不得留白）

| 规程 | 状态 | 确切原因 |
|---|---|---|
| 产品入口自动压缩端到端（构造长会话 → 观察触发/摘要/重建） | `NOT_RUN` | 本机**未安装** `gemini`；无登录凭据；统一由 T19 干净环境调度 |
| 产品入口手动 `/compress` | `NOT_RUN` | 同上（需交互 TTY + 安装） |
| 工具输出截断端到端（跑 shell 工具 → 看落盘文件） | `NOT_RUN` | 同上；且需真实工具执行环境 |
| GEMINI.md 分层加载端到端 | `NOT_RUN` | 同上 |
| 会话恢复端到端（重启 → resume） | `NOT_RUN` | 同上 |
| prompt cache 命中/TTL | `UNOBSERVABLE` | 服务端行为；CLI 只读字段，无法观测（见证据卡 `gemini-cache-01`） |

> **`UNOBSERVABLE ≠ 没有实现`**：缓存命中/TTL 标 `UNOBSERVABLE`，**不写成**"Gemini 无缓存"。CLI 侧确有 `cachedContentTokenCount` 字段读取（`gemini-cache-01`），服务端缓存行为**不可观测**。

## 3. 给 T19 的复现规程模板（干净环境）

```bash
# 前置：干净环境安装 gemini（官方 v0.64.0 或与快照对齐的版本），记录 `gemini --version`（入口自报）
# 前置：确认 ~/.gemini/ 无第三方 hook/扩展污染；记录 settings.json 的 model.compressionThreshold
# 数据：使用 T03-DATA-TRIP-v1（行程任务，HC-01 16:00 约束）
gemini --model gemini-2.5-pro --workdir <独立合成项目目录> 2>&1 | tee <原始日志>
# 1) 首条消息只放任务目标 + 硬约束（逐字引用数据包原文）
# 2) 触发压缩：调低 model.compressionThreshold（如 0.2）以在小数据上强制到线；或 /compress 手动
# 3) 观察：ChatCompressed 事件、压缩前后 token（getLastPromptTokenCount）、落盘 tool-outputs/ 文件
# 4) 恢复：重启后 --resume / 会话选择，恢复后先问"现在有效约束有哪些"
# 5) 判据：T03 检查器（CHK-HC-* / CHK-REJ-* / CHK-FC-STATUS），不靠模型自述
```
**首轮每条件重复 3 次**；记录全部结果 + 中位数/范围；**不声称统计显著**。控制变量：同一模型/provider/窗口/数据/命令，仅改"是否启用自动压缩"或"阈值"。
