## 3. 客户端 vs 服务分层表（**可观测 / 不可观测**，逐条分列）

> **分界纪律（沿用 T09R 教训）**：**同源 ≠ 零耦合**；分层按**代码归属 + 证据可达性**逐条判定，不按"看起来像"二分。
> 「可观测」= 本包能用**快照源码 + 函数级执行 + 官方文档**证明；「不可观测」= 落在 Gemini 服务端，CLI 侧只见字段或完全不可见。

| 环节 | 层 | 可观测证据 | 不可观测 / 不能证明 |
|---|---|---|---|
| systemInstruction / tools / contents 组装 | **CLI** | `geminiChat.ts`、`client.ts` | 服务端如何解析该结构 |
| 历史角色规整（coalesce/stripThoughts/scrub） | **CLI** | `geminiChat.ts:2025-2093`、`historyHardening.ts:383` | — |
| token 本地估算（`estimateTokenCountSync`） | **CLI** | `tokenCalculation.ts`（**函数级已执行**） | 真实分词器切分（服务端） |
| 压缩触发判定（阈值比较） | **CLI** | `chatCompressionService.ts:502-518` | 远端 experiment flag 的**下发值**（`CONTEXT_COMPRESSION_THRESHOLD`）由服务端决定 |
| 摘要生成（LLM 调用） | **CLI 发起 / 服务端执行** | CLI 侧发起两次 `generateContent`（摘要 + 校验），`chatCompressionService.ts:595-645` | **摘要文本内容**不可预知（模型行为）；不能证明"摘要一定保真" |
| 压缩前截断（`truncateHistoryToBudget`） | **CLI** | `chatCompressionService.ts:364-464` | — |
| 工具输出截断 / 落盘 | **CLI** | `tool-executor.ts`、`fileUtils.ts`（**函数级已执行**） | — |
| 工具输出掩蔽 | **CLI** | `toolOutputMaskingService.ts` | — |
| GEMINI.md 记忆发现 / 注入 | **CLI** | `memoryContextManager.ts`、`memoryDiscovery.ts` | — |
| 技能发现 / 激活 | **CLI** | `skillManager.ts`、`activate_skill` 工具 | — |
| 会话落盘 / 恢复 | **CLI** | `chatRecordingService.ts`、`sessionUtils.ts` | — |
| 子 Agent 执行 | **CLI**（本地执行器）/ **服务端**（远端 Agent） | `agents/local-executor.ts`、`docs/core/subagents.md` | 远端 Agent（`remote-invocation.ts`）的服务端行为 |
| 重试与退避 | **CLI** | `utils/retry.ts` | 服务端限流策略 |
| **prompt cache 命中 / TTL / 缓存键** | **服务端（不可观测）** | CLI 仅读 `usage.cachedContentTokenCount`（`telemetry/types.ts:619`）；透传 `cachedContent` 字段（`apiConversionUtils.ts:24,54`） | **命中率、缓存存活期、缓存键** 全部 `UNOBSERVABLE`（Gemini API 隐式缓存，CLI 无显式断点/键） |
| **真实 usage 计量（input/output/cached）** | **服务端** | CLI 读取并记录返回的 `usageMetadata` | 计量口径由服务端决定 |
| **模型窗口 / 模型元数据** | **CLI 常量 / 服务端** | `tokenLimits.ts` 硬编码 1,048,576（**CLI 常量**） | 实际服务端窗口若与常量不符，CLI 不可知 |

**分层结论**：Gemini CLI 的**上下文管理机制绝大部分落在 CLI 侧**（组装、规整、触发判定、截断、落盘、掩蔽、记忆、恢复、重试）——**可观测**；**服务端承担**摘要生成、真实计量与**全部 prompt cache 行为**——**不可观测**。二者边界清晰，不存在"同一段逻辑跨层难判定"的情形（与 OpenCode v1/v2 的"同源≠零耦合"问题不同）。

## 4. 默认 vs 扩展分列（规范 §5"默认 vs 扩展混淆"防范）

> **核心事实**：Gemini CLI 存在**两套上下文管理系统**——**默认启用的传统链路** 与 **默认关闭的实验性图管线**。必须分列，**不得**把实验系统的常量当"产品默认"。

### 4.1 默认核心（`contextManagement.enabled = false`，出厂默认）

| 机制 | 默认实现 | 证据 |
|---|---|---|
| 自动压缩 | `ChatCompressionService.compress`（阈值 0.5×窗口） | `client.ts:719`、`chatCompressionService.ts` |
| 手动压缩 | `/compress`（force=true） | `client.ts:1226-1282`、`docs/reference/commands.md` |
| 工具输出截断 | 40,000 字符 + head20%/tail80% + 落盘 | `tool-executor.ts:202-260`、`config.ts:483` |
| 工具输出掩蔽 | 50k 保护 + 30k 可裁剪 ≈ 80k 总量 / 保护最新轮 | `toolOutputMaskingService.ts:25-27` |
| 旧轮 functionResponse 折叠 | 保护最近 3 轮、2 KB、retrieval 工具豁免 | `chatCompressionService.ts:50,88,131-263` |
| 记忆 | GEMINI.md 四层（模型主动写） | `memoryContextManager.ts`、`docs/tools/memory.md` |
| 后台自动记忆提取 | **默认关**（`experimental.autoMemory=false`）；开启后后台产出 `.inbox` 补丁待审批 | `docs/cli/auto-memory.md`、`config.ts:1202`、`memoryService.ts:1133` |

### 4.2 实验扩展（默认关，需显式开启）

| 机制 | 开关 | 证据 |
|---|---|---|
| 图管线上下文管理（`ContextManager` + `PipelineOrchestrator` + processors） | `experimental.contextManagement=true`（settings schema 默认 **false**） | `config.ts:1208`、`initializer.ts:35-38`、`context/config/profiles.ts` |
| 该管线默认预算 | `generalistProfile`：`retainedTokens=65000` / `maxTokens=150000` / `coalescingThresholdTokens=5000` | `context/config/profiles.ts:77-83` |
| 该管线处理器 | ToolMasking / BlobDegradation / NodeDistillation / NodeTruncation / StateSnapshot（同步 + 异步） | `context/config/profiles.ts:85-168` |
| 上下文管理配置对象 | `contextManagement.historyWindow/messageLimits/tools`（settings 默认 `{}`） | `config.ts:1207-1245`、`schemas/settings.schema.json` |

> **易错点**：`generalistProfile` 在 `context/profiles.ts`（旧接口，`enabled:true`）与 `context/config/profiles.ts`（新图管线）**同名不同物**；`historyWindow.retainedTokens`（默认 40000）属**旧接口默认值**，**不是**新管线的 65000。正文引用时必须带路径。
