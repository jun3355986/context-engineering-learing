# Gemini CLI · 数据走查（DW-*）

> **每条格式**（规范 §6）：**输入 → 处理顺序 → 前后对照（原样留下 / 变摘要 / 移除 / 落盘）→ 写回 → 找回入口**。
> **数字**：给公式 + 代入值 + 结果，标【源码常量】/【演示】/【测试样本】。
> **边界**：至少 1 个"到线/不到线""奇数预算差 1""多字节不切断""装不下 break"类边界。
> **失败分支**：分类（超窗/中断/取消/预算耗尽）+ 是否有界 + 副作用是否可回退。
> 计数：本文件共 **22** 条（`grep -c "^## DW-"` 实测）。

## DW-assembly-01 · 请求组装（CM-01）

- **输入**：`[user:"安排郊游"]` + 已有历史（含一次 `read_file` 调用/结果）。
- **处理顺序**：`getHistoryTurns(true)` 取 curated → `stripThoughts`（剥 thought，补合成签名）→ `coalesceConsecutiveRoles`（合并相邻同 role）→ 组装 `systemInstruction + tools + contents`。
- **前后对照**：环境上下文 turn **原样留下**（首条）；thought part **移除**（其 `thoughtSignature` 若被首个 functionCall 依赖则**合成补齐**）；相邻同 role turn **合并**。
- **写回**：`setHistory` 重建 `agentHistory`；`lastPromptTokenCount` 重算。
- **找回入口**：JSONL 存档（`chatRecordingService`）保留完整录制。
- **边界**：若 `lastMessage.role==='model'` 且含 `functionCall`（工具待响应）→ **不注入 IDE 上下文**（`client.ts:755-758`，保持"call 后必须紧跟 functionResponse"）。

## DW-rule-01 · 记忆加载（CM-02/CM-08）

- **输入**：`~/.gemini/GEMINI.md`（global）、扩展记忆、`<project>/GEMINI.md`（project）、`<projectMemoryDir>/MEMORY.md`（userProject）。
- **处理顺序**：并行发现 4 类路径 → 字符串去重 + **dev+ino 身份去重** → `readGeminiMdFiles`（含 `@import`）→ 分层拼接 → project 并入 MCP 指令。
- **前后对照**：global+userProject → **系统提示词**（原样）；extension+project → **首条 user 消息**（包 `<loaded_context>`）；未受信任目录的 project **移除**（`isTrustedFolder()===false` → `''`）。
- **写回**：`MemoryChanged` 事件；`getSystemInstructionMemory` / `getSessionMemory`。
- **找回入口**：磁盘 GEMINI.md/MEMORY.md 原文件。
- **边界**：JIT 子目录记忆从访问路径**向上**到项目根，**已加载文件不再重复加载**（`loadedPaths`/`loadedFileIdentities`）。

## DW-retrieval-01 · 按需检索（CM-03）

- **输入**：模型发起 `grep`（`pattern`）/`read_file`（`path`）。
- **处理顺序**：工具执行 → 结果进入 `contents` 的 `user` turn `functionResponse` → 若超 40,000 字符走 DW-trunc-01。
- **前后对照**：检索**片段**进请求；全文（若落盘）在 `tool-outputs/`；`read_file` 等 retrieval 工具输出**豁免折叠**（DW-collapse-01）。
- **写回**：工具结果 part。
- **找回入口**：`read_file`/`grep` 可重跑；落盘文件路径可读。
- **边界**：**未发现**"全量装填整个仓库"路径（检索路径：`packages/core/src` grep 无 bulk-load 上下文注入器）。

## DW-trunc-01 · 工具输出截断（CM-04）【含可算数字 + 多字节边界】

- **输入**：shell 工具输出，**100,000 字符**。
- **处理顺序**：`content.length (100,000) > threshold (40,000)` → `saveTruncatedToolOutput` 落盘 → `formatTruncatedToolOutput` 头尾截断。
- **可算数字**：
  - 阈值 `maxChars = 40,000`【源码常量】（`config.ts:483`）
  - `headChars = floor(40,000 × 0.2) = 8,000`
  - `tailChars = 40,000 − 8,000 = 32,000`
  - `omittedChars = 100,000 − 8,000 − 32,000 = 60,000`
- **前后对照**：全量 100,000 字符 → **落盘** `tool-outputs/session-<id>/shell_<callId>.txt`；请求里 **头 8,000 + 尾 32,000** + `... [60,000 characters omitted] ...` + 文件路径。
- **写回**：`functionResponse.response.output` 替换为截断文本。
- **找回入口**：`For full output see: <path>`。
- **边界（多字节不切断）**：截断按**字符**（`.slice`）而非字节，**不会**切断 UTF-8 多字节字符；但**中文字符 3 字节** → 40,000 字符 ≈ **120,000 字节**，**会**触发二次硬截（DW-trunc-02）。
- **边界（不到线）**：`content.length <= 40,000` → **原样**返回，不落盘、不截断。
- **失败分支**：截断/落盘**无模型调用**（本地操作），无超窗；落盘为**已发生副作用**，后续压缩失败**不回退**。

## DW-trunc-02 · 64 KB 硬上限（CM-04）

- **输入**：DW-trunc-01 截断后文本（中文场景 ≈ 40,000 字符 × 3 字节 ≈ 120,000 字节）。
- **处理顺序**：`Buffer.byteLength(truncated,'utf8') > 64×1024` → `truncateToolOutput(truncated, 65,536)`。
- **可算数字**：`MAX_STORED_TOOL_OUTPUT_BYTES = 64 × 1024 = 65,536 字节`【源码常量】。
- **前后对照**：120,000 字节 → 硬截到 65,536 字节。
- **找回入口**：同 DW-trunc-01（落盘全文）。
- **边界**：ASCII 场景 40,000 字符 = 40,000 字节 < 64 KB → **不**触发二次硬截（中英文差异显著）。

## DW-masking-01 · 工具输出掩蔽（CM-04）【含"奇数预算差 1"边界】

- **输入**：历史含 6 个旧 shell 工具输出，各 20,000 token；最新一轮工具输出（受保护）。
- **处理顺序**：`protectLatestTurn=true` → 从 `history.length-2` 向后扫 → 累计工具 token 越过 50,000 保护窗 → 之后全部计入 `prunableParts` → 若总量 ≥ 30,000 才掩蔽。
- **可算数字**：保护窗 `50,000`、批量门槛 `30,000`【源码常量】（`toolOutputMaskingService.ts:25-26`）。
- **边界（差 1）**：
  - 可裁剪总量 = **29,999** token < 30,000 → **不掩蔽**（`return {maskedCount:0}`）。
  - 可裁剪总量 = **30,000** token → **掩蔽**（`>=` 判定，`:152`）。
- **前后对照**：旧 tool part → **落盘** + 替换为 `<tool_output_masked>`（head/tail 各 250 字符预览 + 路径）；最新一轮**原样留下**。
- **写回**：`chat.setHistory(newHistory)`（仅当 `maskedCount>0`）。
- **找回入口**：`Output too large. Full output available at: <path>`。
- **失败分支**：掩蔽无模型调用；`actualTokensSaved<=0` 时不改历史（`:255-257`）。

## DW-collapse-01 · 旧轮折叠（CM-04）【含 2 KB 边界】

- **输入**：5 个工具轮，最早的 2 个各含 5,000 字节 functionResponse。
- **处理顺序**：`toolIndices.length (5) > protectedTurns (3)` → `cutoffToolIndex = toolIndices[5-3]` → 仅 `idx < cutoffToolIndex` 的旧轮折叠；retrieval 工具**跳过**。
- **可算数字**：`maxBytesPerOldResponse = 2048`【源码常量】；`RECENT_TURNS_PROTECTED = 3`。
- **边界（到线）**：字符串正好 **2048 字节** → `<= maxBytes` → **不折叠**；**2049 字节** → 折叠为前 2048 字节 + `... [1 bytes omitted] ...`。
- **前后对照**：旧轮大 functionResponse → 折叠为前 2 KB 预览；最近 3 轮**全保真**；retrieval 工具**原样**。
- **写回**：`chat.setHistory(turns)`（仅 `local-executor.ts` 子 Agent 路径；见证据卡 gemini-collapse-01"不能证明"）。
- **边界（多字节不切断）**：按 `Intl.Segmenter` grapheme 切分，**不切断**中文/emoji。

## DW-trigger-01 · 压缩触发线（CM-05）【含可算数字 + 到线/不到线】

- **输入**：当前历史 token `A`，模型 `gemini-2.5-pro`。
- **公式**：`触发线 = (await getCompressionThreshold()) ?? DEFAULT_COMPRESSION_TOKEN_THRESHOLD` × `tokenLimit(model)`。
- **可算数字**：`0.5 × 1,048,576 = 524,288`【源码常量 + 官方默认 0.5】。
- **边界（到线 / 不到线）**：
  - `A = 524,287` → `< 524,288` → **NOOP**（不压缩）。
  - `A = 524,288` → `>=` → **触发压缩**。
- **前后对照**：不到线 → 历史**原样**；到线 → 走 DW-compact-01/DW-summary-*。
- **写回**：不到线无写回；到线按压缩状态写回。
- **找回入口**：JSONL 存档。
- **失败分支**：远端 flag 改写阈值 → **不可观测**（服务端）。

## DW-trigger-02 · 溢出前置检查（CM-05）【含"装不下 break"边界】

- **输入**：`request` 本地估算 `estimatedRequestTokenCount`；`lastPromptTokenCount`。
- **公式**：`remaining = tokenLimit(model) − lastPromptTokenCount`；若 `estimatedRequestTokenCount > remaining` → `ContextWindowWillOverflow`，**中止本轮**。
- **边界（装不下）**：`remaining = 1,000`，`estimated = 1,001` → **中止**（不发送、不压缩）；`estimated = 1,000` → 放行（`>` 非 `>=`）。
- **前后对照**：中止 → 不产生模型请求；历史不变。
- **找回入口**：—
- **失败分支**：含媒体时 `estimated` 走 `countTokens` API（服务端计量，**UNOBSERVABLE**）。

## DW-summary-01 · 摘要结构与防注入（CM-07）

- **输入**：待压缩历史 + `getCompressionPrompt`。

## DW-summary-02 · 切点与保留预算（CM-07）【含可算数字】

- **输入**：待压缩历史（若干 turn）。
- **公式 A（切点）**：`charCounts[i] = JSON.stringify(content).length`；`totalCharCount = Σ charCounts`；`targetCharCount = totalCharCount × (1 − 0.3)`；返回**累计 ≥ target 的第一个"非 functionResponse 的 user turn"**索引。
  - 代入【演示】：10 条 turn，`totalCharCount = 100,000` → `target = 70,000`；累计到第 8 条（非工具 user）时达 70,500 ≥ 70,000 → **splitPoint=8**；`historyToCompress = [0,8)`，`historyToKeep = [8,10)`（后 30% 左右）。
- **公式 B（函数响应预算）**：倒序累加 functionResponse token，超 `COMPRESSION_FUNCTION_RESPONSE_TOKEN_BUDGET = 50,000`【源码常量】的**旧**响应 → 截断落盘。
- **前后对照**：前段 → **变摘要**；后段 → **原样保留**；超预算旧响应 → **落盘** + 截断。
- **写回**：`historyToKeepTruncated` 进入替代历史。
- **找回入口**：落盘文件 + JSONL。
- **边界（装不下 break）**：无切点且最后一条是**无 functionCall 的 model turn** → `return contents.length`（**整体压缩**）；否则 `return lastSplitPoint`（保守，不整体压）。
- **口径提示**：切点用**字符数**，预算用**token**——两者口径**不完全一致**。

## DW-fail-01 · 有界重试（CM-11）

- **输入**：可重试网络错误（`ECONNRESET` 等）。
- **处理顺序**：`retryWithBackoff`：`attempt ≤ 10`，延迟 `5000ms` 起、指数增长、上限 `30000ms`，叠加抖动。
- **可算数字**：`maxAttempts=10`、`initialDelayMs=5000`、`maxDelayMs=30000`【源码常量】。
- **前后对照**：单次失败 → 重试；**有界**（≤10 次）后抛错。
- **写回**：成功则返回结果；失败则抛错（副作用不回退）。
- **找回入口**：—
- **失败分支**：quota 错误走 `onPersistent429`（切换 auth 或返回），抖动为 `+20%` 且尊重服务端最小延迟。

## DW-fail-02 · 压缩失败分类（CM-11）

- **输入**：压缩流程各失败点。
- **处理顺序**：空历史/未达线/无切点 → `NOOP`；摘要空 → `COMPRESSION_FAILED_EMPTY_SUMMARY`；新用量 > 原用量 → `COMPRESSION_FAILED_INFLATED_TOKEN_COUNT`；此前失败且非 force → `CONTENT_TRUNCATED`。
- **前后对照**：失败 → **保持原历史**（除 `CONTENT_TRUNCATED` 只截断）。
- **写回**：`COMPRESSED` 重建会话；`CONTENT_TRUNCATED` 仅 `setHistory`。
- **找回入口**：JSONL。
- **失败分支**：分类明确，**有界**（不无限重试摘要）。

## DW-fail-03 · 压缩失败降级为仅截断（CM-11）

- **输入**：`hasFailedCompressionAttempt=true` 且 `force=false`。
- **处理顺序**：**跳过摘要 LLM 调用** → 只做 `truncateHistoryToBudget` → 有减量则返回 `CONTENT_TRUNCATED`，否则 `NOOP`。
- **前后对照**：不再生成摘要；只截断超预算旧响应。
- **写回**：`setHistory`（不重置失败标记）。
- **找回入口**：落盘文件 + JSONL。
- **失败分支**：**有界降级**；副作用（已落盘文件）**不回退**。
