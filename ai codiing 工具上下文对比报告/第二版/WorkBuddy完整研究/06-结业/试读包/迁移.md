# 迁移 · 新场景完整设计（题组 C 简版）

> **来源**：`../../06-结业/T18-任务包.md` §3（题组 C）的**简化版**——保留"状态图 / 伪代码 / 失败处理 / 反例自检"四个核心要求。**完整版与参考答案见原文件**（试读时不得查看）。
> **纸面可完成**：不需运行任何工具；限时约 **40 分钟**；**不排名次**。

## C0 · 场景描述（未做过完整设计的新场景）

你要为一个**"多子代理并行调研"**的小型 Agent 设计上下文管理：

- 主代理把任务拆给 **3 个子代理**，**并行**读三份**大文档**（每份几百行，结论在**中段/尾段**），再汇总成一份结论；
- 中途，用户对**子代理 A 提出的一个方案**明确**否决**（"这个方案不要，换成 B"）；
- 整个任务**跨天**：白天跑完三个子代理、汇总一版；晚上关电脑；第二天 `resume` 继续，**先确认"被否决的方案没复活"**，再出最终版。

> **已知教训（沿用全项目靶子）**：整理后忘掉关键约束；复活已否决的决定；把未完成写成完成。

## C1 · 状态图

画出（或文字化）**状态图**，至少含四类状态对象，并**逐对象标"何时被读、何时被写"**：

- **主代理**的材料列表 / 约束表 / 用量计 / 检查点；
- **子代理**的材料列表与**用量计**（关键：子代理是否有**独立消息列表与单独用量**？回传给主代理的是什么？——M08）；
- **否决决定**的状态对象（有效 / 已否决，**不删**）。

**必须回答**："中间几十次工具调用去哪了"、"主窗口怎么不被污染"。

---

## C2 · 伪代码

写出一轮任务的**伪代码**（读输入 → 更新约束 → 组装 → 调模型 → 工具/子代理 → 用量检查 → 整理/恢复），**必须出现"取舍理由"**：

1. 为什么**用户消息优先**（保留算法）？
2. 为什么**约束（含否决状态）单独建表、不跟摘要走**？
3. **标出一处与代表实现（Codex）故意不同**的地方并说明理由。

---

## C3 · 失败处理

给一张"**失败 → 检查 → 行动**"表，覆盖：子代理失败 / 汇总失败 / 整理失败 / 恢复后丢约束 / 工具结果被裁剪。**必须**：

1. 按**原因分类**（超窗口 / 中断 / 取消 / 预算耗尽 / 验收不合格），**各走各的出路**（不是"一律重试"）；
2. 标出**有界重试**，并说明**不同循环用不同计数**（缩副本循环 ≠ 退避循环）；
3. 标出**不可重复执行的动作**（副作用），并说明**恢复重建的是"材料"不是"动作"**。

---

## C4 · 反例自检

1. **对照表（迁移的核心动作）**：把本课程机制 → **新场景里的对应物** → **你要做的动作**，写成一张对照表。至少覆盖：关键约束、长工具结果、整理触发、保存与恢复、失败处理、缓存、**否决决定**、**子代理交接**。
2. **反例自检**：从 `../../03-课程/T14/T14-九工具比较矩阵.md` §G「场景决策表与反例」里**选 2 行**，把该行的**反例**抄进你的方案，写成"**我的方案在什么情况下会翻车**"的自检项。
3. **评估四维并查**：给出**质量 / 成本 / 延迟 / 可恢复**四维的观察方案，并回答：为什么**"压缩率漂亮"不能替代任务质量**？
4. **区分实测 / 推断**：指出你方案里**哪些是源码常量/文档证据、哪些是机制推演、哪些只有实测才能回答**。

## 作答提示（不是答案）

- 迁移的**核心动作是"对照表"**：把讲过的机制**逐条映射**到新场景，而不是重新发明。
- C3 的"失败处理"要**分类**（不同原因走不同出路），**不是一律重试**。
- C4 的"反例自检"是**主动找自己方案的翻车点**，不是罗列优点。
