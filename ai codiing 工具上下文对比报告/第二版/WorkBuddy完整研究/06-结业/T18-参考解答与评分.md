> **这是什么**：`T18-任务包.md` 的配套答案与评分口径。每题给 **①参考答案 → ②允许的替代方案与理由 → ③评分标准（六项能力分别评三级）→ ④补学入口**。

## 0. 六项能力三级评分口径（怎么判"已展示"）

> 判定依据（关键词）取自 **M12 §三「六项能力自评表」**；"已展示"的标准是**能独立给出可复核的证据**，不是"提到过关键词"。

| 能力 | **已展示**（证据充分） | **需提示**（部分具备） | **尚未展示**（缺口明显） |
|---|---|---|---|
| ① 解释信息流 | 能说出"保存的记录 / 当前材料 / 实际请求"**三层差异**，且举出**自己的一个反例** | 能说三层差异，但**举不出自己的反例**（只复述课程例子） | 把三层当一层；或说不出"我看到了 ≠ 模型看到了" |
| ② 推演预算与信息损失 | 算例**含单位与条件**（W/p/M/口径写清），且能指出**一处"会丢约束"的具体环节** | 会算线但**条件/单位不全**，或只说"会丢"但**定位不到具体那一处** | 不会算线；或把"约束丢了"一律归因于"压缩" |
| ③ 选择策略 | 场景 **> 1 个**，每个选择给出**代价**与**一个反例** | 有选择但**缺代价或反例**（只给"建议"） | 只会"选一个"，给不出理由，或写成"排名" |
| ④ 阅读核心源码 | 能在**固定链接（含 SHA）**里指出触发/保留/**写回**三个分支的状态变化（M12 §三 原文作『替换』，此处与 T16 链④ 统一为『写回』） | 能指出**一两个**分支，或**缺 SHA / 缺前后状态** | 指不出分支；或把闭源工具写成"源码" |
| ⑤ 设计与排障 | **四份交付物完整**（状态图 / 伪代码 / 失败处理 / 检查方法），失败表含"**不可重复的副作用**" | 四份**缺一件**，或失败表**漏副作用/幂等** | 只交状态图与伪代码；无检查方法 |
| ⑥ 评估与迁移 | **迁移任务完成**（对照表），验证方案**区分实测 / 推断** | 迁移**部分完成**，或**未区分**实测/推断 | 未迁移；或把推演当实测 |

**两条读表提醒（M12 §三 读表）**：
1. **L5 主落点是 ③⑤⑥**；①②④ 在 L5 是**附带复现**。但**六项都要分别评**——某一项打「尚未展示」，**直接回该列指向的单元补**（见 §5）。
2. **「需提示」是正常的**：两三项需提示**不代表没学会**，代表**还需练习与迁移验证**（M12 §六 可停靠级）。

## 1. 题组 A · 参考答案

### A1 · 独立组装一次请求

**① 参考答案**

**（1）五块料组装表**（本次请求 = 历史 `MSG-001…MSG-014` + 本次输入 `MSG-015`）：

| 块 | 内容 | 由哪些 `MSG-xxx` / 来源构成 |
|---|---|---|
| ① 基础指令 | 系统 / 岗位指令（"你是谁、怎么干"） | **项目内置固定文本**，不在消息序列内（M02 §五块料①） |
| ② developer 材料 | 当前工作状态 + 项目规则 | **项目内置**（工作目录、已加载规则），不在消息序列内（M02 §五块料②） |
| ③ 历史 | 时间序的对话 + 工具调用/结果 | `MSG-001…MSG-014`（含 `MSG-002/005/008/011` 助手消息、`MSG-009` 用户消息、`MSG-010/013/014` 工具结果） |
| ④ 工具说明 | 工具 schema（名称/参数） | 工具注册（`venue_opening_lookup` / `bus_schedule_query` / `ticket_price_query`），不在消息序列内 |
| ⑤ 本次输入 | 用户这一拍说的话 | `MSG-015`（"你整理一下当前状态"） |

**（2）配对不变量**（本段三条工具结果，各带 `toolCallId`）：

| 工具结果 | `toolCallId` | 工具名 | 配对 |
|---|---|---|---|
| `MSG-010` | `call_a1` | `venue_opening_lookup` | ↔ 其助手侧工具调用 |
| `MSG-013` | `call_b1` | `bus_schedule_query` | ↔ 其助手侧工具调用 |
| `MSG-014` | `call_c1` | `ticket_price_query` | ↔ 其助手侧工具调用 |

**配对不变量**（M02；源码对照见 T16-源码桥接 §1②，`history.rs` L962–980，快照 `a07c8eb`）：**每个调用都必须有对应结果**（`ensure_call_outputs_present`）、**每个结果都必须能对回调用**（`remove_orphan_outputs`）。违反时：**孤立结果**（有结果无调用）或**缺失结果**（有调用无结果）都是**坏结构**，程序在材料进历史前强制清洗。

**（3）约束渲染位置**：HC-01/HC-02/HC-03 **渲染在请求头部**（作为"当前工作状态 / 约束表"），并**每轮组装时重渲染**。**不能只靠"历史里说过"**——因为历史里的那句话要过**出口限长 → 活动历史 → 摘要**三关（M05），任何一关都能让它消失；且压缩后"**模型可见层不可自动恢复**"（M06；C-03/C-12）。

**（4）三层区分**：（a）第①层**存档（磁盘）**；（b）第②层**活动历史（内存）**；（c）第③层**请求**。**只有（c）真正影响模型行为**（M06 §一 主结论四句）。

**② 允许的替代方案与理由**

- 把 `MSG-015` 也算进"历史"、把"本次输入"留空：**可接受**，只要**说明你的请求边界定义**（请求是"拼"出来的，边界由你声明）。理由：M02 强调"请求 = 五块料拼装"，边界口径可自定但必须自洽。
- 把 ② developer 材料拆成"工作状态"与"项目规则"两块：**可接受**，更好。理由：M02 §五块料② 本就可细分。
- 只答三条硬约束、不答 SP-01/SP-02：**可接受**（SP 是软偏好，无硬判据）。理由：T03 行程包 §4 明确 SP-01 不参与自动检查。

**③ 评分标准**：本题主要考 **① 解释信息流**（见 §4）。**③④** 不适用。

**④ 补学入口**：① 解释信息流 → **M01 · 为什么需要上下文管理**（三层直觉）、**M02 · 一次请求的组成与工具循环**（五块料 + 配对不变量）、**M06 · 恢复与持久化**（三层记录主结论）；配对不变量源码 → **T16-源码桥接 §1②**（`history.rs` L962–980）。

### A2 · 预测哪些约束会丢

**① 参考答案**

**（1）逐缺陷定位表**（四问：①没读进来？②进过历史但被裁了？③进过历史但摘要漏了？④都在但旧决定没作废？）：

| 缺陷 | 丢在哪一处 | 判断线索 | 人为对策 |
|---|---|---|---|
| D1 漏 HC-01（16:00） | **③ 摘要请求（摘要改写）** | 坏摘要通篇无"16:00"；HC-01 来源 `MSG-001` 是**用户消息**（在历史里，非工具输出） | 约束**单独建表** + 每轮重渲染 + 摘要显式要求保留（写成**验证问题**） |
| D2 复活 REJ-01（17:30 返程） | **③ 摘要改写（状态丢失）** | `MSG-004` 明确否决，摘要却写"返程按 17:30 安排" | 被否项标"**已否决**"不删；结构化字段用 REJ id |
| D3 未完成写成完成 | **③ 摘要改写（状态谎报）** | 真值 `车辆预订/校方报备=未开始`、`行程已确认=false`（§1.1(c)），摘要写"已完成" | `statusClaims` 对齐真值；不得声明已完成 |
| D4 人数漏项（60 vs 64） | **③ 摘要改写** | `MSG-001`：60 学生 + 4 老师 = 64（HC-03） | 摘要显式写 64 人同批 |
| D5 丢失 REJ-02（校门口） | **③ 摘要改写（状态丢失）** | REJ-02，`MSG-006` | 保留"校门口已否决（施工封闭）" |

> **一句话**：本坏摘要的 D1/D2/D4/D5 属**"摘要改写（③）"**环节；**但**若关键事实原本躺在**工具输出中段**（如 §1.1(d) 文件第 154 行 / L7-143 的否定证据），则它**先在"①出口限长 / ②活动历史"就死**——所以**排查不要只怀疑压缩**（M05 §场景）。

**（2）头尾裁剪推演**（`长工具结果-公交查询-v1.txt`，300 行）：

| 关键事实（双标） | 头尾裁剪后 |
|---|---|
| 头 4 / 5 行（总记录数、车程 55 分钟） | **幸存**（保头） |
| 中 150 行 / L7-139（14:20 可选） | **必丢**（中段被删） |
| 中 151 行 / L7-140（14:35 可选） | **必丢** |
| 中 **152 行 / L7-141（推荐，14:50）** | **必丢** → **最优选择丢失** |
| 中 153 行 / L7-142（15:05 压线） | **必丢** |
| 中 **154 行 / L7-143（15:20 不可用）** | **必丢** → **HC-01 的"否定证据"最先死** |
| 中 155 行 / L7-144（15:50 不可用） | **必丢** |
| 尾 295 / 296 行（结论注释） | **幸存**（保尾，但只是"可选班次仅 14:20/14:35/14:50"的**结论**，**不是**原始行） |
| 尾 298 行（车辆报价 1400） | **幸存** |

**为什么否定证据最先死**：154 行在**中段**，头尾裁剪"**保头、保尾、删中间**"（M05 §三）——它**不区分"肯定事实"与"否定事实"**，中段一律删。于是"**15:20 及以后不可用**"这条**支撑 HC-01 的否定证据**丢失，只剩尾部的**结论注释**（而结论注释是**二手概括**，不是原始班次行）。

**（3）复活风险**：D2/D5 属 **"已否决决定复活"** 类失败。**为什么写进摘要仍不够**：摘要**有损**，"否决"是一种**状态**——把状态交给概括，既**不可验证**（不知道它还在不在），又**可能被改写成"有效计划"**（D2 正是如此）。正确做法：**约束表**里被否项标"已否决"而**不删**，渲染时可见"已否决"状态（M11 §一；样章 U09 自测⑨）。

**（4）未完成写完成**：**结构化字段存在时**由 `CHK-FC-STATUS`（`status_claims`）**直接判定**——比较候选 `statusClaims` 与真值 `groundTruthStatus`（`车辆预订/校方报备=未开始`、`行程已确认=false`），声明"已完成"即违规。**只有自然语言时**无法自动判定，须靠**人工 / 语义复核**（对齐 T03 行程包 坏摘要样例 §检验方式）。

**② 允许的替代方案与理由**

- 把 D1 定位到 **"② 活动历史 / ③ 摘要"两处都算**：**可接受**。理由：HC-01 原始句在用户消息（历史），摘要改写漏掉是主因；但若该句曾被工具输出引用过，也可能先在②被裁——**只要给出你的判断线索**（哪一层先动手）即算正确。
- 主张"**D3 也能在①出口限长丢**"：**不适用**——D3 是**状态声明**（"已完成"），其真值来自 `任务定义.json#groundTruthStatus`，不在工具输出里。**扣分点**：把"状态谎报"错归到"工具输出裁剪"。

**③ 评分标准**：本题主要考 **② 推演预算与信息损失**；附带考 **① 解释信息流**（三层）。见 §4。

**④ 补学入口**：② 推演预算与信息损失 → **M05 · 工具输出治理**（§二 三处限长 / §三 裁剪算法 / §四 落盘与找回 / §产出物 损失点定位表）；**M06 · 恢复与持久化**（材料四态 / C-03/C-12 两层事实）；**M04 · 压缩与摘要**（摘要**有损**）；冲突裁决 **附录 C · C-03/C-12**。

### A3 · 给出保留策略

**① 参考答案**

**（1）约束表设计**

```text
ctx.constraints = [ { 文本, 来源(MSG-xxx), 状态(有效/已否决), 更新时间 } , … ]
```

**两条取舍理由**（必须写出）：
- **为什么用户消息优先保留**：硬约束与"否决"的**来源都是用户消息**（HC-01 `MSG-001`、HC-02 `MSG-003`、HC-03 `MSG-001`、REJ-01 `MSG-004`、REJ-02 `MSG-006`、REJ-03 `MSG-012`）——用户消息承载**最值钱的意图**，保留算法"用户消息优先、从新到旧装预算"（M04 保留骨架；T16-源码桥接 链②）。
- **为什么约束单独建表、不跟摘要走**：摘要**有损**，关键状态交给概括**无法验证**（M11 §一）——约束表是**结构化状态**，可每轮**重新渲染**、可被检查器**判定**。

**（2）每轮重渲染 + 恢复先验证**：约束表**渲染在请求头部**，**每轮组装时重新渲染**（不依赖历史里的那句话还在不在）。第二天恢复后，**先重述验证有效约束**（对齐 `MSG-017`："先说一遍现在有效的约束还有哪些"）——对应 **M06 恢复三形态**（Codex = 替代历史 + 后缀回放）。

**（3）否决的保存语义**（正例各一）：
- **结构化正例**：`selectedOptionIds` **不含** REJ id（且不含被否项）——如 T03 行程包正例 `positive-动物园方案.json`：`selectedOptionIds = ["OPT-ZOO", "OPT-BUS-1435"]`，`assemblyPointId = "LOC-PLAYGROUND"`（不是被否的 `REJ-02`）。被否集合 = `rejectedIds`（含 `REJ-01/02/03` 及其别名）。
- **文本正例**：`notes` 带**否决动词**——如 `positive-动物园方案.json`：`"17:30 返程与校门口集合此前均已否决，不再采用；集合点操场，64 人两车同批。"`（含"否决"→ **不判复活**，见 §1.1 判据规则）。

**（4）预算演算**（参数【演示】，非实测）：

```text
给定：W = 200,000；p = 95；M = 150,000；范围口径 = total；A = 152,000
基础线 = (W × 9) / 10 = 200,000 × 9 ÷ 10 = 180,000
范围线 = min(M, 基础线) = min(150,000, 180,000) = 150,000
整段线 H = W × p / 100 = 200,000 × 95% = 190,000
判定：A = 152,000 ≥ 150,000 → 【范围线到线】（整段 152,000 < 190,000 未到）
     → 触发到线 = 范围线 OR 整段线 = 真 → 到线成立
```

- **M 缺失时**：范围线**回退到 90% 基础线 = 180,000**（`map_or(context_limit, …)`）。
- **"缺失 ≠ 限额为 0"**：字段是 `Option`——`None` 表示"**用默认线**"，不是"限额为零 / 永不压缩"（M03 自测②）。

**② 允许的替代方案与理由**

- 约束表用**不同字段名**（如 `constraints[]` 里 `state: "rejected"`）：**可接受**，只要**语义等价**（有效 / 已否决，且**不删**）。
- **保留预算自定**（如"单条工具结果 ≤ 3,000 token"）：**可接受**，但**必须标依据**（照抄 Codex 20,000 常量 / 还是自己定的）——对齐样章 U09 交付 1 要求。
- 主张"**把约束写进系统指令就永远不丢**"：**需提示**——系统指令也在**同一窗口**里、也受触发线约束；"永远不丢"是**过度承诺**（【T19 实测：单次/多轮压缩后约束基本未丢（E1 全 PASS），但 **grok 3 次连续压缩后硬约束丢失** → "永远不丢"确被否证（证据：T19/07-grok.md §连续压缩）】）。

**③ 评分标准**：本题主要考 **③ 选择策略**（保留策略 + 每个选择给代价与反例）；附带考 **⑤ 设计与排障**（约束表 = 设计四件套之一）、**② 推演预算与信息损失**（预算演算）。见 §4。

**④ 补学入口**：③ 选择策略 → **M04 · 压缩与摘要**（保留骨架）、**M11 · 设计与排障**（§一 设计四件套 / §四 场景决策表纪律"每个决定配一个反例"）；② 预算 → **M03 · 预算与触发**（§二 四本账三条线 / §五 算例 / 自测②）；术语 → **附录 A · 预算与触发族**。

### C1 · 状态图（示范）

```text
主代理状态对象：
  ctx.messages     材料列表（含角色 / 配对 / 来源标签）
  ctx.constraints  约束表 {文本, 来源, 状态(有效/已否决), 更新时间}   ← 否决标"已否决"不删
  ctx.usage        用量计 {上次服务端用量, 本地新增估算, 基线}
  ctx.checkpoint   最近一次整理的替代历史（含替代列表 + 窗口号）

子代理状态对象（每个子代理各自一份，互不共享）：
  sub.messages     子代理自己的材料列表（读它那份大文档）
  sub.usage        子代理独立用量计（单独计费/单独窗口）

一轮任务读写：
  读输入 → 更新 constraints（新约束入表；被否的标"已否决"）
        → 组装请求（约束表渲染在头部；messages 按时间序）
        → 调模型 → 若派子代理：主代理只**接收子代理回传的摘要/交接材料**（不回灌子代理全文）
        → 用量检查：范围线或整段线到线？ 是 → 整理 → 写检查点（追加，不删旧记录）
        → 输出或继续循环
```

**必须回答的两问**：
- **"中间几十次工具调用去哪了"**：留在**子代理自己的上下文**里；主代理只拿到**子代理的结论/摘要**（M08：子代理有**独立消息列表与单独用量**）。
- **"主窗口怎么不被污染"**：主代理**不接收**子代理的原始工具输出全文，只接收**交接材料**（M08 交接边界）。

### C2 · 伪代码（示范 + 取舍理由 + 一处故意不同）

```text
function 一轮(输入):
    ctx.constraints ← 更新(输入)            # 新约束入表；被否的标"已否决"（不删）  【理由①】
    请求 ← 组装(①基础指令, ②developer材料, ③ctx.messages, ④工具说明, ⑤输入,
                约束表渲染在头部)          # 约束每轮重渲染  【理由②】
    回复 ← 调模型(请求)
    if 回复要工具:
        结果 ← 执行工具(); ctx.messages.append(配对登记(结果))   # 配对不变量
    if 回复要子代理:
        for 子代理 in 并行派发(3):
            子代理.独立执行(它那份文档)     # 独立 messages / 独立 usage
        ctx.messages.append(子代理回传的摘要/交接材料)   # 只回传结论，不回灌全文
    if 到线(范围线 or 整段线):
        整理() → 写检查点(追加，不删旧记录)
    return 回复或继续循环

恢复（第二天）:
    加载最新检查点 → 用替代历史重建 → 回放其后记录
    **先重述验证"被否决的方案没复活 + 兼容/关键约束仍在场"**   # 先验证再动手
```

**取舍理由**：
- 【理由①】**用户消息优先**：用户消息承载关键约束与否决（最值钱的意图），保留算法"用户消息优先、从新到旧装预算"（M04）。
- 【理由②】**约束单独建表、不跟摘要走**：摘要**有损**，关键状态交给概括**无法验证**（M11 §一）。
- **一处与代表实现（Codex）故意不同**（示例）：**主代理只接收子代理摘要、不接收子代理原始工具输出**（Codex 无此"多子代理并行"形态的直接对照；此处为**面向本场景的设计选择**）——理由：**防止主窗口被三份大文档的工具输出污染**，代价是**丢失子代理的原始证据**（若需取证，须**显式重读**子代理落盘）。

### C3 · 失败处理表（示范）

| 失败 | 分类 | 怎么发现 | 行动 | 不可重复的动作（副作用） |
|---|---|---|---|---|
| 子代理失败 | 中断 / 取消 / 预算耗尽 | 子代理返回错误 / 超时 | **只重跑失败的那个子代理**；已成功的子代理**不重跑** | 子代理若已写盘 → 写盘不可回退 |
| 汇总失败 | 超窗口 / 验收不合格 | 汇总产物缺完成事件 | **活动历史保持原样**（③失败 → ④不执行）；下轮再试或提示用户 | — |
| 整理失败 | 超窗口 / 验收不合格 | 四步哪一步断的（③验收 / ④安装） | 活动历史**保持原样**；记录诊断；下轮再试 | 已写盘文件 / 已推送提交 |
| 恢复后丢约束 | — | **恢复后先验证**（重述检查） | 从**约束表重新渲染**；必要时重发 | —（读操作可重复） |
| 工具结果被裁剪 | — | 日志关键行是否在场 | **重读方案**（重跑测试 / 看落盘文件）；防重复读取 | 重跑测试若会写盘需防护 |

**有界重试 + 双计数**（M11 §二）：**缩副本循环**（如 Codex 超窗口"移除副本最早项 + `retries=0`"）**≠ 退避循环**（针对外部一闪而过的错误，**总次数有上限**）——**两者用不同计数**；看到 `retries = 0` **不是死循环**。

**副作用与幂等**（M11 §三）：**恢复重建的是"材料"不是"动作"**；**副作用不可回退**（写盘 / 已推送提交 / 已应用 sandbox）；**"恢复后是否重复执行工具"未裁决** → **【T19 实测：E4 恢复条件下未见工具重复执行（codex 0 命令、pi 0 工具动作）；专门副作用注入未做 → 保留未决（证据：T19/01-codex.md §A-6、02-pi.md §5）】**——设计时只能**标出不可重复动作并加防护**，**不能宣称**"一定不会重跑"。
