## 1. 最小实现题（三选一，或全做）

> 三题**互相独立**。**推荐顺序**：E1 → E2 → E3（E1 练"损失点"，E2 练"约束保全"，E3 练"用检查器验证"）。

### E1 · 实现"头尾裁剪"函数（对齐 M05 §三）

**要求**：写一个函数 `truncate_middle(text, max_tokens)`，实现 Codex 的**近似 token 头尾裁剪**（口径 = T16-源码桥接 链③ / M05 §三）：

```text
输入：text（字符串）、max_tokens（近似 token 预算）
规则（照 Codex truncate.rs 伪代码）：
  若 text 为空 → 返回空
  若 max_tokens > 0 且 字节数(text) ≤ max_tokens × 4 → 原样返回（装得下就不裁）
  max_bytes = max_tokens × 4
  左预算 = max_bytes ÷ 2           # 整数除法（向下取整）
  右预算 = max_bytes − 左预算       # 奇数时多 1 字节（左右并非严格均分）
  头部 = text 从 0 到"左预算"的最近 UTF-8 边界
  尾部 = text 从 (总长 − 右预算) 的最近 UTF-8 边界到结尾
  标记 = "…N tokens truncated…"（N 按被移除字节数 ÷ 4 估算）
  返回 头部 + 标记 + 尾部
```

**必做的三条断言**（把结论写成可运行断言）：

1. **标记不占预算**：含标记后的**最终字节数 > max_bytes**（不是"严格等于预算"）——照 M05 §三 细节 3。
2. **左右非严格均分**：当 `max_bytes` 为奇数时，**右比左多 1 字节**——照 M05 §三 细节 2。
3. **中文不被切成半个字**：对含中文的文本，头部/尾部都落在 **UTF-8 边界**上（照 M05 §三"裁剪按字节算，但落刀看字符"）。

**自测（对齐 M05 自测① 的同一量级）**：文本 = **30 个 ASCII 字符**（30 字节），`max_tokens = 5` → `max_bytes = 20`（**装不下**，因 30 > 20）→ 左 = 10、右 = 10；移除 = 30 − 20 = **10 字节** → `N = ceil(10/4) = 3`；结果 = **前 10 字符 + `…3 tokens truncated…` + 后 10 字符**；**最终字节数 = 20 + 标记长度 ≠ 20**。
> 对照：**M05 自测①** 直接给"字节预算 = 10"，故得左 5 / 右 5、`N = ceil(20/4) = 5`。两题**同口径**，只是预算单位写法不同（本题用 `max_tokens`，M05 用字节）——**以你的实现输出为准，数量级对齐即可**。

### E2 · 实现"约束表 + 否决状态 + 每轮重渲染"（对齐 M11 §一 / A3）

**要求**：写一个最小的 `ctx.constraints` 结构 + 一个 `render()` 函数，实现：

1. **入表**：从"用户消息"里登记约束（有效）；
2. **否决**：被否项标 `status = "rejected"`，**不删除**（保存"已否决"状态）；
3. **重渲染**：`render()` 每轮把**有效约束 + 已否决项（标注"已否决"）**输出为一段可放进请求头部的文本；
4. **产出候选 JSON**：为行程任务生成一份符合 `candidateSchema` 的候选 JSON（字段见 §3），**其中被否项不得出现在 `selectedOptionIds`**。

**验收点**：
- `render()` 输出里，**被否项带"否决"字样**（不判复活）；
- `selectedOptionIds` **不含** `REJ-01/02/03`（结构化判据）；
- `statusClaims` **与真值一致**（真值未开始时不得声明已完成）。

### E3 · 用 T03 检查器跑你的候选（对齐 T03 检查器 + 判据降级）

**要求**：

1. 用 E2 产出的候选 JSON，跑**检查器单次检查**（命令见 §2.1）；
2. **预期比对**：先**预测**你的候选该 PASS 还是 FAIL、会命中哪条 `CHK-*`，再**跑**、再**对照**（这就是"先写预期事件、后对照"的纪律，照 实验规程 §4 A3）；
3. **反例练习**：把候选**故意改坏一处**（如把 `returnTime` 改成 `17:30`、或把 `assemblyPointId` 改成被否的 `REJ-02`），**预测**命中的 `severity`，再跑；
4. **降级纪律**：如果你的候选在 `notes` 里写了被否项关键词，**说明** `CHK-REJ-TEXT` 是**启发式**——请**同时**给出结构化字段证据（`selectedOptionIds` / `assemblyPointId`），并注明"**已人工复核**"（照 实验规程 §5）。

**接口兼容任务**：

```json
{
  "apiDiff": {
    "addedFields": [{ "name": "displayName", "type": "string", "nullable": true }],
```
