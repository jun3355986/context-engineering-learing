# AI 上下文管理 · 源码导读入口

> **这份入口解决什么**：读完课程母稿后，要"**进工具包、看真实源码/证据**"时，**不知道点哪里**。本页把 **工具包导读 ↔ 固定快照 SHA ↔ 证据卡 ↔ 结论表章节 ↔ 课程单元** 五者**一次性对上**，一条链走到底。
> **依据（三件，文字指称）**：
> 1. **八工具导读索引**——每工具一行（快照 SHA / 本地版本 / 导读文件 / 主链路 / 单元互链）（发布时替换为链接）。
> 2. **源码桥接（代表链）**——最小桥接六件套 + 一条真实调用链（Codex）（发布时替换为链接）。
> 3. **第二套链与差异**——第二套工具链（pi）+ 闭源工具"可见边界怎么读"（发布时替换为链接）。
> **纪律**：**不排名次**；**未知保留未知**（"未发现"≠"没有"）；**双快照不混用**；**闭源不补造源码**；**Gemini 仅历史存档**。

## 一、读表三件事（先看这个）

1. **开源走"源码链"，闭源走"可观测行为链"**——Claude / Grok **没有源码**，每一步都注明【①文档】/【②分发件观察】，**不得写成"源码"**。
2. **快照 ≠ 本机版本**：第一列是研究快照（我读的是哪份代码），第三列是本机跑的版本——**两者别混**。
3. **Gemini 只作存档**：不进正文对照主线，只保留"曾经怎么做的"历史记录。

## 三、代表链（跟着真实代码走一遍）

**代表链 = Codex**，用**样章基线快照 `a07c8eb`**（与课程母稿代表链、附录一致）。源码桥接把**最小桥接六件套**深化到"**可跟做**"：

| 件 | 一句话 | 生活对照 |
|---|---|---|
| ① 列表 / 对象 | 列表=有序格子；对象=带名字的字段 | 购物清单 / 药盒 |
| ② 函数 / 调用 | 一个名字对应一段动作 | 按一个按钮 |
| ③ 条件分支 | 满足条件才走这条路 | 岔路口 |
| ④ 循环 | 反复做直到停下 | 转圈直到说停 |
| ⑤ 数据结构 | 把几条信息装在一起 | 抽屉分格 |
| ⑥ 事件 / 钩子 | 某时刻自动触发 | 定时闹钟 |

**六件套 → 一条链**：`build_prompt`（组装）→ 到线判定（触发）→ `compact.rs`（保留+重组）→ 替换内存+追加检查点（写回）→ `rollout_reconstruction.rs`（替代历史+后缀回放）。

**每条链都配**：进入条件 / 前后状态 / 失败栏 / 自测与答案。详见**源码桥接（代表链）**（发布时替换为链接）。

## 四、第二套链与闭源读法

### 4.1 第二套链 = pi（快照 `b45e0eb`）

**两套链一页对照（同形，差别在每段做法）**：

```text
节点        ① Codex（a07c8eb）                        ② pi（b45e0eb）
────────────────────────────────────────────────────────────────────
组装   build_prompt：input+tools+base_instructions    _installAgentRequestProjection：
       +output_schema；WorldState 差分更新              projection.messages + tools；
                                                        系统提示词具名 section + 逐段 diff
触发   两条线：范围线 min(M,90%W) OR 整段线 W×95%      一条线：A > W − reserveTokens(16384)
摘要   本地模板 / 远端 v2（替代历史 encrypted_content） 固定结构摘要 + UPDATE 增量；序列化截断
保留   候选=真用户消息，从新到旧装 20,000 共享预算      切点=user/assistant 边界，绝不切 toolResult
工具输出 ceil(bytes/4) 头尾 + 分片 64KiB + 落盘预览    2000 行/50KB 先到者；read 保头 / bash 保尾
恢复   替代历史 + 后缀回放                             持久化断点：摘要 + firstKeptEntryId 直接重建
```

**一句话记忆**：**Codex 把"两条线 + 替代历史 + 后缀回放"当骨架；pi 把"一条线 + 可重建投影 + 持久化断点"当骨架。** 两者都在**磁盘上追加、不删旧记录**——差别在**模型看见什么、怎么重建**。

**六节点走读**：组装 / 触发 / 摘要 / 保留 / 工具输出 / 恢复——每段给"进入条件 / 前后状态 / 失败 / 自测和答案"；§7 差异表**只讲差异、不排名次**。详见**第二套链与差异**（发布时替换为链接）。

### 4.2 闭源工具（Claude / Grok）——"没有源码时怎么读"

- 文件名是**证据导读**而非源码导读（实现闭源，无可读源码）。**禁止**把反混淆产物或二进制字符串当"源码"引用。
- **三类证据角标**：**【①文档】**（产品承诺行为）/ **【②分发件观察】**（本机可观测项，标注观察方法）/ **【③社区线索】**（仅线索，不得独立证明）。高风险主张（触发阈值、默认开关、落盘、持久化、缓存）**必须同时给等级与"不能证明"**。
- 每包有**不可观测边界清单 U-01~U-07**，读者据此理解"可见边界"。

### 4.3 Gemini CLI —— "历史·存档"

## 五、三条写法纪律（引用任何源码事实）

1. **三行写法**（至少三行）：① 研究快照 `<仓库> @ <40 位 SHA>`；② 分发件/本地版本 `<版本号>（与快照：一致/漂移）`；③ 与官方最新关系 `<同步/落后/已弃用>（核验日期）`。
2. **双快照不混用**（Codex）：`a07c8eb` 为**只读对比参考**，`76ed3b4` 为**正文默认快照**；**同一段落不混用两份快照证据**；行号会偏（`a07c8eb` 的行号**不能**直接套到 `76ed3b4`）。
3. **闭源不补造源码**；**未知保留未知**；**接口名/桩 ≠ 默认行为**。
