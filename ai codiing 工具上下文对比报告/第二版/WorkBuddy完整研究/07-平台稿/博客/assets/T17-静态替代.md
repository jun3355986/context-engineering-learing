## ① 预算/触发演算器（默认样例 · 静态）

**舞台参数（演示）**：W = 200,000；p = 95；M = 150,000；A = 152,000；scope = total。

```
桌子总容量 W = 200,000 ────────────────────────────────┐
    │ × p% (95)                                        │
    ▼                                                  │
有效窗口 H = 190,000 ══════════════ 整段线（硬检查）    │
    │                                                  │
    │ 基础线 = 90% × W = 180,000 ─ ─ ─ ┐               │
    │                                  ├─ 取小 → 范围线 = 150,000
    │ 模型字段 M = 150,000 ─ ─ ─ ─ ─ ─ ┘               │
    │                                                  │
当前用量 A = 152,000 ●────────→ 比：A ≥ 范围线? 是     │
```

**判定表**

| 项 | 值 | 角标 |
|---|---|---|
| 四本账 W / p / H | 200,000 / 95 / **190,000** | H 公式=源码常量 |
| 基础线 `(W×9)/10` | **180,000** | 源码常量 `codex-trigger-02` |
| 范围线 `min(M, 基础线)` | **150,000** | 源码常量 `codex-trigger-01` |
| 当前用量 A（scope=total） | **152,000** | 演示 |
| 范围线到线？ | **是**（152,000 ≥ 150,000） | — |
| 整段线到线？ | 否（152,000 < 190,000） | — |
| **触发到线 = 范围线 OR 整段线** | **到线成立** | 源码常量 |

**八工具口径（切换对照）**

| 工具 | 触发口径 | W=200,000 时的线 | 类别 |
|---|---|---|---|
| ① Codex | 范围线 `min(M,90%W)` 或 整段线 `W×95%` | 150,000 / 190,000 | 两线式 |
| ② Claude Code | 占窗口百分比（默认未公布 `【T19 实测：代理条件触发 ≈98%（98,014~98,015/100k 窗口）；默认百分比仍未公布（证据：T19/03-claude §3）】`） | 无法判定 | 比例式 |
| ③ pi | `W − 16384` | **183,616** | 预留式 |
| ④ oh-my-pi | `W − max(15%W, 16384)` | **170,000** | 预留式 |
| ⑤ OpenCode v1 | `reserved=min(20000,maxOutput)`；`usable=limit.input−reserved` | 与窗口无关（先扣 2 万） | 预留式 |
| ⑥ OpenCode v2 | `W − max(10%W, 16000)` | **180,000** | 预留式 |
| ⑦ Gemini（历史·存档） | `0.5 × W` | 100,000（1M 时 524,288） | 比例式 |
| ⑧ Grok Build | `85% × W` | **170,000**（与④数字同、机制不同） | 比例式 |
| ⑨ dsh | `floor(min(0.8W, W−O−65536))`，O=16,000 | **118,464** | 双上限 |

**五个算例（母稿 M03 原样）**：例1 范围线到线（见上）；例2 预留式三兄弟 183,616 / 170,000 / 180,000；例3 dsh 118,464；例4 ocv1 绝对预留（W=200,000、maxOutput=32,000 → reserved=20,000、usable=180,000）；例5 同一段 400 汉字（1,200 字节）→ dsh `ceil(400/4)`=**100**（实测 108，低估）/ Codex `ceil(1200/4)`=**300** / Gemini `400×1.5`=**600**。

## ② 裁剪器（默认样例 · 静态）

**默认舞台（演示）**：样本 300 行 ≈ **22,003 字节 / 17,190 字符**（T03 样本）；预算 max_tokens = **1,000**；关键行位置 = **中部（第 150 行）**。

**计算（Codex 近似 token 口径，源码常量 `codex-trunc-01`）**

```
max_bytes = 1,000 × 4 = 4,000
左预算 = floor(4,000 / 2) = 2,000 字节
右预算 = 4,000 − 2,000  = 2,000 字节（奇数差 1 字节给尾部）
每行 ≈ 22,003 / 300 ≈ 73.3 字节
头部保留行数 = floor(2,000 / 73.3) ≈ 27 行
尾部保留行数 = floor(2,000 / 73.3) ≈ 27 行
中段移除 = 300 − 27 − 27 = 246 行
移除字节 = 22,003 − 4,000 = 18,003 → 标记 N = ceil(18,003 / 4) = 4,501
```

**条带示意**

```
[第 1–27 行]  头部保留（含表头/命令）            ← 保留
…4,501 tokens truncated…（中段 246 行被删）        ← 标记另加，不占预算
[第 274–300 行] 尾部保留（含结论/汇总行）        ← 保留
```

**关键行命运（位置切换）**

| 关键行位置 | 命运 | 死在哪一关 |
|---|---|---|
| 中部（第 150 行） | **已消失（位于被移除的中段）** | ① 出口限长（保头尾阶段）——根本轮不到摘要 |
| 头部（第 1 行） | **幸存（头部保留区）** | 过了①；仍可能被②历史裁剪或③摘要带走 |
| 尾部（第 300 行） | **幸存（尾部保留区）**（300 > 300−27=273） | 同上 |

**三处限长链**：`工具执行 → ①出口限长（预览+警告头）→ ②活动历史（裁剪副本；存档另存原载荷）→ ③摘要请求（历史副本）→ 下一次请求`。

## ③ 压缩四幕（默认样例 · 静态）

**默认舞台**：本地摘要路径，保留预算 P_max = **20,000**【源码常量 `codex-retain-01`】；用户过往原话从旧到新 **M1=12,000 / M2=10,000 / M3=6,000**（演示）。

**逐步演推**

| 幕 | 动作 | 结果 | 剩余预算 |
|---|---|---|---|
| 0 | 整理前 | 桌上有 M1/M2/M3 + 一条旧摘要 | 20,000 |
| 1 | ① 筛候选 | 只收真用户消息；旧摘要靠前缀识别**排除** → 候选 M1/M2/M3 | 20,000 |
| 2 | ② 用预算（从新到旧） | 装 M3（6,000 ≤ 20,000）→ 剩 14,000；装 M2（10,000 ≤ 14,000）→ 剩 4,000 | 4,000 |
| 3 | ③ 边界截短（保头尾、就停手） | M1（12,000 > 4,000）→ 头尾片段约 **4,000** + 截断标记；**不回头补缝** | 0 |
| 4 | ④ 产物另加 | 追加**新摘要**（不占原话预算） | 0 |
| 5 | ⑤ 重组规则 | 当前规则与环境**摆回靠前** | 0 |

**最终替代历史（样例 A）**：

```
[① 规则与环境] → [M1 截短片段 ~4,000] → [M2 原样] → [M3 原样] → [新摘要]
```

**变式（母稿自测②）**：M1=9,000 / M2=16,000 / M3=7,000 →
装 M3（7,000，剩 13,000）；M2（16,000 > 13,000）→ 边界截短约 **13,000**，停止。
最终顺序：`[规则] → [M2 截短片段 ~13,000] → [M3 原样] → [新摘要]`；**更旧的 M1（9,000）不会被「补缝」装进来**。

**连续压缩（再压一次）**：新整理把「上一轮摘要」当旧摘要**排除**，基于更新材料重生成摘要 → **摘要套摘要**。增量合并判为**有损**；连续压缩是否漂移（C-04 / LQ-09）→ `【T19 实测：单次压缩各工具 E1 全 PASS；grok 3 次连续压缩后硬约束丢失（首例直证，非复活非幻觉）；方向已证、程度未量化（证据：T19/07-grok §3）】`（本教材按演示对待）。

**两层事实（C-03/C-12）**：模型可见层**不可自动恢复**；磁盘原文层**保留期内可查**（②约 30 天；⑤⑥约 7 天）。

## ④ 状态机（四态 × 三层 · 静态）

**默认舞台（演示）**：压缩前历史 = M1(12,000)/M2(10,000)/M3(6,000)；替代历史 = [规则]/[M1 截短]/[M2]/[M3]/[新摘要]。

| 层面的状态 | 压缩前 | 压缩后 | 关闭程序 | 重开 resume |
|---|---|---|---|---|
| ① 存档（磁盘） | 已有全部记录 | **追加**检查点（旧记录仍在） | 不动 | 不动 |
| ② 活动历史（内存） | 原始列表 | **被替换**为替代历史 | 内存态消失 | 由「检查点替代历史 + 后缀回放」重建（或断点重建） |
| ③ 下次请求 | 原列表组装 | 带上替代历史 | — | 与压缩后一致（除非后缀里又有变化） |

**读表一句话**：**磁盘不动、内存被换、请求跟着内存走。**

**材料四态**：原样留下（②活动历史）/ 变摘要（替代历史里的摘要）/ 移除（仅存于①存档——**「移除」≠「删除」**）/ 落盘（磁盘文件 + ②里的引用）。

**恢复三形态**：A 替代历史 + 后缀回放（① Codex）；B 持久化断点（③④⑤⑥⑨）；C 重放 / 重建（⑦⑧）。**都不重发被替代的原始旧消息。**

## ⑤ 检索 / 记忆 / 交接（静态）

**按需读入三件套（默认演示）**

```
第 1 步 glob（列文件）→ 候选：api.ts / api.test.ts / user.ts / config.ts / …（5 个）   ← 只有名字，无正文
第 2 步 grep（定位行）→ 命中：api.ts:40 → buildPrompt(…)                             ← 只有位置
第 3 步 read(offset=40, limit=50) → api.ts 第 40–90 行正文                            ← 取正文；读不完给下一段起点
```

**对照（错误做法）**：全量装填 = 把整仓库几十万字一次搬上桌 → 窗口装不下，且 99% 内容与本次改动无关。

**`@文件` 引用语义**：`@src/api.ts` → 只把 `src/api.ts` 作为**路径候选**给模型（**不读、不附内容**）；模型必须**再调 read 工具**才看到正文。**提及 ≠ 附带内容。**

**三问判断卡（口径来自 T14 C 表 / M08）**

| 工具 | ① 默认开还是关 | ② 后台跑还是会话内跑 | ③ 人工审批还是自动写入 |
|---|---|---|---|
| ① Codex | 未核（有 memories crate） | 未核 | 未核 |
| ② Claude Code | 开（auto memory） | 会话内（模型自己读写；后台机制文档未描述） | 自动 |
| ③ pi | 无（未发现默认，推断） | — | — |
| ④ oh-my-pi | 关（默认 off） | 会话内（选定后端后注入） | 自动 |
| ⑤/⑥ OpenCode | 无（未发现默认，推断） | — | — |
| ⑦ Gemini（存档） | 关（后台提取默认关） | 后台（空闲≥3h 且 ≥10 条 user 消息） | 人工审批（/memory inbox） |
| ⑧ Grok | 关（实验特性） | 后台（每轮复盘 + Dream） | 自动 |
| ⑨ dsh | 无（未发现默认，推断） | — | — |

**四个边界**：记忆（独立记忆目录，启动注入）≠ 会话（磁盘 transcript，恢复读回）≠ 磁盘原文（落盘文件，用时才读）≠ 缓存（服务端 KV，前缀相同才复用、不改内容）。

**子代理两路线**：全新独立窗口（默认；看不到主对话历史；只回摘要）vs fork 继承（继承全部消息历史）。③ pi = **刻意不含**（设计选择）。

## ⑥ 账单器（三组账单 · 静态）

**统一舞台（演示）**：input = 100,000；稳定前缀 96,000；本次新增 4,000；费率（服务端文档示例，非实测）普通 1× / 读取 0.1× / 写入 1.25×。

**拆账三关系**：① 读/写都是 `input_tokens` 的明细拆分（**不要再加到 input 上**）；② 普通 = input − 读 − 写；③ 当量 = 普通×1 + 读×0.1 + 写×1.25。

| 账 | 场景 | cached | write | 普通 | 当量 | 相对全额 |
|---|---|---|---|---|---|---|
| ① | 一次命中（前缀未变） | 96,000 | 0 | 4,000 | **13,600** | ≈0.14× |
| ② | 一次失效（前缀被改） | 0 | 100,000 | 0 | **125,000** | 1.25× |
| ③ | 一次压缩周转 | 20,000 | 40,000 | 40,000 | **92,000** | ≈0.92× |
| 自算（母稿自测①） | input=50,000 | 40,000 | 2,000 | 8,000 | **14,500** | ≈0.29× |

**账③ 读法**：92,000 **不是「压缩的成本」**——它是「前缀变了导致这一次复用少」的账；压缩的模型调用成本是另一笔（M04 摘要调用）。数字全部为**演示**。

**边界四问（R14）**：缓存 ≠ 摘要 / ≠ 外部记忆 / ≠ 容量扩展 / ≠ 少发材料。

**场景决策表（T14 §G，8 场景 + 反例）**

| 场景 | 建议 | 反例 / 陷阱 |
|---|---|---|
| 需要找回「被压缩掉的原文」 | 走磁盘/存档入口 | ❌ 别信「绝不可能找回」（C-12：仅模型可见层成立） |
| 估算中文内容的成本 | 用真实 tokenizer（T19 可核） | ❌ `chars/4` 系列会低估；Gemini 非 ASCII ≈1.5/字符则高估（C-06） |
| 依赖子代理工作流 | 选默认含子代理的工具（④/⑨ 等） | ❌ pi 刻意不含（`pi-cm09-01`）——「没找到」≠「忘了做」 |
| 想要开箱即用的长期记忆 | 注意：大多默认关（④off / ⑦false / ⑧关） | ❌ 别写「有记忆=默认开」 |
| 引用「统一压缩阈值」 | 逐工具列口径 | ❌「90–95% 总括句」被九工具全部否证（C-01/C-02） |
| 大窗口模型「不会压缩」 | 反例：Gemini 1M 窗口仍 `0.5×W` 触发 | ❌ C-08 旧标签已撤回 |
| 缓存省钱承诺 | 只说 CLI 侧可观测字段 | ❌ 服务端命中/TTL 全部 UNOBSERVABLE——不得承诺命中率 |
| 版本引用 | 快照 SHA + 分发件双口径（三行写法） | ❌ Grok 版本漂移（1.0.50→1.0.52）；OpenCode 同源≠零耦合 |

## ⑦ 时间线 / 演化器（请求组装逐块生长 · 静态）

**默认样例（演示）**：任务 = 「安排郊游……下午 4 点前必须返校」。

| 步 | 阶段 | 材料条数 | 模型调用（累计） | 本步关键变化 |
|---|---|---|---|---|
| 0 | 起点 | 1 | 0 | 只有你的消息 |
| 1 | 模型请求 ① | 4 | 1 | 加入 ①基础指令 + ②developer 材料 + ④工具说明 |
| 2 | 工具执行（查公交） | 6 | 1 | 调用记录 + 300 行结果（同一 call_id） |
| 3 | 模型请求 ② | 6 | 2 | 模型要求再读一份文件 |
| 4 | 工具执行（读文件） | 8 | 2 | 读文件调用（call_002）+ 40 行结果 |
| 5 | 模型请求 ③ | 8 | 3 | 输出最终行程建议 |
| 6 | 任务完成 | 8 | 3 | 材料不再增长 |

**五块料来源**：①基础指令=程序；②developer 材料=程序；③对话历史=一半程序一半你；④工具说明=程序；⑤本次输入=**你**。**你只控制了五块里的最后一块。**

**配对不变量**：每个调用都有结果、每个结果对能回调用。坏结构：A 悬空调用 / B 孤儿结果 / C 内容类型不匹配（图片在进入请求前被剥离）。
