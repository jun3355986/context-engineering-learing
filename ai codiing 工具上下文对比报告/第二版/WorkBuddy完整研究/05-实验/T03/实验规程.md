# T03 · 实验规程

> **本文件解决什么**：把"怎么做一次可复现、可归因、可停下的实验"写成**可执行规程**，供 T19 直接照做。
> **本文件不做什么**：不运行任何真实模型、不产生实验结果；真实运行属于 T19（依赖本规程 + 工具研究包就绪）。
> **对齐**：任务书 §5 T03 / §7 执行边界；第二版方案 §6.1 六场景 / §6.2 比较规则与记录字段；T02 问题地图 FB-12。

## 0. 三条不可跳过的前提

1. **先判任务，再看体积**。任何"省了多少"的结论都排在"任务与硬约束是否仍然成立"之后（方案 §6 开篇）。
2. **两类实验分开设计**：**机制实验**控变量做归因；**产品组合观察**保留原生配置，只描述"这套组合的表现"，不归因到单一 harness 因素（方案 §6.2）。
3. **没测就写没测**。不可观测项写 `UNOBSERVABLE` 并给原因；不得用模型自述、HTTP 200 或"压缩成功"字样替代证据（任务书 §7、§8）。

## 1. 数据与版本（每条实验记录必填）

| 字段 | 取值来源 | 说明 |
|---|---|---|
| 任务数据包 ID | `T03-DATA-TRIP-v1` / `T03-DATA-COMPAT-v1` | 只允许使用本任务冻结包；改动用 v2 |
| 数据版本哈希 | 包内 `manifest.sha256`（整包一句摘要哈希） | 记录所测版本的登记哈希；不得记录"大概是 v1" |
| **实际执行的可执行版本** | 运行入口自报的版本（如 `codex --version`、`claude --version`） | **这是"跑的是哪个东西"**；闭源工具只能拿到这一项 |
| **研究快照 SHA / 冻结分发包** | `00-管理/版本表.md`（T01 已验收九行） | 这是"代码分析依据是哪个东西"。**开源**：记完整 40 位 commit SHA + 分支/tag + 拉取日期。**闭源或无 `git` 的分发件**（如 `workbuddy-sources/claude-code-cli`、Grok Build 二进制）：记**分发包版本号 + 包/二进制 sha256 + 官方来源 URL + 获取日期**，并在工作区保留该分发件；**不得**用社区还原目录充当官方实现 |
| 模型与 provider | 实际使用值（如 model 名、reasoning 档位、登录方式） | 未统一模型时必须在"归因限制"里写明 |
| 配置与覆盖 | 窗口、触发相关配置、门控开关的实际生效值 | 区分"默认"与"配置后启用" |

> **两条版本必须并列写，且不得混为一谈**（T04 已实测出实例：本地 `codex-cli 0.152.0` ≠ 研究快照 `76ed3b4`）。
> - 若**实际执行版本**落后于研究快照：该轮观测**不能**直接用来验证研究包里基于新快照写的结论；记录须写明"观测版本 X / 分析依据 Y"，并在"归因限制"里注明差异方向（本地落后几个版本）。
> - 若**已无法取得**与研究快照一致的可执行版本：该条件标 `NOT_RUN` 或 `UNOBSERVABLE`，**不得**用旧版本观测冒充新快照结论。

## 2. 两类实验的字段模板（**必须不同**）

### 2.1 机制实验（可控变量）

目的：在**同一模型/provider/窗口/任务数据/工具输入**下，只改变待比较**策略**，用于归因。

| 字段 | 内容 |
|---|---|
| 实验 ID | `MECH-<工具>-<机制>-<序号>`（机制名取自 T02 §E 统一机制名） |
| 变量 | 唯一被改变的自变量（如"是否启用自动压缩"）；其余全部固定并逐项列出 |
| 固定量 | 工具版本/SHA、模型、provider、窗口、数据版本、命令、初始材料 |
| 命令模板 | 见 §4，逐字记录可重跑命令 |
| 预期事件 | 依据工具研究包写"应当出现什么事件"（触发/保留/替换/写回/恢复） |
| 观测结果 | 实际事件、失败与重试、恢复语义 |
| 判据结果 | 检查器输出（§5）：任务通过 / 关键约束违背数 / 否决复活数 / 未完成写完成数 |
| 用量 | 输入 token、输出 token、摘要额外 token、缓存读/写（分开，不重复相加）、重读次数、总耗时、可核验费用 |
| 可归因性 | 能/不能把差异归因于该机制，为什么 |
| 归因限制 | 模型不可控、服务端闭源分支等 |
| 状态 | `OBSERVED / NOT_RUN / UNOBSERVABLE / FAILED` |

### 2.2 产品组合观察（原生差异）

目的：描述**某产品在其原生配置下**的表现。**不控变量**，因此**不归因于单一因素**。

| 字段 | 内容 |
|---|---|
| 观察 ID | `PROD-<工具>-<场景>-<序号>` |
| 产品原生条件 | 安装版本/SHA、默认配置、登录/订阅、模型与 provider、可关闭/不可关闭的机制 |
| **本机环境是否被第三方扩展污染** | hooks / 插件 / `settings.json` 改动 / 其他工具写入的同名目录；若"是"，列出具体项并说明它可能影响哪些观测（例：T05 发现本机 `~/.claude/` 下有第三方 hook 产物 `transcripts/ses_*.jsonl`，不是 Claude Code 原生会话目录 `projects/`） |
| 不可关闭项 | 若某机制无法关闭 → **不设"未启用基线"**，只报告过程观察（方案 §6.2） |
| 命令模板 | 见 §4 |
| 过程记录 | 触发位置、可见事件、用户可感知变化 |
| 判据结果 | 同 §5 检查器输出（与机制实验同口径，便于横向并排） |
| 原生差异清单 | 与其他产品**观测到**的差异（只写观测，不写因果） |
| 归因限制 | **必填**：本观察不能说明什么（例如不能说明"该差异由 harness 造成"；也不能说明"污染项与观测无关"，除非有验证） |
| 状态 | `OBSERVED / NOT_RUN / UNOBSERVABLE / FAILED` |

> **允许并排比较的前提**：两类记录都填了"工具版本 + 模型 + 数据版本 + 命令 + 判据结果"，否则不得放进同一张对比表。

## 3. 六个场景 → 规程条目（对应方案 §6.1）

每条给出：数据来源、命令模板族、核心检查、判据入口。

| # | 场景 | 用哪份数据 | 核心检查 | 判据入口 |
|---|---|---|---|---|

| E6 | 错误恢复 | 合成项目 + 临时文件；注入方式必须写明 | 是否**有界**重试、状态是否一致、是否**重复副作用** | 检查器 + 副作用清单（哪些动作不可重复） |

## 4. 命令模板（占位，T19 按工具填实）

```text
# 会话启动（示例骨架，T19 替换 <TOOL> 与参数）
<TOOL> --model <MODEL> --provider <PROVIDER> <启动参数> \
       --workdir <独立合成项目目录> \
       2>&1 | tee <原始日志路径>

# 首条消息只放任务目标 + 硬约束（对应数据包 MSG-00x），逐字引用数据包原文
# 触发压缩：按工具研究包给出的真实入口（自动到线 / 手动命令）
# 恢复：按工具的恢复入口（resume/重启）执行，恢复后先问"现在有效约束有哪些"
```

**命令纪律**：命令逐字记录（含工作目录）；`<原始日志路径>` 落在实验工作区，不写凭据；公开摘录另存。

## 5. 判据：统一走检查器（不靠"模型说它记住了"）

```bash
# 把本轮产出的候选结果（最终方案 / 摘要 / 恢复后陈述）转成候选 JSON，再跑检查器
python3 <检查器目录>/check_task.py --package <数据包目录> --candidate <候选.json>
```

三类判据（对应任务卡"检查行为不只查关键词"）：

| 判据 | 检查器条目 | 为什么不是关键词 |
|---|---|---|
| 硬约束违反 | `CHK-HC-*` / `CHK-SP-02` | 解析 `HH:MM` 做时间比较、对金额求和、判集合成员；写满"16:00"但实际 17:30 仍被抓 |
| 已否决决定复活 | `CHK-REJ-STRUCT` / `CHK-SP-02`（**主判据**）+ `CHK-REJ-TEXT`（**辅助**） | 结构化 id 求交是确定性的；文本层为启发式，见下方降级标注 |
| 未完成写成完成 | `CHK-FC-STATUS` | 候选声明与真值状态逐项比对，不看有没有"已完成"四个字 |

> [!warning] 判据降级标注（T03R 修正轮 1，必读，T19 依赖这条纪律）
> **`CHK-REJ-TEXT` 是启发式判据，不得单独作为"已否决决定复活"的证据。**
> - **必须与结构化判据合取**：判定复活以 `CHK-REJ-STRUCT`（`selectedOptionIds` 命中被否 id）与 `CHK-SP-02`（集合点等字段命中被否集合）为准。
> - `CHK-REJ-TEXT` 命中 **只能作为"提示人工复核"的信号**，不能单独据此判任务失败；反之，它未命中**也不能**证明没有复活。
> - **两条已知边界（已实证）**：
>   1. **召回上限（漏报）**：`约束清单.json#rejected[].aliases` 是枚举式，词表外同义表达会漏报（例：用"学校正门集合"表达"校门口集合"；T03R 对抗例 B，回归样例 `regression-对抗B-别名表外同义复活-已知漏报.json` 期望即 PASS）。
>   2. **否定语境判断**：规则是"小句内出现**否决动词**（否决/排除/拒绝/作废/不采用…）→ 不算复活；否则**状态副词**（不再/不能/不得…）必须出现在**别名之前**才算"。该规则已通过 T03R 对抗例 A/C/E/F，但仍是**规则式而非语义理解**，反讽、跨句指代等情形可能误判。
> - **人工复核兜底**：文本层相关的结论在运行记录里必须写"已人工复核"或"未复核"，不得直接把检查器输出当作定论。
> - 上述标注同时写入 `运行记录模板.md`（§B1 与 §5 判据栏）与 `T03自检.md`（§3 G5）。

**缺字段从严（strict）**：`chk_empty_list` / `chk_is_null` / `chk_all_nullable_true` / `chk_forbidden_membership` / `chk_equals_not_in_set` / `chk_status_claims` / `chk_text_revival` 在字段**缺失**时一律判 FAIL，不再"视为空/空真通过"；`chk_all_nullable_true` 对**空数组**亦判 FAIL（T03R 对抗例 G；回归样例 `regression-对抗G-缺字段空真.json`）。注意：**显式写 `null` 与字段缺失是两件事**（`chk_is_null` 要求显式 `null`）。

**候选 JSON 怎么来**：模型/工具产出的是自然语言时，由实验者按各包 `预期结果.json#candidateSchema` **人工结构化**，并在记录里注明"结构化由人完成"（这一步是已知主观环节，属归因限制）。

## 6. 首轮重复与统计口径

- **每个可运行条件首轮重复 3 次**；记录**全部 3 次结果**，另记中位数与范围。
- 这是**探索性小样本**，不得声称统计显著；出现摇摆再增加次数，并写明增加原因。
- 3 次都不通过 ≠ "机制不存在"：按 §7 分类为 `FAILED`（跑了但没通过）或 `UNOBSERVABLE`（看不到）。

## 7. 异常处理

| 异常 | 处理 | 必须记录 |
|---|---|---|
| 触发未按预期发生 | 先核对配置真实生效值，再判 `NOT_RUN`（条件未成立） | 生效配置、核对动作 |
| 出现重复压缩 / 无界循环 | **立即停止该轮**，保留日志，判断原因后由主 Agent 决定是否恢复 | 停止时间点、已产生的副作用 |
| 未知远端结果（服务端行为不可见） | 标 `UNOBSERVABLE`，附"不能证明什么" | 不可见的具体环节 |
| **看错文件/看错格式**：在某路径找不到落盘或日志 | **先确认这是该工具的原生落盘位置与格式**（对照官方文档的目录结构、文件命名、字段名），再下结论 | 你查的路径、凭什么认为它是原生位置、官方文档怎么说 |
| 工具动作数或耗时超限 | 按 §8 停止条件停；记录原因；**不自动扩大批次** | 已用动作数/耗时 |
| 凭据/登录相关 | 不写入日志、截图、提交文件；缺凭据则该条件 `NOT_RUN` | 缺失项，不记敏感值 |

## 8. 停止条件（硬边界）

- **单轮 ≤ 10 分钟**；**单轮工具动作 ≤ 20 次**。
- 到达任一上限：**停止该轮**，保留日志与状态，记录"停止原因 + 当时已完成到哪一步"；是否调整规程由**主 Agent**决定，执行者不得自行放宽。
- 发现 §7 的"重复压缩/无界循环/未知远端结果"：**立即停止**，优先于其它任何目标。
- 额度受限：保存已有结果，转做不依赖该条件的任务，回到 §6 的 3 次规则在下一轮补齐。

## 9. 观测边界与禁止事项

- 不调用真实模型的实验（本任务 T03）**只能**产出数据与规程，不得被引用成"机制已被验证"。
- **"看不到"不等于"没有"**：判定某能力不存在之前，必须先证明你看的是**该工具的原生位置与原生格式**。
  常见错误：把第三方钩子/插件写的同名目录或文件（如某些 `hooks` 产物）当成工具原生落盘；目录名相近、字段结构不同即是信号。
  证据不足时标 `UNOBSERVABLE` 并写明"我查的是哪个路径、为什么它可能不是原生位置"——**不得**写成"该工具没有实现落盘"。
- **本机环境要如实登记是否被污染**（第三方 hooks / 插件 / 手改 `settings.json` / 其他工具写入的同名目录）。被污染时，该轮观测不能代表产品的默认行为；未验证污染项无关之前，不要在归因里假设它无关。
- "1 − 处理后/处理前"只是**体积缩减率**，不得替代任务质量结论（方案 §6.2 + 样章纪律）。
- 缓存相关数字以服务端返回 usage 为准；**不把缓存 token 重复相加**；不可见时写 `UNOBSERVABLE`。
- 原始日志与公开摘录**分开存放**；日志不含凭据、本机敏感路径、内部项目信息。
- 外部评测数字（如厂商发布的百分比）只进"外部评测"栏，**不得填入本地对照表**。
