# T03 · 重置与重放说明

> **本文件解决什么**：说清"数据怎么版本化、怎么重置回 v1、不调用真实模型怎么重放核对"三件事。
> **一句话**：v1 冻结不原地改；任何改动都会被 `manifest.sha256` 检出；重置=用生成器重建，重建后哈希必须与冻结登记**逐字节一致**。

## 2. 版本化规则（v1 冻结）

1. **v1 冻结后不原地修改**。任务数据包的语义变更（新增约束、改真值、换长结果）一律**另存 v2**：目录名 `任务数据-*-v2/`，`任务定义.json#packageVersion` 改 `v2`。
2. **文字修订**（错别字、说明补充）允许，但必须重新生成该包 `manifest.sha256`，并在更新日志记录"旧哈希 → 新哈希"。
3. **每份数据包与每个可运行目录都有 `manifest.sha256`**，格式 `sha256<两空格>相对路径`，可直接用 `shasum -c`。
4. 新增 v2 时，**v1 的目录与哈希保留**，不覆盖、不删除（T19 需要在已冻结版本上复现）。

## 3. 重置（回到 v1）

**"重置" = 用生成器从脚本重建，而不是从别处复制。** 重建后哈希必须与冻结登记一致，这才证明"重置真的回到了 v1"。

```bash

# 一键：核对 → 重建长工具结果 → 重放核对 → 重放检查器自测
./reset_and_replay.sh

# 指定笔记库数据根（默认已按本机路径内置，可覆盖）
T03_VAULT="/Users/junjielong/Library/Mobile Documents/iCloud~md~obsidian/Documents/我的笔记/程序猿/ai/上下文管理/ai codiing 工具上下文对比报告/第二版/WorkBuddy完整研究/05-实验/T03" \
  ./reset_and_replay.sh
```

日志落在 `experiments/t03/logs/reset-and-replay-<时间戳>.log`。

**从笔记库恢复工作区数据副本**（例如工作区被误删）：
```bash
BASE="<…>/05-实验/T03"; WS=/Users/junjielong/workspace/agent-context-research/experiments/t03
for p in 任务数据-行程任务-v1:T03-DATA-TRIP-v1 任务数据-接口兼容-v1:T03-DATA-COMPAT-v1; do

  mkdir -p "$WS/data/$dst" && cp "$BASE/$src"/* "$WS/data/$dst/" && rm -f "$WS/data/$dst/manifest.sha256"
done
python3 "$WS/scripts/verify_versions.py" --workspace "$WS" --vault "$BASE"
```

## 6. 重置后必须重新核对的三件事（防止"看起来重置了"）

1. 各 `manifest.sha256` 校验（§5 命令）—— 全部 `OK`；
2. `reset_and_replay.sh` 步骤 3 —— 与步骤 1 结果相同（证明重建确定）；
3. 检查器汇总行 —— `全部符合预期`，且反例命中的 **severity** 与 `预期结果.json#expectedVerdicts` 一致。

**并且必须确认脚本退出码为 0**：脚本用 `函数 + PIPESTATUS` 取码；若只看打印文字不看退出码，曾可能漏判（见 §7 E-2）。

## 7. 送审后勘误（两项，均已修并验证）

### E-1 行号口径写错（T04 实测发现）

- **现象**：README §2 把「文件行号」与「内容序号」混用。行程包原先写的"中 139–144 行"实为**班次序号 L7-139~L7-144**，真实文件行号为 **150–155**（推荐班次 14:50 在**文件第 152 行**/班次 L7-141；不可用班次 15:20 在**文件第 154 行**/班次 L7-143）。接口兼容包尾段三处错得更重：`Tests run` 实为 **292**（原写 296）、`BUILD FAILURE` 实为 **293**（原写 297）、结论 3 未提交实为 **298**（原写 300）；头段"计划测试总数 42"实为 **9**（原写 8）。
- **影响**：T19 跨工具比对"关键事实位置"时会漂；`真实可检验` 的核对指引本身失准。
- **修复**：两包 README §2 表改为**双标**（文件行号 + 内容序号），行号改为实测值；新增 `scripts/locate_keyfacts.py` 作为自动校验入口（21 个标记，缺失即报 `[缺失]` 并非 0 退出）；`重置与重放说明.md` §4.4、`运行记录模板.md` §0、`T03自检.md` §4 同步加入行号口径说明与该脚本入口。
- **复验**：`python3 scripts/locate_keyfacts.py data` 退出码 0，标记缺失 0。

### E-2 脚本退出码恒定 0（自检自查发现）

- **现象**：`run_selftest.sh` / `reset_and_replay.sh` 早期把 `rc` 累加写在 `{ ... } | tee "$LOG"` 的花括号内。管道左侧在**子 shell** 中执行，`rc` 的赋值不会传回父 shell，因此**无论中间是否失败，脚本都退出 0**。
- **影响**：把"退出码 0"当作通过证据是**无效证据**；与本文档 §9（规程）里"不能把 HTTP 200 当推理成功"属同一类错误——我自己犯了。
- **修复**：改为 `run_all()` 函数 + `rc="${PIPESTATUS[0]}"`；`run_selftest.sh` 另加"未发现任何数据包即判失败"。
- **负例验证（证明退出码确实会反映失败）**：
  ① 临时移走 `checker/fixtures/T03-DATA-TRIP-v1/positive-植物园方案.json` → `run_selftest.sh` 退出 **1**；
  ② 临时向 `data/T03-DATA-TRIP-v1/README.md` 追加一行制造副本漂移 → `reset_and_replay.sh` 退出 **1**；
  恢复后两者均回归 **0**，且 `verify_versions.py` 报 `全部一致 —— PASS`。
- **连带处理**：用修正后的脚本**重新生成**了 `检查器/自测原始输出-20261015.txt` 并重签该 manifest。
