### 2.5 判据结果

### 2.8 ⚠ 新发现（边界）：`shell` 路径**落盘文件可能缺开头若干字节**（竞态、非确定性）

对同一命令 `grep -n "" v2-sample.txt`（真实输出 **171,307 B / 2,254 行 / sha256 `87468c79…1d20`**）跑 **6 次**（r1–r3 首轮 + r4–r6 经主 Agent 批准的补轮），落盘文件与真实输出的关系：

| 轮次 | 落盘字节 | 缺失（**均在开头**） | 缺失行数 | 落盘 = 真实输出的**后缀**? | 预览（模型可见） |
|---|---|---|---|---|---|
| r1 | **169,213** | 2,094 B | 23 | ✅ 是 | 51,291 B tail（正常） |
| r2 | 171,307 | 0 | 0 | ✅ 是（逐字节一致） | 51,291 B tail |
| r3 | **169,998** | 1,309 B | 12 | ✅ 是 | 51,291 B tail |
| r4 | 171,307 | 0 | 0 | ✅ 是（逐字节一致） | 51,291 B tail |
| r5 | 171,307 | 0 | 0 | ✅ 是（逐字节一致） | 51,291 B tail |
| r6 | **169,998** | 1,309 B | 12 | ✅ 是 | 51,291 B tail |
| **汇总** | — | **3/6 缺头** | 12–23 行 | **6/6 恒为后缀** | **6/6 均正常** |

**观测事实（硬证据）**：
1. **3/6 缺头**（缺 2,094 / 1,309 B，即 23 / 12 行），3/6 完整 → **竞态、非确定性**；
2. 落盘**始终是真实输出的后缀**（`真实输出.endswith(落盘) == True`，**6/6**）→ **从不丢中段或末尾**，只可能丢开头；
3. **缺量只出现两个离散值**（2,094 / 1,309）→ 与「**整块（chunk）丢失**」一致，而非按字节随机截断（旁证候选根因-②）；
4. **模型可见的预览完全不受影响**（6/6 均为 51,291 B、tail 形态、标记与路径正常）→ 缺的是**落盘副本**，不是模型看到的内容；
5. 对照：`cat v2-sample.txt`（161,144 B）3/3 落盘**逐字节一致** → 该现象**未在 cat 路径复现**（n=3，**不能**据此断言 cat 路径无此竞态）。

**候选根因（代码级，⚠️ 未证）**：`shell.ts` 的流式收集（`run()` 内 `Effect.forkScoped(Stream.runForEach(Stream.decodeText(handle.all), …))`，约 487–511 行）存在两处可疑：
- `if (file) { sink?.write(chunk) }` —— `sink` 尚未创建时（`trunc.write(full)` 的 `andThen` 未执行完）该块被**静默丢弃**；
- `handle.all` 若为**推送式/单消费者**流，fork 挂载**之前**产生的首块可能已丢失（与「只丢开头 + 大小随运行变化」最吻合）。

**处置**：标 **`OBSERVED（边界/异常）`**；**未证根因**，**不写成「shell 落盘必然损坏」**。

**v1↔v2 对照（t19-ocv2 复跑，2026-10-15 16:33 回报）**：

→ **倾向「版本差异」**（v2 侧 13/13 未复现）。**谨慎口径（双方一致）**：若 v2 真实缺头率与 v1 观测率同（**3/6 = 0.5**），13 次全中概率 ≈ 0.5¹³ ≈ **1.2×10⁻⁴**，**支持 v2 未共有该竞态/可能已修**；但 **v1 侧 n=6 仍偏小**、两版进程生命周期与驱动方式不同 → 写「**v2 侧未复现（13/13）**」，**不写「v2 已修」**。

**根因调查的边界（如实登记）**：v1 侧 `ChildProcessSpawner` 来自依赖 `@effect/platform-node`（**不在研究快照源码内**，快照无 `node_modules`）→ **无法从快照定位 `handle.all` 的流语义**，故候选根因**停留在「可疑、未证」**。

**v2 出货二进制只读核查（t19-ocv2 协查，2026-10-15 16:39；证据 `logs/ocv2-shell-spill-codecheck-20261015-163940.log`、`08-ocv2.md` §2.7b）**：

|---|---|---|
| `trunc.write` | **0** | v1「先写首个 >maxBytes 缓冲」的两阶段交接在 v2 **不存在** |
| `flags:"a"` | **0** | v2 **不用 append** → 无「后续接管」交接窗口 |
| `if (file) {` | **0** | v1 的守卫形态在 v2 **不存在** |

**口径（严格限定，双方一致）**：
- **可写**：「v2 未复现（13/13）**＋** v2 代码结构与 v1 不同（无 `sink` 可选链 / 无 append 交接 / 新增 `await open`）」→ 支持「**v2 未共有该竞态 / 可能已修**」；

2. **fork 异步 + 一次性 CLI 进程随即退出**（**A 路径的决定性根因**）：调用形如 `compaction.prune({sessionID}).pipe(Effect.ignore, Effect.forkIn(scope))`，随后 `return yield* lastAssistant(sessionID)` 立即返回；`opencode run` 进程结束时 scope 关闭 → 被 fork 的 prune **未获执行机会**（A 路径 5 次尝试日志 `pruning` 全为 0 行）。**B 路径（长驻 serve）下 fork 得以执行** → 3 次 `pruning` 均出现 → 根因确认。
3. **`turns < 2` 门控**：`compaction.ts:283-285` 的 `if (turns < 2) continue` 使**最近 1 个 user turn 内的工具输出全部豁免**；A 路径 r2/r2b 只有 1 个 user turn → 即便进程长驻也无候选。
4. **`PRUNE_MINIMUM=20_000` 门槛 + `Token.estimate` 口径**（**serve-1 未擦的根因**）：prune 用 **`Token.estimate`（字符数/4）**，**不是** provider 上报的 token 数。本样本每条工具输出 42,021 **字符** → 只算 **10,505**；因此 `PRUNE_PROTECT=40_000` 实际约等于 **16 万字符**的受保护量。4 条（42,020 est）只能擦 10,505 < 20,000 → 不擦；**6 条（58,922 est）可擦 21,010 > 20,000 → 擦除**。

> **口径提醒（重要）**：本记录前文用 provider token 描述工具输出规模（每条 ≈25.6k token），而 prune 的阈值用 **`Token.estimate`（≈10.5k/条）**——**两者不同口径，不可混用**。这正是 serve-1「看起来够多却没擦」的原因。

### 6.6 可归因性 / 归因限制

| 项 | 内容 |
|---|---|
| 能把差异归因于该机制吗 | **能**（擦除与否完全由 `PRUNE_PROTECT`/`PRUNE_MINIMUM` 与 `Token.estimate` 决定，且日志数值与推算逐项吻合） |
| 归因限制 | ① 未测 `skill` 工具保护分支（`PRUNE_PROTECTED_TOOLS`）；② 未测「遇摘要即停」分支（B 路径无压缩）；③ 未测 **TUI** 模式（与 serve 同属长驻，但未跑）；④ `Token.estimate` 与真实 token 的偏差（CJK）未校准 |

### 6.7 附带发现（同批，供 `ocv1-fail-02` 回填）

- **doom_loop 防护实测触发**：单轮内连续 **3 次相同工具 + 相同输入**（`cat v2-sample.txt`）→ 第 3 次被拒：`{"name":"UnknownError","data":{"message":"The user rejected permission to use this specific tool call."}}`（非交互 `opencode run` 无审批者，`doom_loop` 默认 `ask` → 拒绝）。改用**不同命令**（`cat ./…`、`sed -n`、`awk`）后全部完成 → 与 `ocv1-fail-02`（`DOOM_LOOP_THRESHOLD=3`、默认 `ask`）一致。
- **provider 不稳定样本**：`opencode.log` 记录多次 `AI_APICallError: Upstream request failed: Endpoint is unavailable`（`opencode-go/step-5-preview-free`），涉及 2 个被中断的会话 → 免费模型上游稳定性**低于**付费模型，作为条件说明登记。
- **`serve` 的 HTTP 入口可用性**：`POST /session`、`POST /session/:id/message`、`GET /session/:id/message` 均 **HTTP 200**（`--format json` 之外的驱动方式，供后续批次复用）。
