### 0.2 关键环境发现：沙箱 `rmdir` 导致 pi 锁无法释放（**根因已定位**）

**现象**：首次 `pi -p` 直接 exit=1，stderr：
```
Credential store read failed for opencode-go: EEXIST: file already exists, mkdir '/Users/junjielong/.pi/agent/auth.json.lock'
Warning: Invalid settings file .../settings.json: EEXIST: ... 'settings.json.lock'
```
（与 T06 OBS-01 完全同一失败模式。`pi auth check` 仍 exit 0/ready，**具误导性**。）

**根因（已实证，非 pi 缺陷、非环境损坏）**：**Bash 工具沙箱在 workspace 路径下拒绝 `rmdir` 系统调用**，`/tmp` 允许。pi 用 `proper-lockfile`（`auth-storage.ts:86,130`、`settings-manager.ts:204`）——**mkdir 建锁、rmdir 释放锁**。rmdir 被拒 → 锁永不释放 → 同一/后续进程再次取锁 `EEXIST` → 凭据库读失败。

实测（可复现）：
```
cd <workspace>/work-pi && rmdir bintest.lock            → rmdir: Operation not permitted
node -e "fs.rmdirSync('<workspace>/x.lock')"            → FAIL（err.code=undefined）
node -e "fs.rmdirSync('/tmp/x.lock')"                   → OK
```
> 结论：所谓「陈旧锁」**不是**历史残留，而是**沙箱使锁无法释放**；清理后必然复发。**`~/.pi` 未被修改（只读使用）**。

**绕过（已验证）**：pi 源码支持 agent 目录覆盖 —— `config.ts:585` `ENV_AGENT_DIR = "PI_CODING_AGENT_DIR"`、`config.ts:605-611` `getAgentDir()` 优先读该环境变量（另有 `PI_CODING_AGENT_SESSION_DIR`）。把 agent 目录放 `/tmp`，锁落 `/tmp` → rmdir 可用 → 正常。

**正式运行条件（逐字，可重跑）**：

| # | 预期 | 依据 |
|---|---|---|
| 1 | 溢出被识别 → `_omitRecoveryAttempt`（追加 `context_edit{replacement:null}`）→ `compaction_start{reason:"overflow"}` → `compaction_end{willRetry:true}` | `agent-session.ts:3007-3074` |
| 2 | 只允许**一次** compact-and-retry；第二次溢出 → `compaction_end{reason:"overflow", result:undefined, errorMessage:"Context overflow recovery failed after one compact-and-retry attempt…"}` | 同上（`_overflowRecoveryAttempted`） |

### 5.3 观测结果（逐字事件序列）

```text
assistant stopReason=error  errorMessage='400: {"message":"Your input exceeds the context window of this model. prompt is too long: 250000 tokens > 8192 maximum", …}'
agent_end willRetry=false            (roles: user, assistant)
entry_appended {type:"context_edit", replacement:null, targetId:ac3b9dde}      ← _omitRecoveryAttempt
compaction_start {reason:"overflow"}
compaction_end   {reason:"overflow", aborted:false, willRetry:true}            ← 第 1 次：compact + 重试
assistant stopReason=error  errorMessage='400: {"message":"… exceeds the context window …"}'   ← 重试轮再次溢出
agent_end willRetry=false
compaction_end   {reason:"overflow", aborted:false, willRetry:false,
                  errorMessage:"Context overflow recovery failed after one compact-and-retry attempt. Try reducing context or switching to a larger-context model."}   ← 守卫拒绝第 2 次
agent_settled {aborted:false}
```
事件计数：`agent_start=2`（原始 1 + 重试 1）、`compaction_start=1`、`compaction_end=2`（1 次成功 + 1 次守卫失败）、`session_compact_failed=0`（未走 `_emitSessionCompactFailed`）。

### 5.4 判定

| 问题 | 实测答案 |
|---|---|
| overflow 是否触发、以什么形式 | **触发**。以 provider 400 + 溢出文本（`exceeds the context window`）→ `explicitOverflow` → `_omitRecoveryAttempt` + `compaction_start/end{reason:"overflow"}` |
| **恢复尝试次数** | **恰好 1 次 compact-and-retry**：第 1 次溢出后压缩并重试（`agent_start=2`），重试轮再溢出时被 `_overflowRecoveryAttempted` 守卫拒绝，输出明确错误文案。**与 T06 `pi-fail-01`「溢出仅一次恢复」一致（实测确认）** |
| 恢复后任务/约束状态 | **不适用**：本注入为 stub provider（非真实模型），第 2 次溢出即终止，未产出任务方案 ⇒ **不喂检查器**（如强行喂，候选内容为空，无意义） |

### 5.5 归因限制（本项）

- 注入是**合成错误**（本地 stub），证明的是 **pi 的错误分类与恢复控制流**，**不证明**真实 provider（opencode-go）在真实溢出时的错误文本形态；`isContextOverflow` 的模式表随版本变化（实测：快照 main 含 `/prompt is too long/i`，而执行版 1.2.0 dist 中该串 **0 命中**，仅 `/exceeds the context window/i` 命中）⇒ **版本差异已在本次注入中规避**（选用两版都有的模式）。
- 三次失败尝试（已记，见 §5.6）说明该注入**对错误体透出形态敏感**，属**条件敏感**，非「机制不可观测」。

### 5.6 已尝试路径与失败原因（不硬凑，如实登记）

| 尝试 | 注入形态 | 结果 | 原因 |
|---|---|---|---|
| A | HTTP 400 + 溢出文本（第一次） | 落入**重试路径**：`auto_retry_start ×3`（maxAttempts=3）→ `auto_retry_end{success:false}` | 该次 pi 把响应体吞成通用 `"Connection error."`，未命中 `isContextOverflow`；同时**顺带观测到 `pi-fail-02` 的「瞬时流错误走 retryAssistantCall（maxRetries=3）」** |
| B | SSE `finish_reason="length"` + `output=1` | 无恢复动作 | 未命中 `isRecoverableLength`（触发条件未满足，具体门控未进一步定位） |
| C | 历史过短时注入溢出 | 仅 `_omitRecoveryAttempt`（context_edit），无压缩、无重试 | 会话历史不足以产生可摘要材料 ⇒ `_runAutoCompaction` 无产物 |
| D | 摘要判别过松（按 `## Goal` 判定） | 压缩成功、重试轮被误放行（stub 把含摘要的请求当摘要） | 注入器缺陷，非 pi 行为 |
| **E** | 摘要判别 = 「缺 pi 主系统提示词」（§5.1） | **成功**：1 次 compact-and-retry + 守卫拒绝 | 定论条件 |
