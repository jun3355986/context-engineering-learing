## §7 操作陷阱附录（跨批次，供复跑者）

1. **沙箱 rmdir**（pi 发现）：workspace 下 `rmdir` 被拒 → mkdir 式锁永不释放（EEXIST）；处置=挪 `/tmp` 或 `PI_CODING_AGENT_DIR` 类覆盖。codex/dsh/omp 批次**未遇**（非通用）。
2. **tmux 驱动 TUI**（codex/claude）：启动确认默认 No 会退出（需 Down+Enter）；流式输入需加节奏（否则消息合并）。
3. **`exec resume` 对活跃 TUI 会话**报 `active writer` 冲突（codex）：关 tmux 后重试。
4. **pi stub 注入**：必须在**同一 shell 调用内**启停 stub（后台进程跨命令被回收）；stub 模式需 `smart`（摘要放行）。
5. **窗口/阈值覆盖优先**：各工具用设计内调参入口（codex `-c model_context_window`；dsh `modelPolicies`；claude `--autocompact`）控制填窗成本——**先小任务验证入口**。
6. **E1 提示词口径**：向模型要结构化判据时**显式给出 `statusClaims` 键名**（grok/ocv2 均见"自造键名→strict 缺键 FAIL"的 schema 遵从问题）。
7. **低阈值停轮线**：ceiling/阈值压得过低会「每步触发压缩」（ocv2 27 次、pi 6 次）——先算好下限再跑，触发即按 §7 停轮。
8. **TUI 启动被 shell profile 钩子卡住**（grok 补测发现）：pane 内 shell 的 `safe-delete` 等 profile 钩子会拦在确认提示（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`），命令从未执行；修法=`tmux new-session -d … "/bin/zsh -f"`（免 rc shell）→ TUI 正常渲染。
9. **触发读数口径**：阈值是**下限判定线**、判定在**轮界**执行 → 实测触发读数 = 阈值 + 轮内增量（grok 70→72% 实测）；横向比较写「读数 ≥ 阈值」并注明口径。
10. **shell spill「缺头竞态」**（ocv1 实测；v2 未复现 + 代码差异）：v1 bash-grep 路径 **n=6 中 3 次缺首部**（缺量 0–2,094B，仅两个离散值 → 与「整块丢失」一致；**恒为后缀，不丢中尾**）；v1 cat 路径 3/3 一致；**v2 侧 13/13 逐字节一致、零缺头**（同率假设下概率 ≈1.2×10⁻⁴）+ **出货代码结构差异**（无 append 交接/无 `sink` 可选链/新增 `await open`）→ 支持「**v2 未共有该竞态（结构上已消除候选窗口）**」；**v1 根因未证**（不作「已修」断言）（spawner 属依赖包、不在快照内）→ **不得写「落盘=原文必然完整」**；引用落盘完整性须带此边界。
11. **停轮判据（统一口径 v2，T19R P-1/P-1R 两轮裁决）**——按**结局**定、不按次数定：**停轮**＝未终止或无法解释的循环｜**单次调用内压缩 ≥6 次**｜单轮 >10min｜>20 动作｜未知远端结果。**继续并登记（不停轮）**＝① **配置边界的设计内重触发**（阈值/ceiling 为控成本调低 → 压缩后「系统+摘要+保留段」底噪仍高于线 → 再次触发）**且终止正常、单次调用内 ≤5 次** → 记「**配置边界（已登记、有界继续）**」；② 跨回合正常到线压缩；③ 专设连续压缩条件按设计次数执行。**全批复判（八批一致）**：omp（3 次）/pi OBS-03（t5 内 2 次）/ocv2 compact-e1（2–4 次）=**配置边界（已登记、有界继续）**；dsh（9 次/5 回合）=跨回合正常；claude pct=1（2 次）/ocv1 r1（3 次）=**保守停轮**（有效，保留）；codex（17 次）/pi 降级（6 次）/ocv2 低 ceiling（27 次）=**停轮** ✓；**grok 条件 3（3 次）=专设连续压缩（③）** ✓。
12. **停轮计数（T19R P-2；P-1R 后口径）**：实际停轮 **6 次**——codex 1 / pi 1（降级配置）/ claude 1（保守）/ **omp 0** / **dsh 0** / ocv1 1（保守）/ grok 0 / ocv2 2（低 ceiling 27 次 + keep=500 80 动作）。**「应停未停」表述废除**——omp/pi/ocv2 的同类情形按 §7-11 v2 归为「**配置边界（已登记、有界继续）**」，非违规。此前派发单计数（omp 1 / dsh 2 / ocv1 2）为主 Agent 错误，已更正。
