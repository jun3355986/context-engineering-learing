## 四、问题单

> 严重度：**高**=影响教学正确性/结论；**中**=影响验收可靠性；**低**=文档/显示；**提示**=非缺陷或边界。

### P-1【高】实验台 ③「样例 B」逐步演推数值与逻辑错误

- **文件/行**：`03-课程/T17/交互教材.html` L1001–1034（`acts()` 内），关键在 **L1003**、**L1013**、**L1017–1021**。
- **依据**：T15 `M04-压缩与摘要.md` 自测②（L280、L296）：「装 7,000（剩 13,000）；**16,000 > 13,000 → 边界截短**，保留头尾合计约 **13,000** tokens 片段……**更旧的 9,000 不会被补缝**」。亦与 `T17-静态替代.md` §③「变式」一致。
- **实际（独立 dump，样例 B 逐步）**：
  - 第 2 幕 note：`倒着装：先装 M3（7,000 ≤ 20,000）→ 剩 13,000；再装 M2（16,000 ≤ 13,000）→ 剩 -3,000。` → **假不等式**（16,000 ≤ 13,000 不成立）+ **剩余为负**。
  - 第 3 幕 note：`M1（9,000）装不下（> 剩余 -3,000）……合计约 -3,000 tokens + 截断标记` → **边界条目认错**（应为 M2=16,000）、**token 数为负**。
  - 替代历史：`[截短] M1 头尾片段（约 -3,000 tokens）`、`[已装] M2 原样 16,000`、`[已装] M3 原样 7,000` → 与母稿结论相反。
- **根因**：`acts()` 以 `newest=msgs[last]; mid=msgs[last-1]; old=msgs[0]` **硬编码**「newest/mid 必装、old 为唯一边界条目」，该假设**仅对样例 A 成立**；样例 B 的边界条目是 `mid`（M2），算法未做「逐条判断是否装得下」的通用实现。
- **连带失真**：
  1. **交互 vs 静态不一致**：`T17-静态替代.md` §③ 变式正确，与交互版冲突。
  2. **说明自检表失真**：`T17-说明.md` §3 第 20 项对「自测②（9,000/16,000/7,000）」标 **✅**，但交互实际渲染与之不符。
  3. **作者断言未拦截**：`build/verify.js` L104–107「③样例B 第3幕 → 边界条目 16,000 截短、已装含 7,000」仅断言拼接文本含 `/16,000/` 与 `/7,000/`；这两个数字恰好来自错误的「M2 原样 16,000」「M3 原样 7,000」，故**在错误内容下仍 PASS**，未验证「边界条目=M2、截短≈13,000」。
- **影响**：教学数据错误（负 token、错误边界条目）+ 交互/静态不一致 + 自检表不可信。属硬错误。
- **建议**：将 `acts()` 改为通用「从新到旧逐条试装、装不下的那条做边界截短、其后停止」；同步订正 `T17-说明.md` §3 #20；并在 `verify.js` 增加对「边界条目 id=样例B 的 M2、截短值≈13,000、无负值」的**实质断言**。
