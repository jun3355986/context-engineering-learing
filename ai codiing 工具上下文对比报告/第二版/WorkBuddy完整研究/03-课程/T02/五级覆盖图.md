# T02 · 五级覆盖图

> **这份文件解决什么**：把学习路线 **建立直觉 → 理解流程 → 掌握机制 → 连接源码 → 独立判断** 拆成五级，逐级写清"先修知识 / 学完能做什么 / 核心概念 / 已有基线材料映射 / 缺口 / 自测落点"，并给出六项能力在五级的落点。
>
> **两条硬要求**：
> 1. 每一级都有**实际产出物**（读者做出来的东西），不是只有一份目录。
> 2. **零基础连续路线**（读完 L1 能接着读 L2……）与**开发者进入细节入口**（可跳过已掌握桥接）两条路都要说清。
>
> **材料映射口径**：`U01–U09` 指样章母稿单元；`I-时间线 / I-演化器 / I-演算器 / I-压缩四幕 / I-裁剪器 / I-状态机 / I-失败选择器 / I-账单器 / I-设计清单` 指样章交互教程对应交互。样章已验收，缺口项须由 T15/T16/T17 补齐。

## 0. 五级总览

| 级 | 名称 | 一句话 | 读者产出物（不是目录） | 对应样章基线 |
|---|---|---|---|---|
| L1 | 建立直觉 | AI 这次根据什么回答？ | 一张"记录还在、当前却没用上"的解释图 | U01、U02 场景；I-时间线 |
| L2 | 理解流程 | Agent 如何读资料、调工具、继续任务？ | 单步追踪一次完整循环，预测下一次请求包含什么 | U01 消息列表、U02 请求组成；I-演化器 |
| L3 | 掌握机制 | 为什么需要选择、裁剪、摘要、检索与记忆？ | 对同一份材料做前后对照，说出几种策略的取舍 | U03–U08；I-演算器/压缩四幕/裁剪器/状态机/账单器 |
| L4 | 连接源码 | 程序在哪里做这些决定？ | 标注一条真实调用链，解释关键分支、配置门控与状态变化 | U03–U08 的「真实实现」段；附录 C 源码索引 |
| L5 | 独立判断 | 换一个任务如何设计、验证和修复？ | 提交可复核的小型方案与实验设计，迁移到未讲过场景 | U09 + 迁移任务；I-设计清单 |

## 1. 逐级明细

### L1 · 建立直觉

- **先修知识**：无（零基础入口）。
- **学完能做什么**：用自己的话解释"为什么我说了一句话，账单却像聊了半小时"；说出"保存的记录 / 当前选中的材料 / 实际请求"不是一回事。
- **核心概念清单**：任务、模型请求、工具、工具结果、消息列表、消息角色、token、上下文窗口、会话。均见 `术语表候选.md` §1。
- **已有基线材料映射**：U01「一句话，很多次请求」全段（小林泡茶→账单爆炸）；U02 场景（婷婷换电脑）；I-时间线。
- **缺口清单**：
  - 缺"从郊游到 coding 任务"的统一主线显式对齐（方案 §1.4 要求的迁移预告，目前只在 U09 出现）。
  - 缺一张面向 L1 读者的"资料柜 / 工作桌"直觉图（现散落在方案 §3，未进样章）。
- **自测落点**：U01 自测①顺序题（工具等待期间模型被调用几次）、②判断题（工具结果是否一定进下一次请求）、③配对题。
- **产出物**：读者画出"一条约束（下午 4 点前返校）在记录里、但没在本次请求里"的图。

### L2 · 理解流程

- **先修知识**：L1（任务/请求/工具/消息列表）。
- **学完能做什么**：单步追踪一次完整工具循环，并**预测**下一次请求会包含哪些块（基础指令、developer 材料、历史、工具说明、本次输入）。
- **核心概念清单**：请求组装、基础指令、developer 材料、工具说明、工具调用与结果配对、配对不变量、工具循环、当前工作状态（WorldState）、项目规则（AGENTS.md）、发现范围、字节预算、差分更新。（其中"**发现范围 / 字节预算 / 差分更新**"三项层级为 **L2–L3**，与 `术语表候选.md` §8 一致。已在 L2 引入，L3 深入。）
- **已有基线材料映射**：U01「真实实现：请求是拼出来的」（`build_prompt` + `normalize_history` 三条不变量）；U02「一次请求的完整组成」；I-演化器。
- **缺口清单**：
  - 缺"配对不变量失败会长什么样"的失败样例（U01 只给答案，无坏结构演示）。
  - 缺系统提示词 vs base instructions 的逐工具差异（标"待 CM-01/CM-02 核验"）。
  - 缺"其他工具怎么组装请求"的对照（现只有 Codex 一条链，T16 补）。
- **自测落点**：U01 自测②（"进列表 ≠ 进下一次请求"）；U02 自测①（无变化时是否重发状态）、③（规则没进模型的排查位置）。
- **产出物**：读者手写一次请求的组成清单，并标出"哪一块来自程序、哪一块来自我"。

### L3 · 掌握机制

- **先修知识**：L1、L2（消息列表、请求组装、配对）。
- **学完能做什么**：给定窗口/用量/配置，**算出一条自动整理线是否到线**；预测整理后哪些材料会被带上；沿"工具出口 → 活动历史 → 摘要"三处限长定位一条约束的丢失点；解释缓存省了什么、没省什么。
- **核心概念清单**：当前用量（A）、输入基线（P）、有效窗口（H）、有效窗口比例（p）、范围口径、范围线、整段线、基础线（90%）、自动整理限额、触发到线、轮前/轮中/轮后、本地近似估算、压缩、摘要、裁剪、保留预算、出口限长、落盘、长期记忆、检索、缓存、缓存命中、前缀退化。
- **已有基线材料映射**：U03（四条数字账 + 两条线 + 五例演算）、U04（两条产物路径与保留算法）、U05（三处限长与裁剪）、U06（三层记录与恢复）、U07（失败分类与手动整理）、U08（缓存与 usage 拆账）；I-演算器 / I-压缩四幕 / I-裁剪器 / I-状态机 / I-账单器。
- **缺口清单**：
  - **检索族（CM-03）在样章里最薄**：U03–U08 没有独立"代码检索 / 按需读入"单元（对应 CM-03、FB-11 的检索侧）。
  - **长期记忆（CM-08）没有样章单元**：样章只到"磁盘记录/恢复"，未覆盖跨会话记忆与后台提取（对应 LQ-08）。
  - **子 Agent 交接（CM-09）没有样章单元**：样章仅提到 fork 与子 Agent 概念，无独立机制链路。
  - **连续压缩（LQ-09）**：U04/U06 有推演，但无"连续三次压缩事实漂移"的完整数据。
  - **数字约束缺实验回填**：所有保留/丢失结论目前是算法推演（样章附录 D 明示"未运行真实模型实验"）。
- **自测落点**：U03 自测①②③④（含"None 不是 0"陷阱）；U04 保留清单推演；U05 损失点定位表；U06 四态对照；U08 三组账单。
- **产出物**：读者对同一份材料（郊游/接口兼容任务）做**前后对照表**，逐条标"原样留下 / 变摘要 / 移除 / 落盘"，并说明选择理由与代价。

### L4 · 连接源码

- **先修知识**：L3 + "读源码的最小桥接"（列表与对象、字段与 ID、函数输入输出、条件与循环、内存状态与文件保存、异步先后）。
- **学完能做什么**：沿真实调用链走完"调用者 → 条件判断 → 处理函数 → 状态写回 → 下一次请求/恢复读取"，用自己的话说明关键分支与配置门控，并指向固定版本证据。
- **核心概念清单**：`build_prompt`、`normalize_history`、`WorldState`、`auto_compact_token_limit`、`AutoCompactTokenLimitScope`、`saturating_sub`、`replacement_history`、`CompactedItem`、`rollout`、`ResponseItem::Compaction`、`set_total_tokens_full`、`prompt_cache_key`、`cached_tokens`、饱和/`Option`/`match` 等最小语法。
- **已有基线材料映射**：U03「真实实现：两段源码」（90% 基础线 + min 钳制 + 两口径 OR）、U04「保留算法的三个关键片段」、U05 裁剪算法源码、U06 替换与检查点、U07 失败与重试、U08 缓存键与 usage；附录 C 固定源码索引（16 条 + SHA）。
- **缺口清单**：
  - 缺**第二套工具调用链**（方案 §5 要求"以首个实现讲透方法，再让读者追踪第二个工具"）→ T16。
  - 缺"闭源部分怎样用文档/运行证据说明边界"的统一示范（Claude Code）→ T05、T16。
  - 缺面向非 Rust/TS 读者的通用桥接单元（现分散在各单元）→ T16。
- **自测落点**：U03 自测③（`Option` 缺失≠0）、④（轮前检查不含新输入）；U06 恢复顺序题；U07 失败分支题；U08 usage 字段拆读。
- **产出物**：读者标注**一条真实调用链**（带固定 SHA 链接），并在图上标出"哪一步决定了保留、哪一步决定了裁剪、哪一步写回状态"。

### L5 · 独立判断

- **先修知识**：L1–L4 全部。
- **学完能做什么**：为一个小型 Agent 设计上下文流程；处理约束丢失、摘要失败、恢复后重复执行；比较同场景方案并迁移到未讲过任务。
- **核心概念清单**：状态图、伪代码、失败分类、有界重试、副作用、幂等与重复执行、评估（质量/成本/延迟/可恢复）、决策表、反例。
- **已有基线材料映射**：U09（行程规划 Agent 四件交付 + 迁移任务 + 六项能力评分表）；I-设计清单；U09「综合自测」。
- **缺口清单**：
  - 缺**独立任务数据包**（目标/约束/否决决定/消息 ID/长日志/坏摘要）→ T03、T18。
  - 缺**参考解答、允许的替代方案、评分标准、补学入口** → T18。
  - 缺**未讲过场景的迁移题**完整版（现只有方向）→ T18。
  - 缺**六项能力"已展示/需提示/尚未展示"三级评分**的落地表 → T18。
- **自测落点**：U09 四件交付自评；综合自测；迁移题。
- **产出物**：读者提交可复核的**小型方案 + 实验设计**（含状态图、伪代码、失败处理、一个未讲过场景的迁移）。

## 2. 六项能力 × 五级落点表

> 能力口径与要求覆盖表一致。`●` 主落点（该级重点训练）｜`○` 附带落点（该级涉及但不为主）｜空白 = 不在此级考核。

| 能力（编号） | L1 | L2 | L3 | L4 | L5 | 验收证据 |
|---|---|---|---|---|---|---|
| ① 解释信息流 | ● | ● | ○ | ○ | ○ | 能标出记录/选材/请求/外部记忆的位置（`数据地图与机制辨析.md` §1） |
| ② 推演预算与信息损失 | | ○ | ● | ○ | ○ | 计算有单位与条件；能找到丢失的约束（U03、U05） |
| ③ 选择策略 | | ○ | ● | | ● | 给出理由、代价、失败条件与反例（U04、U09） |
| ④ 阅读核心源码 | | | ○ | ● | ○ | 说明关键分支与前后状态，指向固定版本证据（U03–U08、附录 C） |
| ⑤ 设计与排障 | | | ○ | ○ | ● | 提交状态图/伪代码/失败处理与检查方法（U07、U09） |
| ⑥ 评估与迁移 | | | ○ | ○ | ● | 迁移任务 + 质量/成本/延迟/可恢复并查（U08、U09 迁移题） |

**读法**：L1 只训练"解释信息流"（零基础先能听懂）；L2 同时铺垫信息流与流程；L3 是**推演与选择**的主战场；L4 是**读源码**主战场；L5 收敛到**设计排障与评估迁移**。②③ 在 L5 仍需复现（评估要算账），④ 在 L5 仍需引用（方案要指向真实实现）。

## 3. 两条进入路线

### 3.1 零基础连续路线（默认）

依次 L1 → L2 → L3 → L4 → L5，每级先修即前一级产出物。关键衔接点：

| 衔接 | 从 → 到 | 桥接内容 | 样章现状 |
|---|---|---|---|
| L1→L2 | 记录/请求 → 请求组装 | "带着什么去问"具体化成一次请求的组成清单 | U01 末尾已有，缺图（T17 补 I-演化器） |
| L2→L3 | 请求组装 → 触发线 | 从"每次请求都带全部"到"桌子会满、要算线" | U02→U03 顺畅 |
| L3→L4 | 机制 → 源码 | **读源码最小桥接**（列表/对象/函数/条件/状态/异步） | **缺独立桥接单元**（T16 补） |
| L4→L5 | 源码 → 设计 | 从"读懂别人"到"自己设计" | U09 顺畅 |

### 3.2 开发者进入细节入口（可跳过已掌握桥接）

- **可跳过**：L1/L2 的代码桥接（列表、对象、函数）；直接进 L3 的预算演算。
- **从 L3 进入的入口**：U03「四本账」+ I-演算器；前提是知道"消息数组"是什么。
- **从 L4 进入的入口**：附录 C 固定源码索引 + U03/U04/U06 的「真实实现」段；前提是能读 Rust 的 `match`/`Option`。
- **从 L5 进入的入口**：U09 + T18 结业任务包。
- **旁注定位**：Java/Spring、Maven 日志、接口兼容迁移属于**可选迁移案例**（方案 §1.4），不进入公共主线先修；标注为"开发者扩展"。

### 3.3 可停靠级

方案 §1.3 明确"读者可按需停在前三级"。**停靠规则**：
- 停在 L1/L2：获得"读懂上下文管理文章不再发懵"的能力。
- 停在 L3：获得"能算账、能选策略"的能力，但**不宣称**达到专项目标。
- 完成 L4+L5：才对应第 1.2 节的"上下文管理专项中级"（仍需练习与迁移验证）。
