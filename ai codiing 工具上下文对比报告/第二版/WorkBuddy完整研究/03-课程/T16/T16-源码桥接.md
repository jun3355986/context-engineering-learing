## 1. 最小桥接六件套（深化到"可跟做"级）

> 每格四件：**① 一句话 → ② 生活对照 → ③ 最小伪代码 → ④ 真实代码片段对照（`a07c8eb`，行号固定）**。④ 后面给"**逐符号读法**"——告诉你哪几个符号是"盒子"、哪几个是"按钮"。

### ① 列表 / 对象

- **一句话**：**列表**是一排**有序**的格子；**对象**是一组**带名字**的字段。
- **生活对照**：列表＝**购物清单**；对象＝**药盒**（每格贴标签）。
- **最小伪代码**：

```text
消息列表 = [ 条目0, 条目1, 条目2, … ]          # 有序数组，顺序有意义
一条条目 = { role: "user", content: "…" }       # 带名字的字段集合
```

- **真实代码对照**：

```rust
// codex-rs/core/src/session/turn.rs  L1563–1591（节选）
pub(crate) fn build_prompt(
    input: Vec<ResponseItem>,        // ← 列表：一排"响应条目"
    step_context: &StepContext,      // ← 对象：带字段的上下文
    base_instructions: BaseInstructions,
    incremental_tools: bool,
) -> Prompt { … }
```

- **逐符号读法**：`Vec<T>` 读作"**一排 T**"（有序、可重复）；`ResponseItem` 是**条目类型名**（一条用户消息 / 一次工具调用各算一个）；带字段的结构体＝**对象**。**读到 `input[0]` 就是"清单第 1 项"。**

### ② 角色 / ID

- **一句话**：**角色**说"这句话谁说的"；**ID**是给记录发的**唯一编号**，用来**配对**。
- **生活对照**：群聊里的发言人（角色）；**快递单号**（ID）——把寄出与收到的对上。
- **最小伪代码**：

```text
调用 = { role: "assistant", 工具: "查公交", call_id: "call_001" }
结果 = { role: "tool",       call_id: "call_001", 内容: "…" }
断言  调用.call_id == 结果.call_id        # 配对不变量
```

- **真实代码对照**：

```rust
// codex-rs/core/src/context_manager/history.rs  L962–980（节选，注释原文三条不变量）
normalize::ensure_call_outputs_present(items);   // 每个调用都必须有对应结果
normalize::remove_orphan_outputs(items);         // 每个结果都必须能对回调用
normalize::strip_images_when_unsupported(input_modalities, items);
```

- **逐符号读法**：`role` 是**标签**；`call_id` 是**配对编号**——**看到 ID 就想"它在和谁配对"**。**一条调用没有配对结果＝坏结构**，程序在材料进历史前强制执行上述不变量（术语表 §1「工具调用与结果配对」）。

### ③ 函数

- **一句话**：函数是**取个名字**的一段代码——**给输入、给输出**（可能顺带改状态）。
- **生活对照**：**榨汁机**——水果进、汁出；它自己不长水果。
- **最小伪代码**：

```text
函数 build_prompt(材料, 上下文, 基础指令) → 请求     # 材料进，拼好的请求出
```

- **真实代码对照**：

```rust
// codex-rs/core/src/session/turn.rs  L1563–1591（节选）
pub(crate) fn build_prompt(input: Vec<ResponseItem>, …) -> Prompt { Prompt { input, tools: …, … } }
```

```rust
// codex-rs/protocol/src/openai_models.rs  L529–540（节选）
pub fn auto_compact_token_limit(&self) -> Option<i64> { … }   // 吃"模型信息"，吐"限额（可能没有）"
```

- **逐符号读法**：`fn 名字(参数) -> 返回类型`＝"按钮：塞什么、吐什么"；`&StepContext` 的 `&`＝"**借用、不拿走**"；`Option<i64>`＝"**可能有值、可能没有**"（**None ≠ 0**，见 §3 链①失败栏）。

### ④ 分支 / 循环

- **一句话**：**分支**＝"如果…就…"；**循环**＝"对每一个…重复做"。
- **生活对照**：**路口看灯**（分支）／**逐个安检**（循环）。
- **最小伪代码**：

```text
如果 到线: 先整理再发请求                      # 分支
对每一个 用户消息(从新到旧): 装进预算; 装不下就停   # 循环
```

- **真实代码对照**：

```rust
// codex-rs/core/src/session/context_window.rs  L60–110（节选）
match config.model_auto_compact_token_limit_scope {
    AutoCompactTokenLimitScope::Total => ( … ),
    AutoCompactTokenLimitScope::BodyAfterPrefix => { … }
};
let token_limit_reached =
       buffered_limit.is_some_and(|limit| auto_compact_scope_tokens >= limit)
    || full_context_window_limit_reached;        // 两条线，OR
```

```rust
// codex-rs/core/src/compact.rs  L690–770（节选）
let mut remaining = max_tokens;
for message in user_messages.iter().rev() {      // ① 从新到旧
    if remaining == 0 { break; }
    …
    if tokens > remaining { break; }             // ⑤ 边界处理完就停
    remaining = remaining.saturating_sub(tokens);
}
selected_messages.reverse();                     // ⑥ 还原时间顺序
```

- **逐符号读法**：`match`＝**多路分支**；`||`＝**或**；`for x in y`＝**循环**；`.rev()`＝**倒着走**。**源码里 90% 的"决策"都藏在分支里**——这正是要你标出来的东西（M10 图 1 ★）。

### ⑤ 内存 / 文件

- **一句话**：**内存**＝程序正用着的草稿（关掉就没）；**文件**＝写到磁盘的存档（关掉还在）。
- **生活对照**：**便签**（撕了就没了）vs **笔记本**（塞抽屉，明天还在）。
- **最小伪代码**：

```text
替换内存历史(新历史)        # 便签：立刻生效、关掉就没
追加检查点到存档(检查点)     # 笔记本：写进磁盘、关掉还在
```

- **真实代码对照**：

```rust
// codex-rs/core/src/session/mod.rs  L4181–4213（节选）
let replacement_history = items.clone();                 // ① 复制替代历史
state.replace_annotated_history(items, …, HistoryReplacement::Compaction { … });  // ② 替换内存历史
…
CompactedItem {                                          // ③ 检查点（→ 交给持久化写盘）
    replacement_history: Some(replacement_history),      // ④ 整份替代历史存入
    window_number: Some(metadata.window_number),         // ⑤ 窗口身份
    …
}
```

- **逐符号读法**：**看到 `replace` 想内存，看到 `persist` / `RolloutItem::Compacted` 想文件**。压缩检查点保存的是"**替代后是什么**"，不是"删了什么"；**存档追加、不删旧记录**（术语表 §3「压缩检查点」/ §7「会话存档」）。

### ⑥ 异步先后

- **一句话**：**异步**＝"**先发出、先干别的、等结果回来再接着做**"——**发出 ≠ 完成**。
- **生活对照**：**点外卖**——下单后不会站着干等，骑手到了才开吃。
- **最小伪代码**：

```text
先 发出请求(异步) → 继续做别的事 → 等 await 拿到结果 才用它
```

- **真实代码对照**：

```rust
// codex-rs/core/src/session/context_window.rs  L60–110 附近（节选）
let window = sess.auto_compact_window_snapshot().await;   // ← 发出后等结果
```

```rust
// codex-rs/core/src/compact.rs  L338–349（节选）
sess.set_total_tokens_full(turn_context.as_ref()).await;  // ← 状态写回也是异步的
```

- **逐符号读法**：看到 `.await` / `async` / `spawn`，就想"**这里有个先后，别当成一步到位**"。**"发出请求"和"拿到结果"是两个时刻**，中间程序在干别的。

> **【当心】** 六件套只帮你**读骨架**，不保证读懂业务。不认识的专名**别猜**——回术语表（§1/§3/§7）或该工具 `源码导读.md`。

## 2. 同一消息样例跨语言桥接示范（郊游任务）

> **拿一条真实消息走完全程**：样章 U01 的郊游委托。**同一条消息**，从"列表/对象形态"一路读到"异步先后"——**六件事不是六个知识点，是同一份数据的六个面**。

**原始消息（样章 U01 原话）**：

> 帮我安排下周五的班级郊游，两个班，60 人，**下午 4 点前必须回到学校**。顺便看看操场集合点怎么安排。

**教学简化后的消息列表**（数字编的，结构模仿真实请求；样章 U01 同款）：

```json
[
  {"role": "developer", "类型": "基础指令",     "内容": "你是 Codex……"},
  {"role": "developer", "类型": "当前工作状态", "内容": "工作目录 /project；已加载规则：AGENTS.md……"},
  {"role": "user",      "内容": "安排郊游……下午 4 点前必须返校"},
  {"role": "assistant", "类型": "工具调用",     "工具": "查公交", "call_id": "call_001", "参数": {"线路": "A→学校"}},
  {"role": "tool",      "类型": "工具结果",     "call_id": "call_001", "内容": "（300 行公交查询结果）"}
]
```

**六步走完**：

| 步 | 六件套 | 在这条消息上落在哪 | 一行读法 |
|---|---|---|---|
| 1 | **列表 / 对象** | 整段 JSON ＝**列表**；每个 `{…}` ＝**对象**（字段：role / 内容 / 类型 / 工具 / call_id） | `input[2]` 就是"第 3 项＝用户那句郊游" |
| 2 | **角色 / ID** | `role`：developer / user / assistant / tool 四种身份；`call_id: "call_001"` 把"查公交"调用与"300 行结果"**配对** | **同一个 `call_001` 出现两次＝配对成功** |
| 3 | **函数怎么读它** | `build_prompt(input=这份列表, …) -> Prompt` 把列表**拼成请求**；`auto_compact_token_limit()` 从模型信息**吐限额** | 函数吃"这份列表"，吐"要发出去的请求" |
| 4 | **分支 / 循环在哪** | 轮前 `if 到线 { 先整理 }`（`context_window.rs` 两口径 OR）；保留 `for 用户消息(从新到旧) { 装 20,000 预算 }`（`compact.rs`） | **决策**在 `match`/`||`/`if`；**取舍**在 `for … rev()` |
| 5 | **内存与文件各存哪份** | **内存**＝当前活动历史（这份列表的"活副本"，可能被裁剪）；**文件**＝rollout 存档（追加式，压缩不删旧行）＋大工具输出的落盘原文 | 便签＝活动历史；笔记本＝rollout + 落盘文件 |
| 6 | **异步先后** | `sess.auto_compact_window_snapshot().await`——查窗口基线要等；`set_total_tokens_full(...).await`——写"局满"标记要等 | **"发出"与"拿到结果"是两个时刻** |

**这条示范想证明什么、不能证明什么**：

- ✅ **能证明**：这条消息在真实实现里**确实以"列表 + 对象"承载**（`input: Vec<ResponseItem>`）、**靠 `call_id` 配对**（`normalize_history` 不变量）、**由 `build_prompt` 拼成请求**——六件套不是比喻，是这份数据在源码里的真实形态。
- ❌ **不能证明**：这份**教学 JSON 的字段名**（`类型`/`工具`/`参数`）就是源码字段名——它是**教学简化**；真实结构以 `ResponseItem` 为准（术语表 §1「响应条目」）。
- ❌ **不能证明**：运行时**一定**按这条链走（九工具端到端全部 `NOT_RUN`）。

## 3. 代表链（可跟做级：进入条件 / 前后状态 / 失败 / 自测）

> **口径**：基线快照 `a07c8eb`。**每条链四项齐全**——**进入条件**（怎么才会走到）、**前后状态**（走之前 / 走之后各是什么）、**失败**（已定义的行为，不是"可能出错"）、**自测**（含答案）。**不排名次**。

**链矩阵（先看全景）**：

| 链 | 进入条件 | 前后状态 | 失败（已定义行为） | 证据（`a07c8eb`） |
|---|---|---|---|---|
| **① 触发到线** | 轮前/轮中/轮后任一检查点取用量 | 前：A 未到线；后：`token_limit_reached = 真` | 轮前检查**不含即将写入的新输入**（源码留 TODO）→ 巨型粘贴仍可一步超限 | `context_window.rs` L60–117；`openai_models.rs` L393–395、L518–540 |
| **② 保留（20,000）** | ① 为真且进入压缩 | 前：旧历史全在；后：选出的旧用户消息 + 摘要（另加） | 边界处单条超预算 → **截短**（保头尾）；带图消息 → **文字回退**（原图不留） | `compact.rs` L63、L574–603、L690–770 |
| **③ 裁剪 / 限长** | 工具输出进列表前；或活动历史写回时 | 前：完整原文；后：头+尾+标记（活动历史）；**存档仍留原载荷** | 裁剪只作用 live 副本；**"存档有" ≠ "以后一定读回模型"** | `output-truncation/src/lib.rs` L17–41；`truncate.rs` L4、L62–183；`history.rs` L517–576 |
| **④ 写回（检查点）** | 压缩成功（验收通过） | 前：旧内存历史；后：替代历史（内存）＋ 追加 `CompactedItem`（磁盘） | 失败**同时保持** live 历史与已持久化 rollout **不变**；替换后**不回滚** | `session/mod.rs` L4130–4222 |
| **⑤ 恢复** | `codex resume` / 启动重建历史 | 前：磁盘存档；后：替代历史 + 后缀回放 | 纯重放 ≠ 本实现路线；旧记录仍在存档（摘要不可逆 ≠ 源记录删除） | `rollout_reconstruction.rs` L480–520 |
| **⑥ 缓存键** | 每次 Responses 请求构造处 | 前：无键；后：`prompt_cache_key`（默认＝`session_id`）+ usage 认 `cached_tokens` | **CLI 只发键、认明细**；命中/TTL/断点**源码读不出** | `client.rs` L641–653；`sse/responses.rs` L117–151 |

### 链① 触发到线

- **进入条件**：轮前 / 轮中 / 轮后三个检查点都先取 `context_window_token_status`。
- **前后状态**：**前**＝`A < 范围线 且 A < 整段线`；**后**＝`token_limit_reached = (A ≥ 范围线+缓冲) 或 (A ≥ 整段线)` 为真 → 进入整理。
- **失败**：轮前检查发生在**新输入写入之前**（源码留 TODO）——**尚未把即将到来的内容估算进去**，一次巨大粘贴仍可能一步跨过安全线（`turn.rs` L180–184、L1304–1332）。
- **自测**：W = 200,000，p = 95，模型字段 M = 150,000。求基础线、范围限额、H，并判断 A = 152,000 是否到线。
- **答案**：基础线 = 200,000×9÷10 = **180,000**；范围限额 = min(150,000, 180,000) = **150,000**；H = 200,000×95% = **190,000**。A = 152,000：**152,000 ≥ 150,000 已到线**（整段线 152,000 < 190,000 未到）。**到线成立**（依据 `codex-trigger-01/02`；性质＝事实，运行证据 `NOT_RUN`）。

### 链② 保留（20,000）

- **进入条件**：链① 为真且进入压缩流程（本地摘要路径）。
- **前后状态**：**前**＝旧历史全在；**后**＝"重组规则 + 直接保留的旧用户消息 + 另加的摘要"构成**替代历史**。
- **失败**：边界处单条超预算 → **截短**（保头尾）；带图片的消息 → 走 `truncate_text` **文字回退**（"带图消息原图必留"是错的）；候选只收**真用户消息**（靠 `SUMMARY_PREFIX` 排除旧摘要）。
- **自测**：本地路径预算 20,000；用户消息从旧到新为 9,000 / 15,000 / 8,000。写出选取过程与最终顺序。
- **答案**：**倒着装**：先 8,000（剩 12,000）；再 15,000 > 12,000 → **边界截短**（15,000 这条保留头尾合计约 12,000 token 的片段），**收尾停止**（更旧的 9,000 不再尝试）。最终顺序：**[15,000 的截短片段] → [8,000] → [摘要]**，外加最前面重组好的规则与环境。注意 9,000 那条**不会"补缝"**（依据 `codex-retain-01`）。

### 链③ 裁剪 / 限长

- **进入条件**：① 工具执行完成后、写回消息列表**之前**；② 材料写进活动历史时。
- **前后状态**：**前**＝完整原文；**后**＝头+尾+标记（`…N tokens truncated…`，标记**另占长度**）；**活动历史**只留被裁副本，**rollout 保存未裁剪原载荷**。
- **失败**：裁剪只作用于 live 副本——**"活动历史里少了" ≠ "存档里少了"**；且**"存档有" ≠ "以后一定读回模型"**（术语表 §7「会话存档」）。
- **自测**：工具结果被活动历史裁剪了，说明存档里也少了？（对/错）
- **答案**：**错。** 活动历史裁剪只作用于**进入活动历史的副本**；存档（rollout）写入的是**未裁剪原载荷**（除非另有层级的持久化预算，如分片命令输出的 **64 KiB 字节**）。但要追问："存档有" ≠ "以后一定读回到模型"（依据 `codex-trunc-01/02`；注意 **64 KiB 字节 ≠ 64,000 token**）。

### 链④ 写回（检查点）

- **进入条件**：压缩流程成功（含验收通过）后。
- **前后状态**：**前**＝旧内存历史 + 旧存档；**后**＝① 用替代历史**替换内存历史**；② **追加** `CompactedItem` 检查点（含 `replacement_history`、window id、用量摘要、恢复元数据）并 `persist_rollout_items`。**存档追加、不删旧记录。**
- **失败**：失败必须**同时保持** live 历史与已持久化 rollout **不变**；**替换后不回滚**（系统不提供"把历史回滚到替换前"的机制）——所以"安装失败"的窗口极小，一旦替换完成即视为成功路径。
- **自测**：压缩失败，说明这次会话"什么都没发生"？（对/错，举两条"已经发生"的事）
- **答案**：**错。** 例如：① 已执行的工具动作**不会撤销**；② 轮前失败时**新用户输入已先被记录**（源码原注释："Compaction runs before the new input is recorded, so preserve it on every failure"）；③ 失败诊断、部分事件已追加进存档（只增不减）。**"失败 ≠ 零痕迹"**（依据 `codex-persist-01`、`codex-fail-01`）。

### 链⑤ 恢复

- **进入条件**：`codex resume` / 应用启动重建历史时。
- **前后状态**：**前**＝磁盘存档（追加式，含压缩检查点）；**后**＝读回最新检查点的 `replacement_history`，在其**之后回放**后续记录条目（ResponseItem→replay、RetainedContext、InterAgentCommunication 等）。
- **失败**：**不是"纯重放历史"**——走的是「**持久化断点 + 后缀回放**」；旧记录仍在 rollout 存档里，属「摘要不可逆 ≠ 源记录删除」。**能否找回原文**：能（读存档）。
- **自测**：为"pi 的恢复走持久化断点"这条结论写一个**三行引用**（借 M10 的写法练手）。
- **答案**（示例三行，答案本身取自 `pi/源码导读.md` §5.3，非 Codex 事实）：
```text
① 研究快照：earendil-works/pi @ b45e0ebcc5ae2fc42a6f2f23104d10e656e6bedb
② 分发件/本地版本：pi 1.2.0（与快照：一致）
③ 与官方最新关系：一致（核验日期 2026-10-15）
```
（Codex 侧对应事实：`codex-recover-01`，`rollout_reconstruction.rs` L480–520。）

### 链⑥ 缓存键

- **进入条件**：每次 Responses 请求构造处。
- **前后状态**：**前**＝无键；**后**＝请求携带 `prompt_cache_key`（默认＝`session_id`；内部子会话＝`{source}:{parent_thread_id}`；可 override），响应 usage 解析出 `cached_input_tokens / cache_write_input_tokens` 进 `TokenUsage`。
- **失败 / 边界**：**CLI 只负责"发键"和"认明细"**；**命中与否、TTL、断点规则由服务端决定——源码读不出**。**不得**把 API 文档的新参数（如 30m TTL、显式断点）安到这份 CLI 上。
- **自测**：某请求 `input_tokens = 50,000`、`cached_tokens = 40,000`、`cache_write_tokens = 2,000`。求普通输入与计费当量（新代际费率：读 0.1×、写 1.25×），并回答 `cached_tokens` 要不要从 50,000 里再被减一次。
- **答案**：普通输入 = 50,000 − 40,000 − 2,000 = **8,000**；当量 = 8,000×1 + 40,000×0.1 + 2,000×1.25 = 8,000 + 4,000 + 2,500 = **14,500**。**不能再减一次**——`cached_tokens` 是 `input_tokens` 的**明细拆分**，已在 50,000 里（依据 `codex-cache-01`；**命中率属服务端，`NOT_RUN`**）。
