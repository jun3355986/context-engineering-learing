## 场景：方案交上去了，领导问三句话

小周按 M11 设计完"多轮选型助手"的上下文流程，交了上去。领导问了**三句话**：

> **第一句**："你怎么知道它**行**？"——小周想答"它省 token"。领导追问："**省 token 就等于好用吗？** 万一它把'已否决的方案'又复活了呢？"
>
> **第二句**："这个方案**换到别的任务**还灵吗？下周我们有个完全不同的活儿。"——小周发现，他**只在这个场景里验证过**。
>
> **第三句**："你这些结论，**哪些是真测出来的，哪些是推的**？"——小周卡住了：**绝大多数是推的**。

三句话各对应一条主线：

- **第一句** → **评估四维并查**：质量、成本、延迟、可恢复，**缺一不可**，而且**"省"不能替代"对"**。
- **第二句** → **迁移**：把机制从"讲过的场景"搬到"没讲过的场景"，靠的是一张**对照表**。
- **第三句** → **证据分级 + T19 预告**：本课程**没有实测**（全研究 `NOT_RUN`），所以**凡是没测的，都得标出来**。

## 核心概念

### 一、评估四维并查：为什么只看一个都不够

**【人话】** 判断一套上下文方案好不好，要**同时**看四样东西——**质量、成本、延迟、可恢复**。它们常常**互相拉扯**：压得更狠 → 成本降了，但质量可能掉了；恢复做得更全 → 更安全，但成本涨了。**只看一个维度，一定会被骗。**

| 维度 | 一句话 | 要记录的指标 | 口径来源 |
|---|---|---|---|
| **质量** | 任务**对不对**、关键约束**有没有丢** | 任务通过与否；**关键约束违背数**；旧决定复活数 | 用含**否定、精确数字、过期决定**的可测样本（样章 U09 交付 4） |
| **成本** | 花了**多少钱** | 普通输入 / 缓存读取 / 缓存写入**分开拆账**；整理本身的额外请求 | T14 **F 表**（CLI 侧 usage 字段） |
| **延迟** | 花了**多少时间** | 首字延迟、总时长；**整理期间**额外耗时 | 记录触发与耗时本身（整理也花时间） |
| **可恢复** | 出事了**能不能查回来** | 磁盘原文/断点/重放入口；恢复后**重读次数** | T14 **E 表**（信息可取回性） |

**【当心】第一个常见误读**："**压缩率漂亮 = 方案好**。"——**错**。`1 − 处理后/处理前` 只是**体积缩减率**，**不能替代任务质量**。压缩率再高，**约束丢了就是丢了**（样章 U09【当心】原话）。**这是本课程反复强调的第一纪律：省 ≠ 对。**

**【当心】第二个常见误读**："**只看成本就行**。"——**错**。只看成本会**优化掉质量**（把关键约束当"冗余"裁掉）；只看质量会**忽略账单爆炸**（每次全量重发，账单像聊了半小时——M01 的场景）。**四维要一起看，才叫评估。**

**【当心】第三个常见误读**："**四维可以排名次**。"——**本课程没有实测，任何"谁更省/更快/更强"的排序一律作废**（T14 不排名次声明）。四维并查的产出是**你这套方案在四维上的观察数据**，不是**工具排行榜**。**"没有实测不排名次"**——这是评估的底线纪律。

### 二、评估卡：一张表把四维落成动作

拿到方案，**先填这张卡**（这就是 L5 产出物里的"实验设计"骨架）：

| 维度 | 我的方案要观察什么 | 怎么观察（方法/口径） | 现状 |
|---|---|---|---|
| 质量 | 关键约束违背数、旧决定复活数 | 含"不能选 X""14:30 前到""A 已否决"的可测样本 | **T19 已运行**：E1 检查器全 PASS（6 工具），约束违背/复活 0（证据：T19 各记录 E1 节、总表 §3） |
| 成本 | 普通/缓存读/缓存写三项 token | 服务端 `usage` 为准；本地估算标"近似" | **T19 已运行**：用量字段已录（codex 37,632~48,896 等；ocv1 cost=0 可核验、其余订阅/代理不可核验）（证据：T19 总表 §3） |
| 延迟 | 首字延迟、总时长、整理耗时 | 记录触发时刻与耗时 | **T19 已运行**：各条件耗时已录（如 codex 21~66s）（证据：T19 总表 §3） |
| 可恢复 | 恢复后约束还在不在、重读次数 | 恢复后**先验证**（重述检查）再继续 | **T19 已运行**：恢复后重述检查通过（codex 6/6、pi 6/6、claude 3/3、ocv1 6/6）（证据：T19 总表 §3） |

**读卡一句话**：**四维都要有"方法/口径"，且"现状"栏诚实填"未运行"。** 填不出"怎么观察"的方案，**不是可复核的方案**。

本课程定义的"**上下文管理专项中级**"，验收口径就是这**六项能力**（五级覆盖图 §2）。给自己逐项打**已展示 / 需提示 / 尚未展示**：

| **② 推演预算与信息损失** | 算例**含单位与条件**；能指出一处"会丢掉约束"的环节 | M03、M05 | 已展示 / 需提示 / 尚未展示 |
| **③ 选择策略** | 场景 **> 1 个**；每个选择给出**代价**与**一个反例** | M04、M11 | 已展示 / 需提示 / 尚未展示 |
| **④ 阅读核心源码** | 能在**固定链接**里指出触发/保留/替换三个分支的**状态变化** | M10（+各工具源码导读） | 已展示 / 需提示 / 尚未展示 |

3. **每一格都有落点单元**：任何一项打"尚未展示"，**直接回那一列指向的单元补**——这就是"补学入口"。

### 四、迁移题方向：把思路搬到没讲过的地方

**迁移**（transfer）不是"把答案抄一遍"，而是**把机制映射到新场景**。核心动作是**对照表**（样章 U09 的做法）：

```
机制（本课程）  →  新场景里的对应物  →  你要做的动作
关键约束        →  "旧客户端必须兼容"  →  写进头尾 + 约束表标"有效"
长工具结果      →  测试日志（几百行）  →  保头尾 + 关键行单独复述
整理触发        →  会话到线自动压缩    →  算两条线 + 决定提前手动整理的时机
保存与恢复      →  隔天 resume 继续    →  恢复后先验证约束还在
失败处理        →  整理/测试失败        →  本轮不动历史；副作用不重复
缓存            →  同一会话稳定前缀    →  别为凑缓存改写旧消息
```

**本单元给 2–3 个"未讲过场景"的方向**（完整版与参考答案 → **T18 结业任务包**）：

- **迁移方向 A · 带"否决决定"的多轮任务**：一场**选型讨论**，中途"排除了方案 X"，隔一天继续。要求：设计上下文流程，确保**被否决的方案不会复活**，且**否决理由**在压缩后仍可查。（陷阱：只存进摘要 = 把状态交给有损概括，且无法验证它还在——样章 U09 自测⑨）
- **迁移方向 B · 多子代理并行的长任务**：主代理派**三个子代理**分别读三份大文档，再汇总。要求：说清"子代理拿到什么、回传什么"（M08），**中间几十次工具调用去哪了**，主窗口怎么不被污染。
- **迁移方向 C · 跨工具迁移**：把在工具 A 上成立的策略，搬到工具 B。要求：**逐格对照口径差异**（触发线、保留预算、恢复形态、缓存字段——T14 B/C/E/F 表），指出**哪些结论不能直接搬**（如"90–95% 总括句"已被九工具全部否证，C-01/C-02）。

**迁移提交格式**（与 M11 交付 1–4 同格式）：① 材料清单；② 状态流程（**标出一处与代表实现故意不同**的地方并说明理由）；③ 约束保全方案（含"恢复后先验证"）；④ 验证设计（**区分实测/推断**）。

### 五、T19 实验预告：哪些问题只有真实实验能回答

本课程**全部结论来自源码常量、文档级证据或机制推演**，**没有一次真实模型实验**（全研究实验状态 `NOT_RUN`）。下面这些问题，**只有真实实验能回答**——T19 已就其中多数给出实测（未覆盖者保留未知；汇总见 `05-实验/T19/T19-结果总表.md`）：

| 问题 | 为什么本课程答不了 | 出处 |
|---|---|---|
| **连续压缩失真** | 压缩后再次触发阈值如何处理、事实会不会漂移，只有**连续三次压缩**的实测能看 | C-04 / **LQ-09** |
| **服务端缓存**（命中/TTL/键） | 九工具**全部 UNOBSERVABLE**（本地不可核，只能以 usage 为准） | T14 C 表脚注 / F 表 |
| **真实 tokenizer 与计费** | `chars/4` 系列对中文**低估**、Gemini 非 ASCII ≈1.5/字符**高估**——只能实测 | **C-06** |
| **失败注入** | 溢出/中断/取消各走什么出路，多为**文档级/未证** | T14 D 维度 |
| **产品端到端默认行为** | 九工具端到端**全部 NOT_RUN** | T14 §"版本基线" |
| **性能与成本对比** | **这是唯一允许排名次的时机**（统一条件实测后） | T14 不排名次声明 |

**【当心】第四个常见误读**："**课程里写了具体数字，就等于实测过了。**"——**错**。本课程的数字分三类角标：**【源码常量】**（固定快照真常量）、**【演示】**（教学假设，**不得暗示为真实阈值**）、**【测试样本】**（仓库自带测试，注明**未运行**）。**看到数字先看角标**——凡没有实测角标的，**都不能当"跑出来的结果"引用**。

**T19 待回填全清单（本课程汇总处）**：产品端到端默认行为（九工具）｜连续压缩失真（C-04/LQ-09）｜服务端缓存（全部）｜真实 tokenizer 与计费｜失败注入（D 维度）｜性能与成本对比。**这七类问题在 T19 之前，一律保留"未知"。**

### 六、课程收束：五级路线回顾与可停靠级

**五级路线 = 一条产出物链**（每一级做出一样东西，下一级拿它当前提）：

```
L1 建立直觉 ──▶ 产出："记录还在、当前没用上"的解释图
L2 理解流程 ──▶ 产出：一次请求组成清单（标注来源）
L3 掌握机制 ──▶ 产出：同一材料的前后对照表 + 策略取舍
L4 连接源码 ──▶ 产出：一条真实调用链标注（含固定 SHA）
L5 独立判断 ──▶ 产出：小型方案 + 实验设计 + 未讲过场景的迁移  ← 你在这里
```

**可停靠级**（读者可按需停下——五级覆盖图 §3.3）：

| 停在哪 | 获得什么 | 不宣称什么 |
|---|---|---|
| **停 L1/L2** | "读懂上下文管理文章不再发懵" | — |
| **停 L3** | "**能算账、能选策略**" | **不宣称**达到专项目标 |
| **完成 L4+L5** | 对应"**上下文管理专项中级**" | **仍需练习与迁移验证** |

**两条进入路线**（五级覆盖图 §3）：**零基础连续路线**（L1→L5，先修即前一级产出物）；**开发者入口**（可跳过 L1/L2 的代码桥接，直接从 L3 预算演算进）。

**【当心】收束纪律**：**本课程不承诺任何"用某工具就更好/更省/更快"的排序性结论**（T14 不排名次声明）。它给的是**判断方法**：会算账、会选策略、会读源码、会设计、会评估迁移。**"用哪家"是你的场景决定，不是课程排名决定。**

## 真实实现锚点（代表实现）

**锚点一 · 成本维的字段来源（T14 F 表）**：CLI 侧 usage 是**可观测**的，服务端是 **UNOBSERVABLE**。

```
CLI 侧（可观测）：① cached/write 明细  ② cache_read/creation + 桶
                 ③ cache-stats  ④ 同 pi  ⑤ usage 字段  ⑥ 同 v1
                 ⑧ 三桶 + total_cost_usd_ticks(1 USD=10^10)  ⑨ usage 映射、无键
服务端（全部 UNOBSERVABLE）：命中 / TTL / 键 —— 九工具一致（本地不可核）
```

逐点：**"成本"这一维你能记录的是 CLI 侧字段**；**服务端的"实际命中率"记不了**——所以评估卡里成本维只能写"CLI 侧可观测"，**不得承诺命中率**（T14 G 表反例）。

**锚点二 · 可恢复维的入口（T14 E 表 + C-03/C-12）**：九工具**均有落盘/存档入口**（路径与保留期见各包 SP-08）。

```
统一裁决（C-03 / C-12）：
  被压缩内容 → 模型可见层「不可自动恢复」；磁盘原文「保留期内可查」
  ❌ 别信"绝不可能找回"——该绝对化只对"模型可见层"成立
保留期差异：② 30 天；⑤/⑥ 7 天（截断目录）；其余见各包
```

逐点：**可恢复维要区分"模型可见层"与"磁盘层"**——这是 C-03/C-12 裁决的落点。**恢复后"先验证"是评估动作**（样章 U09 交付 3）。

**锚点三 · 质量维的样本设计**（样章 U09 交付 4，无源码，属**方法**）

```
可测样本要含三类"坑"：否定（"不能选 X"）/ 精确数字（"14:30 前到"）/ 过期决定（"A 已否决"）
记录：任务通过与否 + 关键约束违背数 + 旧决定复活数
```

> 更细的字段拆读（usage 逐字段、缓存桶、恢复入口路径）属 **L4**，见 M10 源码桥接与各工具源码导读。
