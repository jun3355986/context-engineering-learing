1. 用**六个日常对照**读懂一段 Rust/TS 源码的骨架——**不需要会写**这两门语言。
2. 照着走完**一条 Codex 真实调用链**（调用者 → 条件 → 处理 → 写回 → 下次/恢复），并指出**保留点 / 裁剪点 / 状态写回点**。

5. 交付 L4 产出物：**一条带固定 SHA 链接的调用链标注**。

## 核心概念

### 一、最小桥接六件套（不懂 Rust/TS 也能读）

**六个日常对照**——每一个都是"**一句话 + 生活对照 + 最小例子**"。看完这六格，源码骨架就能读。

| # | 概念 | 一句话 | 生活对照 |
|---|---|---|---|
| 1 | **列表 / 对象** | 一排格子 / 一个贴标签的抽屉 | 购物清单 / 药盒 |
| 2 | **角色 / ID** | 谁在说话 / 每件东西的编号 | 群聊里的发言人 / 快递单号 |
| 3 | **函数** | 一个"输入进去、结果出来"的按钮 | 榨汁机：水果进、汁出 |
| 4 | **分支 / 循环** | "如果…就…" / "对每一个…重复做" | 路口看灯 / 逐个安检 |
| 5 | **内存 / 文件** | 桌上的草稿 / 抽屉里的存档 | 便签 vs 笔记本 |
| 6 | **异步先后** | "先发出、后收结果"的顺序 | 点外卖：下单≠到手 |

**① 列表 / 对象**
- **一句话**：**列表**是一排**有序**的格子（`[a, b, c]`）；**对象**是一组**带名字**的字段（`{ name: …, age: … }`）。
- **生活对照**：列表＝**购物清单**（第 1 项、第 2 项…）；对象＝**药盒**（每个格子贴着标签："早"、"中"、"晚"）。
- **最小例子**（教学伪代码）：`消息列表 = [ 用户消息, 助手消息, 工具结果 ]`；`一条消息 = { 角色: "user", 内容: "…" }`。**读到 `history[0]` 就是"清单第 1 项"，`msg.role` 就是"药盒上那个标签"**。

**② 角色 / ID**
- **一句话**：**角色**说"这句话是谁说的"；**ID**是给每条记录发的**唯一编号**，用来**配对**。
- **生活对照**：群聊里谁发的言（角色）；**快递单号**——把"寄出的件"和"收到的件"对上（ID）。
- **最小例子**：工具调用与工具结果靠 **`call_id` 配对**（术语表 §1）；**一条调用没有配对结果 = 坏结构**（M02 的"配对不变量"）。**看到 ID 就想"它在和谁配对"**。

**③ 函数**
- **一句话**：**函数**是一段**取个名字**的代码——**给它输入，它给你输出**（可能顺带改点状态）。
- **生活对照**：**榨汁机**——塞水果进去（输入参数），出来果汁（返回值）；它自己**不长水果**，只负责"榨"。
- **最小例子**：`fn build_prompt(...) -> Prompt` 读作"有个叫 `build_prompt` 的按钮，塞进材料，**吐出**一个拼好的请求"。**读函数先看两件事：它吃进什么、它吐出什么。**

**④ 分支 / 循环**
- **一句话**：**分支**是"**如果**条件成立，**就**走这条路"；**循环**是"**对每一个**，重复做同一件事"。
- **生活对照**：分支＝**路口看灯**（红灯停、绿灯行）；循环＝**安检**——**每个**行李都要过一遍。
- **最小例子**：`if 到线了 { 先整理再发请求 }`（分支）；`for 候选 in 从新到旧 { 装进预算 }`（循环）。**源码里 90% 的"决策"都藏在分支里**——这正是本单元要你**标出来**的东西。

**⑤ 内存 / 文件**
- **一句话**：**内存**是**程序正用着**的草稿（关掉就没了）；**文件**是**写到磁盘**的存档（关掉还在）。
- **生活对照**：**便签**（贴在显示器上，撕了就没了）vs **笔记本**（塞进抽屉，明天还在）。
- **最小例子**：压缩时"**替换内存历史**"改的是便签；"**追加检查点**"写的是笔记本（M06 的"两层事实"）。**看到 `replace` 想内存，看到 `persist`/`write` 想文件。**

**⑥ 异步先后**
- **一句话**：**异步**＝"**先把请求发出去，先干别的，等结果回来再接着做**"——**发出 ≠ 完成**。
- **生活对照**：**点外卖**——下单（发出）之后，你**不会站着干等**，而是去忙别的，**骑手到了（结果回来）才开吃**。
- **最小例子**：模型请求是异步的——`send(...)` 之后程序继续跑，**等 `await` 拿到返回**才用结果。**读到 `await` / `spawn` / `async`，就想"这里有个先后，别当成一步到位"。**

> **【当心】** 六件套只帮你**读骨架**，**不保证你读懂业务**。看到不认识的专有名词，**别猜**——回术语表（§1–§11 有 84 条）或查该工具的 `源码导读.md`。

### 二、读源码的边界纪律（三条红线）

**红线一：接口名 / 桩 ≠ 默认行为。** 源码里出现一个**函数名**（如 `async_compaction`）或一个**配置项**，**不等于**它默认就开。Codex 新快照**新增 `session/async_compaction.rs`**；其**特性登记**在 `features/src/lib.rs` L2066–2071（**`Stage::UnderDevelopment`、`default_enabled=false`**）——**属"有条件实现（默认关、开发中）"，不能写成默认行为**（`02-工具/codex-cli/源码导读.md` §2.4）。

**红线二："未找到" ≠ "没有"。** 搜索一个文件没搜到某个机制，只能说**"未发现"**。dsh **未发现 CLI 缓存键**（`dsh-cache-01/02`）——**只能写"未发现"，不能写"dsh 不做缓存"**；pi **刻意不含子代理**（`pi-cm09-01`）——那是**设计选择**，不是"忘了做"。**两者完全不同，引用时必须分开。**

**红线三：快照引用"三行写法"。** 引用任何源码事实，**至少给三行**——缺一行，别人就**无法复现你读的是哪一版**：

```text
① 研究快照：<repo> @ <完整 40 位 SHA>          ← 你读的那份代码
② 分发件/本地版本：<版本号>（与快照：一致 / 漂移）  ← 实际跑的那份
③ 与官方最新关系：<同步 / 落后 / 已弃用>（核验日期）  ← 时效性
```

> **【当心】三行写法专治两种翻车**：① 拿**分发件**（二进制/包）当**源码**引用（闭源工具尤其危险）；② **版本漂移**——Grok 从 `1.0.50` 升到 `1.0.52`，同一条文档**行号都会偏移**（`grok-version-02`）。**只给 SHA 不给版本关系，读者会踩坑。**

 └─ 异步先后 ─── send() … await 结果                        ← 别当成一步到位

## 速查卡（贴墙版）

> 撕下来贴桌上：**六件套读骨架；一条链走到底；三条红线别越界。**

- **六件套**：**列表/对象**（清单/药盒）｜**角色/ID**（谁说的/快递单号）｜**函数**（榨汁机：进→出）｜**分支/循环**（看灯/安检）｜**内存/文件**（便签/笔记本）｜**异步**（点外卖：下单≠到手）。
- **代表链（Codex `a07c8eb`）**：`turn.rs` 调用者 → `context_window.rs` 到线 → `compact.rs` **保留+裁剪** → `session/mod.rs` **写回** → `rollout_reconstruction.rs` **恢复**。
- **三个关键步**：**保留**＝`compact.rs` 装 20,000 预算；**裁剪**＝`compact.rs` 边界截短（+ `history.rs` 不变量）；**写回**＝`session/mod.rs` 替换内存+追加检查点。
- **三条红线**：**接口名/桩 ≠ 默认行为**｜**"未找到" ≠ "没有"**｜**快照引用三行写法**（研究快照 SHA / 分发件版本 / 与最新关系）。
- **八工具入口**：开源走源码链、闭源（②⑧）走可观测行为链、⑦Gemini 仅存档——**不排名次**。
- **别混**：**快照 SHA** 说"我读的是哪份代码"，**本地版本**说"我机器上跑的是哪版"——**两回事**。
