# M01 · 为什么需要上下文管理（L1 · 建立直觉）

> **本单元回答一句话**：AI 这一次，究竟是**根据什么**在回答？
>
> **对应交互**：任务时间线（样章 `I-时间线`，逐步播放"一句话"背后的多次模型往返）。母稿与交互内容一致，先读哪个都行。
>
> **本单元是整门课的入口**：零基础可读，不要求任何编程或 AI 背景。读完你只会获得**一种直觉**和**一张图**，不涉及源码、阈值和配置——那些从 M02 起逐级展开。

---

## 先修

**无。** 这是零基础入口。

你只需要带上一件生活经验：**找人帮忙办一件事时，你得把该说的都说清楚，对方才办得对。** 后面的所有概念，都是这句话在 AI 世界里的翻版。

---

## 学完你能做什么

学完这一单元，你应该能用**自己的话**（不背术语）做到三件事：

1. 解释"为什么我只说了一句话，账单却像聊了半小时"——说清**一次任务 ≠ 一次请求**。
2. 说出"**保存的记录** / **当前选中的材料** / **实际发出的请求**"是**三个不同的东西**，不是一回事。
3. 画出并讲清那张直觉图：**一条约束明明被记下来了，这一次却没有被带上。**

> **能力落点（对应六项能力①）**：本单元只训练**「解释信息流」**——能标出"记录、选材、请求"分别在哪里。推演预算（②）、选策略（③）、读源码（④）、设计排障（⑤）、评估迁移（⑥）从 M02 起逐级训练，本单元只**埋线**不考核。

## 场景：两句话，怎么花了这么多钱？

小林第一次用 AI 编程助手（本课以 **Codex CLI** 作代表实现）。他输入了一句话：

> 帮我安排下周五的班级郊游，两个班，60 人，**下午 4 点前必须回到学校**。顺便看看操场集合点怎么安排。

然后他去泡了杯茶。回来时，屏幕上已经滚过了十几个条目：查地图、查公交、读了一份"研学地点说明.txt"、又查了天气……最后 AI 给出了一份行程。

月底账单来了，小林懵了：**我就说了两句话，为什么像聊了半小时？**

这背后有两个他看不见的事实：

1. **"一句话"触发的是一串请求，而不是一次。** AI 每做一步（读文件、跑命令、查资料），都要"带着当前的所有材料"再问一次模型：现在该怎么办？
2. **每次请求带的材料，远比你输入的文字多。** 系统指令、工具说明、你之前的全部对话、工具查回来的结果……都在里面。

**【人话】** 说白了：AI 每走一小步，就会**回头把所有资料重新摊开在桌上**，再问一次模型。你不说的话它记不住；它说过的、查过的，都在这张桌子上摞着，越摞越高。桌子会满，账单就是这么长起来的。

**【当心】** 初学最容易立的两个错误认知：

1. "AI 记得我们所有的聊天"——不。它每次能"记得"的，只是这次请求**实际带上**的那份材料。加上引号，是因为这既不是人类记忆，也不等于完整历史（后面几单元会看到材料如何被裁剪和替换）。
2. "工具结果是完整保存的"——不一定。工具输出在进入列表前就可能被限长（M05 专讲）；磁盘上保存的记录与当前列表也不是同一份东西（M06）。

## 核心概念：先给人话，再给名字

下面九个词，是整门课的**地基**。每个都先给一句人话，再给术语和英文原词。**不要背，先理解生活对照**。

| 人话直给（先看这个） | 术语 + 英文原词 | 生活对照 |
|---|---|---|
| 你说一句"帮我安排郊游"，AI 一直忙到彻底停下来，这一整段 | **任务**（task / turn） | 一次"帮我把郊游安排好"的委托 |
| AI 每走一步，就把当前所有材料打包，问一次"接下来做什么" | **模型请求**（model request） | 把桌上的材料推给专家看一眼 |
| 程序给 AI 用的功能，比如读文件、跑命令、查资料；AI 自己动不了手，只能**要求**去用 | **工具**（tool） | 专家说"我看看那本书"，助理去书架上拿 |
| 工具干完活交回来的东西（比如 300 行公交查询结果【演示】） | **工具结果**（tool output） | 助理把书翻到某一页递回来 |
| 把"问过什么、答过什么、查回了什么"按时间顺序排成的一串 | **消息列表**（message list / messages） | 桌上按顺序摞好的一叠纸 |
| 列表里每条消息的**身份**：你说的、AI 说的、程序放的工作说明、工具的结果 | **消息角色**（role） | 一叠纸里，谁的便条、谁的批复 |
| 模型计量的最小文本单位；同一句话，中文和英文切法不同 | **token** | 计费的"字数单位"，但不是字数 |
| 模型**单次请求**最多能装多少 token（输入 + 输出一起算） | **上下文窗口**（context window） | 这张桌子的最大面积 |
| 你今天开的一个窗口，一直聊到下班，可以保存、可以再打开 | **会话**（session） | 一整天的办公桌，收工时可以整个存起来 |

> **术语纪律**：以上九条与 `00-管理/术语表.md` §1 同源同义（任务 / 模型请求 / 工具 / 工具结果 / 消息列表 / 消息角色 / token / 上下文窗口 / 会话），课程正文不得另起名字。其中 **token** 与 **上下文窗口** 的层级标注为 **L3**（首次深入讲在 M03）；本单元只给直觉，不给阈值。

**同一概念的三种复述姿势**（挑一个你顺手的记住就行）：

- **故事版**：小林说一句话 = 一次**任务**；AI 每回头问一次 = 一次**模型请求**；助理去拿书 = **工具**；书翻到某页递回来 = **工具结果**。
- **比喻版**：**消息列表**是桌子上的那叠纸；**上下文窗口**是桌子的面积；**token** 是纸上的字数单位；**会话**是收工时能整个封存的办公桌。
- **对话版**：
  - 读者："那 AI 到底记得多少？"
  - 答："它记得的 = 这次请求**实际带上**的那些纸。桌上的纸堆多高、有没有被抽走几张，它自己说了不算。"

## 图与数据（文字化直觉图）：约束在记录里，却不在本次请求里

这是本单元的**唯一产出物**。请照着自己画一遍——不用画得好看，**画对箭头**就行。

**故事背景**：小林那句"**下午 4 点前必须回到学校**"是一条**关键约束**。郊游任务跑到中途，它发生了这样一件事：

```
                【保存的记录】（磁盘上的会话存档）
   ┌───────────────────────────────────────────────┐
   │  … 你: 下午 4 点前必须回到学校                 │  ← 这条约束，记录里有 ✓
   │  … 查公交结果(300行) / 读说明(40行) / 查天气 …  │
   └───────────────────────────────────────────────┘
                        │  恢复/继续时读取
                        ▼
                【当前选中的材料】（内存里的消息列表）
   ┌───────────────────────────────────────────────┐
   │  … 查公交结果(被限长) / 读说明 / 查天气 …       │  ← 约束还在？未必！
   └───────────────────────────────────────────────┘
                        │  经过"请求组装"这一个关口
                        ▼
                【实际发出的请求】（推给模型的那一份）
   ┌───────────────────────────────────────────────┐
   │  基础指令 + 工具说明 + 当前材料 + 你这次的新输入 │
   │  模型看到的："下午 4 点前返校" —— 在，还是不在？│
   └───────────────────────────────────────────────┘
```

**一句话读懂这张图**：

> **"记录里存着"和"这一次请求里带着"，是两件事。** 一条约束完全可能**记录里有、当前列表里也有、但这一次实际请求里没有**——因为从"列表"到"请求"中间还有配对检查、限长、整理等步骤（M02 起逐步揭开）。

**三格对照表（本单元的"数据"）**：

| 格子 | 它在哪里 | 一句话 | 最容易误解 |
|---|---|---|---|
| **保存的记录** | 磁盘：会话存档 | 都存档了，但**柜子不是桌子** | "存档完整"要看实际写入 |
| **当前选中的材料** | 内存：消息列表 | 从柜里挑出来摊在桌上的纸；**挑出来 ≠ 全交给 AI** | "进列表"≠"进请求" |
| **实际请求** | 发给模型的那一份 | 真正推给专家看的；**柜里有，不代表这份有** | 顺序和内容都会被处理 |

> 这三格出自 `03-课程/T02/数据地图与机制辨析.md` §1 的"四对象"（第四格是**外部记忆**，本单元先不展开，M08 再讲）。它对应的读者问题就是 **FB-06**："有历史 / 模型看得到 / 可以找回，是几个不同对象？"——答案是：**是不同对象。**

## 统一主线：从郊游任务到 coding 任务（L1 埋线）

本课从头到尾用**同一条主线**，只是把场景换个皮：

| | 郊游任务（本单元） | coding 任务（M02 起） |
|---|---|---|
| 你说的那句话 | "安排郊游……下午 4 点前返校" | "接着改登录页" |
| 关键约束 | 下午 4 点前必须返校 | 接口必须向后兼容 |
| 工具在干什么 | 查公交、读说明、查天气 | 读代码、跑测试、查文档 |
| 桌子会满的原因 | 工具结果越摞越高 | 文件与日志越摞越高 |

**埋线预告**：下一单元（M02）起，我们会把"郊游"换成"改登录页"，你会看到**同一套机制原封不动地生效**——约束怎么进请求、材料怎么被处理、桌子满了怎么办。**"下午 4 点前返校"和"接口向后兼容"，在程序眼里是同一类东西：一条必须一直带上的约束。**

> **为什么先讲郊游？** 因为郊游任务不需要任何编程知识，就能让你看清"一句话 → 一串请求 → 桌子越摞越高"这件事。**看懂郊游，再看 coding，只是换了名词。**（这正是 `五级覆盖图` §1 L1 缺口清单里点名要补的"迁移预告"。）

  ```json

    {"role": "developer", "类型": "当前工作状态", "内容": "工作目录 /project；已加载规则：AGENTS.md……"},
  ```

## 自测（含答案）

**① 顺序题**：小林看到"AI 停下来等工具结果"的那段时间里，模型被调用了几次？

A. 0 次，工具是本地跑的，与模型无关
B. 1 次：发出"调用工具"那次
C. 2 次：发出调用的那次 + 拿到结果后让它继续的那次
D. 不确定，看实现

**② 判断题**：工具结果出现在消息列表里，就说明它一定会出现在下一次请求里。（对 / 错）

**③ 配对题（本单元产出物）**：请用"记录 / 选材 / 请求"三格，解释一件事：**为什么"下午 4 点前返校"这条约束，可能明明被记下来了，这一次却没有生效？**

**④ 概念题**：把下面四个词分别填进"郊游故事"的对应位置——任务、模型请求、工具、工具结果。

- "帮我安排郊游"这句委托 = ______
- AI 每回头问一次"接下来做什么" = ______
- 助理去查公交 = ______
- 查回来的 300 行结果 = ______

<details>
<summary>参考答案</summary>

**① C。** 模型先被问一次"现在做什么"，它要求调用工具；工具执行完，结果写入列表，模型再被问一次"接下来做什么"。工具执行本身不调用模型，但**两侧各要一次模型请求**——这就是"一句话"变成"一串请求"的最小例子。

**② 错。** "进入列表"和"出现在下一次请求"之间还有处理步骤：配对与内容检查、限长、当窗口紧张时的整理。现有材料可能被裁剪或摘要替代（M04、M05）。这正是直觉图要你记住的那条缝。

**③** 三格分开看：**记录**（磁盘存档）里有这条约束 ✓；**选材**（内存列表）里它可能还在，也可能已被限长/整理动过；到**请求**（真正发给模型的那一份）这一关，还要过配对、限长、整理——**任何一步都可能让它在"这一次"里缺席**。所以"记录里有"不等于"这一次用上了"。要定位它到底在哪一步没的，是 M05 的任务。

**④** 任务 / 模型请求 / 工具 / 工具结果。

</details>

## 要点速查卡（M01）

> 撕下来贴桌上：**一句话 → 一串请求 → 桌子越摞越高 → 记录 ≠ 选材 ≠ 请求。**

- **一次任务 ≠ 一次请求**：AI 每走一步都回头重问一次模型。
- **九概念**：任务、模型请求、工具、工具结果、消息列表、消息角色、token、上下文窗口、会话。
- **三格直觉图**：保存的记录（磁盘）/ 当前选中的材料（内存列表）/ 实际请求（发给模型的那份）——**柜里有 ≠ 桌上摊着 ≠ 这次带上了**。
- **产出物**：画出"下午 4 点前返校"在记录里、却可能不在本次请求里的那条缝。
- **下一步**：M02 把"带着什么去问"变成**一次请求的组成清单**；郊游 → coding 只是换个皮。
- **当心**：AI 不是"记得所有聊天"，它只"记得这次请求实际带上"的那份材料。
