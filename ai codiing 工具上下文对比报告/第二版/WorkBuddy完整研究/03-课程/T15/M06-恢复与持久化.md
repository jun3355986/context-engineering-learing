## 场景：昨天的会话，今天续上

小林合上电脑。今天打开终端，`codex resume`，选中昨天的会话，继续问："把行程再压缩一版。"

AI 接得上话。小林好奇两件事：

> **疑问一**：昨天压缩过一次，今天恢复的**到底是什么**？是完整的原始记录，还是那一小段摘要？
>
> **疑问二**：那被压缩掉的原话，**还在不在**？我**还能不能**找回来？

两个疑问各对应一条主线：

- **疑问一** → 恢复采用什么：要看程序走的是**替代历史 + 后缀回放**，还是**持久化断点**，还是**重放/重建**（三种形态）。
- **疑问二** → 统一裁决 **C-03 / C-12**：**模型这一次看得见的材料**里，被压缩内容**不能自动恢复**；但**磁盘上的原文**，在保留期内**通常可以查回来**。两件事**同时为真**，只是**层不同**。

而这两个疑问，都建立在一个前提上——**你必须先把"三层"分清**。过去很多误解，都来自把这三层当成一层。

## 核心概念

### 一、三层记录：本单元的主结论

**【人话】** 同一个会话，程序里其实有**三份不同的东西**，它们不是一份的三个名字：

```
第③层 下一次模型请求        ← 真正影响模型行为的，只有这一层
     ↑ 组装自
第②层 当前活动历史（内存）   ← 可能已被裁剪/压缩/恢复改写
     ↑ 加载自；压缩时又被写回
第①层 会话存档（磁盘记录）   ← 事件逐个追加写入，压缩不删除旧记录
```

**本单元主结论（四句，必须背下）**：

- **磁盘上有** ≠ **活动历史里有**；
- **活动历史里有** ≠ **下次请求带上**（还要过组装与裁剪）；
- **下次请求带上** ≠ **模型一定照做**（行为是另一层问题）；
- 再补一句：**磁盘上有原文** ≠ **模型此刻看得见原文**（这是 C-03/C-12 的关键）。

**【当心】第一个常见误读**："磁盘上全都有，所以随时能全恢复"——**恢复只采用替代历史 + 后缀**（或断点），**旧原话不会自动回来**。想把某条老记录补回来，要靠"重新读文件 / 重新检索"这类**显式动作**，而且还要它此刻**还在磁盘、还在读得到的范围里**。

### 二、整理完成时，程序到底写了什么

整理（压缩）完成时，程序做**两件事**（Codex 固定快照的实现）：

1. **替换当前活动历史**：用"**替代历史**"（`replacement_history`，= 重组后的规则 + 直接保留的旧消息 + 新摘要/压缩条目）替换内存里的历史；
2. **向磁盘追加一条"压缩检查点"**：一条记录，里面装着这次替代历史的**完整副本**、窗口编号与 ID、用量摘要、恢复元数据等。

关键点（**这是"能不能找回"的证据基础**）：

- 检查点保存的**不是"被删掉了什么"，而是"替代后是什么"**；旧记录仍留在**之前已写入的存档行**里——**追加式写入，不覆盖**。
- **没有任何"删除旧 JSONL"的操作**——但再次强调：**存档保的是文件内容，不是"以后自动回模型"的承诺**。

**【当心】并发细节（容易被忽略）**：整理在后台进行时，用户**可能又提了新的目标更新**（改需求、改约束）。若直接拿"整理开始前的快照"覆盖一切，新更新会丢。固定快照的处理是：**安装替代历史前，先等待已接受更新的持久化完成（持写锁防乱序），再把"整理输入快照里没有、替代历史里也没有"的新更新，按原顺序追加到替代历史之后**。这就是"替代历史 ≠ 时间倒流"的关键保护。

### 三、三种恢复路线形态（LQ-10 已裁决全表）

恢复时要"重建当前工作材料"，业界做法可归为**三种形态**（LQ-10 原设"重放 vs 持久化断点"两分，核验后细化为三种）：

| 形态 | 一句话 | 恢复时做什么 | 代表 |
|---|---|---|---|
| **A · 替代历史 + 后缀回放** | 先采用**选中的检查点里的替代历史**，再**逐条回放"检查点之后"的记录** | 不从头重放全部旧消息；把压缩之后发生的事按序补上 | ① Codex |
| **B · 持久化断点** | 恢复时**不重算**，直接用存档里的"摘要 + 保留段起点"重建 | 追加式日志里存着断点（摘要条目 + 起点 ID），投影重建 | ③ pi、④ oh-my-pi、⑤ ocv1、⑥ ocv2、⑨ dsh |
| **C · 重放 / 重建** | 从落盘记录**重新走一遍**，重建出历史 | 从 JSONL/权威日志**重放**出对话历史 | ⑦ Gemini（存档）、⑧ Grok |

**A 与 B 的差别**（一句话记住）：**A 是"用检查点当底、把后面的补上"；B 是"直接用断点、不重算"**。两者都**不**把被替代掉的原始旧消息重新发给模型——这正是"恢复 ≠ 重发全历史"的实现含义。

### 四、核心裁决 C-03 / C-12：两个事实并存

冲突 **C-03** 的表面对立是：**「压缩不可逆 / 不进入恢复上下文」**（`claude-ds` §3.3.10）**vs「历史物理保留」**（`MANAGEMENT_RESEARCH` §4.4）。旧学习笔记 §10 更写成"**绝不可能找回**"（绝对化）。

**裁决（C-03 + C-12，各工具侧均已裁决）**：

> **两个事实并存**——① **模型可见层**：被压缩内容**不可自动恢复**（替代历史/断点里不含它）；② **磁盘原文层**：被压缩内容**在保留期内可查**（原条目/存档不删）。
>
> **"绝不可能找回"仅对"模型可见层"成立**——一旦限制到这一层，说法成立；一旦外推到"磁盘也没有、任何方式都取不回"，**被否证**。

逐工具口径（C-12 裁决原文要点）：

- **① Codex**：源不删（追加式存档，压缩不删旧记录）；
- **② Claude**：**保留期内可查**（磁盘 transcript；`claude-resume-05`：压缩**不改磁盘**、原消息留在 transcript）；
- **③ pi / ④ oh-my-pi**：限「**模型可见层**」（原条目仍在 JSONL，但投影不再包含被压部分）；
- **⑤ ocv1 / ⑥ ocv2**：**持久化断点**（原始消息在 DB **不删**）；
- **⑦ Gemini / ⑧ Grok**：**重放/重建**；
- **⑨ dsh**：**持久化断点**（追加式 JSONL，**原文保留**）。

**【当心】第二个常见误读**："恢复 = 精确还原昨天那一刻"——**也不是**。恢复是**重建当前工作材料**的过程，期间**双向差异都会出现**：压缩前被替换掉的部分**不会回来**；后缀里**新发生的变化会补上**。

## 四态对照（本单元产出物演练）

### 表 A · 恢复四态（交互 I-状态机逐格）

| 层面的状态 | 压缩前 | 压缩后 | 关闭程序 | 重开 resume |
|---|---|---|---|---|
| ① 存档（磁盘） | 已有全部记录 | **追加**检查点（旧记录仍在） | 不动 | 不动 |
| ② 活动历史（内存） | 原始列表 | **被替换**为替代历史 | 内存态消失 | 由"检查点替代历史 + 后缀回放"重建（或断点重建） |
| ③ 下次请求 | 原列表组装 | 带上替代历史 | — | 与压缩后一致（除非后缀里又有变化） |

**读表一句话**：**磁盘不动、内存被换、请求跟着内存走**。

### 表 B · 材料四态（L3 产出物）

对**同一份材料**（郊游/接口兼容任务），整理后逐条标它去了哪一态：

| 材料四态 | 含义 | 去哪了 | 对应机制 |
|---|---|---|---|
| **原样留下** | 在保留预算内的**近期原话**原样进替代历史 | ② 活动历史 | 保留算法（M04） |
| **变摘要** | 旧材料被压成一段更短文本 | 替代历史里的摘要 | 摘要（M04） |
| **移除** | 既不在保留预算、也没进摘要 | 仅存于①存档（磁盘） | 替换（本单元） |
| **落盘** | 大输出存磁盘，请求里只留路径/预览 | 磁盘文件 + ②里的引用 | 落盘（M05） |

**【当心】四态里最容易被忽略的一格是"移除"**：它**不是"消失"**——材料**仍在①存档**里（磁盘原文层可查，C-03/C-12）；它只是**不再出现在模型可见层**。把"移除"读成"删除"，就会推出错误的"绝不可能找回"。

### 两问必答（L3 产出物）

- **问 1 · 恢复后会不会重复执行？**
  **恢复重建的是"材料/对话历史"，不是"重跑已完成的动作"。** 已经产生的**副作用不可回退**（例：整理前已写进磁盘的文件，恢复/压缩失败都**不会撤回**；⑧ Grok 的 `/rewind` **只截断对话、不还原文件** `grok-recover-01`）。是否会把同一条命令**再跑一遍**，取决于恢复后模型**是否被重新驱动**去调那个工具——这是**幂等/重复执行**问题，属 L4–L5 深水区，本单元只给结论方向，机制细节见 **M08（记忆/子代理/交接）与 M11（设计与排障）**。**【T19 部分：E4 恢复条件下未见工具重复执行（codex 恢复轮 0 命令、pi 溢出恢复 0 工具动作）；专门副作用注入未做 → 保留未决（证据：T19/01-codex.md §A-6、02-pi.md §5）】**

- **问 2 · 会不会找回被压内容？**
  **分两层答**：**模型可见层——不会自动找回**（替代历史/断点里没有它）；**磁盘原文层——保留期内可查**（走各工具的落盘/存档入口，E 表 SP-08）。"绝不可能找回"**只对前一层成立**（**C-03 / C-12**）。

**读表三件事**（不排名次，只讲形态）：

1. **三形态分布**：**A 替代历史 + 后缀回放**（①，1 家）；**B 持久化断点**（③④⑤⑥⑨，5 家）；**C 重放 / 重建**（⑦⑧，2 家）。**同一件事，三种画法。**
2. **"原文还在不在"是共同点**：**九工具均有落盘 / 存档入口**（E 表），被压缩内容在**保留期内可查**（C-03/C-12）——差异在**保留期**与**取回入口**（② 30 天；⑤/⑥ 截断目录 7 天；其余见各包 SP-08）。
3. **"崩溃恢复"不是每家都有**：**⑥ ocv2 有 write-ahead claim**（跨进程），⑤ ocv1 **未见**跨进程 claim（进程内中断清理）——**同为 OpenCode，v1/v2 在此处分叉**（`ocv2-recover-02`）。

**【当心】两个别写错的说法**：

- ❌ "resume **绝不可能找回**被压缩内容"——**被否证**（C-12：仅"模型可见层"成立；磁盘原文保留期内可查）。
- ❌ "恢复 = 精确还原昨天那一刻"——**双向差异都会出现**（被替换的不回来；后缀里的新变化补上）。

## 自测（含答案）

**① 三层判断题**：以下三句话分别说的是哪一层？（a）"文件里还存着"（b）"这段不在当前列表里"（c）"这次请求带着它"。

**② 恢复题**：昨天压缩后你又聊了三轮，今天 `resume`。走"替代历史 + 后缀回放"路线时，恢复后的初始历史由哪**两部分**组成？

**③ 并发题**：整理进行中，用户改了口径（"行程按新版本算"）。如果不做保护，风险是什么？程序怎么防的？

**④ 裁决题（C-03/C-12）**：同学说"压缩过的内容绝不可能找回"。这句话**哪一部分成立、哪一部分被否证**？

**⑤ 产出物题**：同一份材料里有 5 条用户原话 + 1 条 8 万字日志。整理后，8 万字日志最可能落在**四态**中的哪一态？为什么它**不等于"删除"**？

**⑥ 对照题**：③ pi 与 ⑧ Grok 的恢复路线**形态不同**，各属 A/B/C 哪一类？它们"原文还在不在"这一点是否相同？

<details>
<summary>参考答案</summary>

**①** （a）第①层**存档**（磁盘）；（b）第②层**活动历史**（内存）；（c）第③层**请求**。注意（c）才是**影响模型行为**的层面。

**②** 最新可用**检查点的替代历史**（含重组规则、保留的消息、摘要/压缩条目）+ **该检查点之后的记录后缀**（那三轮的条目按序回放）。**不包括**更早的、已被替代历史覆盖的原始旧消息。

**③** 风险：用整理开始前的快照覆盖一切，把"新接受的更新"丢掉，等于**时间倒流**回整理开始那一刻。防护：安装替代历史前**先等待已接受更新的持久化完成**（写锁防乱序），并把"输入快照后新接受的目标更新"**按原顺序追加到替代历史之后**。

**④** **成立的部分**：对**模型可见层**成立——被压缩内容**不可自动恢复**。**被否证的部分**：外推成"磁盘也没有、任何方式都取不回"——**磁盘原文在保留期内可查**（各工具落盘/存档入口，E 表 SP-08）。**C-03/C-12 裁决：两事实并存、层不同**。

**⑤** 最可能落**"移除"**态（也可能先经"落盘"：大输出被落盘、请求里只留路径/预览）。它**不等于"删除"**：材料**仍在①存档（磁盘）**，只是**不再出现在模型可见层**——正是 C-03/C-12 的"层不同"。

**⑥** ③ pi = **B 持久化断点**（`pi-recover-01`）；⑧ Grok = **C 重放/重建**（`grok-recover-01`）。**"原文还在不在"这一点相同**：**九工具均有落盘/存档入口**，被压缩内容在保留期内可查（C-03/C-12）——**路线形态不同 ≠ 可查性不同**。

</details>

## 速查卡（贴墙版）

- **三层**：① 存档（磁盘）→ ② 活动历史（内存）→ ③ 请求。**磁盘有 ≠ 历史有 ≠ 请求带 ≠ 模型照做**。
- **整理写两处**：替换**内存**历史（替代历史）+ **追加**磁盘检查点（不删旧记录）。
- **恢复三形态**：**A 替代历史 + 后缀回放**（①）/ **B 持久化断点**（③④⑤⑥⑨）/ **C 重放·重建**（⑦⑧）。**都不重发被替代的原始旧消息**。
- **恢复四态**：磁盘不动、内存被换、请求跟着内存走。
- **材料四态**：原样留下 / 变摘要 / 移除 / 落盘——**"移除" ≠ "删除"**。
- **核心裁决**：**C-03 / C-12** ——"压缩不可逆"与"物理保留"**两事实并存**；"绝不可能找回"**仅对模型可见层成立**。
- **当心**：❌"绝不可能找回"（C-12 限制绝对化）；❌"恢复 = 精确还原那一刻"；❌"移除 = 删除"。
