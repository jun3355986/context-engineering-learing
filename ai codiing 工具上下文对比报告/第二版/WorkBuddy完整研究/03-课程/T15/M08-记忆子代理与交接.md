# M08 · 记忆、子代理与交接（L3 · 掌握机制）

> **这一单元回答**：AI 关掉再开，**为什么有时还记得上周的偏好**？那份"记忆"是谁写的、什么时候写的、默认开还是关？把一件大活儿**交给一个"子代理"**去做，它**拿到什么、回传什么**？最后：**"记忆""会话""磁盘原文""缓存"**这四样东西，到底哪一样是哪一个？
>
> **对应基线**：样章 `Codex CLI 上下文管理-教学母稿.md` 未覆盖本单元（样章只到"磁盘记录/恢复"）。本单元**补齐五级覆盖图 L3 的三个缺口**：**CM-08 长期记忆**、**CM-09 子代理交接**、**跨会话信息边界**（T02 五级覆盖图 §1 L3「缺口清单」）。
>

## 学完你能做什么

1. 用**一句话**切开四个常被混为一谈的东西：**记忆 ≠ 会话 ≠ 磁盘原文 ≠ 缓存**。

## 场景：下周一，换了目录，它还认得我

周一早上，小林在**另一个项目目录**打开 AI：

> **疑问一**：上周我让它"这个仓库的时间统一用 UTC"，它**今天还记得**。这条"记忆"是谁写的？我昨天没提过它啊。
>
> **疑问二**：有个任务太大——让它把一份 **8 万字日志**读完再给结论。它没有直接塞进主对话，而是**派了一个"子代理"**去读。那个子代理**看到了什么**？它**回来的又是什么**？

两个疑问各对应一条主线：

- **疑问一** → **长期记忆（CM-08）**：跨会话保存、下次重新提供的那份"笔记"。它是**后台自动抽取**的，还是**会话内由模型自己写文件**的？默认开还是关？（多数工具：**默认关**。）
- **疑问二** → **子代理交接（CM-09）**：主 Agent 让子 Agent 去干活，它**有独立上下文窗口**；干完**只回摘要**，中间的几十次工具调用**不进主上下文**。

而这两条主线，都建立在一个前提上——**你必须先把"四样东西"分清**。过去很多误解（"它有记忆就等于它什么都记得""子代理看得到我们全部聊天"），都来自把这四样当成一样。

## 核心概念

### 一、四个东西，四种边界：本单元的主结论

**【人话】** 这四样都可能"让 AI 想起点什么"，但它们是**四种不同的对象**，不能互相顶替：

| 对象 | 存在哪 | 谁写 | 什么时候进请求 | 术语表落点 |
|---|---|---|---|---|
| **记忆**（长期记忆 / 会话记忆） | 独立记忆目录 / 记忆文件 | 模型自己写、或后台提取、或人工审批 | **下次会话启动时注入**（部分） | §5 |
| **会话**（transcript / 存档） | 磁盘会话文件（JSONL / DB） | 程序逐条追加 | 恢复时读回（M06） | §7 |
| **磁盘原文** | 落盘的工具输出 / artifact | 程序落盘 | **不自动进请求**，要用时才读（M05/M09） | §3 |
| **缓存** | 服务端 KV（+ CLI 侧键） | 服务端复用 | 前缀相同才复用，**不改变内容** | §6 |

**本单元主结论（四句，必须背下）**：

- **记忆里有** ≠ **下次请求带上**（记忆也要过"注入预算"，如 Claude 的"前 200 行/25 KB"）；
- **会话里有** ≠ **子代理看得到**（子代理默认**全新窗口**，看不到主对话历史）；
- **磁盘原文有** ≠ **记忆里有**（原文是落盘文件，记忆是抽取后的笔记）；
- **缓存命中** ≠ **记忆生效**（缓存只复用**相同前缀**的计算，**不改内容**）。

**【当心】第一个常见误读**："这工具**有记忆**，所以它**默认就会记**。"——**错**。T14 矩阵 C 表"长期记忆（默认）"一行给出的口径是：**大多默认关**（④ oh-my-pi 默认 off / ⑦ Gemini 默认关 / ⑧ Grok 默认关），② Claude 是"**文档未描述后台机制**"，③⑤⑥⑨ 是"**未发现默认实现（推断）**"。**"有实现"与"默认开"是两件事**。

### 二、长期记忆（CM-08）的三种形态

把各工具的实现形态归一下，只有三类（**不排名次，只讲形态**）：

| 形态 | 一句话 | 谁在写 | 代表 |
|---|---|---|---|
| **A · 后台提取** | 程序在**后台**扫旧会话、抽要点，写成候选 | 后台 Agent（**非**主对话） | ⑦ Gemini（实验，默认关）、⑧ Grok（每轮复盘 + Dream） |
| **B · 会话内读写** | **模型自己**在会话里用文件工具**读写**记忆文件 | 主模型（用户可见 `Saved N memories`） | ② Claude（auto memory，默认开） |
| **C · 未发现默认实现** | 出货路径内**没有**独立长期记忆 | —（跨会话信息由**规则文件/扩展**承担） | ③ pi、⑤ ocv1、⑥ ocv2、⑨ dsh |

**【当心】第二个常见误读**："**未发现**默认实现 = **这个工具没有**记忆。"——**不能这么写**。各包原文口径是"**未发现默认实现（推断）**"（③ `pi-memory-01`、⑤ `ocv1-memory-01`、⑥ `ocv2-memory-01`、⑨ `dsh-memory-01`），并明确**"未发现"≠"没有"**（可能存在于插件生态、远端服务或未覆盖路径）。**这就是"未发现≠没有"纪律**：照抄"未发现默认实现（推断）"，**不写成"没有"**。

**【当心】第三个常见误读（LQ-08）**："AI 会**后台持续抽取会话记忆**。"——这句**在多数工具上不成立**。冲突表 **LQ-08** 的核验结论是：② Claude **文档未描述后台机制**（`claude-memory-03`）；⑦ Gemini **有实现但默认关**（`gemini-memory-02/03`）；⑧ Grok **有后台复盘但默认关**（`grok-memory-04`）；⑨ dsh **未发现后台提取**（`dsh-memory-01`）。即：**"后台抽取"只在少数工具上"有条件成立"（且默认关）**，不能当默认行为讲。

### 三、子代理（CM-09）的两条路线

主 Agent 派子 Agent 干活，**第一步就要选路线**——它**继承多少上下文**：

| 路线 | 子代理看到什么 | 代价 | 代表 |
|---|---|---|---|
| **全新独立窗口**（fresh） | **看不到**主对话历史、已读文件、已调用技能；由父写一条**委派消息**（含任务摘要）起步 | 需要父把任务讲清楚；上下文**隔离**换来主窗口不被污染 | ② Claude 默认（`claude-subagent-01`）、⑦ Gemini（`gemini-cm09-01`） |
| **fork 继承** | **继承**主对话的 system prompt、工具、模型与**全部消息历史**（首请求读父级缓存） | 牺牲输入隔离；拿主对话**完整**工具池 | ② Claude 的 `/fork`·`--fork-session`（`claude-subagent-01`） |

**回传**这一步同样关键：**子代理的工具调用不进主上下文，完成后只回摘要**（② `claude-subagent-02`；⑦ `gemini-cm09-01`；⑧ Grok"usually a summary" `grok-cm09-01`；⑨ dsh 以 `delivery:'parent'` 的 **user 角色状态通知**回传 `dsh-cm09-02`）。⑨ dsh 进一步区分：**进程内 `spawn`（全新）/ `fork`（以父的已完成历史为种子）**保留 durable 子会话可续聊；**进程外 `acp`/`codex`/`claude-code`/`dsh-sdk` 只执行一次**（`dsh-cm09-01`）。

**【当心】第四个常见误读**："子代理 = 把主对话复制一份。"——**多数默认不是**。默认是**全新独立窗口**（② `claude-subagent-01`、⑦ `gemini-cm09-01`），子会话**不共享消息列表**（⑨ `dsh-cm09-01`）。

### 四、交接材料：拿到什么、回传什么

"交接"（handoff，术语表 §7）不是把整段历史递过去，而是**两段窄接口**：

- **去程（父 → 子）**：一条**委派消息**——父把**任务摘要**写给它起步（② `claude-subagent-01`；⑦ 工具 schema 明确要求 prompt "comprehensive and detailed" `gemini-cm09-01`）；子会话**继承父的 origin 元数据与权限根，但不共享消息列表**（⑨ `dsh-cm09-01`）。④ oh-my-pi 走"**按 agent 定义（自带 systemPrompt）+ task/solutionSpace 生成独立子会话**"（`ohmy-cm09-01`）。
- **回程（子 → 父）**：**只回摘要 + 一小段元数据**（含 token 数与时长，② `claude-subagent-02`）；④ 单 agent 输出上限 **500000 字节 / 5000 行**（`ohmy-cm09-01`）；⑨ 含子最终文本块 + 可选 `Structured result: <JSON>`，空收尾报 "It left no closing message."（`dsh-cm09-02`）。

**为什么这样设计**：中间几十次工具调用**留在子窗口**，主窗口只收一段结论——这就是"**子代理省主上下文**"的实现含义。

**【当心】pi 的写法（本单元专有纪律）**：③ pi 对 CM-09 的正确表述是"**刻意不含**"（`pi-cm09-01`），**不是**"未找到"。README 明示 "Pi ships with powerful defaults but **skips features like sub-agents and plan mode**"；主仓源码**无内建**子代理实现，仓库**随附** `examples/extensions/subagent/` 属**扩展层**、非默认核心。**"刻意不含"与"未找到"是两种不同的结论**——前者是**设计选择（事实）**，后者是**检索结果（推断）**。⑤ ocv1/⑥ ocv2 则相反：**适用**（`ocv1-cm09-01` / `ocv2-cm09-01`）。

## 真实实现锚点（代表实现）

**锚点一 · ④ oh-my-pi 的记忆后端（"默认 off + 多后端"的形状）**：`packages/coding-agent/src/memory-backend/settings.ts#L12-40`【源码常量】`ohmy-memory-01`

```
memory.backend 默认 off
  可选 local     —— 本地 rollout 摘要管线（注入 "Memory Guidance"，上限 5000 token）
     hindsight   —— 远程向量服务
     mnemopi     —— 本地 SQLite
     sharpshooter—— 项目决策文件
  （共 5 个取值：off + 4 后端；默认仍是 off）
```

逐点：**"有记忆"是真的（有 4 个后端可选），"默认开"是假的（默认 off）**——这正是"有实现 ≠ 默认开"的教科书例子。

**锚点二 · ② Claude 的两条记忆线**（文档级，闭源；`claude-memory-02`）

```
CLAUDE.md      —— "你写的持久指令"（用户/团队写）
auto memory    —— "Claude 自己写的笔记"（~/.claude/projects/<project>/memory/）
                  type 分四类：user / feedback / project / reference
                  MEMORY.md 启动注入前 200 行或前 25 KB
```

**锚点三 · ⑦ Gemini 的两条记忆路径（"模型主动写" vs "后台提取"并存）**：`gemini-memory-01` 与 `gemini-memory-02/03` **互补**

```
路径① 模型主动写：模型用 write_file/replace 编辑 GEMINI.md/MEMORY.md（默认开，分层注入）
路径② 后台提取  ：SkillExtractionAgent 后台扫「空闲≥3h 且 ≥10 条 user 消息」的会话
                  → 产出 .inbox/{private,global}/extraction.patch（不自动应用）
                  → 用户 /memory inbox 人工审批（apply/dismiss）
                  → 由 experimental.autoMemory 门控，默认 false
```

**锚点四 · ⑧ Grok 的后台复盘 + Dream**（文档级；`grok-memory-03`）

```
每完成一轮 → 后台复盘该轮 → 新事实写入 observations/_inbox/
Dream：一个 scope ≥20 条 inbox 观察 或 最旧观察 ≥24 小时 → 自动折叠进 topics
索引每会话注入一次（每 scope ≤ 8 KiB）
```
注意：这是**默认关的实验特性**（`memory.enabled` / `memory_v2.enabled` 默认 **false**，`grok-memory-01`）——对 LQ-08 的裁决是"**有条件成立**（仅当显式开启）"（`grok-memory-04`）。

## 三问判断卡（本单元 L3 产出物）

拿到任一工具，**先问三句**，就能判断它的"记忆"是什么货色：

| 工具 | ① 默认开还是关 | ② 后台跑还是会话内跑 | ③ 人工审批还是自动写入 |
|---|---|---|---|
| ① Codex | **未核**（有 memories crate） | **未核** | **未核** |
| ② Claude Code | **开**（auto memory） | **会话内**（模型自己读写；后台机制文档未描述） | **自动**（Claude 写；用户可整体关闭） |
| ③ pi | **无**（未发现默认，推断） | — | — |
| ④ oh-my-pi | **关**（默认 off） | **会话内**（选定后端后注入） | **自动**（无审批环节） |
| ⑤ ocv1 / ⑥ ocv2 | **无**（未发现默认，推断） | — | — |
| ⑦ Gemini（存档） | **关**（后台提取默认关） | **后台**（空闲≥3h 且 ≥10 条 user 消息） | **人工审批**（`/memory inbox`） |
| ⑧ Grok | **关**（实验特性） | **后台**（每轮复盘 + Dream） | **自动**（写入 inbox 后自动折叠） |
| ⑨ dsh | **无**（未发现默认，推断） | — | — |

**读卡一句话**：**② 是"默认开但会话内"；⑦⑧ 是"后台但默认关"；④ 是"会话内、默认关"；③⑤⑥⑨ 是"未发现默认"。**——**四类各不相同，"有记忆"这句话本身不携带任何判断**。拿一个没学过的工具，只要查到"默认开关 + 机制位置 + 有无审批"三项，就能把它填进这张卡——这就是 L3 要求的"当场判断"。

**④ 子代理题**：② Claude 默认派出的子代理，**看得到**主对话历史吗？它干完活**回传**什么？中间几十次工具调用去哪了？

<details>
<summary>参考答案</summary>

**①** （a）**记忆**（§5，独立记忆目录）；（b）**会话**（§7 transcript，磁盘记录）；（c）**磁盘原文**（§3 落盘文件）；（d）**缓存**（§6，前缀相同才复用，**不改内容**）。**四样是四种对象，不能互相顶替。**

**②** 因为**"有实现" ≠ "默认开"**：`ohmy-memory-01` 明确 `memory.backend` **默认 off**，只是**有 4 个后端可选**（local/hindsight/mnemopi/sharpshooter）。正确写法："**有、默认 off**（需选后端才生效）"。

**③** 该写"**刻意不含**"（`pi-cm09-01`）。差别：**"刻意不含"= 设计选择（事实）**——README 明示 skips sub-agents；**"未找到"= 检索结果（推断）**——只说"我没搜到"。pi 有 README 一级证据，故是**事实**，不是推断；写成"未找到"会**弱化**证据强度、并暗示"也许有只是没搜到"。

**④** **默认看不到**主对话历史、已读文件、已调用技能（**全新独立窗口**，`claude-subagent-01`）；由 Claude 写一条**含任务摘要的委派消息**起步。干完**只回摘要**（加一小段 token 数与时长元数据，`claude-subagent-02`）。**中间几十次工具调用留在子窗口，不进主上下文**——这正是"子代理省主上下文"的含义。

**⑤** **不成立（或未证实）**：② Claude **文档未描述后台机制**（`claude-memory-03`）；⑨ dsh **未发现后台提取**（`dsh-memory-01`）；③⑤⑥ pi/ocv1/ocv2 未发现默认记忆。**有条件成立**：⑦ Gemini **有实现但默认关**（`gemini-memory-02/03`）；⑧ Grok **有后台复盘但默认关**（`grok-memory-04`）。**安全改写**："**部分工具有后台抽取实现，但默认关（需显式开启）；多数工具出货路径内未发现默认实现**"——**不写成默认行为**。

**⑥** 还缺 **②"后台还是会话内"** 与 **③"人工审批还是自动"**。必须补，因为**默认开只说明"会不会用"，不说明"谁在什么时候写"**：同样是"默认开"，② Claude 是**会话内模型自己写**（用户可见），⑦ Gemini 的后台提取是**后台跑 + 人工审批**——**机制位置与审批环节决定了"这条记忆可不可信、会不会写错"**，是 L3 判断的核心。

## 速查卡（贴墙版）

- **四个边界**：**记忆 ≠ 会话 ≠ 磁盘原文 ≠ 缓存**（§5/§7/§3/§6）。**能想起 ≠ 进请求。**
- **记忆三形态**：**A 后台提取**（⑦⑧，默认关）/ **B 会话内读写**（②，默认开）/ **C 未发现默认**（③⑤⑥⑨）。
- **"未发现"≠"没有"**：照抄"**未发现默认实现（推断）**"，**不写"没有"**（③⑤⑥⑨）。
- **子代理两路线**：**全新独立窗口**（默认）/ **fork 继承**；**只回摘要**，中间调用留子窗口。
- **pi 专有写法**：CM-09 = "**刻意不含**"（设计选择，非"未找到"）。
- **三问判断卡**：**默认开/关 · 后台/会话内 · 人工审批/自动**——四项组合决定"这记忆是什么货色"。
- **LQ-08 裁决**：**"后台持续抽取"只在少数工具上"有条件成立"（且默认关）**，不能当默认行为讲。
- **当心**：❌"有记忆=默认开"；❌"未发现=没有"；❌"子代理看得到全部历史"；❌"缓存=记忆"。
