# 十章零基础通读与源码中文解读修订记录

这一轮的读者假设是：不了解上下文管理，也不会 Rust，但希望沿着例子走到能解释具体实现、设计 Agent 上下文流程。公开主线从可观察的问题起步；正式术语和源码都接在例子之后。

## 本轮发现与修改

| 原问题 | 修改后的阅读或交互 |
| --- | --- |
| 第一章突然出现“世界状态” | 先提出“规则与工具变化以后，只带旧聊天够不够”，说明当前工作情况表，再给 WorldState 正式名称与结构。 |

| 源码链接有用，但不会 Rust 就难读 | 第一至八章各增加“源码怎么做”单元，先讲输入、条件、动作和结果，再放真实代码及逐句中文释义；第八章有词典，第七章有可选 Java 映射。 |

| 数字与公式之间跳跃 | 四个预设例子把下方演算器填成具体数字；先算总量和增长，再读字母与公式。 |

| 20K/64K 只看到数字边界 | 预算耗尽时补边界消息的开头、中间、结尾示意，以及直接留下的头尾；指出摘要是否另外留下约束仍需核对。 |
| HookPrompt / AgentMessage 等名字替代解释 | 类型筛选表补来源与作用，区分用户输入、钩子提示、代理消息、一般配对工具输出以及开关限制。 |

| 缓存 P/S 与第二章意义不同 | 缓存费用公式改中文变量，保留图解但移到具体两次调用之后；分模型主路线与折叠差异。 |
| usage 只有字段、无法自己算账 | 请求 JSON 逐字段解读；完整演算首次写入、再次读取、普通输入和合计；1.25是写入输入的完整价格。 |
| 多列账单在手机挤成竖排 | 手机按行显示带字段名的条目，桌面保留对照表。 |

## 实现深度补充

源码仍固定为 `a07c8ebd57feedc4cf5dfe854c8e9101de54186b`。新增的13段 Rust 连续节选逐段与本地固定提交原文核对；真实片段与教学伪代码分别标明。

- **请求结构**：Prompt 的 input、tools、base_instructions、output_schema；ResponseItem 的角色和内容块；WorldState.sections 的栏目容器。说明工具声明、调用、输出分别在哪份数据里。
- **阈值算法**：窗口解析与配置覆盖、90%基础线、95%缺省有效比例、total 与 body_after_prefix、基线 P、范围线与整段线的 OR，以及缺失值和有符号饱和减法的边界。
- **执行条件**：轮前已有材料检查；轮中 needs_follow_up 和到线/新窗口请求；轮后 `model_post_turn_compact_threshold_percent` 缺省0、q=80对应76K例子；手动停止旧任务后的独立整理。
- **保留和裁剪**：候选先过滤、倒序用预算、边界截短、恢复时间顺序、新摘要或压缩条目另加；UTF-8长度近似、头尾字符边界、标记额外长度、多块工具输出预算。
- **状态与恢复**：ResponseItem::Compaction 与 CompactedItem 的区别、replacement_history、相关窗口/usage/恢复字段、成功安装、持久化与后缀回放；整理期间新接受的目标更新按原顺序补入替代列表，避免旧快照覆盖新目标。
- **失败与重试**：本地摘要普通重连缺省5、配置上限100；摘要输入超限缩小副本并重置计数；远端v2常规流阈值取min(provider,2)，传输切换等路径可重置；completed事件与恰好一个压缩条目的验收。
- **缓存 API 与工程取舍**：完整请求结构、显式断点、普通/读取/写入三类费用、旧消息变更和压缩影响、整体任务记录，而不把缓存内部实现说成开源CLI源码已揭示。
