# 04 会话树：日志不删，只换叶子

- **目标观众**：用过 `/rewind`、`/tree`、`--fork`，但担心回退会删掉历史的人。
- **预计时长**：3 分 05 秒；旁白 443 字（按 3.0–3.2 字/秒并留停顿估算）。
- **核心比喻**：树干不长回去，年轮只增不减；回退只是把尺子插在某一圈。
- **一句话论点**：日志负责不丢，投影负责这次看哪段，检查点负责从哪继续；三件事分开，才能既审计又压缩。
- **前置知识**：主线第 11 章前半；知道会话与记忆不是一回事。

## 旁白完整版

先看一棵树。树干向上长，每年加一圈年轮；年轮不会因为哪一年过得不好就消失。你从外面看到的，是最后一圈；但里面每一圈都还在。

会话日志就是这样，每条消息、每次调用、每个检查点按顺序追加。压缩不是砍树，是在某一圈贴一张索引卡。树还是那棵树，只是某一段的读法变了。

模型看到的不是整棵树，是一条从根到叶子的路径。换一个叶子，看到的历史就变了。所以「会话有几个分支」和「模型这次看到什么」，是两个问题。

回退不是删记录，是把尺子插回某一圈。Grok Build 只在末尾追加一个 marker，重放时截回那个位置，磁盘一行没删。被截断的切片还在磁盘上，只是不再进入这次投影。

分叉是从某个点复制一根新枝，原枝不动。pi 的 fork 新建文件；Claude Code 用 parentUuid 串树，文件快照最多一百个版本。复制的是记录，不是模型状态。

压缩也留检查点。pi 追加 CompactionEntry，记录摘要和 firstKeptEntryId；Codex 找最新 CompactedItem，用 replacement_history 做起点，再回放后缀。两条路不同，原则一样：先找到锚点，再往后接。

所以「摘要不可逆」不等于「原文被删」。原文还在日志里，只是模型当下看不到；按条目 id 还能找回来。找回来之后，它又是一段可读的原文。

会话树的问题不是怎么删，而是不删的前提下这次看哪段。日志负责不丢，投影负责选择，检查点负责续跑。把这三层混在一起，迟早会在某次回退里丢掉不该丢的东西。
