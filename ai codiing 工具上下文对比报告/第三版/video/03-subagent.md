# 03 子代理：把噪声关在另一间屋子

- **目标观众**：已经开始用 `task` / `subagent`，但说不清省下来的到底是什么的人。
- **预计时长**：3 分 05 秒；旁白 416 字（按 3.0–3.2 字/秒并留停顿估算）。
- **核心比喻**：两间屋子，中间一扇小窗；噪声留在隔壁，只递回一张纸条。
- **一句话论点**：子代理的收益不是「并行更快」，而是「探索的中间过程不进入父会话」；代价是你要把任务写成一张清楚的纸条。
- **前置知识**：知道什么是会话历史与 token。

## 旁白完整版

左边是父会话，桌上堆满文件、命令、失败尝试；右边是空的。两间屋子只隔一堵墙。左边越挤，下一轮能塞进去的新信息就越少。

子代理不复制父会话的桌子，只拿到一张纸条：查什么、回来告诉我什么。通常还写一句：只读，不要改文件。这句话决定了它是侦察兵，还是第二个施工队。

它在自己屋里读文件、跑搜索、走错路。噪声都留在右边，父会话的桌子没有被弄乱。你甚至可以同时开三个侦察兵，各查一个方向，回来交三张纸条。

中间有一扇小窗。结束时只把结果递回来，可能是一段文字，也可能是按 schema 校验的结构。窗口很小。所以「返回什么」本身就是一个设计决定，不是事后再说。

父会话只多了任务纸条和结果，不是子代理的全部历史。收益大小，取决于噪声多少和纸条长短。左条是父会话增量，右条是子代理历史；两者不是一个量级。

收益有上限：Claude Code 默认全新上下文，只读代理不注入 CLAUDE.md；omp 输出上限五十万字节、五千行，深度默认二；opencode 与 Grok 深度一；pi 没有这个能力。这些数字不是排行榜，只是说明：隔离有收益，但收益有边界。

所以子代理不是免费并行。纸条要写清目标、边界、返回格式；写得越糊，回来的越长，最后还得自己读完。那时候，省下来的 token 又花回去了。

> **动画**：`two-rooms`（左实线、右虚线）；`note-fly`（贝塞尔曲线 + 落桌压扁）；`noise-stack`（80ms 一个，堆三层停）；`window`（固定小窗，超出用遮罩裁）；`compare-bars`（8–12 倍，标注示意）。
