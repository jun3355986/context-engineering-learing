## §2 用户侧的五个动作（第 6 章）

| 动作 | 改动了历史的哪一段 | Claude Code | Codex |
|---|---|---|---|
| 继续 | 不改，只在末尾追加 | 直接输入 | 直接输入 |
| 回退 | 剪掉某次提问之后的全部轮次 | `/rewind`，或输入框为空时按两次 Esc【文档】 | 按两次 Esc（backtrack）【源码】`app_backtrack.rs` |
| 压缩 | 用摘要替换旧历史 | `/compact [保留什么]` | `/compact` |
| 清空 | 丢掉全部历史，**等于开新会话** | `/clear` 会重新生成会话 ID【源码】`conversation.ts#L195-L206` | `/clear`，说明是「清屏并开始新对话」【源码】`slash_command.rs#L96-L106` |
| 派子代理 | 主会话只多出任务说明和结论 | Agent（Task）工具 | 子代理【源码】`child_config.rs` |

- 「清空」和「新会话」在这两家是同一个动作，不要写成两个。
- 决策顺序，前一问答「是」就停：① 换事了吗 → 清空，并写交接便条；② 走错了吗 → 回退；③ 塞满了吗 → 压缩，并写明要保留什么；④ 下一步会不会产生大量只需要结论的输出 → 派子代理；四问都答「否」→ 继续。
- 子代理是**事前**预防：只能让以后的输出不进主会话，已经进了历史的输出它拿不走。

## §3 缓存成本的统一算法

**符号**：`P` 是固定前缀（系统提示词 + 工具定义），`B` 是当前整段输入，`A` 是压缩后的输入（`P` + 摘要 + 保留段），`r` 是缓存读取单价，`w` 是缓存写入单价，`o` 是输出单价（都相对普通输入计），`S` 是摘要长度。示意值沿用正文已用的 `r = 0.1`、`w = 1.25`。正文如果要写具体价格，必须查当期官方价目并注明日期。

| 做法 | 一次性成本 | 之后每次请求 |
|---|---|---|
| 继续 | 无 | 约 `B·r`，加上新增部分的写入 |
| 压缩 | 压缩请求本身约 `B·r + S·o`（Claude Code 的压缩请求复用主对话前缀，命中缓存【源码】`compact.ts#L431-L438`）；压缩后第一次请求约 `P·r + (A−P)·w` | 约 `A·r`，比继续每次少 `(B−A)·r` |
| 清空 | 新会话第一次请求要写入新内容 | 约 `P·r` 加上新内容；固定前缀照样命中 |

**结论（第 6 章已采用，其他章节须与此一致）**

- 持续的花费来自每次请求都要重发的历史。清空和压缩通常是省钱的。
- 压缩的一次性成本主要是压缩请求本身，特别是按输出单价计费的摘要，而不是「缓存失效」。
- 「从改动处往后的缓存失效」是真的，但失效的那段内容在压缩或清空之后已经不发送了，不能把它的重写当成成本。

**算例**（沿用第 20 章的数字：B=180k、P=30k、A=45k）：压缩后每次请求省 `135k × 0.1 = 13.5k`；压缩后第一次请求多付 `15k × 1.25 − 150k × 0.1 = 3.75k`；压缩请求本身 `18k + S·o`，若 `S = 10k`、`o = 5`，约为 68k；合计约 5–6 次请求回本。第 20 章原文算的「172.5k / 121.5k / 1.4 次」不对，问题清单 A3 写了原因。

- 「请求」指模型调用的次数，不是用户的轮数。一轮用户对话里通常有多次请求。
- 缓存有存活时间（TTL）。间隔太久，继续的那条路也会未命中。正文用到时要说明。

## §5 跨章会引用的事实

只收录已对照出处的条目。正文引用时，链接仍然以对应章节里的固定提交链接为准。

- Claude Code 会把 CLAUDE.md 读一次后缓存，`/clear` 时重新读取【源码】`context.ts#L155-L172`；官方文档说 `/compact` 之后也会重新读取【文档】`/memory`；会话中途修改，当前会话可能看不到【推断】。
- Claude Code 有效窗口 = 模型窗口 − min(最大输出, 20,000)；自动压缩线 = 有效窗口 − 13,000【源码】（见 `research/claude-code.md` 与第 15 章）。
- Claude Code 连续 3 次自动压缩失败后，本会话不再自动压缩【源码】`autoCompact.ts#L241-L351`（第 7 章）。
- Codex 压缩请求自己超窗时，删掉最旧一条再重试；只剩一条还超窗就报错【源码】`compact.rs#L345-L380`（第 7 章）。
- 规则文件上限：Codex AGENTS.md 拼接到 32 KiB 为止（第 9 章）；Claude Code 单个 CLAUDE.md 超过 40,000 字符会给出警告【源码】`doctorContextWarnings.ts#L44-L66`（第 6 章）。
- Claude Code 压缩后重新附带的文件，来自 `readFileState`（本会话读过或写过的文件），按 `timestamp` 倒序取最多 5 个，每个不超过 5,000 token，总预算 50,000；plan 文件和 CLAUDE.md 类记忆文件另有处理，已出现在保留消息里的文件不重复附带【源码】`compact.ts#L1415-L1462`（2026-10-24 第 1 批核对）。**不能写成「最近修改的文件」**，只读过的文件也会被重附；第 35 章（`src-claude-code-03`）已有一条【注意】说明这一点。
- Claude Code 被动压缩（服务端拒绝后再压缩）对同一次请求只试一次：`hasAttemptedReactiveCompact` 在每次循环（即每次模型请求）后重置，压缩成功后以 `reactive_compact_retry` 重发这次请求【源码】`query.ts#L1150-L1183`（逻辑 2026-10-24 对照源码；行号沿用第 7 章链接）。
