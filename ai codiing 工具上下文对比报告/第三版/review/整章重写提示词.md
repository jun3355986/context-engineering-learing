# 整章重写提示词

> 适用：结构和标题都要换的重写（不是改词句）。只改表达用 `重写提示词-通用.md`。
> **前置冲突**：CONVENTIONS §4 写着「不增删小节、弹窗 id 不变、篇幅 ±15%」，整章重写必然破这三条。先决定是开例外条款，还是做对照稿不进主站。

**版本**：v1 ｜ 2026-10-26

---

## 1. 为什么不能直接重写

结构一动，人眼就对不出少了什么。原来在第 3 节的一句话，可能被并进第 5 节，也可能直接消失；你重读新稿会觉得"挺完整的"，因为缺失是看不见的。

唯一靠得住的办法：**把原稿的信息点编号建台账，重写完逐条核对落在哪。**

台账 + 对账是这个流程的核心，不是可选项。

---

## 2. 先看到的两个事实

**(1) 结构是模板化的，不是按内容长的。**

`main-09`（多模态上下文）和 `main-05`（上下文占用）小节标签完全一致：

```
01 场景 → 02 Codex 主线 → 03 概念拆解 → 04 七个智能体 → 05 八个对比表 → 06 设计取舍 → 07 小测验
```

两章讲的东西毫无关系，骨架却一样。说明这个顺序是按"每章该有什么"定的。

**(2) 三条具体病灶**

| 问题 | 表现 | 后果 |
|---|---|---|
| 产品主线排第 2 节 | 读者还没拿到框架，先看 Codex 怎么实现 | 不知道"它为什么这么做"，因为没有对照物 |
| 04 与 05 重复 | 七个弹窗讲七家，后面又一张八家表 | 读两遍相似内容，第二遍更简略 |
| 标题对仗不说内容 | 「一把尺子，两次读数」「七种量法，七种可见性」 | 从标题看不出这节讲什么（问题清单 C5） |

## 3. 第 1 段：建台账（原样复制）

```
这一章要整章重写，结构和标题都换。动笔之前先建台账，保证重写不丢东西。

读 <文件>，抽出所有读者可能要用到的信息点，编号：
- 每个事实断言（谁做了什么、参数是多少）
- 每个数字、公式、算例
- 每个源码链接、文档链接
- 每个【已核实】【推断】【待核实】标签和脚注
- 每个测验题和答案
- 每个弹窗里的结论

输出：
| # | 内容（一句话） | 原位置 | 类型 | 可否合并 |

"可否合并"指和另一条讲同一件事、能并成一条但要保住差异。
只抽信息点。过渡句、场景描写、作者评论不算信息点。
```

---

## 4. 第 2 段：只诊断结构（原样复制）

```
现在只看结构，不看句子。列这一章的结构问题，每条给依据：

1. 顺序：读者在哪一节需要用到后面才给的概念？
2. 重复：哪两节在讲同一件事的两面？
3. 分散：哪些信息点散在多处，本该合成一节？
4. 模板：这个排列是在套通用模板，还是内容真的需要这个顺序？
5. 标题：哪些标题读完不知道这一节讲什么？

每条写：位置 + 问题 + 读者会怎么卡。
不要提改法，只诊断。
```

---

## 5. 第 3 段：出新骨架（原样复制）

```
按诊断给新目录。规则：

1. 先给框架，再给细节。读者读到第二节时，应该已经知道全章地图。
2. 产品实现放后面当例子。不要拿某一个产品当参照系——
   读者没有对照物时，看不懂"它为什么这么做"。
3. 每节只讲一件事。一节里有两个并列主题就拆。
4. 标题直接说这一节讲什么，或者直接给结论。
   不写对仗、不写谜语、不写"三道题，检验你是否真的会 X"。
5. 弹窗群和对比表不要重复：表在前（一屏看完），弹窗在后（要细节再点）。
6. 6~8 节。

输出：
| 节号 | 标题 | 这节讲什么（一句） | 认领台账编号 | 取自原稿哪几节 |

再列：台账里没着落的条目，以及你打算怎么处理。
停在这里等我确认，不要写正文。
```

---

## 6. 第 4 段：逐节写（原样复制，每节跑一次）

```
按确认的骨架写第 N 节。

1. 开头一句：这节解决什么问题。
2. 例子或场景在前，概念在后。
3. 术语首现给一句白话，口径表里已有的照抄。
4. 比喻只用全书定过的：上下文窗口是白板，缓存比较是两排方块，
   会话历史是纸带（只在第 6 章）。
5. 这节结尾一句话落到下一节的起点。
6. 这节认领的台账条目逐条落实，落不进去的在汇报里说。

不要：新增原稿没有的事实；加限定语；写"本文将"；用 emoji。
```

**一次只写一节。** 让它连写三节，第三节一定注水——篇幅预算用完了，只能拿形容词补。

---

## 7. 第 5 段：对账（原样复制）

```
逐条核对台账：

| # | 台账内容 | 落在新稿哪一节 | 原意是否保住 |

三种情况单独说明：没落进去（为什么删、读者会缺什么）、
合并了（和哪条合并、差异是否保住）、改写了（意思有没有变）。

另外报告：
- 新稿里台账没有的新断言，逐条给依据（这可能是编的）
- 字数变化
- 哪些跨章引用要同步改
```

最后那条不能省。结构一重排，模型会顺手补它以为顺理成章的过渡逻辑——那些内容原稿里没有，也没人核过。

## 8. 收尾要同步的东西

| 项目 | 为什么 |
|---|---|
| 页头阅读时长 | 按 CONVENTIONS §3 公式重算，结构变了必然变 |
| `toc.js` 的章名 | 章名改了就同步，否则侧栏和正文对不上 |
| 搜索索引 | 改完跑 `node assets/js/build-search-index.js tutorial/` |
| 导读页 changelog | 整章重写算一次实质改版，补一条 |
| 其他章对本章的引用 | 原来"见 2.3 节"的，节号可能已经不存在 |
| `口径表.md` | 重写时若统一了新说法，记进去，后面批次才不会改回去 |

## 9. 先做一章

54 章、几十万字，一次全重写，到第十章就没有基线可比了。

建议路径（复用现有 worktree 流程）：

1. 拿 `main-09` 做样板，原稿 `84caf62` 那版当基线。
2. 跑完四段，用 `评测-第20章-评分表.md` 的框架打分（A 内容 / B 讲解 / C 表达）。
3. 你自己通读对照，判断"明显更好懂"还是"差不多"。
4. 结构对了再推广。结构错是系统性的，推广快；改错了也是系统性的，返工更贵。

## 10. 和另外两份的关系

| 文档 | 管什么 | 动不动结构 |
|---|---|---|
| `重写提示词-通用.md` | 词句层：直译词、名词化、长句、缺复述 | 不动 |
| 本文件 | 结构层：顺序、合并、拆节、标题 | 全动 |
| `评测-第20章-两步改写提示词.md` | 第 20 章专用，含核查步骤 | 不动 |

**顺序是：先结构，后词句。** 结构定了再用通用版改表达，两件事混在一起做，模型会在重排的同时顺手改词，两边都做不干净。

## 11. 依据分布（哪些是书上的，哪些是项目里的，哪些是我推的）

写这份时参考的东西分三类，不能混着说成"书上的方法"。

### 有实证依据的三条（Mayer 多媒体学习原则，2001/2008）

| 原则 | 内容 | 对应本文哪条 |
|---|---|---|
| **Segmenting**（分段） | 分成学习者能自己控制节奏的小段，比连续讲效果好 | §5 规则 6「6~8 节」+ §6「一次只写一节」 |
| **Pre-training**（预训练） | 先让学习者知道主要概念的名称和特征，再讲过程 | §5 规则 1「先给框架，再给细节」 |
| **Redundancy**（冗余） | 同一内容用旁白 + 画面 + 屏幕文字三种方式重复，学习效果反而变差 | §5 规则 5「弹窗群和对比表不要重复」 |

注：前两次讨论只用到 Mayer 的 seductive details（装饰性图形降低学习），这三条是同一套原则里的另外三条。

### 来自项目既有资料（占比最大）

| 做法 | 来源 |
|---|---|
| 判断标准「读者会不会停下来想这是什么意思」 | CONVENTIONS §4 原话 |
| 不加限定语 | 问题清单 C11 + arXiv 2610.11355 |
| 术语首现给白话 | 口径表 §4 |
| 比喻只用全书定过的 | 口径表 §1 |
| 标题不写对联、谜语 | 问题清单 C5 |
| 自检脚本、worktree 流程、评分表 | `评测-第20章-*` 三份文件 |
| 收尾同步清单 | CONVENTIONS §3 + 项目 MEMORY |

### 没有书目依据、由编辑实务推出来的

| 做法 | 性质 |
|---|---|
| **信息点台账 + 对账** | 工程手段，为可控性，不为可读性。没有哪本书讲这个 |
| **产品实现放后面、不当参照系** | 从"读者需要对照物才能看懂取舍"推出 |
| 诊断的五个问题（顺序/重复/分散/模板/标题） | 编辑实务的常规检查项 |
| 「新断言逐条给依据」 | 防模型补造过渡逻辑 |
| 「一次只写一节」（防注水那一层） | 经验判断，与 segmenting 同向但依据不同 |

### 要不要用那六本书当依据

**不要把整章重写挂到那六本书上。** 它们管的是单篇可读性、句子层、认知偏差、文档类型分类、单节节奏，没有一本讲"这一章该分几节、先讲什么"。

真正支撑结构重写的是两块：Mayer 的分段与预训练（做"怎么切"），和项目问题清单（做"读者卡在哪"）。
