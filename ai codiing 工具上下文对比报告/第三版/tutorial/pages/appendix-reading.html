这份清单只回答一个问题：读完这一条，你能多解决什么。不列「必读经典」，也不列与本教程重复的入门文章；每条都标了读它的最佳时机。

先看这一句

不要从论文开始。先用一条主线章建立「一次请求长什么样」，再去读源码；否则你会在别人的抽象里迷路。论文放在最后读，它的作用是给你一把尺子，而不是给你一个实现。

A · 官方文档与手册

先确认「用户能按到哪个按钮」

源码告诉你机制，文档告诉你入口。两者不一致时，先以源码为准，再把文档的措辞当作「用户以为会发生什么」的证据。

C · 论文与长文

三把尺子，不是三个实现

论文的价值在于给你可复用的实验设计与失效模式，不是给你一段能抄的代码。读的时候只抓两件事：它怎么定义指标、它在什么条件下失效。

材料 类型 / 版本 读它能解决什么问题
Lost in the Middle: How Language Models Use Long Contexts 论文 · Liu et al., 2023 给「位置效应」一个可引用的实验依据：为什么关键约束要放在开头或结尾，而不是埋在中段；也解释为什么「窗口够大」不等于「中间能用」。
Prompt Cache: Modular Attention Reuse for Low-Latency Inference 论文 · Gim et al., 2023 把「前缀缓存为什么只能从第一个不同 token 处断开」讲清楚；读完再看各工具的断点位置，就不会把「多打断点」当成「多省钱」。
SWE-bench: Can Language Models Resolve Real-World GitHub Issues? 论文 · Jimenez et al., 2023 给「用任务成功率而不是主观感受评估」一个模板：真实仓库、可执行验收、按任务分层。它是主线第 16 章评测集设计的直接参照。

论文链接指向 arXiv 摘要页，版本以页面为准。不要把论文里的模型与预算直接套到今天的工具上：上下文窗口、计价与缓存策略都变了，结论的方向仍成立，数值不能照搬。

D · 对照阅读顺序

三条路线，按你的目标选

同一个材料，在不同目标下的读法不同。下面三条路线都从教程内部开始，读到卡住的地方再跳到外部材料；不要反过来。

  • 路线 A · 先懂原理（L2）

    入门第 1 章 → 入门第 4 章 → 入门第 5 章 → 主线第 8 章 → 主线第 13 章 → 主线第 14 章。走完这条线，你能解释「为什么压缩会同时省 token 和丢信息」，也能判断一次缓存失效是不是计划内的。

  • 路线 B · 要改代码（L3）

    主线第 7 章 → 主线第 8 章 → 源码 · pi 第 2 节 → 源码 · DeepSeek Harness 第 2 节 → 源码 · oh-my-pi 第 1 节 → Codex compact.rs。先看「日志与投影」，再看「切点」，最后看「方法链」；顺序反了会以为压缩就是调一次模型。

  • 路线 C · 要做评估（L5）

    主线第 16 章 → 进阶第 5 章 → SWE-bench → 回到主线第 8 章做一次消融。先定指标与分层，再选材料；不要先跑一轮再找指标，那样只会得到一张无法解释的曲线。

一个常见的读法错误

把「源码」当成「文档的补充说明」，从头读到尾。源码是按实现组织的，不是按学习顺序组织的；正确做法是带着一个具体问题（切点在哪、什么时候停、失败了怎么办）去读一个函数，读完就停。
