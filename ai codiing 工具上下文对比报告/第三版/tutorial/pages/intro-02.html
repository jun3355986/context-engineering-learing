一次请求里装了什么

你只敲了一句话，请求里已经叠了五层材料。看懂这五层，才谈得上删得对。

  • 约 13 分钟
  • 前置：intro-01
  • L1 → L2

读完你能做到

  1. 说出一次请求里固定出现的五类材料，以及每一类从哪来。
  2. 指出哪一块最容易变大、哪一块几乎不变。
  3. 解释拼接顺序为什么会影响第 5 章的缓存账。

01 · 一个“我什么都没干”的请求

2.8 万 token，从哪来的

早上九点零五，你开了一个全新会话，只打了一行字：「登录接口 500，帮我看看」。工具的状态栏已经显示用掉两万八千 token。你还没让它读任何文件。

你往上翻，对话里也确实只有这一句。于是你怀疑是不是计数错了。

场景 · 你打的字，常常是最小的一块

按下回车时，工具不是把你的那句话单独发出去。它先准备好一份“岗位说明书”，再附上这个岗位能用的全部工具，再贴上项目规矩、当前目录和今天的时间，最后才把对话记录和你这句话接上去。这一整摞，才是模型看到的请求（request）。

说白了，你写的是便签，工具交上去的是一整个文件夹。

这一章就做一件事：把文件夹打开，一层一层看。不用记参数，只要记住每层“从哪来、多久变一次”。

02 · 骨架：四块加一层历史

系统提示、工具、规则、环境、历史

不同工具的字段名不一样，骨架却很像。以 Codex 为例，它每个采样步都调用 build_prompt 组装一个 Prompt，里面是四块：input（历史条目）、tools（模型可见的工具规格）、base_instructions（岗位说明书）、output_schema（结构化输出格式）。已核实 client_common.rs#L22-L40、turn.rs#L1666-L1695

要注意：Codex 走的是 Responses API 形状，没有独立的 system 字段；平时说的“系统提示词”，在它这里是 base_instructions。名字不同，位置一样——都排在最前面。

Claude Code 这边，getSystemPrompt 返回的是一个字符串数组：先是静态的七段（身份、系统通则、做事方式、行动准则、工具使用、语气、输出效率），然后插一个字符串常量当边界标记（boundary），再拼上随环境变化的动态段。工具定义不在这串里，单独走 toolSchemas 数组。源码 v2.1.88 prompts.ts#L444-L577、claude.ts#L1358-L1379

打个比方，这像你去外地出差报销：公司财务制度是系统提示，报销系统里能填的那几张表单是工具定义，部门自己那套“打车要选经济型”的惯例是规则文件，今天在哪个城市、是几号是环境信息，前面几封来回的邮件是历史，你刚说的“帮我报一下”才是最后那句。

并排看会发现一个反直觉的事实：变化最慢的几层往往体积最大，变化最快的那句往往最小。所以“省上下文”的第一反应，不该是把自己的话写短。

系统提示：一份写死的岗位说明书

它决定“你是谁、怎么做事、什么时候该问”。为了稳定，工具尽量让它不变：Claude Code 用边界标记把静态段和动态段隔开，动态段算一次就记住，只有 /clear 或 /compact 才清空源码 v2.1.88（systemPromptSections.ts#L16-L58）。

工具定义：不是“一个工具一句话”

每个工具都要告诉模型：叫什么、干什么、参数有哪些、哪个必填。工具一多，这段就长。Claude Code 的做法是默认把 MCP 工具延迟：首轮只给名字，模型要用时再拉完整定义；它还留了一个 10% 的阈值判断源码 v2.1.88（toolSearch.ts#L46-L49、#L154-L198）。Codex 也有类似开关，由模型元数据 supports_search_tool 决定 MCP 工具是延迟还是直连已核实（mcp_tool_exposure.rs#L63-L90）。

规则文件：拼起来，不是覆盖

Codex 从当前目录往上找到项目根，再把沿途每一级的 AGENTS.md 按从浅到深拼起来，总字节数受 project_doc_max_bytes 限制，默认 32 KiB，超出从尾部截掉已核实（agents_md.rs#L60-L160、mod.rs#L254）。Claude Code 也是拼接：受管策略、用户目录、项目逐级、本地文件，一层层加，最后包成一条用户消息前插到消息列表头部源码 v2.1.88（claudemd.ts#L790-L950、api.ts#L449-L474）。

注意最后半句：规则文件不在系统提示里，它是一条消息。这个细节在你后面排查“为什么改了 CLAUDE.md 没生效”时会救命。

环境与权限：不是单独一段，是插进来的碎片

Codex 没有“环境”这个字段，它把 <environment_context>、<current_time_reminder> 这类片段当普通输入项插进 input已核实（contextual_user_message.rs#L1-L40）。Claude Code 则把环境信息与规则一起包成 <system-reminder> 前插。所以“现在是几点”这句话，在不同工具里位置完全不同。

历史：唯一每轮都长的部分

你说的话、模型的回复、它调了什么工具、工具返回了什么，都会按顺序追加。第 3 章专门画它的增长曲线。这里先记住：历史是唯一没有上限感的一层。

04 · 顺序不是排版，是钱

稳定的放前面，易变的放后面

五层的排列顺序看起来理所当然，其实是刻意设计的：从最稳定排到最易变。

原因要提前说一句：Prompt cache 只认“从头开始一模一样的前缀（prefix）”。前面动一个字，后面全部作废。所以工具会把几乎不变的说明和工具表放在最前，把每轮都变的时间、提醒、你的新消息放最后。Codex 甚至把当前时间单独做成一个尾部片段，而不是塞进说明书的开头；Claude Code 把 agent 列表、MCP 指令做成“只发增量”的 delta，源码注释里写明：把这些列表放回工具描述，曾经带来约 10.2% 的全局 cache_creation源码 v2.1.88（attachments.ts#L1490-L1556）。

05 · 收口

先认清这一摞，再谈删哪一张

回到开头那个 2.8 万 token 的请求：你的话可能只有几十 token，剩下的全是工具替你准备好的材料。这不是浪费，是让模型知道“在哪个项目、用什么规矩、有哪些手”。

但这也意味着：想省上下文，先看那几层大而稳定的材料，而不是先删自己的话。规则写太长、MCP 连太多、工具描述太啰嗦，都是比“少说两句”有效得多的杠杆。

Q没有傻问题

问：规则文件是不是每轮都要重新读一遍、重新拼一遍？

答：读一次、拼一次，之后不一定重发。Codex 用 WorldState 按 section 比较快照，没变就不发，变了发“替换通知 + 新全文”已核实（mod.rs#L380-L395）；Claude Code 的动态段算一次就缓存，直到 /clear 或 /compact。所以“我改了规则它没反应”，先确认它有没有被重新读取，而不是怀疑模型不听话。

✓要点小结

  • 一次请求 = 系统提示 + 工具定义 + 规则 + 环境与权限 + 历史 + 你这句话，再加输出预留。
  • 你打的那句话常常是最小的一块；工具定义随工具数量增长，历史随轮次增长，这两层没有天花板。
  • 规则文件是“拼起来”的，不是覆盖；Codex 有 32 KiB 上限，超出从尾部截断。
  • 环境与权限不是独立字段，是以片段或 system-reminder 插进消息流的。
  • 顺序按“稳定 → 易变”排，是为了让缓存前缀尽量不动。
