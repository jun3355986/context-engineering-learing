用户侧怎么管理上下文：决策流程图

你管不了模型怎么想，只能管下一次请求里装什么。手上有五个动作，按四个问题的顺序选。

  • 约 15 分钟
  • 1 个交互
  • 前置：第 3–5 章
  • L1 → L2

读完你能做到

  1. 说出继续、回退、压缩、清空、派子代理各自改动了历史的哪一段，各要多花什么。
  2. 按“换事 → 走错 → 塞满 → 下一步”四个问题选出动作，并说明顺序为什么不能乱。
  3. 清空之前写出一张交接便条，让新会话能接着干。

01 · 上午的结论，在回答下午的问题

“和上午一样，先查探活配置”

你花了一上午排查登录接口偶发的 500，最后定位到负载均衡的探活（health check）超时太短，改完收工。下午两点，你在同一个会话里问：「首页推荐位为什么不刷新？」

它回：「这和上午的问题很像，先检查探活超时配置。」

场景 · 它没糊涂，是上午那一摞还在桌上

第 3 章说过，每次请求都会把历史整摞重发。上午那几千行日志、那条“探活超时是根因”的结论，下午照样每轮都发给模型。在模型眼里，这些就是“当前任务的背景”。你换了话题，旧历史并不会自己退场。

你能管的只有一件事：下一次请求里装什么。

agent 给了你五个动作来改它：继续、回退、压缩、清空、派子代理。先看清每个动作改的是哪一段，再学什么时候用哪一个。

02 · 五个动作

每个动作改的是历史的哪一段

把会话想成一条从左往右长的纸带，也就是第 3 章那摞纸横过来放。最左边是固定前缀：系统提示、工具定义、规则文件，每轮都一样；后面是一轮轮历史。为了看出差别，假设历史里既有有效的工作，也有最近几轮走错的路。

落到具体命令上，两家的入口如下。

03 · 主图：四个问题

按顺序问，前一问答“是”就停

知道了每个动作改哪一段，选动作就变成按顺序问四个问题。顺序本身就是这张图最重要的内容。

① 先问换没换事。换了，后面三问都不用答，因为清空会把错路、冗余一起拿走。开头那个下午，答案就停在这一问。上午有要带走的结论，就写成交接便条（第 06 节）。

② 再问走没走错。这一问必须排在压缩前面，原因见下一节。

③ 然后问塞没塞满。信号见第 3 章：占用贴近软线、开始重复问你答过的事、开头的约束被忘。压缩时补一句保留什么，比如「保留探活超时的结论、upstream.conf 的路径和否掉的两个方案」，比默认摘要可靠。

④ 最后问下一步。前三问处理的都是已经在历史里的东西，这一问是在动手之前预防：接下来要翻两百个文件、跑一长串测试，而你只要一句结论，就把这一步派出去。

?动动脑

它沿着错误方向连改了三轮代码。你可以在下一条消息里说「不对，别改超时，去看探活路径」，也可以回退到三轮之前重新提问。两种做法，下一次请求里装的东西差在哪？

提示：对照图 1，纠正是在纸带末尾追加，回退是把一段剪掉。

04 · 两个常见的误用

拿压缩收拾错路，等脏了才派子代理

先回答动动脑。纠正之后，历史里同时躺着错误方向的三轮和你那句“不对”。两种说法同时在场，就是第 4 章说的干扰：模型可能这一轮听你的，下一轮又被前面三轮的“证据”拉回去。回退则把三轮直接剪掉，模型看到的是一个从没走错过的会话。

误用一：用压缩处理走错的路

压缩比纠正更糟。写摘要的是同一个模型，它在走错时是相信那条路的。Codex 的压缩模板要求写下“当前进度与关键决策”已核实（prompt.md#L1-L9），错误方向很可能被当成“已做的决策”写进摘要，而原文里那些让你起疑的报错反而被丢掉。错路进了摘要，就没有原文可以对照了。这就是第 ② 问排在第 ③ 问前面的原因。

回退时注意一点：回退对话不等于还原代码。Claude Code 的回退菜单可以选“只回对话”或“对话和代码一起回”，但只还原它用编辑工具改过的文件官方文档；Codex 的说明只讲了回到那次提问之前、把提问放回输入框重新编辑已核实。错路改过的文件，最稳的兜底是 git。

误用二：事后才派子代理

子代理的价值在于大块输出不进主历史。主会话已经读完两百个文件，再派子代理也拿不走那些输出，图 1 最后一行的“旧账一点没少”说的就是这个。所以第 ④ 问问的是下一步，要在动手之前问。

子代理还有两个代价要提前想到。第一，它从空白开始，看不到主会话：Claude Code 的子代理默认不继承父对话源码 v2.1.88（runAgent.ts#L248-L330），Codex 的子会话也有独立的历史已核实（child_config.rs#L55-L160），所以任务说明要写全。第二，它只带回结论，结论错了你看不到证据，所以让它附上“文件:行号”，方便你抽查。

05 · 钱的账

清空和压缩，通常是省钱的

上面算的都是质量账。还有一笔钱的账，常被算反：既然第 5 章说清空、压缩都会让缓存失效，那它们应该很贵？

不对。缓存给重复发送的前缀打折，但打折不等于免费。持续花钱的，是你每一轮都要重发的那段历史。用一组示意数字算一下：固定前缀 2 万 token，历史 10 万 token，之后每轮新增约 3 千，再做 10 轮。

  • 继续：每轮至少重发 12 万，10 轮累计约 137 万 token。大部分走缓存读，有折扣，但窗口一直被占着 12 万以上。
  • 清空：每轮从 2 万起步，10 轮累计约 37 万。固定前缀可能要重写一次缓存（比如 Codex 换会话就换缓存 key，见第 5 章），那也只是一次 2 万。
  • 压缩：多一次请求，把 12 万历史读一遍再写摘要；之后每轮是前缀加一段摘要。连同压缩请求本身，10 轮累计约 54 万。

压缩请求那 12 万也不必按原价算。Claude Code 特意让压缩请求沿用主对话的系统提示、工具和历史，目的就是让它走缓存读。源码注释记录，关掉这一点后压缩请求 98% 缓存未命中源码 v2.1.88（compact.ts#L431-L438）。

所以“压缩让缓存失效”要读准：失效的是被摘要换掉的那段历史，而那段已经不在请求里了，不会再花钱。固定前缀照样命中。选动作时先算质量账；钱的账几乎总是站在“少带点”这一边。

06 · 跨过清空

带走一张交接便条，而不是整段历史

清空最便宜，可它把有用的结论也一起拿走了。要带走的东西，得写成一张交接便条。

压缩其实也是在写便条。Codex 压缩模板的第一句，就是要模型为接手任务的另一个 LLM 写一份交接摘要已核实（prompt.md#L1-L9）。两者的区别在于谁写、谁审：压缩是模型替你写，写完直接生效；清空加便条是让它写、你审一遍，再带进新会话。历史里有错路，或者你想确认带过去的到底是什么时，后者更稳。

交接便条 · 示例 
# 交接便条：登录接口偶发 500
目标：登录接口不再偶发 500
已确认：探活超时 2s 太短，改为 5s 后不再复现（nginx/upstream.conf:42）
否掉的方案：调大数据库连接池（无效）；关闭 keepalive（副作用太大）
相关文件：nginx/upstream.conf、src/health/HealthController.java
下一步：为探活超时补一个回归测试

用法分三步：清空前让它「把上面的排查按这个格式写成交接便条，存进 NOTES.md」；你审一遍，删掉不确定的；清空后第一句说「先读 NOTES.md」。“否掉的方案”最容易漏，漏了，新会话会把它们再试一遍。

便条和规则文件的分工也很简单：每个任务都成立的（构建命令、禁用操作、目录约定）写进规则文件；只对这件事成立的写便条。规则文件每轮都在前缀里，所以要短。Codex 合并后的 AGENTS.md 超过 32 KiB 会从尾部截掉已核实（agents_md.rs#L60-L160）；Claude Code 超过 40,000 字符只告警、不截断源码 v2.1.88（doctorContextWarnings.ts#L44-L66），官方文档建议单个 CLAUDE.md 控制在 200 行以内官方文档（memory）。

补充 · 会话中途改规则文件，未必马上生效

Claude Code 第一次读到 CLAUDE.md 后会把结果缓存起来（getUserContext 做了记忆化），到 /clear 时才清掉重读源码 v2.1.88（context.ts#L155-L172、caches.ts#L45-L56）；官方文档说 /compact 之后也会从磁盘重读项目根的 CLAUDE.md官方文档。由此推断：会话中途改了 CLAUDE.md，当前会话通常看不到，要等清空或压缩之后推断。实用的结论是：规则在开会话前改好；中途改了，就清空一次让它生效。

07 · 收口

一句话：换事清空，走错回退，塞满压缩，脏活外包

这四个短语对应图 2 的四个问题。都不是的时候，就放心继续，继续本身没有任何问题。

Q没有傻问题

问：agent 会自动压缩，我是不是什么都不用管？

答：自动压缩只看容量，也就是第 3 章那条软线，回答的是“装不装得下”。它不知道你换了任务，也不知道最近几轮走错了，会把上一件事和错路一起写进摘要。四个问题里，它只替你答了第 ③ 个，而且是等到快满了才答。

✓要点小结

  • 你能管的只有下一次请求里装什么；继续、回退、压缩、清空、派子代理，各改历史的一段。
  • 按顺序问：换事了吗 → 走错了吗 → 塞满了吗 → 下一步脏吗；都不是就继续。
  • 走错的路用回退剪掉。纠正会让对错并存，压缩会把错误写成“决策”。
  • 子代理只防新账、不清旧账，要在大块输出出现之前派。
  • 清空和压缩通常省钱：持续花钱的是每轮重发的历史，不是一次性的缓存重写。
  • 清空前写交接便条，别漏“否掉的方案”；长期规则进规则文件，并在开会话前改好。
