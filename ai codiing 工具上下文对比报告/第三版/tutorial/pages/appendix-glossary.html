A · 容量与计量

先能数清楚，才能谈怎么省

这一组的词都围绕一个问题：这次请求到底占了多少、还剩多少、超了会怎样。不同 agent 的估算口径不同，所以定义里尽量写「是谁的视角」，不写死一个数。

Token token 模型读写与计价的离散单位，不等同于字或词；中文一个字可能拆成多个 token。 第 1 章
上下文窗口 context window 一次请求里输入与输出共享的最大 token 容量，不是「输入可用」的容量。 第 1 章
输出预留 output reserve 留给本次生成、不能全部让给输入的 token；留多少直接改变可用输入上限。 第 1 章
有效上下文 effective context 名义窗口里模型实际能稳定用上的那部分，只能靠任务表现去测，没有官方数字。 第 4 章
上下文腐化 context rot 材料变长后，即使任务没变、干扰不多，整体表现也会下降。1 第 4 章
中段遗失 lost in the middle 长上下文里，位于开头与结尾之间那段的信息更容易被忽略。3 第 4 章
用量回执 usage 服务端返回的输入、输出、缓存读写 token 数；本地估算最终要向它对账。 第 12 章
字符估算 chars/4 estimation 用字符数除以 4 近似 token；对中文、代码和 JSON 的误差都不小。 第 12 章
上下文压力 context pressure 已用 token 占窗口的比例，用来决定何时裁剪、压缩或拒绝请求。 第 12 章

B · 组装与规则

一次请求里，谁排在前、谁说了算

这一组描述「装什么」：系统提示、工具、规则文件、按需加载的内容，以及运行时补进来的状态。它们的共同点是——位置决定缓存，顺序决定优先级。

术语 英文原词 一句话定义 首次讲解
请求组装 request assembly 把系统提示、工具定义、规则、环境说明与历史拼成一次请求的全过程。 第 8 章
系统提示词 system prompt 位于请求最前、定义身份与行为的长指令；多数 agent 把它拆成静态段与动态段。 第 8 章
工具定义 tool definition 描述工具名、参数与用法的 schema；它本身占 token，而且通常在最稳定的前缀里。 第 8 章
MCP Model Context Protocol 把外部工具与资源接入模型的协议；接入方式决定工具定义是预加载还是延迟。 第 8 章
规则文件 rules file 写在项目里、每次会话都要遵守的持久指令文件，如 AGENTS.md、CLAUDE.md。 第 9 章
AGENTS.md AGENTS.md Codex 等 agent 默认读取的项目规则文件名；各家对候选名与合并顺序的处理不同。 第 9 章
包含深度 include depth 规则文件递归引用其它文件的最大层数；超限后引用被忽略，且各家默认值可能不同。 第 9 章
规则合并 rules merge 多层规则按顺序拼接；多数 agent 是叠加而不是覆盖，越靠近工作目录的越靠后。 第 9 章
渐进披露 progressive disclosure 先只给目录或描述，模型需要时再取正文，用一次额外读取换常驻 token。 第 10 章
技能 skill 可按需加载的指令包，正文通常在 SKILL.md；系统提示里只放名称与描述。 第 10 章
延迟加载 deferred loading 工具定义不进首轮请求，模型先检索、需要时再取完整 schema。 第 10 章
代码模式 Code Mode 把工具调用改写成写代码执行，工具定义只留一份目录，靠 execute 间接调用。 第 10 章
动态注入 dynamic injection 运行中把状态、提醒或环境变化追加进上下文，而不是重写系统提示词。 第 11 章
系统提醒 system reminder 以消息形式插入的提示（常包在标签里），不改系统提示词本身；插在哪里，决定它会不会截断缓存前缀。 第 11 章
差分注入 delta injection 只发送发生变化的部分：未变不发、变化发替换、删除发移除通知。 第 11 章

规则文件的「合并」在不同 agent 里语义差别很大：Codex 拼接后按字节截断，Claude Code 拼接后作为一条 meta 用户消息前插，omp 还会做内容包含去重。

C · 减量与压缩

从「切掉」到「改写」，代价一级比一级高

这一组是全书最密的地方。记住一条主轴：能不调模型就不调模型。截断与裁剪只改模型可见的投影，压缩会真的让模型重写一遍历史，代价与信息损失都更大。

术语 英文原词 一句话定义 首次讲解
截断 truncation 超过上限时直接切掉输出的一部分；按方向分保头、保尾、头尾保留三种。 第 13 章
落盘 spill / offload 把完整输出写进文件或 artifact，上下文只留路径、预览与回读提示。 第 13 章
回读 read-back 模型按路径或 offset/limit 重新读取被落盘的内容，是「卸载」而不是「删除」。 第 13 章
历史裁剪 pruning 不调用模型，直接把旧内容省略或替换成占位符；原文通常仍在日志里。 第 14 章
陈旧结果 superseded result 同一文件被更新的一次读取覆盖后，旧的读取结果不再需要留在上下文里。 第 14 章
微压缩 microcompact 只清理旧工具结果、不做摘要的轻量压缩；Claude Code 的这条路径默认关闭。源码 v2.1.88 第 14 章
压缩 compaction 调用模型把一段历史改写成摘要，再用摘要加保留尾部替换原历史。 第 15 章
切点 cut point 历史被分成「写成摘要」和「原样保留」两段的位置，必须落在合法边界上。 第 15 章
保留预算 keep recent tokens 压缩时留给最近原文的 token 上限；太小会把刚发生的细节也压掉。 第 15 章
工具配对 tool pairing 工具调用与它的结果必须成对保留或成对丢弃，切点不能落在二者中间。 第 15 章
单回合拆分 split turn 一个回合长到放不进保留预算时，把轮前缀单独摘要，再与历史摘要合并。 第 15 章
压缩累积 compaction accumulation 后一次摘要继承前一次摘要；具体合并规则各家不同，但都不能从零重写。 第 15 章
整段替换 full-replace 用一条摘要加保留尾部整体替换旧历史；Grok Build 的默认形态。 第 49 章
方法链 method chain 压缩按可用性依次尝试多种方法（remote、snapcompact、handoff、shake、soft）并逐级回退。 第 40 章
机械省略 shake 不调模型，把大块工具结果或代码围栏换成占位符与可恢复的 artifact 指针。 第 41 章
历史转图 snapcompact 把被丢弃的历史渲染成 PNG 帧，交给视觉模型「读图」，用图像 token 换文本 token。 第 42 章
图片驱逐 image eviction 按请求体字节或图片数量预算把旧图片移出上下文，并留一句「图已不可见」的占位。 第 16 章

「裁剪」与「压缩」不是同义词，也不是同一条流水线上的两个档位：前者可以随时撤回，后者一旦写进摘要就只能靠原文存档找回。

D · 隔离与延续

把噪声关在别处，把历史留在磁盘

这一组解决两个不同的问题：并行（子代理）与时间（会话日志、分叉、回退、跨会话记忆）。它们的共同点是「模型看到的」只是全部记录的一层投影。

术语 英文原词 一句话定义 首次讲解
子代理 subagent 拥有独立上下文与工具池、只把最终结果回传父会话的代理。 第 17 章
子会话 child session 子代理自己的会话，有独立历史与 token 计数，通常从空上下文开始。 第 17 章
结构化返回 structured return 子代理按事先给的 schema 返回结果，而不是一整段自由文本。 第 17 章
工作树隔离 worktree isolation 子代理在独立 git worktree 上改文件，完成后合并或丢弃，避免互相踩踏。 第 17 章
会话日志 session log 只追加的记录，是恢复、审计与重放的唯一真实来源；压缩通常只追加检查点，不删旧行。 第 18 章
投影 projection 从日志派生出的、本次请求真正发给模型的历史视图。 第 18 章
可见面 surface DeepSeek Harness 的术语：日志中进入模型请求的那层有序视图，可被 replace 遮蔽。 第 52 章

分叉 fork 从某个点复制出新会话，原会话不变；复制的是记录，不是模型状态。 第 18 章
回退 rewind 把对话或文件恢复到之前的检查点；有的工具只回对话，不动磁盘。 第 18 章
分支摘要 branch summary 切换分支时，给离开的那条分支写一份摘要，避免回来时从零重建。 第 18 章

记忆污染 memory poisoning 错误或过期的记忆被反复注入，模型把旧结论当成当前事实。 第 19 章

E · 质量与缓存

省下来的钱，别用正确性去换

这一组一半讲成本（缓存），一半讲证明（评估）。它们经常被分开讲，其实是一件事的两面：缓存决定了「省多少」，评估决定了「省得值不值」。

术语 英文原词 一句话定义 首次讲解
前缀缓存 prompt cache 服务端复用相同前缀的中间计算结果，命中部分按缓存读取计价。 第 5 章
前缀 prefix 从请求第一个 token 开始、必须逐字节相同的部分；一位不同，后面全部作废。 第 5 章
缓存命中 cache hit 本次请求的前缀在服务端已有缓存，可直接复用。 第 5 章
缓存写入 cache write 为后续复用而新建缓存的那部分 token；计价方式因 provider 而异，不能默认「写入一定比输入贵」。 第 5 章
存活时间 TTL 缓存保留多久；过期后下一次请求要重新写入。 第 5 章
缓存断点 cache breakpoint 显式标记「到这里为止可以缓存」的位置；多一个断点不等于多一份收益。 第 20 章
缓存失效 cache invalidation 前缀任一处变化，导致从该处起后面的缓存全部不可复用。 第 20 章
失败恢复 failure recovery 溢出或压缩失败后的重试、降级与兜底；恢复路径本身也有成本。 第 21 章
熔断 circuit breaker 连续失败后停止自动尝试，避免每次请求都为一次注定失败的压缩付费。 第 21 章
钩子 hook 挂在生命周期事件上的外部逻辑；能改什么、只能看什么，各家边界不同。 第 22 章
配对 A/B paired A/B 同一任务、同一初始状态下比较两套配置，用差值而不是两组均值判断优劣。 第 23 章
信息保留率 IRR 只从「被压缩掉的那段历史」里出题，看模型还能答对多少；压缩质量最直接的指标。 第 23 章
每成功任务成本 CPS 总成本除以成功任务数，失败任务的成本也计入分子，避免奖励「提前失败」。 第 23 章
缓存命中率 CHR 缓存读取占全部输入 token 的比例；只作诊断，不作越高越好的 KPI。 第 23 章

缓存指标的口径依赖 provider：有的把缓存写算进输入，有的单列。跨工具比较前先把分母写成同一句话。

F · 易混词对照

四对词，四句话分清

这四组词在正文里经常被并列提到，但它们的代价、可逆性和失败模式完全不同。下面每个框只回答一个问题：什么时候该用哪一个。

对照一 · 裁剪（pruning） vs 压缩（compaction）

裁剪
不调用模型，只改「模型这次能看到什么」。原文仍在日志或数据库里，改回来很便宜。适合旧工具结果、重复读取、空搜索结果。第 14 章
压缩
调用模型，把一段历史重写成摘要。语义被改写、细节不可逆，但能把很长一段压成很短一段。适合任务还在继续、但早期过程已经不需要逐字保留。第 15 章
一句话判断
如果「不花钱就能撤回」，先裁剪；如果裁剪完仍然装不下，才压缩。

对照二 · 会话（session） vs 记忆（memory）

会话
这一次任务的完整记录，重、可按检查点恢复、可分叉。它回答「我们刚才做了什么」。第 18 章
记忆
跨会话留下的结论或偏好，轻、按需检索、可能过期。它回答「以前学到过什么」。第 19 章
一句话判断
需要逐字复现过程，用会话；只需要下次别再犯同样的错，用记忆。别把会话日志当记忆库直接塞进请求。

对照三 · 摘要（summary） vs 检查点（checkpoint）

摘要
一段新写出来的内容，会丢信息，也会带入写摘要时的判断。模型看到的是它，不是原文。第 15 章
检查点
日志里的一个位置标记，不产生新知识。它只告诉系统「从这一条之后继续」，模型看不到「检查点」本身。第 18 章
一句话判断
压缩 = 写摘要 + 落检查点。只有检查点、没有摘要，模型会看不到被遮蔽的历史；只有摘要、没有检查点，系统不知道保留段从哪里开始。

对照四 · 编码智能体（coding agent） vs 编码助手（coding assistant）

编码智能体
能自己规划多步、读写文件、执行命令、跑测试并自我修正。你给目标，它跑「读—改—跑—修」的循环，你审结果。本教程比较的八个产品都属于这一类。导读
编码助手
在你敲代码时补全下一行、回答一个问题；控制权始终在人手里，它不自己动手改仓库。早期的 Copilot 补全、IDE 里的行内建议属于这一类。
一句话判断
看控制流：人一步一步指挥，是助手；给一个目标、它自己跑循环，是智能体。

正文里的「工具」只指协议层的 tool——工具定义、工具调用、工具结果；产品一律写 agent，正式名是编码智能体。

脚注

  1. 关于 context rot：本教程采用「材料变长导致整体表现下降」这一描述，但公开研究里对它的度量方式并不统一，也没有跨模型的统一阈值。正文与术语表都只把它当作现象名，不当作可计算的指标。 ↩
  2. 关于 lost in the middle：本教程采用「开头与结尾较好、中段较差」这一实验结论，但它依赖具体任务、模型与文档长度，不能换算成一个固定的「中段召回率」。第 4 章已标【待核实】，这里只把它当作位置效应的现象名。 ↩
