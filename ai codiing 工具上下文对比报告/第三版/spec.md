# 教程总规格：AI Coding Agent 上下文管理

> 所有 ticket 都以本文件为准。子 agent 开工前必须先读本文件，再读自己负责的 ticket。

## 1. 目标
写一套「AI Coding Agent 上下文管理」交互式 HTML 教程：
- 让不懂上下文管理但感兴趣的人入门（达到 L1–L2）；
- 让已有一定认识、但了解不全不深的人，达到 Agent 上下文管理专家水平（L4，并初步具备 L5 的评估能力）。

能力分级：
- L1 会用：会写规则文件，知道何时用 /compact、/clear、子代理
- L2 懂原理：知道上下文由哪些部分组成、各占多少；理解 prompt cache、context rot、lost in the middle
- L3 能实现：能自己写 agent 循环，实现计数、截断、压缩、子代理和会话持久化
- L4 能权衡：能针对场景设计策略，并说清每种取舍的代价
- L5 能评估：能用评测数据证明一种策略比另一种好

## 2. 目标读者
1. 作者本人（有软件开发背景，正在系统学习 Agent 开发）
2. 对 Agent 上下文管理感兴趣的入门读者
3. 想成为 Agent 上下文管理专家的开发者

## 4. 上下文管理清单（16 类，分 5 组）
### A. 装什么（组装）
1. 请求组装：系统提示词、工具定义（含 MCP）、环境信息、权限和沙箱说明、历史消息，以及拼接顺序
2. 规则文件的发现与合并：全局、用户、项目、子目录逐层查找；优先级与覆盖；文件引用；体积上限与截断
3. 按需加载（渐进披露）：Skills、MCP 工具延迟加载、@ 引用文件
4. 动态注入：system reminder、todo 和计划状态、环境变化提示、规则变更时只注入变化部分
### B. 量多少（预算）
5. Token 计量与可视化：估算方法、输出预留空间、阈值、/context、可切换的上下文窗口大小
### C. 怎么减（减量，按代价从低到高）
6. 单次工具输出控制：截断、卸载到文件后只留引用、可以重新读回原文
7. 历史裁剪（不调用模型）：旧工具结果、过期文件读取、空搜索、思考过程换成占位符
8. 压缩（调用模型做摘要）：触发条件、切点选择、工具调用与结果成对、单个回合过长时拆分、摘要模板、多次压缩时摘要累积、读写文件跟踪、服务端压缩、手动压缩附带指令
9. 多模态上下文：图片移出上下文、把历史渲染成图片、附件转成文字描述
### D. 怎么隔离、怎么延续
10. 子代理隔离：独立上下文、只读和计划子代理、结构化返回还是自由文本、并行与 worktree 隔离
11. 会话时间线：会话日志是唯一的真实来源；恢复、分叉、树状分支、回退、检查点、切换分支时生成摘要
12. 跨会话记忆：写入时机、整理合并、检索、按项目隔离、过期与删除、防止错误记忆污染
### E. 怎么保证质量
13. 缓存友好设计：前缀保持不变、只在末尾追加、工具定义稳定、压缩与缓存失效的权衡
14. 失败恢复：上下文溢出时压缩并重试、压缩失败兜底、无法再压缩的情况
15. 扩展点：hooks、插件、自定义压缩
16. 评估与可观测：评测指标、评测集设计、A/B 对比方法

## 5. 教程结构
- 第 0 章 导读：教程地图、L1–L5、阅读方法、版本表（工具、版本或提交号、核实日期；opencode v2 注明 beta）、Claude Code 源码声明
- 第一部分 入门（L1–L2，Head First 风格）：
  1. 上下文窗口是什么
  2. 一次请求里装了什么
  3. Agent 循环中上下文如何增长
  4. 窗口装得下，不等于模型用得好
  5. Prompt cache 与成本
  6. 用户侧怎么管理上下文（决策流程图）
  7. 总流程图
- 第二部分 主线（16 类，每类一章，L2→L3）：每章的固定结构是
  ① Codex 主线讲解（Codex 没有这项能力时，写明“Codex 无此能力”，改用做得最好的工具作为主例）
  ② 7 个工具按钮，点击后各自弹窗讲解（做法、关键参数、设计意图、来源）
  ③ 8 个工具的对比表
  ④ 设计取舍：为什么各家做法不同
  ⑤ 3 道小测验，点击显示答案和解析
- 第三部分 进阶（L4，Karpathy 四级输出）：
  1. 设计取舍专题
  2. 失败案例分析
  3. 架构对比
  4. 设计你自己的上下文策略
  5. 评估方法（L5 入门）
- 第四部分 源码解读：每个工具 2–4 个功能，每段解读的格式为：
  1. 功能说明
  2. 固定到提交的链接，带行号
  3. 源码摘录，不超过 60 行（Claude Code 不超过 20 行），逐行加中文注释
  4. 逐段解读，配流程图
  5. 和其他工具同类实现的差异
  6. 思考题
- 附录：术语表（中英对照）、参数速查表、16 类总表、推荐阅读、视频分镜脚本

## 6. 写作要求
- 入门部分用 Head First 风格：先讲场景和痛点，再讲概念；口语化；每章包含类比、“动动脑”问题、“没有傻问题”问答、要点小结；每屏信息量要少。详细说明见 `refs/HeadFirst式写作规范.md`。
- 进阶部分用 Karpathy 四级输出，按需选用：
  1. 文字：受控中文，参照 ASD-STE100 的精神，严格度约 80%。短句，一个步骤一个动作，术语一致。
  2. 图表：内联 SVG，标出关键环节和关系。
  3. 交互 HTML：用于有参数可调的概念。
  4. 视频：不放进网页，只在附录提供 3–5 个主题的 3Blue1Brown 风格分镜和旁白稿。
- 必须有的交互演示：
  1. 上下文窗口组成拖拽器
  2. 压缩模拟器（可调阈值、保留量、预留空间，观察切点）
  3. 工具调用与结果成对保留演示
  4. Prompt cache 命中演示
  5. 多次压缩时信息丢失与摘要累积对比
  6. 子代理上下文隔离演示
  7. 会话树、分叉与回退演示
- 参考样例：`refs/CodexCLI 上下文管理-交互教程_workbuddy 版.html`（参考样例 1）与 `refs/CodexCLI上下文管理-交互教程_Notion版.html`（参考样例 2），只参考风格，不参考内容范围。

## 7. 技术约定（所有子 agent 必须遵守）
- 纯 HTML、CSS、JS，不依赖构建工具，用 file:// 双击就能离线打开。采用多页面结构，不用 fetch 加载章节。
- 目录结构：
```
tutorial/
  index.html                 第 0 章导读
  pages/<章节ID>.html        每章一个页面
  assets/css/main.css
  assets/js/toc.js           导航清单（唯一来源，只由主控修改）
  assets/js/app.js           导航、弹窗、测验、搜索、主题切换
  assets/js/demos/<名字>.js  交互演示，每个演示一个文件
  assets/js/search-index.js  搜索索引（集成阶段生成）
research/<工具ID>.md         事实卡片
research/source-map/<工具ID>.md  源码模块地图
video/<主题>.md              分镜脚本
```
- 章节 ID：intro-01…07、main-01…16（与清单序号一致）、adv-01…05、src-<工具ID>-NN、appendix-<名字>
- 组件的写法、class 名和用法，以 01 号 ticket 产出的 `tutorial/CONVENTIONS.md` 为准。子 agent 不得自行发明新组件；确实需要时，在交付说明里提出。
- 子 agent 只写自己 ticket 范围内的文件，不修改 toc.js、app.js、main.css。需要改这些文件时，在交付说明里提出，由主控统一修改。

## 8. 准确性规则
1. 所有关于工具行为的描述都要附来源（源码 permalink 或官方文档）。
2. 可信度标签：【已核实】【推断】【待核实】；Claude Code 另外标注来源类型：【源码 v2.1.88】【官方文档】【两者一致】。不得编造参数名、默认值或文件路径。
3. 源码链接必须固定到提交并带行号，形如 `blob/<commit>/<path>#L10-L40`。
4. 工具名称统一：Grok Build、DeepSeek Harness（dsh）、oh-my-pi（omp）。

## 9. Claude Code 源码使用边界
- 只用于个人学习和分析。
- 每段原文摘录不超过 15–20 行；其余部分用伪代码、流程图和文字说明。
- 不整文件复制，不复制完整的系统提示词原文，只概括它的结构和要点。
- 教程开头加声明：Claude Code 部分基于非官方版本的源码分析，仅供学习参考，不代表 Anthropic 的官方实现或当前版本。

## 10. 事实卡片格式（research/<工具ID>.md）
每个工具一个文件，按 16 类分节。每节包含：
- 做法（3–6 句）
- 关键参数和默认值
- 来源链接
- 可信度标签
- 建议用于源码解读的位置（可选）
某类不存在时写“无此能力”并附依据。文件开头写明：仓库地址、提交号、核实日期。
