子代理读完 12 万字节的日志，父会话只多了 932 字节；整个过程发出的输入却多了 33%

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 模型 gpt-6.1-sol、gpt-5.5，思考级别都是 low（注明的除外）· 对照 Claude Code 官方文档（2026-11-02 查阅）

实验里让 gpt-6.1-sol 派一个子代理去读 4 份日志，每份约 3 万字节：子代理自己的请求从 59,292 字节涨到 178,940 字节，父会话的请求只从 54,878 字节涨到 55,810 字节。可是把父会话和子代理的所有请求加起来，一共发出 761,485 字节的输入，比父会话自己读（573,510 字节）多 33%。子代理省的是父会话的窗口，不是总量。

子代理：父会话（你正在对话的那个会话）派出去干活的另一个会话，有自己的历史和窗口，干完把结果交回来。本章实验在 自学单元/U06-实验/。模型服务器是本机的假服务器，它按我写的剧本回话，同时扮演父会话和子代理（靠请求里带的会话编号 client_metadata.thread_id 区分这次请求是谁发的），不联网。日志来自我写的假 MCP 服务器（第 6 章讲过 MCP）里的 dump_log 工具：调用一次返回 400 行、29,769 字节的假日志。模型的回答是剧本写死的，所以本章回答「请求里装了什么、发了多少字节」，不回答「真实模型会不会在该派的时候派」。请求大小的算法同第 2 章：input 里每一条转成 JSON 文本后的字节数相加，再加顶层 tools 字段；token 按「字节 ÷ 4」估算。

Codex 有两套子代理的实现，源码里叫 V1 和 V2，工具和请求里的说明都不一样。gpt-6.1-sol 用 V2，gpt-5.5 用 V1；由什么决定，第一节末尾讲。本章以 gpt-6.1-sol 为主线，gpt-5.5 在每节里对照一段。

一、没人要求派子代理，请求里也先放了 8,514 字节

最朴素的做法是：你没要求派子代理，请求里就不放跟它有关的东西。Codex 对 gpt-6.1-sol 不是这样。第 2 章那次请求里有两条子代理说明，加上工具定义里的一组协作工具，一共三块：1

这一块是什么在请求里的位置大小（字节）内容
协作工具input 第 1 条（工具定义）里的 collaboration 这一组5,5296 个工具：spawn_agent（派出子代理）2,728、followup_task（给已有的子代理布置新任务）667、wait_agent（等子代理干完）662、send_message（给子代理发消息）523、interrupt_agent（打断子代理）437、list_agents（列出子代理）381
角色说明一条 developer 消息，以 <multi_agent_role> 开头2,575告诉模型：你是 /root，团队里的主代理；上面的工具怎么用；子代理发来的消息长什么样；大家共用同一个工作目录；有 4 个并发名额；派子代理时用 fork_turns 参数决定带走多少上下文（第三节）
开关说明一条 developer 消息，以 <multi_agent_mode> 开头410「除非用户或 AGENTS.md、技能明确要求派子代理、委派或并行，否则不要派」

三块合计 8,514 字节，约 2,129 token，占这次请求（54,878 字节）的 15.5%。缺省的开关说明叫模型「不要主动派」，所以你没要求派子代理时，这 8.5 KB 每次都跟着请求发出去，却用不上。思考级别设成 ultra 时，开关说明换成另一条（661 字节）：「只要能并行，就应该派」。4

第 2 章的表里，这两条说明写的是 2,400 和 271 字节，那是正文的长度；本章按整条转成 JSON 文本计，带上外层标签和 JSON 的引号、字段名，是 2,575 和 410，所以数字不同。

gpt-5.5 的请求里没有这三块

gpt-5.5 不改配置时的请求（思考级别 low，37,032 字节）里没有协作工具，也没有两条说明。它的子代理工具属于第 6 章讲过的「延后」工具：定义先不写进请求，模型要先调用 tool_search 搜索才拿得到。实验里剧本让它搜 spawn a sub-agent，返回 5 个工具共 10,424 字节（其中 spawn_agent 一个就 6,711 字节），追加进历史。不接 MCP 时，请求里那个 tool_search（829 字节）就是为这些延后的子代理工具放的：关掉子代理，它也跟着消失（第五节）。3

谁决定用 V1 还是 V2

第一看配置，第二看模型资料。第 4 章讲过，Codex 有一份模型资料，每个模型一组设置；其中 multi_agent_version 这一项，gpt-6.1-sol 写的是 v2，gpt-5.5 没写。没写时，Codex 再看配置里的 features.multi_agent，它缺省是开的，就用 V1。配置里有两个键能盖过模型资料：features.multi_agent_v2 = true 强制用 V2，[agents] 下的 enabled = false 整个关掉。完整顺序见下面的源码。2

V2 的协作工具直接写进请求，两条说明也只在 V2 里出现；V1 的工具是延后的。角色说明的文字也写在模型资料里，只有 4 个 gpt-6 开头的模型有（gpt-6.1-sol、gpt-6-astra、gpt-6-sol、gpt-6-luna）。所以实验里给 gpt-5.5 强制开 V2（features.multi_agent_v2 = true）后，6 个协作工具直接进了顶层 tools，不再需要 tool_search，顶层 tools 从 9,414 字节变成 14,116 字节（+4,702）；开关说明（410 字节）出现了，角色说明没有。2

看源码：V2、V1 还是关掉，按什么顺序决定

core/src/config/mod.rs 第 1637–1664 行，中文注释是我加的。2

pub(crate) fn multi_agent_version_override(&self) -> Option<MultiAgentVersion> {
    if self.features.enabled(Feature::MultiAgentV2) {
        Some(MultiAgentVersion::V2)        // ① features.multi_agent_v2 = true：强制 V2
    } else if !self.agents_enabled {
        Some(MultiAgentVersion::Disabled)  // ② [agents] enabled = false：整个关掉
    } else {
        None                               // ③ 都没写：交给下面
    }
}

pub(crate) fn multi_agent_version_from_features(&self) -> MultiAgentVersion {
    self.multi_agent_version_override().unwrap_or_else(|| {
        if self.features.enabled(Feature::Collab) {   // features.multi_agent，缺省开
            MultiAgentVersion::V1
        } else {
            MultiAgentVersion::Disabled
        }
    })
}

pub(crate) fn multi_agent_version_for_model(
    &self,
    model_multi_agent_version: Option<MultiAgentVersion>,
) -> MultiAgentVersion {
    self.multi_agent_version_override()
        .or(model_multi_agent_version)             // ④ 模型资料的 multi_agent_version
        .unwrap_or_else(|| self.multi_agent_version_from_features())  // ⑤ 最后看 features
}

回答问题 1

一次都没让它派子代理，请求里有没有跟子代理有关的内容？多大？gpt-5.5 一样吗？

有。gpt-6.1-sol（思考级别 low）的请求里固定有三块：6 个协作工具 5,529 字节、角色说明 2,575 字节、开关说明 410 字节，合计 8,514 字节，占请求的 15.5%。gpt-5.5 不改配置时没有这三块：它的子代理工具是延后的，要搜了才进历史（一次搜索 10,424 字节），请求里平时只多一个 829 字节的 tool_search。差别来自模型资料里的 multi_agent_version：gpt-6.1-sol 写了 V2，gpt-5.5 没写，用 V1。

二、同样读 4 份日志，父会话少带 11.9 万字节，总量多发 18.8 万字节

最朴素的做法是父会话自己读。读 4 份各 29,769 字节的日志，每次工具调用和输出都写进父会话的历史，之后每一次请求都要带着。实验里父会话的请求从 54,878 字节涨到 174,526 字节，5 次请求发出的输入合计 573,510 字节。5

派子代理去读，这些调用和输出就留在子代理自己的历史里。同一个任务换一个剧本：父会话派一个子代理（fork_turns 用缺省值，它决定子代理带走父会话多少历史，第三节讲），自己调用 wait_agent 等它；子代理读完 4 份日志，回一句结论。结果：5

父会话省下的是窗口。派子代理时，父会话最后一次请求比自己读时少 118,716 字节，约 29,679 token。从第一次请求到最后一次，父会话只多了 932 字节：spawn_agent 的调用和结果、wait_agent 的调用和结果，以及子代理那一句结论。

总量反而多，是因为同样的活一次没少干，还多了父会话的请求。拿 all 那一行算：子代理读日志的 5 次请求，和父会话自己读的 5 次一一对应，每次还多 4,414 字节从父会话继承来的内容（第三节），5 次共多 22,070 字节；父会话自己另外发了 3 次请求（你说话后的第一次、派出子代理之后、等到结论之后），每次都带着约 5.5 万字节的固定开头（工具定义、系统提示词等），共 165,905 字节。两项加起来 187,975 字节，正好是 761,485 和 573,510 的差。

动手算：自己读还是派子代理

滑块的初始值就是上面的实验：读 4 次，每次输出 29,769 字节，结论 24 字节，干完活后父会话不再发请求。改了数，请求大小按实验里的增量推算：每调用一次工具，多 143 字节加这次的输出；派出、等待、收结论，让父会话多 908 字节加结论本身。「折价」是按第 5 章的缓存价目，把花费折合成多少个 token 的全价（gpt-6.1-sol：从缓存读按 0.05 倍，新写进缓存按 1.25 倍，假设每次都接上上一次的缓存）；假服务器没有真的缓存，这一项没有实验。16

回答问题 2

子代理替父会话「省」了什么？自己读和派子代理，父会话的窗口占用、整个过程发出的输入各是多少？

省的是父会话的窗口：读 4 份 3 万字节的日志，父会话自己读时，最后一次请求涨到 174,526 字节；派子代理去读，只到 55,810 字节，少 118,716 字节（约 29,679 token），之后父会话的每一次请求都少带这些，压缩时也不用处理它们。总量没省：子代理把读日志的请求一次不少地发了一遍，父会话还要另发几次请求，所有请求的输入合计 761,485 字节（fork_turns 缺省）或 732,677 字节（none），比自己读多 33% 或 28%。

三、子代理开头带了什么：gpt-6.1-sol 缺省带走父会话的全部历史

最朴素的做法是让子代理从空白开始，只给它任务。这样子代理的请求最小，但它不知道父会话里说过什么。gpt-5.5 是这样做的；gpt-6.1-sol 相反，缺省把父会话的历史整份交给子代理。这种「从父会话分出一份历史」的做法叫 fork（分叉）。

gpt-6.1-sol：fork_turns 缺省是 all。fork_turns 是模型调用 spawn_agent 时可以填的一个参数，决定子代理带走父会话的多少历史。工具说明写的是「Defaults to all」，源码里也是：没填或填空，就当作 all，带走全部；填 none 才不带；填数字（如 "3"）也不会只带最近 3 轮，仍当作 all；填别的会报错。实验里填 "3" 的子代理，第一次请求和不填时一样是 14 条，只是调用参数的文字多了 23 字节。7

gpt-5.5：对应的参数是 fork_context，缺省 false，不带。子代理的第一次请求只有 4 条：系统提示词、技能目录、AGENTS.md 加环境信息、一条任务消息，没有父会话的历史。8

动手看：子代理的第一次请求

三组都是实验里子代理的第一次请求，每一段的宽度按这一条的字节数画，鼠标停在一段上能看到名字。颜色表示它和父会话的请求比较的结果。「能接上父会话的缓存」是按第 5 章的规则推的（请求开头逐字相同，并且父会话已经发过这个开头），没有实验。

fork 之后，子代理的历史和父会话的有几处不同，都能在实验的请求里看到：6

  • 父会话那次 spawn_agent 调用留着，调用结果换成了 aborted。子代理看到的是自己「被派出」的那次调用，没有真正的返回值。
  • 末尾追加了 5 条：一条「你是新派出的子代理，前面的对话是继承来的父会话上下文，前面的身份和任务属于祖先」（504 字节）；子代理自己的角色说明（2,628 字节）；一条「这些工具不可用」（239 字节，实验里不可用的是 request_user_input_async）；再一条开关说明（410 字节）；任务消息（317 字节）。所以子代理的请求里，父会话的 /root 角色说明和子代理自己的角色说明同时在，开关说明也有两条。
  • 填 none 时，子代理的工具定义也不同：23,801 字节，比父会话的少 1,546 字节，少的就是 request_user_input_async。第一条就和父会话不同，后面的内容再一样，缓存也接不上。填 all 时，子代理保留父会话的工具定义，改用末尾那条说明告诉模型哪个工具不可用，所以开头不变。

缓存上，all 和 none 差得很多。按第 5 章的规则，all 的第一次请求里有 54,878 字节能从缓存读：父会话的第一次请求已经把这段写进了缓存，两边请求里的 prompt_cache_key 也相同，都是整个会话的编号。这次请求折合约 2,066 个 token 的全价。none 的开头接不上，要整份写进缓存，折合约 16,725 个 token 的全价。9省窗口的是 none，省钱的反而是缺省的 all。这是按规则推的，真实服务上能不能接上没测【待核实】。

fork 之后换模型

spawn_agent 还有一个参数 model，可以让子代理用另一个模型。角色说明里写着「全量 fork 不接受模型覆盖」（意思是带走全部历史时，别给子代理另指定模型），但这只是写给模型看的话，代码没有拦。实验里 fork_turns 用缺省值，同时填 model = "gpt-6-luna"：子代理用 gpt-6-luna 发请求，请求里保留父会话的整个开头，再追加一条 18,535 字节的 <model_instructions>（gpt-6-luna 的指令），整份请求 78,777 字节，比同一个模型 fork 时的 59,292 字节多 19,485 字节。13这呼应了第 5 章讲过的做法：换模型时，Codex 把新模型的说明追加到后面，保留原来的请求开头；这里因此多带了一份模型指令。

对照：Claude Code 的子代理缺省从空白开始

据官方文档（2026-11-02 查阅），Claude Code 的子代理缺省拿到「全新的、隔离的上下文窗口」，看不到你的对话历史，只有父会话写给它的那条委派消息；系统提示词用子代理自己的，加上工作目录等环境信息。CLAUDE.md 和 git 状态缺省会带上，内置的 Explore、Plan 两种子代理不带。要让子代理继承对话，得明确用 fork（文档里「fork the current conversation」一节）。和 Codex 的 gpt-6.1-sol 正好相反。15

回答问题 3

子代理开始干活时带着父会话的哪些内容？gpt-6.1-sol 和 gpt-5.5 一样吗？对窗口和缓存各有什么影响？

不一样。gpt-6.1-sol 的 fork_turns 缺省 all：子代理带着父会话的全部历史（实验里第一次请求 59,292 字节，前 55,070 字节和父会话的请求逐字相同）；填 "none" 才从空白开始（53,520 字节）；填数字也当 all。gpt-5.5 的 fork_context 缺省 false，从空白开始（36,188 字节）。窗口上，none 的第一次请求小 5,772 字节；缓存上，all 能接上父会话已经写进缓存的开头，none 要整份重写。

四、回到父会话的是子代理的最终回答，整份进来，没有上限

子代理干完活，它的最终回答变成父会话历史里的一条消息。Codex 给每个代理起一个路径样的名字：父会话是 /root，它派出的子代理叫 /root/scan（scan 是剧本里给这个任务起的名）。在 gpt-6.1-sol 里，回到父会话的是一条 agent_message，作者 /root/scan、收件人 /root，正文以 Message Type: FINAL_ANSWER（最终回答）开头，后面是子代理的原话。wait_agent 本身不带回答的内容，只回 {"message":"Wait completed.","timed_out":false}（170 字节），工具说明里写着「Does not return the content」。10

最终回答没有长度上限。实验里让子代理最后回一段 3,000 行的文字（231,068 字节），父会话的请求从 55,226 字节一下涨到 289,787 字节，这段文字原样进了历史。我在源码里没找到截断这条消息的代码【待核实：没有穷尽搜索】。所以第二节算的「父会话只多 932 字节」，只在子代理的回答很短时成立；在第二节的交互里把「子代理的结论」调到 100 KB，父会话在窗口上的优势就没了。

在 gpt-5.5 里，同一段回答会进历史两次。实验里父会话调用 wait_agent 等子代理，结果里有 {"status":{"…":{"completed":"结论：日志无异常"}}}；紧接着 Codex 又追加一条 user 消息 <subagent_notification>…</subagent_notification>（子代理完成的通知），里面是同一句结论。结论只有一句话时无所谓，几万字节时就是两份。10

子代理中间读了什么、试过什么，父会话看不到，它们只在子代理自己的历史里。要追问「你为什么排除了方案 B」，父会话得用 followup_task 或 send_message 再问一次。

回答问题 4

子代理干完活，父会话收到什么？收到的内容有长度上限吗？

父会话收到子代理最终回答的原文：在 gpt-6.1-sol 里是一条标着 FINAL_ANSWER 的 agent_message，没有长度上限，实验里 231,068 字节整份进了父会话的历史。子代理中间的工具调用和输出不进来。在 gpt-5.5 里，wait_agent 的结果和一条 <subagent_notification> 通知里各有一份回答。

五、能开几个、能套几层、怎么关

gpt-6.1-sol（V2）下，同时活着的代理缺省最多 4 个，父会话自己也算一个，所以最多 3 个子代理；子代理可以再派子代理，层数没有限制。4 这个数写在两处：配置的缺省值，和角色说明里那句「There are 4 available concurrency slots」（有 4 个并发名额）。实验里父会话连派 4 个子代理，第 4 个得到报错 collab spawn failed: agent thread limit reached。再做一组：让每个子代理再派一个，一层一层往下，直到代理总数用完才停：/root/a/g/g（父会话下面第 3 层）那一层派成功，再往下一层报同样的错。在 config.toml 的 [agents] 下写 max_threads = 1，代理总数就变成 2（父会话加 1 个子代理），角色说明里的数字也跟着变成 2。11

gpt-5.5（V1）下，缺省只能派一层。层数由 [agents] 下的 max_depth 管，缺省 1；V2 不看这个键。实验里 gpt-5.5 的子代理，请求顶层的工具里没有 tool_search，也就搜不到 spawn_agent。我没让它真的去派下一层，只看了它的请求里没有这个入口。11

怎么关

下面每一项都是改完配置后，抓一次 gpt-6.1-sol 的第一次请求（思考级别 low，不接 MCP；不改配置时 54,878 字节）。实验里在命令行用 -c 键=值 改配置，同样的键可以写进 ~/.codex/config.toml，按钮下面显示的就是写进文件时的样子。12

协作工具角色说明开关说明

三个容易踩的地方：

  • features.multi_agent = false 和 features.multi_agent_v2 = false 对 gpt-6.1-sol 都没有效果。前一个只在模型资料没写版本时才看，后一个只有设成 true 才算数（第一节的源码）。要整个关掉，在 [agents] 下写 enabled = false，这时三块都消失，请求少 8,516 字节。
  • 只关两条说明：在 [features.multi_agent_v2] 下，把 root_agent_usage_hint_text（角色说明）和 multi_agent_mode_hint_text（开关说明）设成空字符串。这样工具还在，模型还能派子代理，只是请求里不再有说明；要注意，缺省的开关说明本来是在叫模型别主动派。
  • disable_native_tools = true 去掉了 6 个工具，两条说明却还在。请求里仍然告诉模型「用 spawn_agent 派子代理」，而这个工具已经不存在。源码注释说，这个键是「隐藏 Codex 自带的子代理工具，保留 V2 的运行机制，给宿主提供的工具用」：从字面看，是给把 Codex 嵌进别的程序、由那个程序自己提供子代理工具的场景【推测】。平时用 Codex 不要开它。

对照：Claude Code 的上限和开关

据官方文档（2026-11-02 查阅）：15

  • 层数：子代理缺省可以再派子代理，最多到主会话之下 3 层；设环境变量 CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 就不能再往下派。
  • 同时运行的个数：缺省最多 20 个，用环境变量 CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS 改（v2.1.217 起），超了报 Concurrent subagent limit reached；一个会话里累计派多少次没有上限。
  • 关闭：在设置文件的 permissions.deny 里写 Agent(Explore) 这样的规则，关掉某一种子代理；写 Agent 关掉全部委派。
  • 只读的子代理：内置的 Explore、Plan 不能写文件（禁用 Write 和 Edit 工具）。Codex 有没有这样的子代理，见设计笔记。

回答问题 5

同时能开几个子代理，子代理还能再派子代理吗？想关掉子代理，或者只关掉请求里的两条说明，怎么写、请求能少多少？

gpt-6.1-sol：代理总数缺省最多 4 个（含父会话，即最多 3 个子代理），子代理可以再派，层数不限，总数满了报 agent thread limit reached。gpt-5.5：缺省只能派一层。整个关掉，在 config.toml 的 [agents] 下写 enabled = false，请求少 8,516 字节（15.5%）；只关两条说明，在 [features.multi_agent_v2] 下把 root_agent_usage_hint_text 和 multi_agent_mode_hint_text 设成空字符串，少 2,985 字节，工具仍在。

设计笔记

  • 隔离省的是窗口，不是钱，也不是 token 总量。子代理的每次请求都重发固定开头，实验里总量多 28%–33%。按第 5 章的缓存价目折价后，差别小得多：在第二节交互的初始值下，缺省 all 折合 63,481 个 token 的全价，自己读折合 59,527，多 6.6%；如果干完活之后父会话再发 3 次请求，all 就比自己读便宜（65,574 对 66,072），none 要再发 13 次才便宜。这些是交互里的推算，没用真实服务验证。真正要省的是父会话的窗口：它决定什么时候压缩（第 4 章），以及压缩之后摘要里还剩什么。
  • 缺省带走全部历史，代码没写理由【推测】。可能的理由有两个：一是缓存，前面算过，all 的开头和父会话逐字相同，能从缓存读；二是不丢父会话里你随口说过的约束（比如「别动 API」）。源码里有个配置 preserve_fork_prefix（缺省 false），说明是「全量 fork 时保留父会话里模型看得到的历史，并追加子代理指令」；缺省 false 时，代码会在继承的历史里过滤、替换一部分 developer 消息（core/src/agent/control/spawn.rs:1124-1260）。可实验里父会话的角色说明和开关说明仍留在子代理的请求里，过滤规则我没逐条核对，打开这个开关的效果也没实验【待核实】。
  • 「别派」靠提示词，不靠权限。缺省的开关说明只是一句话；子代理和父会话的工具一样（none 时少 1 个），只有代理总数满了，Codex 才会拦。想真正不让它派，要关掉工具（[agents] enabled = false）。
  • 内置角色里没有只读的。源码里有 default、explorer、worker 三个内置角色（core/src/agent/role.rs:342-385），explorer 的说明是「用来问具体的、范围明确的代码库问题」，但它的配置文件 explorer.toml 是 0 字节：没有限制工具，也没有换模型。本章抓到的 gpt-6.1-sol 和 gpt-5.5 的 spawn_agent 参数里都没有 agent_type（选角色的参数），模型挑不了角色。自己定义角色（在 config.toml 里写 [agents.名字] 加 config_file，config/src/config_toml.rs:784 附近的注释有例子）也许能限制工具，本章没做实验【待核实】。14
  • 没测的：真实模型会不会在该派的时候派、不该派的时候忍住（开关说明起多大作用）；真实服务上能不能接上缓存；子代理自己触发压缩时，结果怎样回到父会话；多个代理同时改文件会不会冲突（所有代理共用同一个工作目录，角色说明里写了「别人的改动你马上看得到」，隔离文件的办法我没找到【待核实】）。这些归第 11 章（评估）。

小结

  1. gpt-6.1-sol 的请求里固定有 6 个协作工具（5,529 字节）、角色说明（2,575 字节）、开关说明（410 字节），共 8,514 字节、占 15.5%；gpt-5.5 缺省没有，它的子代理工具是延后的，搜一次 10,424 字节。
  2. 读 4 份 3 万字节的日志，派子代理让父会话的最后一次请求从 174,526 字节降到 55,810 字节，但所有请求的输入合计多 28%–33%；省的是父会话的窗口。
  3. gpt-6.1-sol 的 fork_turns 缺省 all，子代理带走父会话的全部历史，开头和父会话逐字相同，能接上缓存；填 "none" 才从空白开始，但要整份重写；gpt-5.5 缺省不带。
  4. 回到父会话的是子代理最终回答的原文，没有上限，实验里 231,068 字节整份进来；gpt-5.5 还会在 wait_agent 的结果和完成通知里各放一份。
  5. gpt-6.1-sol 最多 4 个代理（含父会话）、层数不限；整个关掉写 [agents] enabled = false，少 8,516 字节；两条说明设成空字符串，少 2,985 字节；features.multi_agent = false 对它没效果。
