第 4 章

压缩之后，留下你最近的原话和一段摘要

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 模型 gpt-6.1-sol，思考级别 low · 对照 Claude Code 官方文档（2026-11-02 查阅）

压缩，是把前面的对话交给模型写成一段摘要，再用摘要换掉原来的对话。在一次 5 轮对话的实验里，压缩之后，第 1 轮那句「我叫 Drake，规则：不要改数据库 schema」的原文不见了，只剩摘要里转述的一句；命令的调用和输出、模型自己的回复也都没了。请求却只从 35,003 token 降到 33,965 token，因为留下来的两条长消息占了约 2 万。

第 3 章说过，旧的命令输出只有压缩或新开会话才能清掉，这一章接着讲压缩。token 仍是 Codex 的估算：UTF-8 字节数 ÷ 4，向上取整（见第 2 章）。实验用本机假服务器，每轮是一次 codex exec 或 codex exec resume --last，不联网。1

一、什么时候压

最朴素的做法是等请求被拒了再压：服务器说「超出窗口」，就把历史压一压再发。问题是这一轮已经白发了一次，而压缩本身也要把整段历史发出去（第二节），这时它多半也装不下。所以 Codex 在窗口满之前留了余量。

压缩线是窗口的 90%。你在 ~/.codex/config.toml 里写 model_auto_compact_token_limit = 100000 这样一行，可以把线压低，但不能高过 90%。2 窗口看你连的是哪：

gpt-5.5 在两份表里都是 272,000。另有一条「窗口 95%」的线，因为压缩线最高只到 90%，95% 那条总是后到，平时碰不上。3

「用了多少」主要看服务器报的数。每次请求完成，服务器会报这次用了多少 token；Codex 拿上一次报的数，加上之后新写进历史、还没发出去的条目的估算，和压缩线比。4

比的时机有两个。

  • 一轮开始前：你发了新消息，Codex 先比一次，到线就先压再处理你的消息。这时你的新消息还没写进历史，所以它不在压缩范围里，会原样留到压缩之后。源码里留了一条待办：这一步没把「即将写入的新消息」算进去，一条很大的新消息可能直接把请求撑过窗口。5
  • 一轮中间：模型调了工具、还要接着干时，每一步之后比一次，到线就压，压完接着干。如果模型这一步已经说完了，就不压，等下一轮开始前再说。

此外还有两种情况会压：6

  • 手动：在 Codex 的输入框里打 /compact。
  • 会话中途换模型：模型表里每个模型有一个「压缩格式编号」（comp_hash），gpt-5.5 是 2911，gpt-6.1-sol 是 3000。编号不同，下一轮开始前先用旧模型压一次，所以这两个模型来回换，每换一次就压一次。编号相同、但新模型窗口更小且当前用量已过新模型的线，也会压。

回答问题 1

用到多少会自动压缩？什么时候压？能自己压吗？

用到窗口的 90% 就压：官方登录时 gpt-6.1-sol 是 45 万 token（窗口 50 万）；你可以用 model_auto_compact_token_limit 把线调低，不能调过 90%。比的时机是一轮开始前和一轮中间模型还要接着干的时候。手动压就在输入框里打 /compact。

二、压缩时发生了什么，压完剩什么

实验做了 5 轮：第 1 轮说名字和规则，模型跑一次 seq 1 3000（这次沙箱报了错，输出只有一行错误信息，不影响结论）；第 2 轮发一条约 1.5 万 token 的长消息；第 3 轮发一条约 6 千 token 的消息，假服务器报告「这次用了 12 万 token」。压缩线配成 10 万，所以第 4 轮一开始就压了。1

压缩是一次单独的请求。Codex 把整段历史原样发出去，末尾加一段 9 行的英文提示词，大意是「你在做一次上下文检查点压缩，给接手的模型写一份交接摘要：进度和关键决定、约束和用户偏好、剩下要做的、继续工作需要的数据」。实验里这次请求 140,656 字节，比上一次正常请求还大 644 字节。7 模型回一段摘要，Codex 再拼出新历史。

动手看：压缩前后的请求

三次请求都是实验抓到的（input 里每一条的 JSON 字节数）。点按钮切换，划线的是这次请求里已经没有的。

压缩后的请求从前往后是：

  1. 工具定义、系统提示词：照旧放最前。
  2. 你的原话：从最新往前挑，最多约 2 万 token（第三节）。这次留下第 2 轮（被截短）和第 3 轮，第 1 轮没留。
  3. Codex 自己写的那几条：技能目录、权限、子代理说明、AGENTS.md 和环境信息。它们不是被「保留」下来的，是按当前设置重新生成、插回去的，位置在最后一条保留的原话前面。所以第 2 轮被夹在了它们前面。8
  4. 摘要：作为一条「用户」消息放在末尾，前面拼一段固定的英文说明，大意是「另一个模型做过这件事，下面是它的思考摘要，在它的基础上继续，别重复」。9
  5. 你这一轮的新消息：第 4 轮「继续」，压缩时还没写进历史，原样接在最后。

不见了的有：第 1 轮原话、命令的调用和输出、三条模型回复。它们只在摘要里留下转述，转述成什么样由写摘要的模型决定。这次摘要是假服务器写死的一句「用户叫 Drake；规则是不要改数据库 schema；已跑过一次 seq 命令」，真实模型会写多长、漏不漏，这个实验测不出来。

原文还在本机存档里。会话存档（~/.codex/sessions/ 下的 .jsonl）不删旧记录，只在后面追加一条「压缩」记录，里面存着新历史。第 5 轮是新起的进程，恢复会话时用的就是这份新历史，第 1 轮没有回来。10 压完 Codex 还会提示一句：长会话和多次压缩会让模型变得不那么准，尽量新开会话。11

回答问题 2

压缩后，第 1 轮那句原话、命令输出、模型回复还在吗？

都不在了（本地压缩的实验）。第 1 轮只剩摘要里的转述；命令的调用和输出、模型回复全部删掉。还在的是最近的两条原话、重新生成的 AGENTS.md 和环境信息、摘要，以及你这一轮的新消息。原文只留在本机的会话存档里，模型看不到。

三、你的原话留多少

只靠摘要，风险是模型把你的要求转述歪了。全留原话，又占地方。Codex 的做法是只留你说的话，从最新一条往前留，留满约 2 万 token 为止。12

  • 只算你亲手发的消息。历史里还有几条「用户」角色的条目是 Codex 自己写的，比如 AGENTS.md、环境信息、上一次压缩的摘要，这些不算。模型的回复、工具调用和输出也不算。
  • 从新到旧，装得下就整条留。每条按「字节 ÷ 4」估算 token，从预算 20,000 里扣。
  • 装不下的那条截短后留下，然后停。截法和第 3 章一样：留开头和结尾，中间换成 …N tokens truncated…。消息里的图片在这一步丢掉。更早的消息一条都不再看。

实验对上了这个规则：第 3 轮 5,957 token，整条留下，预算剩 14,043；第 2 轮 15,060 token 装不下，被截成开头 28,086 字节 + 结尾 28,086 字节，中间标记 …1017 tokens truncated…，正好是 15,060 − 14,043；第 1 轮只有 23 token，但已经轮不到了。12

所以压缩省多少，要看你说过的话有多长。这次两条长消息占了约 2 万，压完只少了约 1 千 token。按规则算，压缩后的请求至少有：第 2 章那 13,410 token 左右的固定部分，加上最多约 2 万的原话，再加摘要。

回答问题 3

留哪几条原话、最多多少？1.5 万 token 的长消息会怎样？

只留你亲手发的消息，从最新往前，最多约 2 万 token（本地压缩）。装不下的那条留开头和结尾、中间截掉，然后就停，更早的全靠摘要。1.5 万 token 的消息如果是最新的，整条留下；如果前面已经用掉一部分预算（实验里用掉 5,957），它被截短，再往前的消息哪怕只有 23 token 也留不下。

看源码：从新到旧，装不下就截短再停

core/src/compact.rs 第 64、722–803 行，节选，注释是我加的。12

const COMPACT_USER_MESSAGE_MAX_TOKENS: usize = 20_000;

let mut remaining = max_tokens;                       // 预算 2 万
for message in user_messages.iter().rev() {           // 从最新一条往前
    if remaining == 0 {
        break;
    }
    let tokens = approx_token_count(&message.message); // 字节 ÷ 4
    // 装得下、并且全是文字，才整条留
    let preserve_content = tokens <= remaining
        && content.iter().all(|part| matches!(part, ContentItem::InputText { .. }));
    if !preserve_content {
        // 只取文字部分（图片丢掉），截到剩下的预算：留头留尾
        set_annotated_content(&mut item, truncate_annotated_text(parts, remaining));
    }
    selected_messages.push(item);                     // 先放进去
    if tokens > remaining {
        break;                                        // 截过的这条是最后一条
    }
    remaining = remaining.saturating_sub(tokens);
}
selected_messages.reverse();                          // 倒回时间顺序

四、官方通道：摘要是加密的

上面两节是本地压缩：摘要由模型按 Codex 的提示词写成文字，Codex 自己拼新历史。用 ChatGPT 账号或 OpenAI API 密钥连官方服务（还有 Azure）时，走的是另一套远端压缩；连自己配的服务地址（比如本章的假服务器），才走本地压缩。13

远端压缩有三处不同：1415

  • 摘要你看不到。Codex 仍把整段历史发出去，末尾不加提示词，而是加一条 {"type":"compaction_trigger"}，意思是「请压缩」。服务器回一条 compaction 条目，内容在 encrypted_content 字段里，是加密的。Codex 原样存下、下次原样发回，它和你都读不到摘要写了什么。你在 config.toml 里配的 compact_prompt（换掉那 9 行提示词）也只对本地压缩有效。
  • 原话留得多。预算是 64,000 token，还是从新到旧、装不下的截短后停。能留的除了你的消息，还有钩子（hook，你配置的、在特定时机自动运行的脚本）注入的提示，以及别的代理发来的消息（每条不超过 1 万 token，子代理交回的最终结果不留）。
  • 工具输出照样不留。有一个保留工具输出的开关 retain_client_tool_outputs，还在开发中，默认关闭。另外，如果压缩前历史已经超过窗口，Codex 会从最新往前，把工具输出换成一句「Output exceeded the available model context and was truncated」，直到装得下再发。

本地压缩遇到「压缩请求本身超出窗口」时，做法是删掉历史最前面的一条再试，一直删到装得下。16

远端压缩只读了源码，没做实验：假服务器给不出真的加密摘要，连官方服务又要花额度。服务器那边用什么提示词、摘要多长，都看不到【待核实】。

回答问题 4

官方通道的压缩还是同一套吗？能看到摘要吗？

不是同一套。官方通道走远端压缩：服务器返回一段加密的摘要，Codex 和你都看不到内容；你的原话留得更多（64,000 token，本地是 20,000）；工具输出和模型回复同样不留。只有连自己配的服务地址时，才走本地压缩、摘要是明文。

五、让一句话压缩后还在

从上面几节能推出：压缩后一定还在的，是 Codex 每次重新生成的那几条，以及最近的原话。所以办法按稳的程度排：

  1. 写进 AGENTS.md。它每次压缩后都被插回去（实验里那条 752 字节的就是），不靠摘要。第 2 章讲过：项目里的 AGENTS.md 一个会话只读一次，会话中途改了文件，插回去的是会话开始时读到的版本【推测：按第 2 章的源码结论，压缩时没单独验证】。17
  2. 快压缩时再说一遍。最近的原话优先保留。反过来，很长的消息（贴日志、贴代码）会把预算占满，挤掉更早的短要求。
  3. 用钩子在压缩后补一段。在钩子配置文件 hooks.json（放在 ~/.codex/ 或项目的 .codex/ 下）里配一个 SessionStart 钩子，匹配来源 compact，它的输出会在压缩后加进上下文。PreCompact、PostCompact 两个钩子只能叫停压缩，改不了摘要。【读了源码，没做实验】18
  4. 本地压缩可以换提示词。在 config.toml 写 compact_prompt = "……"，或用 experimental_compact_prompt_file 指向一个文件，比如要求「原样抄下用户给过的所有规则」。官方通道无效（第四节）。19

对照：Claude Code 重新读文件

据官方文档（2026-11-02 查阅），Claude Code 压缩也是把对话写成摘要，文档只说摘要会保留「你的请求和关键代码片段」，没说保留原话。差别在压缩后补回什么：20

  • 从磁盘重读：项目根目录的 CLAUDE.md、不带 paths: 的规则、自动记忆、计划模式写的计划。带 paths: 的规则和子目录里的 CLAUDE.md 要等再碰到相关文件才重新加载。
  • 重读最近的文件：本会话读过或改过的文件，按最近修改挑最多 5 个重新读进来；超过 5,000 token 的只给路径。
  • 用过的技能：正文重新放回，每个最多 5,000 token、合计 25,000，超了先丢最早用的。
  • 你能插手：输入框里打 /compact focus on the auth bug fix，指定摘要重点；或在 CLAUDE.md 里写一节「Compact Instructions」。
  • 什么时候压：不设置时，原生 100 万窗口的模型大约在 96.7 万 token 压，其他多数情况到模型窗口上限才压；输入框里打 /autocompact 500k 可以提前。21

一句话：Codex 留你的原话，不管文件；Claude Code 不承诺留原话，但会把最近的文件和规则文件重新读回来。

回答问题 5

想让一条规则压缩后一定还在，写在哪最稳？Claude Code 呢？

Codex 里写进 AGENTS.md 最稳：每次压缩后都会插回去，不靠摘要。其次是快压缩时再说一遍，或配一个匹配 compact 的 SessionStart 钩子在压缩后补进去。Claude Code 里写进项目根目录的 CLAUDE.md，压缩后会从磁盘重读；带 paths: 的规则不会立刻回来。

设计笔记

  • 为什么只留你的原话。你的要求换个说法可能就变了意思，而且没处再找；文件和命令输出，模型需要时可以重读、重跑。代价是压缩后模型手里没有精确的代码和输出，得重新读。代码里没写理由【推测】。
  • 为什么截短最后一条、不跳过它去找更早的短消息。跳过会让留下的原话不连续，「先说 A、再说 C」，中间的 B 没了。代价是那条可能被截在要紧处【推测】。
  • 本地 2 万、远端 6.4 万。本地压完还要把系统提示词、AGENTS.md 等插回同一份历史，留太多压完就又贴着线，可能一轮接一轮地压【推测】。远端为什么敢留 6.4 万，源码看不出来。
  • 加密摘要的取舍。摘要由服务器生成、只有服务器能读，可能带着纯文字表达不了的模型内部状态；代价是你没法检查它漏了什么【推测】。
  • 别的做法。第三版资料里提到，有的 agent 留的是「最近一段连续的历史」，连工具输出一起留，切点要避开把工具调用和它的输出拆开。本机没有那些 agent 的源码，没核对【待核实】。

小结

  1. 用到窗口的 90% 自动压缩（官方登录时 gpt-6.1-sol 是 45 万 token），时机是一轮开始前和一轮中间；可以配置调低，手动压打 /compact。
  2. 压缩后，较早的原话、命令调用和输出、模型回复都不在了，只剩摘要里的转述；AGENTS.md 和环境信息会重新插回，原文只留在本机存档。
  3. 本地压缩只留你亲手发的消息，从最新往前最多约 2 万 token，装不下的那条截短后停。
  4. 官方通道走远端压缩：摘要加密、你看不到，原话留 6.4 万 token，工具输出同样不留。
  5. 要一条规则压缩后还在，写进 AGENTS.md 最稳；Claude Code 则是写进项目根目录的 CLAUDE.md，压缩后会重读。
