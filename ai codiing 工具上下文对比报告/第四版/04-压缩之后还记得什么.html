第 4 章

压缩之后，留下你最近的原话和一段摘要

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 模型 gpt-6.1-sol，思考级别 low · 对照 Claude Code 官方文档（2026-11-02 查阅）

压缩，是 Codex 把前面的对话交给模型写成一段摘要，再用这段摘要换掉原来的对话。在一次 5 轮对话的实验里，压缩之后，第 1 轮那句「我叫 Drake。规则：不要改数据库 schema」的原文不在请求里了，只剩摘要转述的一句；命令的调用和输出、模型的回复也都删掉了。可是请求只从 35,003 token 降到 33,965 token，少了约 1 千：这次占地方的是你自己贴的两段长日志，而压缩恰好保留你的原话。

这一章接着第 3 章：第 3 章说过，旧的命令输出要等压缩或新开会话，才会从请求里清掉。token 仍是 Codex 的估算：UTF-8 字节数 ÷ 4，向上取整（见第 2 章）。实验在本机起一个假的模型服务器，它按脚本回话，不联网；每一轮是一次单独的 codex exec 命令。1

Codex 有两套压缩做法。用 ChatGPT 账号或 OpenAI API 密钥连 OpenAI 的服务（下文叫「官方通道」）时，服务器来压缩，叫远端压缩；连你在配置文件里写的别的服务地址（下文叫「自定义通道」）时，Codex 在本机压缩，叫本地压缩。实验的假服务器属于自定义通道，所以第二、三节讲本地压缩，第四节讲远端压缩哪里不同。

一、什么时候压缩

最朴素的做法是等服务器拒绝了再压缩。这样有两个毛病：这次请求白发了；压缩本身也要发一次请求，把整段历史交给模型写摘要（第二节），历史已经超出窗口，这次请求多半也装不下。所以 Codex 在窗口满之前就压缩。

Codex 拿窗口的 90% 当压缩线：用量到了这条线，就自动压缩。你可以把压缩线调低：在 ~/.codex/config.toml 里加一行 model_auto_compact_token_limit = 100000，压缩线就是 10 万 token。但调不过 90%：写得比 90% 高，Codex 仍按 90%。2

90% 是多少，要看 Codex 认为 gpt-6.1-sol 的窗口多大。Codex 有两份模型资料：源码自带的模型表，跟着 CLI 一起装好；官方通道登录后从 OpenAI 服务器下载的模型列表，缓存在 ~/.codex/models_cache.json。下载到列表时用列表里的数：

条件gpt-6.1-sol 的窗口压缩线（90%）
官方通道登录，用下载到的模型列表（2026-11-02 下载）500,000450,000
下载不到列表时，用源码自带的模型表（本章的假服务器实验就是这种）272,000244,800

gpt-5.5 在两份资料里都是 272,000。Codex 还算了一个「有效窗口」，是窗口的 95%（272,000 时是 258,400），用量到了它也会压缩。压缩线最高只到 90%，总比有效窗口先到，所以平时触发压缩的是压缩线。第 10、12 章还会用到有效窗口。3

用了多少，主要看服务器报的数。每次请求完成，服务器会报这次一共用了多少 token；Codex 拿上一次报的数，加上之后新写进历史的条目（按字节 ÷ 4 估算），和压缩线比较。4 实验就利用了这一点：请求本身只有约 3.5 万 token，离压缩线很远；为了不真发几十万 token，实验让假服务器在第 3 轮报「用了 12 万 token」，又把压缩线配成 10 万，第 4 轮开始时用量就过了线。

Codex 在两个时刻比较用量和压缩线。先说清「一轮」：你发一句话，到模型给出最终回答，算一轮。一轮里模型可能调好几次工具，每调一次，Codex 把工具的输出写进历史，再发一次请求，模型接着干。

  • 一轮开始前：你发了新消息，Codex 先比较一次，过了压缩线就先压缩，再处理你的消息。这时你的新消息还没写进历史，不在压缩的范围里，压缩完原样接在最后。源码里留了一条待办，说这一步没把即将写入的新消息算进用量；一条很大的新消息，可能直接让请求超出窗口（超出以后怎样，见第 10 章）。5
  • 一轮中间：模型调了工具、还要接着干时，每调一次工具，Codex 比较一次，过了线就压缩，压缩完模型接着干。如果模型这一步已经给出最终回答，Codex 这时不压缩，留到下一轮开始前再比较。

另外还有三种情况会压缩：6

  • 一轮结束后：默认不压缩。在 config.toml 写 model_post_turn_compact_threshold_percent = 40，模型给出最终回答后，用量过了有效窗口的 40%（103,360 token）就压缩。第 12 章用它让压缩落在一件事做完时。
  • 手动：在 Codex 的输入框里打 /compact。它不带参数，不能指定摘要写什么（第 12 章）。
  • 会话中途换模型：模型表给每个模型一个编号 comp_hash，源码注释叫它「压缩兼容性哈希」，Codex 用它判断前后两个模型的压缩结果能不能通用。gpt-5.5 是 2911，gpt-6.1-sol 是 3000。换模型时编号不同，Codex 在下一轮开始前先用旧模型压缩一次，所以这两个模型来回换，每换一次就压缩一次。编号相同时，如果新模型的窗口比旧模型小、当前用量又已过新模型的压缩线，也会先压缩。

用到多少会自动压缩？什么时候压缩？能自己压缩吗？

用量到窗口的 90% 就自动压缩：官方通道登录时，gpt-6.1-sol 的窗口是 50 万，压缩线是 45 万 token。你可以在 config.toml 里用 model_auto_compact_token_limit 把压缩线调低，调不过 90%。Codex 在一轮开始前、以及一轮中间模型还要接着干时比较用量和压缩线；一轮结束后默认不压缩，可以在配置里打开。想自己压缩，在输入框里打 /compact。

二、压缩时发生了什么，压缩完剩什么

先把实验的 5 轮列出来，这一节和下一节的数字都出自这次实验。括号里是这句话的 token 数。1

轮你说的话这一轮发生了什么

压缩是一次单独的请求。Codex 把整段历史原样发给模型，末尾加一段 9 行的英文提示词，大意是「给接手的模型写一份交接摘要：进度和关键决定、约束和用户偏好、剩下要做的事、继续需要的数据」。实验里这次请求 140,656 字节，比第 3 轮的正常请求（140,012 字节）还多 644 字节：多出来的是第 3 轮模型的回复（125 字节）和这段提示词（519 字节）。7 模型回一段摘要，Codex 再用摘要拼出新的历史。

这次压缩请求要是本身也超出窗口，服务器会拒绝它。本地压缩这时从历史最前面一条删起，删一条重发一次，直到发得出去。第 10 章第三节做了这个实验：最前面的是工具定义、系统提示词这些 Codex 自己放的条目，所以最先删掉的是它们，然后才轮到你的话。16

动手看：压缩前后的请求

三次请求都是实验抓到的。每行是请求 input 里的一条，数字是它的 JSON 字节数（含引号等格式字符，比正文略大）。划线的是这次请求里已经没有的条目。

压缩后，第 4 轮的请求有 10 条，从前往后是：

  1. 工具定义、系统提示词：照旧放在最前面。
  2. 第 2 轮你的话：截短后保留（截法见第三节）。
  3. Codex 自己写的 4 条：技能目录、权限和协作模式（一条），子代理的两条说明，AGENTS.md 和环境信息（一条）。它们不是从旧历史里保留的，是 Codex 按当前设置重新生成、插在最后一条保留的原话（第 3 轮）前面，所以第 2 轮排到了这 4 条前面。8
  4. 第 3 轮你的话：整条保留。
  5. 摘要：作为一条「用户」消息，前面拼一段固定的英文说明，大意是「另一个模型做过这件事，下面是它的摘要，在此基础上继续」。9
  6. 第 4 轮你的新消息「继续。」：压缩时还没写进历史，原样接在最后。

第 4 轮的请求和压缩请求比，少了 6 条：第 1 轮你的原话、命令的调用和输出、三条模型回复。它们只在摘要里留下转述。这次的摘要是假服务器写死的一句「用户叫 Drake；规则是不要改数据库 schema；已跑过一次 seq 命令」；真实模型会不会漏掉规则，这个实验测不出来。

为什么请求只少了约 1 千 token。和第 3 轮的请求比：删掉的 5 条（第 1 轮原话、命令调用和输出、两条回复）一共只有 980 字节，因为命令没跑成，输出只有一行报错；第 2 轮截短，少了 3,969 字节；新加摘要 639 字节、第 4 轮的话 156 字节。合起来少 4,154 字节。占地方的是两段日志，而压缩保留原话。命令正常跑完的话，seq 1 3000 约 1.4 万字节的输出也会整条删掉【按规则推，没实验】。

原文还在本机存档里，模型看不到。压缩换掉的是内存里的会话历史；磁盘上的会话存档（~/.codex/sessions/ 下的 .jsonl，第 3 章分过这两处）不删旧记录，只在后面追加一条压缩记录 compacted，里面存着新历史。实验里第 1 轮原文在存档第 12 行，压缩记录在第 49 行。第 5 轮新起进程，从存档恢复时用的是新历史，第 1 轮的话没有回来。10 想让压缩前的对话回到请求里，可以回退到压缩那一轮之前（第 8 章第四节）。22

压缩完，Codex 会显示一句提示：长会话和多次压缩会让模型变得不那么准，尽量新开会话。11

回答问题 2

压缩后，第 1 轮那句原话、命令输出、模型回复还在吗？

都不在了（本地压缩的实验）。第 1 轮的话只剩摘要里的转述；命令的调用和输出、模型回复全部删掉。还在的是：工具定义和系统提示词，最近两轮的原话（一条截短），重新生成的 AGENTS.md 和环境信息，摘要，第 4 轮的新消息。原文只留在本机存档里，模型看不到。

三、你的原话保留多少

只留摘要，风险是模型把你的要求转述歪了；原话全部保留，又太占地方。Codex 取中间：只保留你亲手发的消息，从最新一条往前，保留满约 2 万 token 为止。12

  • 只算你亲手发的消息。Codex 自己写的「用户」条目（AGENTS.md 和环境信息、上次压缩的摘要）不算，模型回复、工具调用和输出也不算。
  • 从新到旧，装得下就整条保留。每条按「字节 ÷ 4」估算 token，从 20,000 的预算里扣。
  • 装不下的那条，截短后保留，然后停下。截短的办法和第 3 章一样：保留开头和结尾，中间换成一行 …N tokens truncated…，意思是「这里截断丢掉了 N token」。更早的消息一条都不再看。
  • 保留下来的消息里有图片的，图片都去掉，只留文字。整条装得下也一样。

拿实验对一下。第 3 轮最新，从它算起：

  • 第 3 轮 5,957 token，装得下，整条保留，预算剩 20,000 − 5,957 = 14,043。
  • 第 2 轮 15,060 token，超过剩下的 14,043，截短：开头留 28,086 字节，结尾留 28,086 字节，合起来 56,172 字节，正好 14,043 token；中间的标记是 …1017 tokens truncated…，1,017 = 15,060 − 14,043。预算用完，停下。
  • 第 1 轮只有 23 token，但已经轮不到它了，只剩摘要里的转述。

所以压缩后的请求多大，主要看你说过的话多长。这次 Codex 固定放的条目（工具定义、系统提示词和第二节那 4 条）是 54,696 字节，约 13,674 token；原话正好用满 2 万预算；加上摘要和第 4 轮的话，就是 33,965 token。你的话再长，压缩后也大致是这个数【按规则推】。

保留哪几条原话、最多多少？贴过的 1.5 万 token 日志会怎样？

只保留你亲手发的消息，从最新往前，最多约 2 万 token（远端压缩 6.4 万）。装不下的那条保留开头和结尾、中间截断，然后停下，更早的全靠摘要。1.5 万 token 的日志如果是最新一条，整条保留；如果后面的话先用掉了一部分预算（实验里第 3 轮用掉 5,957），它就截短，再往前的话哪怕只有 23 token 也保留不了。

四、官方通道：摘要是加密的

第二、三节讲的都是本地压缩：摘要是模型按 Codex 的提示词写出来的文字，新历史由 Codex 在本机拼。走官方通道时（连 Azure 上的 OpenAI 服务也一样），Codex 用远端压缩。13 这一节只读了源码，没做实验：假服务器给不出加密摘要，连官方服务要花额度。

远端压缩和本地压缩有三处不同：1415

  • 摘要你看不到。Codex 仍发整段历史，末尾不加那 9 行提示词，而是加一条 {"type":"compaction_trigger"}（请压缩）。服务器回一条 compaction 条目，摘要在 encrypted_content 字段里，是加密的。Codex 原样存下、之后原样发回，Codex 和你都读不到。服务器用什么提示词、摘要多长，也看不到【待核实】。
  • 原话保留得多。预算是 64,000 token（本地压缩是 20,000），规则一样：从新到旧，装不下的截短后停下。除了你的消息，还保留两类：钩子注入的提示（钩子是你在配置里写的脚本，在特定时机自动运行，第五节讲），以及别的代理发来的消息（多个代理协作时互相发的消息，见第 7 章）。别的代理发来的消息，超过 1 万 token 的那条不保留，子代理交回的最终结果也不保留。
  • 工具输出照样不保留。有一个保留工具输出的开关 retain_client_tool_outputs，还在开发中，默认关。

历史已经超出窗口时，两边的办法也不同。本地压缩等服务器拒绝以后，从历史最前面一条删起（第二节）。远端压缩在发之前先估算：超出了，就从最新一条往前，把工具输出换成一句「Output exceeded the available model context and was truncated」，碰到不是工具输出的条目就停；换完仍超出，也照样发。15

回答问题 4

官方通道的压缩还是同一套吗？能看到摘要吗？

不是同一套。官方通道走远端压缩：服务器返回加密的摘要，Codex 和你都看不到；原话保留得更多（64,000 token，本地压缩 20,000）；工具输出和模型回复同样不保留。连自定义通道（比如本章的假服务器）时才走本地压缩，摘要是明文。

五、让一条规则压缩后还在

前面几节说明，压缩后一定还在的有两类：Codex 每次重新生成、插回去的条目（AGENTS.md 和环境信息等），以及最近的原话。所以办法按稳的程度排：

  1. 写进 AGENTS.md。比如在项目根目录的 AGENTS.md 写一行「不要改数据库 schema」。每次压缩后它都重新插回去，不靠摘要（实验里那条 752 字节）。插回去的是 Codex 手里那份，压缩时不重读磁盘：项目 AGENTS.md 一个会话只读一次（第 2 章），用 resume 新起进程时才重读（第 8 章）；会话中途改了文件，压缩后插回的仍是旧版本【读了源码，没做实验】。17
  2. 快压缩时再说一遍。最近的原话优先保留。反过来，贴日志、贴代码会占满 2 万的预算，把更早的短要求挤出去，实验里第 1 轮的规则就是这样没的。第 12 章量过：规则只写在第 1 句话里，后面贴的日志超过约 8 万字节（2 万 token），压缩后规则就不在请求里了。
  3. 用钩子在压缩后补一段。钩子写在 ~/.codex/ 或项目 .codex/ 目录下的 hooks.json 里。配一个 SessionStart 钩子，匹配来源 compact，它的输出会在压缩后加进上下文。PreCompact、PostCompact 两个钩子只能叫停压缩，改不了摘要【读了源码，没做实验】。18
  4. 本地压缩可以换提示词。在 config.toml 里写 compact_prompt = "……"，或写 experimental_compact_prompt_file = "文件路径"，换掉第二节说的那 9 行提示词，比如要求「原样抄下用户给过的所有规则」。走官方通道时无效（第四节）。19

对照：Claude Code 重新读文件

据官方文档（2026-11-02 查阅），Claude Code 压缩也是写摘要，文档只说保留「你的请求和关键代码片段」，没说保留原话。差别在压缩后补回什么：20

  • 从磁盘重读：项目根目录的 CLAUDE.md、不带 paths: 的规则、自动记忆、计划模式写的计划。带 paths: 的规则和子目录里的 CLAUDE.md，要等 Claude 再碰到相关文件才重新加载。
  • 重读最近的文件：本会话读过或改过的文件，按最近修改挑最多 5 个重新读进来；超过 5,000 token 的只给路径。
  • 用过的技能：正文放回，每个最多 5,000 token、合计 25,000。
  • 你能指定摘要的重点：在输入框里打 /compact focus on the auth bug fix；或在 CLAUDE.md 里写一节「Compact Instructions」。
  • 什么时候压缩：不设置时，窗口本身就是 100 万的模型约在 96.7 万 token 压缩，其他多数情况到窗口上限才压缩；输入框里打 /autocompact 500k 可以提前。21

简单说：Codex 保留你的原话、插回 AGENTS.md，但不重读你的代码文件；Claude Code 不承诺保留原话，但会把最近的文件和规则文件重新读回来。

回答问题 5

想让一条规则压缩后一定还在，写在哪里最稳？Claude Code 呢？

Codex 里写进 AGENTS.md 最稳：每次压缩后都插回去，不靠摘要。其次是快压缩时再说一遍，或配一个匹配 compact 的 SessionStart 钩子。Claude Code 里写进项目根目录的 CLAUDE.md，压缩后从磁盘重读；带 paths: 的规则不会马上回来。

设计笔记

  • 为什么只保留你的原话。你的要求换个说法，意思可能就变了，而且没处再找；文件和命令输出，模型需要时可以重读、重跑。代价是压缩后模型手里没有精确的代码和输出，得重新读。代码里没写理由【推测】。
  • 为什么截短最后一条，不跳过它去找更早的短消息。跳过会让保留的原话不连续：你先说 A、再说 B、最后说 C，跳过 B 就只剩 A 和 C。代价是那条可能正好在要紧处截断【推测】。
  • 本地 2 万、远端 6.4 万。本地压缩完，还要把系统提示词、AGENTS.md 等插回同一份历史；原话留太多，压缩完又贴着压缩线，可能一轮接一轮地压缩【推测】。远端为什么敢留 6.4 万，源码看不出来。
  • 加密摘要的取舍。摘要由服务器生成、只有服务器能读，里面可能带着文字表达不了的模型内部状态；代价是你没法检查它漏了什么【推测】。
  • 别的做法。据别的 agent 的资料，有的 agent 保留的是「最近一段连续的历史」，连工具输出一起保留，切的位置要避开把工具调用和它的输出拆开。本机没有那些 agent 的源码，没核对【待核实】。

小结

  1. 用量到窗口的 90% 自动压缩（官方通道登录时，gpt-6.1-sol 是 45 万 token）；Codex 在一轮开始前和一轮中间比较；压缩线可以在配置里调低，一轮结束后压缩要另外打开，手动压缩打 /compact。
  2. 压缩后，较早的原话、命令的调用和输出、模型的回复都不在请求里了，只剩摘要里的转述；AGENTS.md 和环境信息重新插回；原文只留在本机存档里。
  3. 本地压缩只保留你亲手发的消息，从最新往前最多约 2 万 token，装不下的那条截短后停下；贴一大段日志，会把更早的话挤掉。
  4. 官方通道走远端压缩：摘要加密、你看不到，原话保留 6.4 万 token，工具输出同样不保留。
  5. 要一条规则压缩后还在，Codex 里写进 AGENTS.md 最稳；Claude Code 里写进项目根目录的 CLAUDE.md，压缩后会重读。
