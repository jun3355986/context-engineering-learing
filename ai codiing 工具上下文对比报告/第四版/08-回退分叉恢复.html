回退以后，模型还能看到什么？分叉和恢复又从哪里接着聊？

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 模型 gpt-6.1-sol，思考级别 low · 对照 Claude Code 官方文档（2026-11-02 查阅）

实验里，我和 Codex 聊了三轮，随后回到第二轮开始之前，换了一句话。模型收到的请求里，前面聊过的只剩第一轮。但打开磁盘上的旧会话文件，三轮对话都还在。如果第二轮里 Codex 还改过一个项目文件，回退后打开它，也仍能看到那次改动。

这里有三样东西。会话记录是 Codex 存在你电脑上的聊天存档。每当你发来新消息，Codex 从存档中选出这次要接着聊的部分，连同新消息一起发给模型，这就是下一次请求。至于你让 Codex 编辑的代码或 SQL，它们是项目文件，保存在你的工作目录里。回退以后，分别去这三个地方看，会得到三个不同的答案。

这一章要回答的五个问题

  1. 回退到第 2 句之前，再发一句新话，模型还能看到哪几轮对话？答案 ↓

一、回退以后，下一句话接在第一轮后面

你发一句话，Codex 答完，算一轮。假如已经聊了三轮，你想换掉第二句，可以在 Codex 终端的输入框为空时连按两下 Esc，用左右方向键选中自己发过的第二句，再按回车。那句话会回到输入框里。你可以重新措辞，再把它发出去。这里选的是从哪句话开始重说，所以保留到第一轮的回复为止。5

为了看清 Codex 究竟发了什么，实验用脚本让 Codex 执行同样的回退，再发一句新话。本机有个程序代替模型接收请求，把收到的内容记下来，再按剧本回复。因此下面可以直接对照存档和请求。终端按键的说明来自源码，实验实际操作的是后台接口。

同一次回退，打开两处看

先看请求。回退后发出的第一份请求里，和这段对话有关的内容依次是「我的第一句 → 第一轮的回复 → 我刚发的新话」。前面还有六条工具和运行环境等说明。这样数下来一共九条。第二轮和第三轮的原话、回复都没有发过来，也没有一条摘要告诉模型「刚才试过另一条路」。320

再看存档。聊完三轮时，旧文件一共有 36 行。刚回退完，旧文件一个字节都没改，旁边却多了一个只有 2 行的新文件。第一轮的一问一答去了哪里？还在旧文件里。新文件记下了从哪里读和读到哪里，用白话说就是「先读旧文件的前 18 行，到第一轮结束为止，以后的对话接着写在我这里」。存档里也会写入设置和运行时的事件。这次实验里，前 18 行恰好记到第一轮结束。2

Codex 给每个会话一个编号，内部叫「线程编号」。它另外记着每个编号当前对应哪个会话文件。回退时，Codex 把这个编号对应的文件换成刚建的那份。等你再发消息，你仍在原来的会话里，新消息和回复会记进新文件。旧文件里虽然还有后两轮，Codex 读取旧文件时已经知道该停在哪里。1

二、回退了改文件的那句话，打开文件会看到什么？

沿用刚才的三轮对话，只加一个条件。假设第二轮你让 Codex 改了项目里的 schema.sql，它已经把修改写进文件。现在回退到第二句之前。Codex 会按第一节的办法改用新的聊天存档，而这次回退操作只处理存档。你这时打开 schema.sql，看到的仍是改过的版本。这个例子用来说明源码里规定的行为，前面的对话实验没有实际改 SQL 文件。7

假如你问「这段 SQL 为什么这样写」，模型从随请求送来的对话里找不到你当时的要求，也找不到它自己修改文件的经过。如果接下来让它读 schema.sql，它能看到现在的写法。文件告诉它代码现在是什么样，先前为什么这么改，却可能需要你重新交代。

所以，如果你想从改动前的代码重新试，在回退对话之外，还要检查工作目录。在 Git 仓库里，例如可以先用 git diff -- schema.sql 看工作区里尚未暂存的差异，再决定要还原哪一处。尤其是同一个文件里还有你自己写的内容时，只想撤销第二轮，并不等于想撤销整份文件的修改。

Claude Code 可以把对话和代码分开回退

按 Claude Code 官方文档，在输入框里打 /rewind，选定你先前的一句话，可以只回退对话、只还原代码，或两者一起做。这里的「还原代码」有范围。以同一个 SQL 文件为例，如果 Claude 用文件编辑工具改过它，就有相应的文件检查点可供还原。如果它从头到尾只通过 shell 命令改这个文件，检查点就不追踪这个文件。下面按这条文档规则对照，未运行 Claude Code 实测。8

三、分叉以后，两段对话可以分别继续

回到最初聊完三轮的那个时刻。刚才你决定放弃后两轮，所以用了回退。现在换一个目的：原来的做法还想留着，又想沿另一种思路聊下去。在终端会话的输入框里输入 /fork，Codex 会另开一个会话，带上分叉时已有的对话。你在新会话里接着问，稍后也可以回到原会话，沿原来的思路继续。这里的「分叉」说的就是把一段对话分成两条可以各自继续的对话。

为了看出两条对话从哪里分开，实验特意选了更早的分叉点。终端的 /fork 从当前末尾分叉。实验用后台接口指定「带到第二轮结束为止」。于是，同一段三轮对话有了下面两种读法。10

打开哪个会话分叉后各自的对话
原会话第一轮 → 第二轮 → 第三轮
新会话第一轮 → 第二轮 → 你在这里另发的新话

还记得回退时那个只有两行的新文件吗？分叉时 Codex 也建了这样一份文件。这次它指向旧文件里前两轮的内容。区别在于，Codex 给这份新文件分配了另一个会话编号。原来的编号继续指向三轮都在的旧存档，所以两段对话才可以分别打开。一份聊天存档只记录对话；如果两个会话在同一工作目录里改代码，它们读写的仍是同一批项目文件。

分叉时会另外建工作目录吗？

原文所查的源码里有选择当前工作目录或新建一份检出的界面，但本机 CLI 的功能列表与源码标注不同。0.165.0 实际是否弹出这个选择【待核实】。9

两段对话能共用请求缓存吗？

请求缓存是服务端对相同请求开头的复用。实验能看到，在新会话里发的第一份请求，前十条与原会话发第三句时逐字相同，但标识缓存分组的 prompt_cache_key 已换成新会话的编号。本地实验没有真实服务的用量数据，能否命中原来的缓存【待核实】。11

Claude Code 如何另开一条对话

按官方文档，在当前会话里输入 /branch 可以复制出一个会话，接下来的话写进新会话。要回到原来那条对话，可以用 /resume 选回来。两种工具都能留住原来的路线，前面实验中 Codex 的新存档靠引用旧记录接上历史。12

回答问题 3

想试另一种做法，同时保留原来的对话，该怎么分叉？

在当前对话里输入 /fork，沿新会话尝试另一种做法。原会话也可以从原来的位置继续。

四、压缩过的回复，还能通过回退找回来吗？

前面三轮说过的话都还以原来的样子发给模型。现在做一组单独的实验，在第三轮答完后通过后台接口发起一次压缩（终端里的命令是 /compact）。Codex 让模型把较早的对话整理成摘要。在这次实验里，压缩后的请求仍带着我发的前三句话，三条对应的回复则由摘要代替。随后我又说了第四句和第五句。13

把顺序写在一行就容易看出区别了：前三轮对话 → 压缩 → 第四轮 → 第五轮。压缩时，Codex 在存档里追加了一条记录，写下接下来该使用的摘要和保留的消息。原先那三条完整回复仍在更早的记录里。回退后会不会重新发出它们，取决于 Codex 会读到这行记录的前面，还是它的后面。15

  • 先回到第五句之前。此时第四轮刚结束，压缩早已发生。在这里另发一句，模型收到的是压缩后的历史，包括摘要和第四轮对话。
  • 再往前，回到压缩开始之前。此时第三轮刚结束，存档中保留下来的那一段到第三轮为止。再发一句，模型收到前三轮完整的一问一答，三条回复都以原文出现。

第二步是怎么选中的？后台把手动压缩也记成单独的一轮，脚本可以按这轮的编号指定「回到它之前」。终端里按两下 Esc 显示的是你发过的话；这次压缩是单独的后台操作，本身没有一条用户消息供你在那个菜单里选。14

回答问题 4

对话已经压缩成摘要，回退到哪里才能再看到压缩前的回复？

回到压缩发生之前，Codex 会再次读取压缩前的完整回复。只回到压缩之后的某句话之前，请求仍然沿用摘要。

五、关掉后再恢复，旧对话和新项目规则怎么接起来？

现在接回第一节那段对话：原先说了三句，回退到第二句之前，又换了一句新话。至此，当前会话只有第一轮和刚换的那一轮。关掉 Codex 后，你可以在终端里运行 codex resume，从列表选中它继续聊。如果就是要接最近的会话，也可以用 codex resume --last。

为什么恢复时没有把撤回的两轮也读回来？因为 Codex 按会话编号找到的是上次离开时正在使用的那份存档。这份存档让它先读旧文件里的第一轮，然后读回退后新写的一轮。若这段有效历史中还有压缩记录，它就用最近一次压缩留下的历史作起点，再接上后来聊的内容。这样接起来的，才是你上次离开时的对话。1516

恢复前改了 AGENTS.md 会怎样

AGENTS.md 是项目里写给 Codex 的工作说明。实验又多做了一步：在关掉 Codex 之后、重新启动之前，把文件里用来辨认旧规则的文字 OLD-RULE 换成 NEW-RULE。这样，只看恢复后的第一份请求，就能认出模型收到的是哪个版本。

结果是两个版本都出现在这份请求里，而且顺序有意义。先是旧规则，跟在原来的工具和环境说明中。再往后是留下来的两轮对话。到了我刚发的新问题前面，Codex 另加了一条说明，明确告诉模型「以下项目指令替换此前提供的所有项目指令」，随后给出新版全文。读到新问题时，模型就收到了该用哪份规则的明确指示。16

Codex 怎么发现文件改了？它在存档里记下了上次发给模型的规则。新启动的进程重新读取当前文件，把两份文字作比较。内容相同就沿用原来的说明，有变化才追加替换说明。源码还处理了文件已删除的情况，会追加一句「之前的项目指令不再适用」；删除文件这一种只读了源码。17

Claude Code 从哪里接着聊

按官方文档，在终端运行 claude --continue 会接当前目录最近的会话，claude --resume 可以从列表里选。压缩过的对话从最近一次摘要接起。再次启动时，它也重新读取设置文件；若上次通过命令行额外指定了配置文件或目录，这次要再传相应参数。19

回答问题 5

关掉 Codex，改了项目规则再恢复会话，下一次请求里会出现什么？

请求会带上次离开时有效的对话。如果关掉 Codex 后改过项目规则，旧规则仍位于历史中，新问题前面会出现一条明确替换它的新版说明。

设计笔记

回退和分叉都能保留旧记录，又不用把相同的对话复制一遍，靠的是新文件能指回旧文件的某个位置。这也解释了为什么光看新文件里的行数，会低估这段会话实际有多长。单独拷走新文件，能否在缺少旧文件时恢复完整历史，本章没有做迁移实验【待核实】。

这种设计也留下了一个实际问题。假如撤回的几轮里恰好有一条你还需要的结论，例如某个方案已经试过、会失败，回退不会替你把这个教训单独摘要出来。你可以在新消息里写明失败的原因。如果你想留着整个尝试过程以便再看，分叉给了你一条可以重新打开的对话。20

小结

你做的事接下来会看到什么
回退到第二句之前新话接在第一轮回复后面。旧存档里仍可查到其余两轮。
回退改 SQL 的那一轮聊天历史里少了修改经过，项目里的 SQL 仍是改过的版本。
从当前会话分叉多出一个可以单独继续的会话，你也能回到原来的对话。
压缩后再回退回到压缩之前可再见完整回复，停在压缩之后则继续用摘要。
改了项目规则后恢复会话对话从离开时的位置接起，下一份请求会在新问题前说明新规则取代旧规则。
