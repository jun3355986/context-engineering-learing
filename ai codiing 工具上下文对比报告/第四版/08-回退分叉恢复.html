第 8 章

回退、分叉、恢复都不删磁盘上的记录，也都不动你的文件：被撤销的只是下一次请求里的历史

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 模型 gpt-6.1-sol，思考级别 low · 对照 Claude Code 官方文档（2026-11-02 查阅）

实验里在 Codex 中说了 3 句话，再回退到第 2 句之前：磁盘上原来的会话文件仍是 36 行、99,888 字节，一个字节没变；下一次请求的历史里只有第 1 句和它的回复（请求共 9 条，含固定开头），第 2、3 句不再出现。回退、分叉、恢复改的都是「下一次请求里装什么」，不删旧记录，也不碰你磁盘上的文件。

会话文件（Codex 叫 rollout）：每个会话在 ~/.codex/sessions/年/月/日/ 下有一个 .jsonl 文件，一行一条记录。线程（thread）：会话的编号，就是文件名里那串 UUID。轮（turn）：你发一句话到 Codex 答完。本章实验在 自学单元/U07-实验/：假 Responses 服务器当模型，用 codex app-server（标准输入输出上的 JSON-RPC）直接发下表的底层请求，TUI 里的按键最终调用的就是它们（源码位置见第一、三节），我没有在真实终端里按过键盘。模型的回答是剧本写死的，所以本章只回答「请求里有什么、磁盘上写了什么」。

操作在哪里用底层请求
回退输入框为空时按 Esc 两下，← → 选一句你说过的话，回车；那句话回到输入框thread/revert
分叉输入框里打 /fork（后面可跟名字），或命令行 codex fork --lastthread/fork
恢复命令行 codex resume（--last 接最近一个；不带参数出选择器，--all 列全部目录的会话），或会话里打 /resumethread/resume
压缩（第 4 章）输入框里打 /compactthread/compact/start

一、回退：旧文件一个字节不动，另存一份新文件接着写

最朴素的做法是把被撤回的那几行从会话文件里删掉。删了就找不回来，也没法事后查「它当时到底看到了什么」。Codex 不删：它另建一个新文件，让新文件引用旧文件里保留的那一段开头，再把「这个线程现在用哪个文件」的指针改过去。1

实验：3 句话，回退到第 2 句之前

先说 3 句话（每句假服务器回一句），再发 thread/revert，beforeTurnId 填第 2 轮的编号；然后在同一个线程上再说一句。每一步之后列出 sessions/ 下的文件：

说完 3 句36 行 / 99,888 字节—
回退之后36 行 / 99,888 字节（逐字未变）2 行 / 23,480 字节
再说一句之后36 行 / 99,888 字节11 行 / 28,787 字节

新文件的第一行 session_meta 里多了一项 history_base：end_ordinal_exclusive 是 18，end_byte_offset 是 89,403。意思是「前缀 = 旧文件的前 18 行」，正好是第 1 句说完时旧文件的长度（之后每句约 9 行、5.2 KB）。新文件的行号从 18 接着数，所以只有 2 行就能代表整个历史。文件名多一段 _新文件编号；线程编号和 prompt_cache_key 都没变。2

回退后第一次请求有 9 条：固定开头 6 条（工具定义、系统提示词、技能目录、两条子代理说明、AGENTS.md 加环境信息，共 54,707 字节）、第 1 句、它的回复、你新说的话。它和回退前最后一次请求（11 条）的前 8 条逐字相同，按第 5 章的规则这 8 条能接上缓存，之后重写（规则推，没用真实服务验证）。3

TUI 里能选的是你发过的消息，不能回到某次工具调用的中间。输入框是空的时 Esc 才触发：第一下预备，第二下打开记录，从最近一句往前选；回车后 TUI 请求 thread/revert，把那句话放回输入框，同一个线程继续。5

回退只对分页格式的会话有效：本机 0.165.0 新建的会话在 session_meta 里都写着 history_mode: paginated；临时会话（不落盘）和旧格式会话会被拒绝。另有一种旧写法：追加一条 ThreadRolledBack 标记，意思是「丢掉最近 N 轮」，恢复时从后往前扫描跳过。0.165.0 还认这条标记，但我没有找到写入它的代码（搜索，未穷尽）。6

回答问题 1

你在 Codex 里说了 3 句话，按 Esc 两下回到第 2 句之前。磁盘上的会话文件删了哪些行？下一次请求里，模型还看得到第 2、3 句吗？

一行都没删：旧文件仍是 36 行、99,888 字节。Codex 另建一个新文件，用 history_base 引用旧文件的前 18 行（第 1 句说完时的位置），线程编号不变，指针换成新文件。下一次请求 9 条，只有第 1 句和它的回复，第 2、3 句不在里面，模型不知道发生过。

二、回退不管你的文件：对话回到过去，磁盘还在现在

最朴素的做法是回退时顺手把文件也恢复。这要每一轮之前都存快照，而且 shell 命令改的文件很难全部追踪。Codex 没这样做：thread/revert 的协议注释写的是「只改持久化的对话历史，不还原本地文件改动」，实现里只动 thread-store，没有碰工作目录；曾经的 ghost_snapshot（文件快照）配置在源码 76ed3b4 里只留作兼容，注释写明「快照不再产生」。7

后果是对话和磁盘分开：模型的历史里没有第 2 轮，第 2 轮改的文件还在，下一轮它会按「没改过」去读和改。兜底靠 git。

动手看：对话和磁盘还一致吗

设定：第 2 轮 agent 改了 schema.sql，现在回退到第 2 轮之前。Codex 的结果来自源码和协议注释，Claude Code 的来自官方文档，都按规则画，未实验（上面的实验没有执行命令）。8

对照：Claude Code 的 /rewind 把「代码」和「对话」拆成两个选项

/rewind 或输入框为空时按 Esc 两下，菜单里列出你发过的每句话（每句一个检查点，文件快照只保留最近 100 个）。选一句之后有四种动作：代码和对话都回退、只回退对话、只回退代码、把这里往后（或到这里为止）压缩成摘要。官方文档列出的限制：只追踪 Claude 用文件编辑工具做的改动，只被 shell 命令改过的文件要靠 git；子代理的改动一般不恢复；你在 Claude Code 之外手动改的文件不追踪。文档还写明，检查点不是版本控制的替代品。8

回答问题 2

被撤回的那几轮里，agent 改过你磁盘上的文件。回退之后，这些文件会恢复吗？Claude Code 一样吗？

Codex 不会：回退只换对话历史，工作目录不动，也没有文件快照可还原，需要时用 git。Claude Code 不一样：/rewind 可以单独或同时还原代码，但只还原它用编辑工具改过的文件（以及这些文件之后被 shell 命令做的改动）；只被 shell 命令改过的文件不还原。

最朴素的做法是把整个会话文件复制一份。Codex 分叉也建新文件，但不复制历史，只引用。实验：3 轮之后以第 2 轮为终点分叉（lastTurnId 填第 2 轮），再在分叉线程上说一句：10

对照：Claude Code 的 /branch

在会话里打 /branch 名字（不写名字就用第一句话命名），或命令行 claude --continue --fork-session。它复制当前转录文件并让正在运行的进程切过去写新文件，原会话留在磁盘上，用 /resume 回去。「本会话允许」这类授权在 /branch 里带过去，--fork-session 开新进程则要重新批准。文档在讲压缩摘要的地方写明：想保留原会话、换条路试，用 /branch 或 --fork-session。12

回答问题 3

输入 /fork 和回退有什么不同？分叉之后原会话变不变？新会话的第一次请求和原会话能共用缓存吗？

回退保持线程编号、把原历史换成保留的前缀；分叉生成新线程，原线程的文件和历史一字不变，两条线各自继续。分叉后第一次请求的前 10 条和原线程逐字相同，但 prompt_cache_key 换成新线程编号，能不能接上原线程的缓存没有证据【待核实】。

四、压缩也能被回退撤销：回到压缩之前，摘要就没了

最朴素的做法是把压缩当成不可逆：旧历史换成摘要，原话丢掉。第 4 章讲过，Codex 的存档不删旧记录，压缩只是追加一条带「替换后历史」的 compacted 记录。回退到压缩之前，新文件引用的前缀里没有这条记录，压缩就不存在了。13

实验：说 3 句 → 手动压缩（thread/compact/start；假服务器回一句摘要）→ 再说第 4、5 句 → 回退到第 5 句之前，说第 6 句 → 再回退到压缩那一轮之前，说第 7 句。压缩本身也是一轮：thread/turns/list 列出 4 个轮，最后一个没有用户消息，事件条目类型是 contextCompaction。14

动手看：回退到压缩之前还是之后

三个读数是实验里的第 6、7、8 次请求，条目和字节来自 out/compact。

请求：
固定开头你的话回复压缩摘要

第 7 次请求里摘要和第 4 句都还在，因为回退点（第 5 句）在压缩之后。第 8 次请求里摘要不见了，第 1、2、3 句的原话和回复一条不少，顺序回到压缩前，前 11 条和压缩前那次请求（第 3 次）逐字相同，AGENTS.md 也回到开头（压缩后它被挪到第 2 句和第 3 句之间）。13

这是恢复用的同一套重建规则：从后往前找最新一条带「替换后历史」的压缩记录当起点，只回放它后面的记录；没有压缩记录就从头回放。回退后新文件引用的前缀在压缩之前结束，重建时看不到这条记录。15

回答问题 4

会话已经压缩过一次，之后再回退：压缩会被撤销吗？这取决于回退到哪里？

取决于回退点。回退到压缩之后的某句话之前，压缩还在（实验第 7 次请求仍有摘要）；回退到压缩之前，压缩被撤销，原话和回复逐字回来（第 8 次请求前 11 条与压缩前相同）。因为压缩只是日志里的一条记录，回退时它在不在保留的前缀里，就决定它生不生效。

五、恢复：存档里最后的状态，加上你现在的 AGENTS.md

最朴素的做法是把存档从头重放一遍。这会重拼压缩过的历史，也可能让被回退的轮次回来。Codex 的重建规则：先找这个线程当前用的文件（回退过的就是新文件，连同它引用的旧文件前缀），从后往前找最新的压缩记录当起点，回放起点之后的记录，旧格式的「丢掉最近 N 轮」标记也在这一步生效。此外，它把存档里记下的「上次给模型看过的环境状态」（含 AGENTS.md 全文）取出来当基线。15

实验：回退之后，改了 AGENTS.md，再恢复

接第一节的实验：回退到第 2 句之前、说完第 4 句后，关掉进程；把 AGENTS.md 从 OLD-RULE… 改成 NEW-RULE…；起新进程，thread/resume 同一个线程，再说一句。请求有 12 条：16

  • 被回退的第 2、3 句没有回来，历史是：固定开头、第 1 句、回复、第 4 句、回复。
  • 原来那条 AGENTS.md（763 字节，含 OLD-RULE）还在第 6 位，一字未改。
  • 在你新说的话前面追加了一条 380 字节的用户消息：「These AGENTS.md instructions replace all previously provided AGENTS.md instructions.」加新的全文（含 NEW-RULE）；存档里也追加了一行 world_state，full 为 false，只记新文本。

规则在源码里：把现在读到的 AGENTS.md 和存档里的基线比，一样就什么都不加，不一样就追加一条带「替换」前缀的新全文，文件被删了就追加「之前的 AGENTS.md 不再适用」（这一条只读了源码，没做实验）。第 2 章说项目 AGENTS.md 中途改了要新开会话才生效，其实新进程接着旧线程（恢复）也会重新读。旧条目不动，所以缓存前缀不被破坏，代价是旧规则和新规则会在这个线程的历史里同时存在，直到下一次压缩重新生成初始上下文（第 4 章）才只剩新的。17

隔天恢复，缓存早过期（第 5 章：存 30 分钟），第一次请求整份按写入价算（规则推，未验证）。18

对照：Claude Code 的 resume

claude --continue 接当前目录最近的会话，claude --resume 开选择器，/resume 在会话里切换。恢复的有对话历史（压缩过的从最后一次压缩的摘要接上，被摘要的消息不再加载）、模型、权限模式（有例外）等。settings.json 这类设置文件每次启动重新读，但 --mcp-config、--settings、--add-dir 这类启动参数要重新传。隔了很久恢复，会弹出「Resume this conversation?」，估算这段对话会用掉 5 小时用量上限的多少。19

回答问题 5

关掉 Codex，过一天用 codex resume 接着聊。模型拿到的是什么？这期间你改过 AGENTS.md，它知道吗？

拿到存档里这个线程当前的历史：回退过就是回退后的，被撤回的轮次不会回来；压缩过就从最新那条压缩记录接着。AGENTS.md 它会重新读并和存档里的基线比，不一样就在你新说的话前面追加一条「替换」消息，旧条目原样保留（实验：380 字节的新消息，旧的 763 字节不动）。

设计笔记

  • 撤销一个只追加的日志，Codex 选了「新文件加指针」。旧文件不可变，回退可审计、可重来，分叉和回退都不用复制历史。代价：多一个文件；换指针靠 SQLite（没有 SQLite 时 revert_thread 直接返回不支持）；换的时候「旧值没变才换」，防两处同时改。
  • 新文件不自足。回退和分叉的新文件只有 2 行，历史在旧文件里。只拷走新文件、或用 codex delete 删掉旧会话后还能不能读，我没试过【推测：读不全，待核实】。
  • 不还原文件是个取舍。文件改动留给沙箱、审批和 git，对话层只管对话；源码没写理由【推测：快照在大仓库里太贵，或和用户自己的 git 操作冲突】。代价就是第二节的「对话和磁盘分开」。
  • 回退和分叉都不给被放弃的路径写摘要。历史干净，代价是你得自己告诉它「上次试过 X，不行」；或者先分叉再回退，把旧路径留在分叉线程里。
  • 其他 agent（第三版源码解读的说法，本机没有源码，没核对）。Grok Build 往日志追加回退标记，读取时按标记截断，shell 里可选「全部 / 只文件 / 只对话」；pi 和 oh-my-pi 在同一个文件里换叶子，离开分支时可以生成摘要。三种办法：追加标记、新文件加指针、同文件换叶子。21
  • 没做的实验。真实终端里的按键；回退时 agent 正在运行；有工具调用的轮次；改文件后回退；真实服务上的缓存命中。

小结

  1. 回退一行都不删：旧文件仍是 36 行、99,888 字节，另建新文件引用前 18 行，线程编号不变；下一次请求只剩第 1 句和它的回复，模型不知道有过被撤回的轮次。
  2. 回退不还原你的文件，也没有快照可还原，用 git 兜底；Claude Code 的 /rewind 能单独或一起还原代码，但只还原编辑工具改过的文件。
  3. 分叉是新线程，原线程文件一字不变；分叉后第一次请求的前 10 条与原线程逐字相同，但缓存键换成新线程编号，能否接上缓存【待核实】。
  4. 压缩只是日志里的一条记录：回退到压缩之后它还在，回退到压缩之前它被撤销，原话逐字回来。
  5. 恢复拿到存档里当前的历史（回退过、压缩过的都按最新状态），并把现在的 AGENTS.md 与存档基线比，不同就追加一条替换消息，旧条目不动。
