新开一个会话，它怎么还记得你？后台提炼旧会话，再下一个会话才生效

2026-11-02 · Codex 源码 76ed3b4 / CLI 0.165.0 · 对话模型 gpt-6.1-sol，思考级别 low · 记忆后台模型 gpt-5.6-luna（low）与 gpt-5.6-terra（medium）· 对照 Claude Code 官方文档（2026-11-02 查阅）

每次新开会话，发给模型的对话历史都是空白的。打开 Codex 的记忆功能（memories）后，新会话的第一次请求里会多塞一份从旧会话提炼出来的文字摘要。不过这份摘要不是当场写的：当你在一个会话里发出消息时，后台会调另外两个模型去提炼更早的旧会话。这意味着你昨天在会话里交代的事，要等今天你在某个会话里开口时才开始提炼，提炼出的摘要要到再下一个新会话才读得到。

这里说的记忆专指 Codex 的 memories 功能，默认关闭。打开后，你可以使用下面几项操作来开关、查看或清空它：

你想做的事怎么操作
打开记忆（默认关闭）在终端运行 codex features enable memories，会在 ~/.codex/config.toml 的 [features] 下写入 memories = true，对之后新开的会话生效1
分开控制「读」和「写」在终端会话输入框里打 /memories，切换 Use memories（新会话是否读取）和 Generate memories（是否从会话提炼）；或在 config.toml 的 [memories] 下配置 use_memories、generate_memories2

一、让新会话知道旧规则的三条路

新会话从空白历史起步（第 2 章），想把昨天交代过的事带进来，一共有三条路。它们的核心区别在于由谁来写、什么时候读取：

办法由谁写入什么时候读取在哪里配置或触发对应章节
规则文件你自己写每个新会话开头读一次；恢复旧会话时与存档比对，有改动则追加新版全文项目里的 AGENTS.md、全局的 ~/.codex/AGENTS.md第 2、8 章
恢复旧会话不改写，原样接上旧历史你主动恢复会话的那一刻命令行 codex resume，或会话内输入 /resume第 8 章
跨会话记忆后台模型提炼每个新会话开头读一次默认关闭，运行 codex features enable memories 开启本章

前两条路里，带什么内容完全由你决定；而第三条路交给后台模型去挑重点、写摘要，因此引出了三个新问题：后台什么时候写（第二节）、摘要怎么塞进请求（第三节）、写错了或者过期了怎么办（第四节）。

回答问题 1

昨天在会话里说过「测试用 pnpm」，今天新开一个会话，有哪几条路能让模型继续知道这条规则？

共三条路：写进 AGENTS.md 让每个新会话固定读取、用 codex resume 原样接着昨天的会话聊，或者打开记忆功能让后台把昨天的对话提炼成摘要。如果只是口头在旧会话里提过、今天又另开新会话，就只能靠第三条路。

二、写入：发消息时后台异步跑两步，晚一个会话才生效

记忆不是在关闭会话时保存的，而是在你发出一轮消息时顺带启动的后台任务。只要同时满足四个条件，后台任务就会启动：已打开 memories 功能、当前是你直接开启的主会话（不是第 7 章的子代理）、不是退出即销毁的临时会话（codex exec --ephemeral），并且这一轮确实有输入内容。后台任务异步运行，不阻塞当前对话，也不写进当前会话的历史。3

先挑出合格的旧会话

后台任务处理的不是你正在聊的这个会话，而是更早之前的旧会话。一个旧会话必须同时满足下面四条规则才会被选中；符合条件的按最近活动时间从新到旧排序，每次启动最多取 2 个：4

  • 交互式来源。Codex 会记录每个会话是从哪里启动的，只挑选来自 cli（终端界面）、vscode、atlas、chatgpt 的会话。用命令行批处理 codex exec 跑出来的会话来源记为 exec，不会被提炼。5
  • 开启了记忆生成。该旧会话创建时没有关闭 generate_memories（数据库里该会话的 memory_mode 为 enabled）。
  • 最近 10 天内活跃过。距离最后一次活动不超过 10 天（配置项 max_rollout_age_days，范围 0–90 天）。
  • 已空闲至少 6 小时。最后一次活动距今已满 6 小时（配置项 min_rollout_idle_hours，范围 1–48 小时），防止把还在聊的会话半途抓去提炼。

第一步「提炼」：把单个旧会话压成一段摘要

第一阶段针对每个入选的旧会话单独发一次请求，让模型把它写成一段单会话摘要。默认使用 gpt-5.6-luna（思考级别 low，可通过 extract_model 更换），最多并发处理 8 个旧会话。实验里提炼一轮简短对话的请求共 7,367 字节，包含写摘要的指令（3,355 字节）和渲染成纯文本的旧会话记录（2,843 字节），要求模型按 JSON 格式返回单会话摘要（rollout_summary）和用于文件名的英文短名（rollout_slug）。6

如果旧会话很长，Codex 只读取会话文件末尾的 8 MiB，再按优先级装填到提炼模型上下文窗口的 70%：你说的话最优先保留，其次是模型的最终回答，工具输出排在最后（每条工具输出最多留 2,000 token）。生成的摘要会先经过一次敏感信息脱敏（遮盖密钥等字符串），并截断在 9,000 字节以内，存进记忆目录的 rollout_summaries/ 下。7

第二步「合并」：后台智能体改写总摘要文件

第二阶段启动一个受限的后台智能体，读取新增的单会话摘要，改写全局的 memory_summary.md。这个智能体默认使用 gpt-5.6-terra（思考级别 medium），自己能调用读写文件的工具，但沙箱权限被严格锁死：只允许写记忆目录、禁止联网、不弹确认框，同时关闭子代理、MCP 和记忆读取本身。8

为了避免无意义的重复调用，Codex 在记忆目录里用 Git 记录上次合并后的状态。只有当目录内容发生变化、或者上次生成的摘要文件不合格时，才会真正启动合并智能体；合并成功后进入 6 小时冷却期，失败则在 1 小时后重试。合并智能体一启动，首轮请求就有 50,466 字节（其中合并指令占 4,349 字节，其余是工具定义和系统提示词）。写完后，代码会校验生成的 memory_summary.md：第一行必须是 v1、总长度不超过 10,000 字节，且必须包含 ## User Profile、## User preferences、## General Tips、## What's in Memory 四个二级标题，否则算作合并失败。89

时间线：为什么新记忆要等到「再下一个会话」

把读取和写入的时机放在同一条时间线上，就能看清为什么昨天说的话今天立刻开新会话还用不上：新会话的摘要是在会话刚启动时读取的（第三节），而后台提炼任务是在你发出第一句话时才触发的。11

按时间顺序开启的会话会话开头读到的记忆摘要你发出第一句话后，后台发生的事
会话 A（例如周一，你说「测试用 pnpm」）更早之前的旧摘要去提炼比会话 A 更早的旧会话
会话 B（例如周二，此时 A 已空闲超过 6 小时）仍是更早的旧摘要，还不包含 A选中会话 A，完成提炼并改写 memory_summary.md
会话 C（在 B 完成合并之后新开）读到包含 A 的新摘要继续检查有没有其他满足空闲条件的旧会话

实验验证了这一过程：在配置里把最小空闲时间设为 1 小时，先开会话 A 说一句话，再把数据库中会话 A 的更新时间往前拨 2 小时模拟空闲达标，随后开启会话 B。抓包显示，会话 B 的第一次请求里只带着预置的旧摘要；而提炼会话 A 和合并新摘要的请求，是在会话 B 发出第一句话的同时由后台发出的。要到之后再开的会话 C，才能读到会话 A 留下的规则。11

展开了解：记忆管线的 v1 与 v2 两个版本有什么区别？

Codex 代码里有 v1 和 v2 两套记忆管线（可在 [memories] 下用 version = "v1" 或 "v2" 切换）。本机终端界面（走 codex app-server）实际使用的是 v2，目录为 ~/.codex/memories_v2/；而直接跑 codex exec 在未指定配置时默认走 v1（源码里 MemoriesConfig 的默认字段也是 v1，为什么 app-server 路径变成了 v2 尚未在源码里定位到【待核实】）。两版的产物和请求体积对比如下：10

对照：Claude Code 当场写入、按需读取

Claude Code 除了你手写的 CLAUDE.md，也有自动记忆（auto memory），在本地会话中默认开启，可通过 /memory 命令或环境变量 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 关闭。21

它的读写时机与 Codex 截然不同：Claude Code 由当前正在聊天的同一个模型在会话中途当场写入（界面会提示「Saved 2 memories」），你说一句「记住：测试用 pnpm」它立刻写盘，不需要等下一个会话触发后台任务。在读取上，Claude Code 开局只加载索引文件 MEMORY.md 的前 200 行或前 25 KB，具体的分类主题文件等模型需要时再去按需读取；而 Codex 是把整份 memory_summary.md 一次性塞进请求开头。

回答问题 2

记忆在什么时候写下来？后台提炼和合并旧会话时，会占用当前对话的上下文窗口吗？

记忆在你发出一轮消息时由后台异步启动，处理的是已经空闲满 6 小时的旧会话：先用 gpt-5.6-luna 提炼单个旧会话，再用 gpt-5.6-terra 合并进 memory_summary.md。这些后台请求独立于当前对话，不占用当前会话的上下文窗口，但共用同一个账号通道和额度【按源码推，未测真实账单】。

三、读取：开头多塞一段指令，超 1 万字节从中间截断

新会话读取记忆的方式非常直接：把 memory_summary.md 填进一段固定模板，塞进请求开头的开发者指令里。回顾第 2 章，gpt-6.1-sol 的请求输入依次是工具定义、系统提示词、开发者说明（含技能目录与权限），然后才是 AGENTS.md 和你的问题。打开记忆后，这段记忆说明就排在第三条开发者说明的最前面。实验里发送同一句「你好，帮我看看测试怎么跑」，不同配置下的请求体积变化如下：12

摘要超过约 1 万字节：保留头尾，截掉中间

读取摘要时有一道硬上限：2,500 token（Codex 按 4 字节 ≈ 1 token 本地估算，即约 10,000 字节），超出部分从正中间截掉。实验里放入一份 500 行、31,003 字节的英文摘要，实际进请求的只剩第 1–80 行和第 421–500 行，中间被替换成一行 …5251 tokens truncated…；换成 30 KB 的中文摘要，同样只留下头尾共约 1 万字节（约 3,300 个汉字）。这道截断上限与第二节合并智能体的 10,000 字节合格线正好配套。如果你自己手动编辑摘要文件，最重要的规则一定要放在开头或结尾，别埋在中间。13

摘要只在会话开头读一次，中途改文件或恢复旧会话都不重读

记忆摘要一旦在会话开头读入，就固定写进了这个会话的历史，后续轮次不再重新读取磁盘文件。实验里先开一个会话读入旧摘要，随后修改磁盘上的 memory_summary.md，再用 codex exec resume --last 恢复这个会话继续提问：发出去的请求里依然是旧摘要，新改的文字完全不会出现。这一点和 AGENTS.md 明显不同——第 8 章测过，恢复旧会话时 Codex 会比对并追加新版 AGENTS.md，但记忆摘要没有这个比对步骤。14

由于记忆说明排在第三条输入（在工具定义和系统提示词之后、AGENTS.md 和用户消息之前），只要后台更新了摘要，下一个新会话从第三条输入起的缓存前缀就会改变，前两条（工具定义和系统提示词）则不受影响【按第 5 章缓存规则推算，未测真实服务账单】。

回答问题 3

打开记忆后，新会话的第一次请求里多了什么？摘要太长或中途改了摘要文件会怎样？

请求第三条输入的开头会多出一段固定模板（v2 为 2,096 字节，v1 为 6,717 字节）加上 memory_summary.md 的内容。摘要超过约 10,000 字节（2,500 token）时只留头尾各约一半、截掉中间。摘要只在会话刚开启时读一次，会话中途或恢复旧会话时修改文件都不会生效。

四、纠错、开关与淘汰：30 天没人引用就出局

发现记忆里有错，有三种处理办法，但任何修改都要到新开的会话（或下一次后台合并后）才会体现在请求里：

  • 在对话里直接让 Codex 记下或改掉。记忆模板规定：只有当用户明确说出「记住……」「忘掉……」「把……改成……」时，模型才在记忆目录的 extensions/ad_hoc/notes/ 下新建一份随手笔记（文件名格式为 时间-短名.md），不直接改动总摘要文件。等下一次后台合并智能体运行时，会把这些笔记当作最高优先级的权威修正写入总摘要，并打上 [ad-hoc note] 标记。18
  • 手动打开 memory_summary.md 编辑。摘要本身就是普通 Markdown 文件。v2 的合并提示词明确要求后台智能体「保留用户的手动编辑，不要把用户已修正或删掉的结论恢复回来」。而且只要你改过这个文件，记忆目录的 Git 状态就会变化，下一次发消息时就会触发后台合并。18
  • 分开关闭读写或一键清空。只想暂停注入，设 use_memories = false（请求恢复到不开记忆时的大小）；不想让当前会话以后被提炼，设 generate_memories = false。还有一个防污染开关 disable_on_external_context（默认关闭）：打开后，凡是用过 MCP 工具或网页搜索的会话都会被标为已污染（polluted），不再纳入记忆提炼，防止外部网页或第三方工具返回的内容混进长期记忆。19

淘汰机制：按被引用次数排序，30 天未引用则出局

旧会话摘要不会无限堆积：每次合并最多取 256 条，优先保留被引用次数多的，超过 30 天没人引用的直接淘汰。

Codex 是怎么知道哪条记忆「被引用过」的？原来，记忆模板要求对话模型在每次回答末尾如果用到了某条记忆，就附带一段 <oai-mem-citation> 标签，写明引用了哪个摘要文件、哪几行以及对应的旧会话 ID。Codex 收到回复后，在展示给你看之前会把这个标签剥离掉，同时在后台数据库里给那个旧会话的引用计数加 1，并更新最近引用时间。16

当后台合并智能体挑选素材时，会按两条规则筛选和排序（默认过期天数为 30 天，可通过 max_unused_days 在 0–365 天之间调整）：17

  1. 先过滤过期条目：如果一条记忆被引用过，看它最近一次被引用是否在 30 天内；如果从来没被引用过，则看产生它的那个旧会话是否在 30 天内。超过 30 天的不再进入合并（若上次合并也没用到它，启动时还会直接从数据库清理掉）。
  2. 再按热度排序：未过期的条目，先按被引用总次数从高到低排；次数相同时，再按最近引用时间（未引用过的按会话活动时间）从新到旧排，取前 256 条送去合并。

回答问题 4

一条记错的记忆怎么纠正或清空？长时间没用到的记忆会被怎么处理？

纠正可以口头让 Codex 记笔记（写入 extensions/ad_hoc/notes/）或直接手改 memory_summary.md；彻底清空可用 /memories 里的 Reset all memories 或运行 codex debug clear-memories。模型每次用到记忆会在回复末尾附带隐藏的引用标签，超过 30 天未被引用（或从未被引用且会话已满 30 天）的记忆会被淘汰。

五、作用范围：一个用户共用一份，不按项目隔离

Codex 的记忆存放在全局的 CODEX_HOME（默认 ~/.codex）下，整个账号共用同一份 memory_summary.md，代码层面没有按项目目录做隔离。实验里切换到另一个完全无关的工作目录开启新会话，请求里注入的记忆说明段与原目录逐字相同。20

那不同项目的习惯怎么区分？全靠摘要里的文字标注：第一步提炼出的每个单会话摘要文件头部都记着当时的工作目录路径（cwd），第二步 v2 的合并提示词要求智能体把近期工作按 ### 项目范围 和 #### 日期 分组整理。至于对话模型读到总摘要时会不会把项目 A 的经验张冠李戴到项目 B，完全取决于模型自己的判断。因此，如果项目 A 用 pnpm 而项目 B 必须用 npm，最稳妥的办法是在项目 B 的 AGENTS.md 里明确写清构建命令，用项目级硬规则压住全局记忆。对比之下，Claude Code 的自动记忆存放在 ~/.claude/projects/<项目>/memory/ 下，天然按 Git 仓库隔离，不同项目互不干扰。2021

回答问题 5

在项目 A 里留下的记忆，会带进项目 B 的新会话吗？Claude Code 也是这样吗？

会。Codex 的记忆是一个用户全局共用一份，不同项目的新会话读到的是同一份 memory_summary.md，只靠摘要里的标题文字区分项目。Claude Code 则按 Git 仓库分目录存放自动记忆，不同仓库之间互不可见。

设计笔记

  • 后台事后提炼，而不是边聊边写。把记忆写入做成后台异步的两阶段任务，好处是不打断当前对话、不往当前会话历史里塞工具调用记录；代价是用户当场看不到它记了什么，缺少即时确认，且新记忆至少滞后一个会话才能生效【推测】。
  • 每个会话只在开头读一次摘要。把记忆固定放在第三条输入、且会话中途绝不重读，能够保证同一个会话在多轮对话和恢复会话时前缀保持稳定，有利于命中服务端前缀缓存；代价是会话中途刚刚合并出来的新摘要，当前会话自己用不上【推测】。
  • 靠隐藏引用标签来计票淘汰。用模型回复末尾的 <oai-mem-citation> 给旧会话记使用次数，30 天未引用就淘汰，相当于用「模型觉得有用」代替人工清理。隐患在于：如果某条记忆本身记错了，却在后续会话里被模型反复引用，它的排名反而会越来越靠前；源码里目前没有针对「被引用但内容有误」的自动降权机制【推测】。
  • 全局共用一份摘要，不按仓库隔离。跨项目共享的好处是用户的通用偏好（如回答用中文、提交信息风格）只需教一次就能处处生效；代价是项目特有的技术栈或命令容易串台，只能靠合并模型在摘要里分小节、以及用户在项目 AGENTS.md 里写明规则来兜底。

小结

你关心的环节Codex 的实际行为
跨会话保留信息的途径手写 AGENTS.md（每开新会话必读）、codex resume（原样接旧历史）、打开 memories（后台提炼旧会话摘要，新会话开头读入）。
记忆何时写入默认关闭；开启后在你发消息时触发后台任务，挑选空闲满 6 小时、10 天内的交互式旧会话，先由 gpt-5.6-luna 提炼、再由 gpt-5.6-terra 合并，最早到再下一个新会话才读得到。
记忆如何读入请求填入固定模板（v2 为 2,096 字节），塞进请求第三条输入的开头；摘要超过约 10,000 字节（2,500 token）时留头尾、截掉中间；每个会话只在开头读一次。
纠错与自动淘汰口头说「记住/忘掉」会写进 extensions/ad_hoc/notes/ 等下次合并生效，也可直接手改 memory_summary.md；按模型回复末尾的引用标签计数，超过 30 天未引用的淘汰。
跨项目是否隔离不隔离，整个 CODEX_HOME 共用一份摘要，靠摘要内的文字分组区分项目（Claude Code 则按 Git 仓库分目录隔离）。
