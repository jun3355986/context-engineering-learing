你只说了一句话，请求里装了 1.3 万 token

你在 Codex 里打一句「帮我看下这个报错」，它发给模型的远不止这句话：还有工具说明、系统提示词、会话设置、项目规则和环境信息。这一章把这次请求拆开，看每块是什么、占多少、为什么这样排，以及会话往下走时请求怎么变。

本章的数字都来自上面这个模型。思考级别（reasoning effort）指模型回答前想得多深，分 low、medium、high 等几档。换一个模型，请求的结构和大小都会变，第 1 节末尾用 gpt-5.5 做了对比。

1 一句话的请求，拆开看

真实抓到的这次请求有 53,637 字节，约 13,410 token，你的那句话只占 6 token。1 input 是请求里按顺序排好的消息列表，一共 7 条：

换个模型，请求就不一样

同一句话、同样是思考级别 low，换成 gpt-5.5，请求只有 36,201 字节，约 9,051 token，结构也不同：4

  • 工具定义不在 input 里，而是放在请求顶层一个单独的 tools 字段。
  • input 只有 4 条：系统提示词、技能目录和权限说明、AGENTS.md 和环境信息、你的话。没有协作模式，也没有两条子代理说明。
  • 工具和系统提示词是另一套：gpt-5.5 有 9 个工具，各自独立（执行命令、改文件、看图片等），共 9,414 字节；gpt-6.1-sol 是 3 组共 11 个工具，25,347 字节。系统提示词也是另一份。

原因在 Codex 内置的模型表：每个模型一行设置，这两个模型有好几项不同。我核对过的是工具放在哪：由 use_responses_lite 这一项决定。在这个版本的表里，只有 gpt-5.5 设成 false，工具放在顶层；其余模型都是 true，工具放进 input 第一条。4 工具集、子代理说明这些差别分别对应哪一项设置，我没有逐条核对【待核实】。模型一直在更新，所以本教程写数字时都注明模型和思考级别。

2 为什么这样排

从前往后，是从「所有人都一样」到「只属于这一轮」：

通用：工具定义 → 系统提示词。同一个模型、同一个版本，所有人、所有项目都一样。
会话配置：技能目录、权限、协作模式、子代理说明。跟这次会话的设置有关。
项目与环境：AGENTS.md、环境信息。跟你在哪个目录有关。
本轮：你的话。每次都不一样。

整个请求里没有 system 角色，只有两种：developer，指应用（这里是 Codex）写给模型的指令；user，指来自用户这边的内容。Codex 把 AGENTS.md、环境信息和你的话都放成 user，所以 AGENTS.md 虽然是规则，角色却是 user。3 历史里要是出现 system 消息，Codex 也会把它过滤掉。13

第 1 节末尾的 gpt-5.5 请求只有 4 条，排法相同：内置的在前，你的话在最后，也没有 system 角色。4

回答问题 2

请求由哪几块组成？谁前谁后？有没有 system 角色？

gpt-6.1-sol 的请求 7 条，顺序是：工具定义 → 系统提示词 → 会话配置（技能、权限、协作模式、子代理说明）→ AGENTS.md 和环境信息 → 你的话。没有 system 角色：前 5 条是 developer，后 2 条是 user。为什么稳定的放前面，见章末设计笔记。

3 AGENTS.md：读哪几份，怎么拼，多长会被截

最简单的做法是只读当前目录那一份。可大项目常在根目录写通用规则、在子模块写局部规则，只读一份就丢了另一半。Codex 沿着目录链把每一级都读进来，再用一个总预算封顶。

读哪几份

  • 先找项目根：从当前目录往上找，找到含 .git 的那一级就停（配置项 project_root_markers 可以改标记）。找不到，就只看当前目录。5
  • 每级最多一份：从项目根到当前目录，每一级按顺序找第一个存在的文件：AGENTS.override.md → AGENTS.md → 你在配置里加的备用文件名。5
  • 不往下看：当前目录下面的子目录不读。
  • 不信任的项目不读：项目在配置里被标成不信任（trust_level = "untrusted"）时，项目里的 AGENTS.md 一份都不读。6

怎么拼

从项目根往下，依次拼接。你个人的全局规则（~/.codex/AGENTS.md，同样优先找 override 那份）放在最前，和项目规则之间隔一行 --- project-doc ---。拼好的全文包成一条 user 消息，就是第 1 节的 input[5]。7 文件内容原样放进去，写在里面的 @某文件 不会被展开成那个文件的内容。9

多长会被截

项目里所有 AGENTS.md 合计最多 32,768 字节（32 KiB）。按字节算，不按字符；预算先给根目录，读一份扣一份；超出的部分从尾部截掉。截了不报错，也不告诉模型，只在日志里留一条警告。8 汉字在 UTF-8 里占 3 字节，所以 32 KiB 大约装 1.09 万个汉字。

回答问题 3

多级目录都有 AGENTS.md，读哪几份、怎么拼、太长会怎样？

读项目根（默认以 .git 为准）到当前目录这条链上的每一级，每级一份（AGENTS.override.md 优先），从根往下拼，个人全局规则排在最前。项目文件合计上限 32,768 字节，先给根目录，超了从尾部截掉，不报错也不通知模型。所以要紧的规则应该写在上层目录、写在文件前面。

对照：Claude Code 的 CLAUDE.md

据官方文档（2026-11-02 查阅）18，思路和 Codex 明显不同：

  • 往上：当前目录和它上面的每一级都读，文档没提在项目根停下。
  • 往下：子目录里的 CLAUDE.md，等 Claude 读、写或编辑那个子目录里的文件时才加载。Codex 不看子目录。
  • 长度：启动时加载的文件，每份都整份给模型，单个文件超过 4 MiB 才整份跳过。子目录里按需加载的 CLAUDE.md 另有单个文件的上限，按字符算：上下文窗口 20 万 token 时是 40,000 字符；100 万 token 时，Claude Opus 4.6 和 Sonnet 4.6 是 200,000 字符，之后的模型是 150,000 字符（v2.1.309 起）。超了只给开头，末尾附一句提示，让模型需要时用 Read 工具（读文件的工具）看剩下的。Codex 是项目文件共用 32 KiB，尾部静默截掉。
  • 导入：在 CLAUDE.md 文件里写一行 @路径（例如 @docs/规范.md），那个文件的内容就和 CLAUDE.md 一起加载。这是写在文件里的语法，不是在输入框里打的 @。被导入的文件里还能再写 @路径，一层套一层，最多 4 跳（原文 maximum depth of four hops）：CLAUDE.md 导入 A 是第 1 跳，A 再导入 B 是第 2 跳，依此类推。Codex 不展开 @。
  • 位置：同样作为一条 user 消息，放在系统提示词之后。

一句话：Codex 开局就把规则定下来，总量封顶；Claude Code 边干边加载，单个文件给得多，请求大小随你碰过的目录变化。

4 第二次请求：发出去的不一定等于模型看到的

模型回了一个工具调用（比如「执行这条命令」），Codex 执行完，要把结果交回模型，于是发第二次请求。最直接的做法是把整个请求再发一遍，末尾加上这次的工具调用和执行结果。Codex 走 HTTP 时正是这样；走 WebSocket（一条一直开着的连接）时，可以只发新增的部分。

走哪条：官方通道默认先走 WebSocket，出错且重试用尽后，这个会话剩下的请求全改走 HTTP；你在配置里自己加的第三方通道只走 HTTP。没有用户开关。12

传输方式：
第 1 次请求 · 线上发送
第 2 次请求 · 线上发送
第 2 次请求 · 模型看到的

回答问题 4

第二次请求，线上发出去的和模型看到的一样吗？

不一定。走 HTTP 时一样：整份重发，末尾多出工具调用和执行结果两条。官方通道默认走 WebSocket，这时线上只发新增的执行结果，再加一个「接着上次往下」的编号，模型看到的仍是完整历史。

5 会话中途变了，请求怎么变

最直接的做法是每次请求都重新拼一遍：重读 AGENTS.md、重新生成环境信息，替换掉旧的。这样请求的前半段会跟着变。Codex 不这么做。它把这些设置当成一组状态，每次请求前和上一次比：没变，什么都不加；变了，就在历史末尾追加一条更新，前面发过的内容一字不改。14 第 1 节的会话配置（权限、协作模式、子代理说明）、AGENTS.md、环境信息都按这个规则走。追加的更新排在你的新消息前面。14

环境信息：变了才追加

当前目录、日期、时区、网络、文件权限，任何一项变了（比如会话跨过了午夜），下一次请求就多一条新的环境信息。15

AGENTS.md：全局那份重读，项目那份不重读

两份 AGENTS.md 的待遇不一样：16

每次请求前重读吗中途改了会怎样

看源码：AGENTS.md 变了，追加什么

core/src/context/world_state/agents_md.rs 第 11–13、44–80 行，节选，省略了 current 的构造，注释是我加的。16

const REPLACEMENT_NOTICE: &str =
    "These AGENTS.md instructions replace all previously provided AGENTS.md instructions.";
const REMOVAL_NOTICE: &str = "The previously provided AGENTS.md instructions no longer apply.";

fn render_diff(&self, previous: PreviousSectionState<'_, Self::Snapshot>)
    -> SectionTransition<Self::Snapshot> {
    let current = /* 本次的快照：目录 + 全文 */;
    // 和上次完全一样：什么都不追加
    if matches!(previous, PreviousSectionState::Known(previous) if previous == &current) {
        return (None, Vec::new());
    }
    // 上次可能发过规则吗？不确定（Unknown）时按「发过」处理
    let previous_may_contain_instructions = match previous {
        PreviousSectionState::Known(previous) => previous.text.is_some(),
        PreviousSectionState::Unknown => true,
        PreviousSectionState::Absent => false,
    };
    let instructions = match (&self.instructions, previous_may_contain_instructions) {
        // 现在有、以前可能有：替换说明 + 全文
        (Some(instructions), true) => UserInstructions {
            directory: instructions.directory.clone(),
            text: format!("{REPLACEMENT_NOTICE}\n\n{}", instructions.text),
        },
        // 现在有、以前没有：直接发全文
        (Some(instructions), false) => instructions.clone(),
        // 现在没有、以前可能有：只发一句「不再适用」
        (None, true) => UserInstructions { directory: None, text: REMOVAL_NOTICE.to_string() },
        // 两边都没有：只记下快照
        (None, false) => return (Some(current), Vec::new()),
    };
    (Some(current), vec![WorldStateUpdate::fragment(instructions)])
}

它只回答「要不要追加、追加什么」。决定项目 AGENTS.md 要不要重读的，是另一个文件 agents_md_manager.rs：只有工作环境或信任级别变了才重新扫目录，否则直接用缓存。16

回答问题 5

会话中途改了项目里的 AGENTS.md，下一次请求模型能看到吗？

看不到。项目里的 AGENTS.md 一个会话只读一次，后面一直用当时的快照；要生效就新开会话（换工作目录或改信任级别也会触发重读）。全局那份 ~/.codex/AGENTS.md 不同：每次请求前都重读，改了会在历史末尾追加一条「替换之前全部 AGENTS.md 指令」的新消息。

设计笔记

  • 稳定的在前、变化的追加在后。Codex 自带测试明确要求：一般的第二轮请求要「保留前一次的前缀」（原文 retain the cached prefix）。17 可见保住前缀是设计目标，和提示词缓存有关；能省多少钱，第 5 章算。
  • 项目 AGENTS.md 为什么不中途重读？代码里没写理由。【推测】一是同一个会话里规则不会忽然变；二是工作环境可能在远程机器上，沿目录链探测文件要走网络（agents_md.rs:51-53 的注释提到探测走远程传输），每次请求都探测不划算。
  • 静默截断的代价。超了不报错，模型不知道自己少看了什么，你只能翻日志。因为从尾部截、先给根目录，要紧的规则写在根目录、写在文件开头最稳。
  • 和 Claude Code 的取舍。Codex 开局定死、总量封顶，请求大小可预期，代价是子目录里的规则用不上；Claude Code 按需加载，覆盖面大，代价是请求大小随你碰过的目录变化，什么时候加载了哪份规则也更难预料。

小结

  1. 一句 24 字节的话，请求约 1.34 万 token；你的话占 0.04%，工具定义和系统提示词合计 88%。
  2. gpt-6.1-sol 的请求 7 条：工具定义 → 系统提示词 → 会话配置 → AGENTS.md 和环境 → 你的话。没有 system 角色，只有 developer 和 user。
  3. AGENTS.md 读项目根到当前目录的每一级，每级一份，从根往下拼，全局规则在最前；项目文件合计 32 KiB，超了尾部静默截掉。
  4. 第二次请求：HTTP 整份重发；官方通道默认走 WebSocket，线上只发新增的，模型仍看到全部。
  5. 会话中途的变化都追加在末尾，不改前面。全局 AGENTS.md 每次重读；项目 AGENTS.md 一个会话只读一次，中途改了要新开会话。
